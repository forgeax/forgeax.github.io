1始める前に

ForgeaX とは何か、そしてそれが作るゲーム

ForgeaX は、AI ネイティブのゲーム開発スタジオです。あなたはゲームを平易な言葉で説明しています。と呼ばれる AI リードフォージ 計画し、設計し、実行中のゲーム コード自体に書き込みます、結果をブラウザにホットリロードします。あなたの発言があなたのプレイとなります。

その下には 2 つの社内基盤があります。AIの観点から再設計されたエンジン（見るなぜ AI ネイティブ エンジンなのか）と機能を正しい結果に収束させる開発ループ（見るAI が機能を適切に取得する方法）。

似合ってるよ2D / 2.5D / 3Dウェブゲーム。プレイ可能な FPS、ディアブロ スタイルの ARPG、2 レベルのサバイバルおよびシューティングのデモがすでに存在します (ショーケース);このエンジンは、PBR / IBL / SSAO レンダリング、2D/3D 物理学、スケルタル アニメーション、およびデュアル RHI をカバーします (このガイドの下部にある「エンジン機能」を参照)ショーケース）。

すべてが 1 つのスタック上のブラウザ (WebGPU)、Web、およびデスクトップで実行されます。 Apache License 2.0 に基づくオープン ソース (ライセンス）。

2中心となる概念

「プロジェクト」とはゲームです

ForgeaX では、「プロジェクト」と「ゲーム」は同じものです— ゲームは 1 つですゲーム/<スラッグ>/フォルダ。実際のゲーム フォルダーは通常次のようになります。

  • forge.json — ゲームマニフェスト。少なくとも 3 つのフィールド:ID、名前、 そしてエントリ(エントリーコードを指しながら、例:src/main.ts）。
  • FORGE.md — ゲーム独自の Readme / ゲームプレイの概要 (コントロール、メカニクス、ストーリー ビート)。
  • src/ — ゲームのコード。それに加えて、main.tsエントリでは、通常、関心ごとにモジュールに分割されます (例:プレイヤー.ts、敵/、エフェクト.ts、セットアップ.ts）。
  • design/ · assets/ — デザインドキュメントとアート/オーディオアセット。
  • package.json · tsconfig.json — 標準の TS プロジェクト ファイル。

のmain.tsエントリはエンジン機能をからインポートします@forgeax/エンジンランタイム/エンジンEC/エンジンアプリそしてエクスポートしますゲームエントリー— エンジンがゲームをロードするための契約。完全な機能セットについては、「エンジン機能」を参照してください。ショーケース。

複数のゲーム = 複数のプロジェクト。トップバーのプロジェクトスイッチャーで切り替えられます。シーン/レベルの構成方法については、を参照してください。シーンとエディター。

セッションとは何ですか

あセッションそれはエージェントの記憶です -追加のみイベントのストリーム (それぞれがユーザー メッセージ / アシスタント メッセージ / 思考 / ツール呼び出し / ツールの結果)。 Forge (メイン) と各サブエージェントはそれぞれ独自のものを保持します。

UI は、イベントをメイン スレッドとサブエージェントに発行した人によってイベントを分割し、各サブエージェントのスライスを埋め込みカードとしてレンダリングします。したがって、1 つの画面に、Forge のメイン スレッドと、Forge がディスパッチしたサブエージェントが実際に行ったことの両方が表示されます。

上部バーのセッション スイッチャーを使用して、過去のセッションを確認して切り替えることができます。セッションを切り替えても何も再開されない— UI は別のエージェントのイベント ストリームを読み取るだけです。

3チャットで構築する

自分のアイデアを明確に説明する方法

より具体的であればあるほど、Forge は最初に試行するやり直しが少なくなり、より適切な結果を得ることができます。通常、適切なプロンプトには次の内容が含まれます。

  • ジャンルと見方— トップダウン / 一人称視点 / 2.5D 横スクロール…
  • コアループ— プレイヤーがやり続けることの 1 つ
  • コントロール、勝ち/負け、敵/障害物、そして感じる

小さなことから始めて実行し、その後メカニズムを重ねていきます。例えば：

トップダウン ゲーム: キャラクターがアリーナを走り回り、宇宙から弾丸が発射され、敵が出現し続け、ヒットで敵を除去し、スコアを追加します。

最初のゲームの段階的な手順については、「クイックスタート;何が達成できるかについては、ショーケース。より重い設計の場合、Forge は設計サブエージェントを取り込みます (「中心となる概念）。

Forge の計画、コーディング、実行を観察する

リクエストを送信すると、チェーンは次のようになります。

  • 理解+計画— Forge は要件を明確にし、より重い作業のためにデザイン/ゲームプレイのサブエージェントを派遣します (「中心となる概念）。
  • コードを書く— フォージは書きます自体の中へゲーム//src/main.ts(およびその分割モジュール)。
  • ホットリロード— 保存時に、エンジンの vite が変更を検出し、プレビューします。モジュールを活性交換します所定の位置に — 完全なリロードは不要で、画像はほぼ瞬時に更新されます。
  • 結果を見る— Forge はプレビューを通じて実行結果を確認します (これにより、ゲームの転送も行われます)コンソール戻る)、次のステップを決定します。

プロセス全体は透過的です。メッセージ ストリームには、Forge の思考、各ツールの呼び出し、および派遣されたサブエージェントのカードが表示されます。プレビューと拡張ページの切り替え/制御については、を参照してください。シーンとエディター;ホットリロードの仕組みについては、を参照してください。実行とプレビュー。

4シーンとエディター

プレビューウィンドウと拡張ページ

右側のメイン領域では、2 つのビューが切り替わります。

  • プレビュー— ゲームは iframe でライブ実行され、FPS 読み出しと再生 / 一時停止 / リロード コントロールが使用されます。 Forge がコードを記述すると、ここで即座にホットリロードされます (「チャットで構築する）。
  • 拡張ページ— ファイル ブラウザ + エディタ: テキストとコードの表示/編集/保存、マークダウン設計ドキュメントのレンダリング、画像、オーディオ、ビデオ、および 3D モデルのプレビュー。また、ファイルのアクティビティや「誰が編集しているか」のロックも明らかになるため、ユーザーと AI は同じファイルを破壊することなく編集できます。

ファイルが開かれていない場合、拡張ページにはすべての作成拡張ページ (キャラクター / アニメーション / 3D / シーン / UI / 音楽など) のエントリが表示されます — を参照してください。作成ツールそして市場。アセットの作成については、を参照してください。資産。

シーンを編集すると、変更がライブで反映されます

シーン エディターはレベルのコンテンツをシーンデータファイルゲームフォルダー内 (シーン.パック.json) —唯一の真実の情報源そのレベルの場合: ディスク上にあるものがゲーム内で実行されます。

オブジェクトを配置して編集モードを終了すると、変更は次のようになります。ディスクにフラッシュされ、実行中のゲームがそれらを再読み取りします, そのため、プレビューには編集がすぐに反映されます (編集→再生の往復)。逆に、Forge がチャットによってコードを変更すると、同じホットリロード パスが実行されます (「チャットで構築するそして実行とプレビュー）。
