ワンタップのコンテキスト圧縮 + WebGPU ソフトウェア フォールバック

この日は「長い会話やあらゆる種類のマシンが故障しないようにする」ことに取り組みました。ワンタップの会話圧縮、目に見えるコンテキストゲージ、スラッシュコマンドの自動補完。ハードウェア アクセラレーションが欠落している場合の 3D のソフトウェア フォールバック。新しいゲームはクリーンな ECS テンプレートから開始され、エンジンには 2D スプライトシート アニメーションと一連の堅牢性修正が追加されました。

「長く・幅広く使える」を確固たるものにする

機能が整ったら、次の質問は、それを長期的かつ広範囲に使用できるかどうかです。長期とは、コンテキストが溢れ出ることなく 1 つの会話が継続できるかどうかを意味します。幅広いとは、開発者のハイエンドマシンだけでなく、あらゆる種類のマシンで実行できるかどうかを意味します。この日の項目は、それぞれこれら 2 つに答えます。ワンタップの会話圧縮は「長時間チャットすると天井に達する」という問題に対処し、WebGPU ソフトウェアのフォールバックは「適切な GPU がないということは黒い画面を意味します」という問題に対処します。クリーンなニューゲームの開始点、2D アニメーション、堅牢性の修正を加えれば、全体像は明らかです。新しいギミックではありませんが、「より多くのマシンでの毎日の長時間実行」を確実なものにします。

ワンタップ圧縮: /compact + コンテキスト使用リング

大きなモデルを長くやり取りすると、モデルが保持できる「コンテキスト」が積み重なっていきます。限界に近づくと、応答が遅くなり、品質が低下し、さらには忘れ始めます。この日は、/compact コマンドを追加しました。ワンタップで以前のやり取りが簡潔な要約に圧縮され、作業を続行するためのスペースが解放されます。また、圧縮自体は会話のターン全体を消費するものではなく、バックエンドで直接行われます。また、作曲家は、燃料計のように予算がどのくらい残っているかを一目で示す「コンテキスト使用リング」も獲得しました。そのため、予算がいっぱいになりそうになったら、それを見て、片づけるべきかどうかを積極的に決定できます。スラッシュ コマンド オートコンプリートを使用すると、 / を入力すると、使用可能なすべてのコマンドが表示され、すばやく選択できます。この一連の変更は、「AI との長期的なコラボレーション」という中核的な制約に正面から直面しています。つまり、コンテキストは有限です。管理をユーザーの手に委ね、簡単に実行できるため、長時間のセッションが本当に持続可能になります。

WebGPU ソフトウェア フォールバック: 3D はより多くのマシンで実行されます

3D レンダリングは最新の GPU の機能に依存しますが、実際には一部のマシンや環境ではハードウェア アクセラレーションを利用できません。おそらく GPU が古すぎるか、ランタイムに制限がある可能性があります。以前は、これは黒い画面を意味し、ユーザーを完全にシャットアウトしていました。この日は、ソフトウェア フォールバックが追加されました。ハードウェア アクセラレーションのレンダリング デバイスが入手できない場合、システムはステップバックし、ソフトウェア実装を使用して画像をレンダリングします。速度は遅くなりますが、少なくとも実行、表示され、作業を続けることができます。その下に、マルチレベルのフォールバックが追加され (失敗した場合は次のパスを試行し、エラーは最後の手段としてのみ)、ハードウェア アクセラレーションが使用されなかった理由 (たとえば、安全でないオリジンで実行されている場合) を説明する明確な診断が追加されました。重要なのは対象範囲です。大衆市場向けのプラットフォームでは、誰でも始められるようにしたいため、誰もがハイエンド マシンを持っていると想定することはできません。より弱いマシンで実行することも、本当にハードルを下げます。

新しいゲームはクリーンな ECS テンプレートから始まります

新しいゲームの作成は、適切なアーキテクチャに沿って編成されたクリーンで適切に構造化されたテンプレートから生成されるようになりました。この日は、そのデフォルトのテンプレートを「適切な ECS アーキテクチャ」スタイルで書き直し、インライン文字列からバージョン管理されたスタンドアロン ファイルに抽出し、行数を半分に減らしました。つまり、ゲームを作成した瞬間に、編集する前に最初に理解する必要がある定型文の山ではなく、構築の準備が整ったクリーンでコンパクトなベースが得られることを意味します。 AI に供給されるテンプレートとシステム命令は、最新のエンジン インターフェイスに更新されました。これは、「AI がゲームを書く」場合に特に重要です。AI はテンプレートの形状を継承するため、テンプレートがよりクリーンで標準的であればあるほど、AI のコードが正しい可能性が高く、読みやすく再利用しやすくなります。適切な出発点があれば、後から数え切れないほど修正を加える必要がなくなります。

2D スプライトシート アニメーション

このエンジンはこの日、2D スプライト シート アニメーションを追加しました。「スプライト シート」(1 つの画像内にレイアウトされた一連のアクション フレーム) から複数のフレームを順番に再生し、2D キャラクターとエフェクト アニメーションに既製の標準的なアプローチを与えました。これは 2D ゲームで最も一般的なアニメーション方法です。小さな人物が歩いたり、炎が点滅したりするのは、基本的に数フレームが高速で循環するものです。これ以前は、2D コンテンツは静的なスプライトのみでした。シートアニメーションを使用すると、2D ラインを実際に動かすことができます。以前のスプライト レイヤーと合わせて、エンジンの 2D の基本、つまり正しいレイヤー化とスタッキング、さらに各スプライトの動きを実現します。 2D ゲームを作りたい人にとって、これは「画像を配置できる」から「アニメーションができる」までの重要なステップです。

エンジンの堅牢性: 回帰テスト + 一連のレンダリング修正

この日、エンジンは地味だが重要な堅牢性の向上にも取り組んだ。回帰テストは、レンダー クエリ、親子階層、「シーンにライトが 1 つもない」というエッジ ケースなど、失敗しやすいいくつかの状況に対して追加されました。これにより、将来の他の場所での変更によってそれらが壊れることがないよう、テストで問題を特定します。一部のあいまいな名前のフィールドは、コードが読み間違えられにくくなるように、より正確に名前が変更されました。また、マージ後にのみ表面化したいくつかの互換性の問題が修正されました。これらは、「新たに追加された機能を徹底的に検討する」作業です。前日までに多くの機能を集中的に追加した後、この日はテストを追加してエッジをクリーンアップし、機能が「一度だけ実行される」だけでなく「今後も信頼性が維持される」ことを確認しました。高速な反復と安定した統合を交互に行うことで、この製品ラインは稼働し続けることができます。
