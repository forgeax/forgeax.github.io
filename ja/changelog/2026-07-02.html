Forge は長期記憶を獲得します: 話せば話すほど、より多くのことを知るようになります

この日の最大の変更点は、Forgeに「長期記憶」を与えたことだ。以前は、新しい会話はすべて初対面のように始まりました。過去のセッションから重要な情報を自動的に抽出し、新しいセッションでそれを呼び出すことができるようになりました。ユーザーの設定、プロジェクトの規約、修正途中のバグなど、すべてを覚えています。メモリの切り替えが [設定] パネルに追加されたため、常に制御できるようになります。エディター側では、メッシュ パネルにエンティティごとのジオメトリ統計を表示できるようになりました。その下に、新しいエージェント/ホスト プロセス スーパーバイザが配置されました。また、Cursor の統合を妨げていた Windows の引数の長さの制限が修正されました。

魂の記憶：「毎回新しく始める」から「進みながら学ぶ」まで

AI アシスタントに関して最もイライラすることの 1 つは、「セッション間の記憶喪失」です。昨日 20 分かけて、プロジェクトのコード規則、名前の設定、避けるべき落とし穴を説明し、今日新しい会話を開いたら、すべて忘れられてしまい、ゼロからスタートすることになります。この日出荷されたソウルメモリーシステムは、それを解決するために存在します。各会話の終わり (または会話中の適切な瞬間) に、「このプロジェクトは Node ではなく Bun を使用している」、「ユーザーは過剰なコメントのない簡潔なコードを好む」、「ゲームの主人公の名前はアリン」など、長期保持する価値のある情報を自動的に抽出し、これらの記憶をディスクに保存します。新しい会話が始まると、これらの記憶が Forge のコンテキストに注入されるため、会話は「記憶から始まる」ようになります。技術的には、メモリ抽出ではフォーク メカニズムが使用されます。現在の会話から軽量の抽出タスクをフォークし、進行中のチャットを妨げることなく非同期で実行し、完了するとメモリ ストアに書き込みます。

設定パネル: メモリを制御可能

記憶力があるのは良いことですが、「何を覚えるべきかをAIが勝手に決める」ということも不安になることがあります。そこでこの日、[設定] パネルに [メモリ] セクションも追加されました。自動メモリ抽出のオンとオフを切り替えたり、Forge が記憶した内容を確認したり、保持したくないエントリを削除したりできます。この設計は原則に従っています。AI は積極的に学習できますが、人間は常に拒否権を持っています。メモリ スイッチはデフォルトでオンになっています (そのため、ほとんどのユーザーはすぐに恩恵を受けることができます) が、ワンクリックでいつでもオフにできます。オフにすると、Forge は残留物のない「毎回新しく開始する」モードに戻ります。

エディタ: メッシュ パネルにはエンティティごとのジオメトリの詳細が表示されます

この日、エディターのメッシュ パネルに便利な小さな機能が追加されました。エンティティ モードでは、各オブジェクトに頂点数、三角形数、マテリアル数などのジオメトリ統計が並べて表示されます。以前は「これはメッシュだ」ということだけしか見えず、その重さを知ることができませんでした。これで、「このモデルには 500K の面があり、おそらくデシメーションが必要である」または「これは 200 の面しかないので、多く配置しても安全である」ことが一目でわかります。以前に表示されていた「種類」フィールドは、この文脈では誤解を招く可能性がありましたが、同時に非表示になりました。小さな変更のように見えますが、シーンの最適化を行う人にとっては、ポリゴン数を確認するためだけに外部ツールを開く必要がなくなったことを意味します。

エージェントホスト: エージェント専用のハウスキーパー

新しいエージェント/ホスト プロセス スーパーバイザがインフラストラクチャ レベルに導入されました。エージェントの「家政婦」と考えてください。リング 0 サイドカーとして実行され、エージェント プロセスのライフサイクル管理 (開始、監視、再起動、正常なシャットダウン) とプロセス間通信 (IPC) を処理します。以前は、エージェントのプロセス管理はコードベース全体に分散しており、統一されたスーパーバイザーはありませんでした。エージェントホストを使用すると、クラッシュしたエージェントが自動的に再起動され、複数のエージェント間のメッセージ受け渡しに標準チャネルが使用されます。これは、チームのマルチエージェント コラボレーションをより堅牢にするインフラストラクチャです。チームは、誰かが各メンバーを「監視」している場合にのみ効率的に作業できます。

Windows CLI の修正: カーソル統合が切り詰められなくなりました

Windows のみの問題も修正されました。カーソルを介して Forge CLI を呼び出すと、引数の長さの制限により、長いプロンプトが Windows の「cmd.exe」によって切り詰められ、エージェントが命令の半分しか受信できなくなりました。この修正により、コマンドライン引数の長さの制限が回避され、代わりに標準入力を介してプロンプトが送信されます。この種のプラットフォーム固有のエッジケースは潜伏性があり、Mac では完璧に動作しますが、Windows では不思議なことに失敗します。しかし、これを修正することは Windows ユーザーにとって真の信頼性を向上させます。

この日が意味するもの

この日のキーワードは「積み重ね」。ソウルメモリーとは、Forge の機能が毎回ゼロにリセットされるのではなく、使用するたびに蓄積されることを意味します。使用すればするほど、プロジェクト、習慣、好みをよりよく理解し、より効率的になります。エージェントとホストはマルチエージェントのコラボレーションに信頼性の高い基盤を提供し、エディターのジオメトリ統計は最適化にデータ基盤を提供します。すべての変化は同じ方向を向いています。つまり、Forge を「各セッションを即興で提供する派遣社員」から「覚えていて信頼でき、長期的に一緒に働けるパートナー」に変えるのです。
