コマンド 1 つ — Windows でも利用できるようになりました

この日、インストールおよび起動スクリプトが bash からクロスプラットフォームの Bun TypeScript に大幅に移行されました。同じコマンドが macOS、Linux、Windows で同様に実行され、Windows は Git-Bash を必要としなくなりました。一連の Windows 固有のブロッカーを修正するとともに、「セッション」をグローバルにバインドされたものからゲームごとにスコープされたものに変更し、アセットのインポートをより安定させ、基盤となる CLI をより高速にし、より制御しやすく、監査しやすくしました。

最大の障壁: プラットフォームを切り替えるとインストールできない

長い間、これをインストールして実行するには、大量の bash スクリプトが必要でした。 macOS と Linux には問題ありませんが、Windows ユーザーにとっては厳しい壁です。bash は Windows にネイティブではないため、Git-Bash などの互換性レイヤーをインストールするか、さまざまな不可解なエラーが発生する必要がありました。 「誰でもアイデアをゲームにできるようにしたい」というツールにとって、「インストールされない」ということは、最初の失敗として最も致命的です。この日はまさにそれを修正しました。すべてのインストールおよび起動スクリプトを、bash から Bun によって実行されるクロスプラットフォーム TypeScript に大規模に書き換えました。 Bun は 3 つの主要なシステム間で同一に動作するため、Windows 上でも Mac 上とまったく同じコマンドとロジックが実行され、互換性レイヤーは必要ありません。

コマンドは 1 つの記憶に残るセットにまとめられます

移動に伴い、エントリポイントも整理されました。過去に散在していたプラットフォームごとのスクリプト (.sh、.bat、.ps1 など) は一緒に削除され、1 つのプレーンで覚えやすいセットに統合されました。環境を 1 回インストールするための bun run setup、スタック全体を起動するための bun run start、それを停止するための bun run stop、デスクトップ アプリ用の bun run app です。どのようなシステムを使用しているとしても、覚えておく必要があるのはこれらのいくつかだけです。新規ユーザーにとって、これは「README から 4 行をコピーすると実行される」ことを意味し、「Windows を使っているが、これをどれと交換すればよいか」という必要はもうありません。既存のユーザーにとって、これは「各スクリプトの 2 つのコピー (sh 1 つ、ps1 1 つ) を同時に編集する必要があり、見逃しやすい」というメンテナンスの負担がなくなることを意味します。複数の同等のスクリプトを 1 つのクロスプラットフォームの信頼できるソースに統合することが、その日の作業の中心です。同期を維持する必要があることが 1 つ減り、間違いが 1 つ減ります。

Windows 固有の一連のブロッカーをクリアする

Windows を本当にスムーズにするには、クロスプラットフォーム スクリプトだけでは十分ではありません。Windows でのみ表面化する奇妙な点も 1 つずつ修正する必要があります。この日扱われた典型的なケースは、システムの「偽」 Python です。Windows には、実際にはインストールされておらず、呼び出されたときにのみアプリ ストアを表示する python3 プレースホルダーが同梱されています。また、単純に動作すると想定しているスクリプトは、セットアップ中に不思議なことに停止します。この日は、プレースホルダーを認識してスキップし、実際に動作する Python を見つけるインストール フローについて説明しました。このような詳細 — 他のシステムには存在せず、Windows でのみつまずく — は、クロスプラットフォーム サポートの最も骨の折れる、しかし最も必要な部分です。追加機能はありませんが、各機能が修正されるということは、一連の Windows ユーザーが停止する時間が 1 回減り、作業を続けることができることを意味します。

セッションがグローバル バインドからゲームごとのスコープに変更される

この日は、セッションが誰に属するかという、より内部構造にも触れました (セッションは Forge との会話の 1 つの延長です)。セッションは以前はグローバルであり、特定のゲームとは別のものでした。この日は、ゲームごとにスコープを設定して、各ゲームの下にそれらをネストしました。意味: 「スペース シューター」プロジェクトに関するフォージとの会話と「ファーム シム」プロジェクトに関する会話は、それぞれ独自のものとなり、互いに混ざることはありません。これはより直観的であり、そもそも会話は特定のゲームに属しており、後でよりクリーンなプロジェクト管理のための基礎を築きます。ゲームを切り替えると、混合セッションの 1 つのグローバル ポットに直面するのではなく、そのチャット履歴とコンテキストが付属します。この種の「データを本来の場所にファイリングする」という整理整頓は、日常的には地味な作業ですが、システム全体のメンタル モデルをクリーンに保ちます。

より安定したアセットインポート + より高速で制御しやすい CLI

この日は、毎日の使用をより安定させるためのいくつかの修正も行われました。アセットに関しては、より大きなモデルをインポートする際のインデックス作成の問題 (大きなメッシュでは頂点のインデックスを作成するためにより広い整数が必要ですが、以前は失敗していました) が修正され、モデルのインポートで書き込まれるメタデータが 1 つの標準形式に従うようになりました。そのため、より大きく、より複雑なモデルのインポートが簡単に失敗することはなくなりました。 AI を駆動する CLI コアにもいくつかの改良が加えられました。冗長性をトリミングして、場合によっては最初のターンがより速く動作し始めるようにしました。エージェントの「行動規範」を導入する際の問題を修正します。ユーザー自身の外部ツールのオプションのマスキングと、ホスト ツールに対するエージェントの呼び出しの監査証跡を追加します。後者は、「AI が今回実際にどのツールを使用したか」を意味し、記録上追跡可能になります。これにより、「より高速で、より制御可能で、より信頼できる」という基盤がさらに強化されます。

この日が意味するもの

この日の主役は「結界」。どんなに強力なツールであっても、システムが間違っていてインストールされないという理由で大規模なグループが締め出されてしまうと、誰かが使用する前にその価値の半分が失われてしまいます。インストールと起動を完全にクロスプラットフォームにすることで、Windows ユーザーも 1 つのコマンドで実行できるようになり、その扉が誰にでも開かれます。これは、「誰でもゲームを作成できる」という前提条件の 1 つが当てはまります。そして同じ日に、ゲームの下でセッションをファイルし、アセットのインポートが安定するように修正し、CLI コアをより高速かつ監査可能に磨き上げることで、ドアが開いている間に部屋が片付きました。参入障壁を下げ、次に内部の品質を高めます。この日はその両方が行われました。
