ゲームをスタンドアロン サイト + スカイボックスおよびブルームとしてエクスポートする

この日は「構築から出荷まで」の大きな一歩を踏み出しました。ゲーム全体を自己完結型の静的 Web サイトとしてエクスポートし、任意のホストにドロップして実行できます。シーンには実際のスカイボックスとブルームが追加され、複合オブジェクトは正しく配置されます。プレビューはプレフィックス付き URL で正しく読み込まれます。インタラクティブナラティブ パイプラインは完全なループを実行します。

「作った」から「送った」まで

ゲーム プラットフォームの場合、「構築」できるだけでは十分ではありません。作成したものをツールから離れて他の人がプレイできるように、「出荷」できなければなりません。この日最も重要だったのは、「エクスポート」ステップの入力でした。つまり、ゲーム全体を、誰でもホストでき、誰でも開くことができる Web サイトにパッケージ化することでした。一方、エンジンは雰囲気のためにスカイボックスとブルームを追加し、展開の柔軟性のためにプレフィックス付き URL での読み込みを修正し、ナラティブ パイプラインをループに実行しました。一方では「見栄えをよくする」、もう一方では「完成したら取り去る」という、作ることを楽しむことと、その結果をどこかに届けることという、創作の両端を押し上げた一日でした。

ゲームを Web サイトにパッケージ化して持ち運べます

出荷に向けた大きな一歩です。ゲーム全体を自己完結型の静的 Web サイトとしてエクスポートできるようになりました。スタジオ全体を持ち込む必要はありません。エクスポートしたフォルダーを任意の静的ホストにドロップすると、フォルダーが自動的に実行されます。言い換えれば、ここでチャットして作成したゲームは、このツール内に閉じ込めるのではなく、パッケージ化したり、友達に送ってプレイしたり、オンラインで全員が楽しめるようにしたりすることができます。最初にエクスポートされたサンプルは、エクスポート チェーン全体を実行して検証するために、Sector Strike と呼ばれる FPS ゲーム (独自のシーンと Readme 付き) として付属していました。重要なバグも修正されました。バックエンドのルート アドレスがフロントエンドのルーティング ルールによって誤って「キャプチャ」され、一部の埋め込みページが開かなくなりました。修正されると、エクスポートされた製品は、フロントエンドとバックエンドのリクエストをそれぞれ適切な場所に確実にルーティングします。 「ツール内で遊べる」から「ツール外で遊べる」へ、出荷への道が初めて開かれます。

スカイボックス + ブルーム: より雰囲気のある

この日、エンジンにはすぐに目に見える 2 つの機能が搭載されました。 1 つは可視のスカイボックスです。シーンの背景はもはや平らな単色ではなく、シーン全体を包み込む実際の空の環境であり、遠くに空と雰囲気があります。空間の感覚がすぐに変わります。もう 1 つはブルームです。明るい領域に柔らかい光があふれます。ネオンサイン、強い光源、光る物体が後光を放ちます。これは、SF、夢のような雰囲気、または夜景の雰囲気を表現する最も一般的な動きです。どちらも見た目と感触に直接作用する「雰囲気効果」です。その下には、階層的な世界が変化するという重要なことが配線されていました。親と子の位置、回転、スケールがレイヤーごとにレンダラーに正しく伝達されるようになりました。これは、複合オブジェクトのパーツ (武器を持ったキャラクター、パーツが取り付けられた乗り物) が最終的に位置ずれすることなく、全体とともに正しく配置および移動することを意味します。雰囲気と正しい階層が組み合わさることで、シーンは見栄えが良く、「正しく配置された」ものになります。

プレビューは URL プレフィックスの下で正しく読み込まれます

この日は、地味ではあるが展開の柔軟性が重要なパス、つまりプレビューですべてのリソースを「URL パス プレフィックス」の下で正しく読み込むという作業にも取り組みました。実際のデプロイメントの多くでは、アプリは Web サイトのルートではなく、サブパス (サイトのサブディレクトリ) の下にあります。リソース アドレスがそのプレフィックスを考慮していない場合、読み込みでファイルが見つからず、エラーが発生します。この日は、エンジンからパッケージング、リソース インデックスに至るチェーン全体を「パス プレフィックスを尊重する」ように調整し、再び問題が起こらないように回帰テストをロックしました。また、必要なランタイム部分の完全なセットが起動前に正しく構築されるように、起動フローも修正されました。これは、環境問題の中で最も頭痛の種となる「別の場所にデプロイするとロードが中断される」という問題に対処します。このパスが機能するということは、エクスポートされたゲームと埋め込まれたプレビューがそのリソースを確実に見つけて、どのような URL パスの下に配置されていても実行されることを意味します。これはまさに、「Web サイトにパッケージ化して取り込む」ことを真に使用可能にする根本的な保証です。

インタラクティブナラティブ パイプラインは完全なループを実行します

この日、物語主導のゲームのストーリー パイプラインがエンドツーエンドのループに配線されました。プロットは本質的に分岐する「ストーリー ツリー」であり、そのツリーを正しく描画して実行することは、一連のやっかいな問題を解決することを意味します。繰り返される番号付けの曖昧さをなくし、バック エッジを修復し、長いスパンの接続をルーティングし、最初から見えるように起動時に自動マウントすることです。この日はすべて修正され、ストーリー全体の構造が正しく表示されます。ナラティブを担当するエージェントは完全なパイプライン ツールセットに接続され、実行中に進行状況をライブでレポートします。重要な部分: パイプライン全体が終了すると、システムは途中で停止して未解決の終わりを残すのではなく、そのエージェントを自動的にウェイクアップして終了の要約を実行します。これにより、分岐があり、テンポの良いプロットを構築することは、最初から最後までスムーズで目に見え、自動的に終了する流れになります。物語のラインは、「ツールがある」から、真の意味で「一度最後まで実行できる」へと移行します。

この日が意味するもの

この日の最も重要な変化は、プラットフォームが初めて完全な「出口」を持ったことです。以前は、どんなによく作られていても、ゲームはまだツールの中に閉じ込められていました。 「Web サイトとしてエクスポート」と「どのパスでも正しくロード」を組み合わせることで、あなたの作品が初めてここから純粋に発信され、他の人に届くようになります。スカイボックスとブルームによって見栄えが良くなり、物語のループによって完成度が高まり、この日は「作成 - 形をとる - 船」チェーンの最後のリンクを埋めました。創作ツールの価値は、最終的には「作ったものが世界に見てもらえるかどうか」で決まります。今日から、ここで作成するゲームは単なるローカル デモではなく、パッケージ化し、ホストし、誰でもプレイできるように共有できる実際の作品になります。
