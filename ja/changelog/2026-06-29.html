Forge はチームワークを学習します: 一度に多くのエージェント

この日の最大の変化: Forge はもはや孤独なワーカーで次々とタスクを実行するのではなく、チームを編成することができます。複数のエージェントが 1 つのタスク ボードを共有し、並行して作業を進めます。また、エディターの単一メッシュ シーン アセットはディスクに保存され、再度開いてもプレイテストでも存続するようになりました。最初のパッケージ化 UI が表示されます。 QR をスキャンして、携帯電話から作業エージェントを引き継ぐことができます。特定の扱いにくい書式設定でチャットがフリーズすることもなくなりました。それに加えて、プロジェクトの日常的なコマンドは 1 つのエントリ「bun fx」に統合されました。

「1 つの鍛冶場」から「チーム」へ

これまで、Forge はリクエストを受け取ると、基本的に計画、コードの作成、検証を順番に段階的に実行していました。小さなタスクには問題ありませんが、リクエストが大きく、いくつかの独立したチャンクに分割される場合、シリアルがボトルネックになります。一度に実行できるものがキューでスタックしてしまいます。この日は、マルチエージェント チーム モードを導入しました。Forge は、1 つのタスク ボードを共有する多数の「チームメイト」エージェントを育成し、各エージェントが並行して要求して進行し、結果をまとめて折り返すことができます。技術的には、これは複数の機能が連携して動作するものです。つまり、チームメイトを同時に実行できるエグゼキュータ、チームメイトが互いにメッセージを送信できるインプロセスの「メールボックス」、誰もが参照、要求し、一貫性を保つことができる共有タスク テーブルです。 「1 つの AI を指導する」ことを「AI のチームを指導する」ことにアップグレードします。

デフォルトでオン、「コーディネーター ビュー」

この日の時点では、チーム モードはデフォルトでオンになっています (スイッチは維持されているため、いつでも単一のエージェントに戻ることができます)。 「多数のエージェントが勤務中」がわかりにくくなるのを防ぐために、「コーディネーター ビュー」が付属しています。コーディネーターが仕事をタスクに分割し、割り当てて進捗状況を監視します。このビューから、「誰が今何をしているのか、どこまで進んでいるのか」が明確にわかります。同時に、システムは、必要に応じて、参加しているエージェントに「あなたはチーム モードです」と示唆するため、エージェントの動作は単独で作業する場合とは異なります。つまり、それぞれが独自の方法で作業を複製するのではなく、ボードからタスクを要求して協力することを知っています。デフォルトでオンになっているということは、これが片隅にある実験ではなく、この日からの Forge のデフォルトの作業方法の 1 つであることを意味します。

エディター: 単一のメッシュがシーン内に留まるようになりました。

編集者は信頼性の重要な部分を記入しました。以前は、スタンドアロン メッシュをシーンに配置した後、その「シーン アセット」がディスクに確実に保存されなかったため、プロジェクトを再度開くか、▶ を押してプレイテストすると、メッシュが消えたり、レンダリングに失敗したりすることがありました。この日は、単一メッシュ シーン アセットがディスクに書き戻されて正しく保持されるようになりました。配置したものは閉じて再度開いた後もそこに残り、プレイテストに切り替えると通常どおりレンダリングされます。また、メッシュをドラッグすると、テクスチャのない灰色の塊に変わるのではなく、メッシュの元の glTF マテリアルが復元されます。見たとおりの編集体験を実現するには、「配置したものがそこに残る」という最も基本的な信頼が、この日それを完了しました。

最初のパッケージング UI + 携帯電話からの引き継ぎ

さらに2つのことにより、「作品を持ち歩く、いつでも見る」がよりスムーズになります。まず、最初のパッケージ化 UI がエディターの上部バーに表示されます。パッケージ化のターゲット プラットフォーム、エンジン ルートの選択、履歴、およびその他のオプションが表示される UI (バイリンガルも) に移動され、「ゲームを配布可能なビルドにエクスポートする」ことがコマンド ラインからグラフィカル インターフェイスに一歩近づきます。次に、「QR をスキャンして携帯電話から引き継ぐ」機能が登場しました。コードをスキャンすると、電話で勤務中のエージェントとメッセージを送受信できます。デスクから離れても、進捗状況を確認したり、指示を追加したりできます。どちらも同じ方向を向いています。つまり、作成を 1 つの固定された場所に固定しないでください。簡単にビルドを実行し、そのコントロールを自分の手で保持できます。

より安定: チャットがフリーズしなくなりました + 実際のプロセス テスト

信頼性も置き去りではなかった。チャット インターフェイスは、特定の複雑な Markdown 形式の解析が無限ループに陥り、最終的にすべてのメモリを消費してフリーズする可能性がある問題を修正しました。そのため、奇妙な形式のコンテンツを貼り付けても会話ウィンドウが下にドラッグされることはなくなりました。その下に、「実際のプロセス」のエンドツーエンド テストのバッチが追加されました。もはや理想的な設定で実行するだけでなく、実際にプログラムを完全なプロセスとして起動し、クラッシュ リカバリ、コンテキストの圧縮、バックグラウンド常駐、コマンド ライン インターフェイスなどの主要なパスをカバーします。テストは日々目に見えませんが、「変更が静かに壊れることはないとわかっていて、あえて物事を変更する」という自信が生まれる場所です。実際のテストをもう 1 層重ねることで、前進するための安全クッションが 1 つ増えます。

日常的なコマンドは 1 つのエントリに統合されます: bun fx

この日は、プロジェクトの日常的な操作コマンドも統合されました。以前は散在していたセットアップ / 開始 / 停止スクリプトが 1 つのエントリ bun fx <command> の下に存在し、独自の bun fx を実行すると、使用可能なすべてのコマンドのヘルプが表示されます。一般的なもの: bun fx setup (最初に環境を準備する)、bun fx update (最新のルート コードを取得してサブモジュールを同期するだけです。deps の再インストールやプラグインの再構築も不要になるため、範囲が狭くなり高速になります)、bun fx start (デフォルトで Web モード)、bun fx start app (デスクトップ モード)、さらに bun fx stop / bun fx restart です。 1 つのエントリに折りたたむということは、macOS、Linux、または Windows では「bun fx」だけを覚えておく必要があることを意味します。また、「コードの更新」と「環境のセットアップ」の絡み合いも解消されます。そのため、毎日の更新の取得が軽くなり、誤って完全な再インストールが発生する可能性が低くなります。 README、開発ドキュメント、およびパブリック サイトの手順はすべて、この新しいエントリに同期されます。

この日が意味するもの

この日のキーワードは「スケールアップ」。それ以前は、Forge のスループットの上限は「1 人のエージェントがどれだけ速く作業できるか」でした。チーム モードでは、その上限が「チームが並行して実行できる量」まで上がります。つまり、ソロからチームへの質的な飛躍です。つまり、リクエストが大きく分割可能であればあるほど、一度に実行できる量が多くなり、より速く完了できるようになります。その中核を中心に、その日はいくつかの経験を安定させました。エディターに配置した内容はそのまま残り、ビルドは UI からパッケージ化でき、デスクから離れた携帯電話から直接指示し続けることができ、奇妙な書式設定でチャットがフリーズすることはなくなりました。一方では AI のスループットを「1 人」から「チーム」に拡張し、他方では日常のエクスペリエンスの隅々まで強化しました。この日は、能力の上限とエクスペリエンスの下限が両方とも一段階上がりました。
