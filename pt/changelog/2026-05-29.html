O motor ganha física e seleção + uma base de UI reconstruída

Hoje, o motor eliminou várias partes difíceis de fazer um jogo de uma só vez: física 2D/3D, seleção de tela, anti-aliasing, além de seleção de tronco para cenas grandes e mais suaves. A interface mudou para uma base de componentes moderna com uma rede de segurança contra erros de renderização; os materiais ganharam leitura de herança, escolher um jogo o ativa e uma bancada de carretel se juntou à família de ferramentas.

De “pode renderizar” a “pode reproduzir”

As capacidades acumuladas do motor permaneceram principalmente na "renderização correta e bonita"; mas um jogo precisa de mais do que aparência – tem que ser jogável: os objetos devem cair e colidir, o jogador deve ser capaz de clicar e operar. O desempenho do motor neste dia estava eliminando de uma vez as partes difíceis que "jogáveis" exigem: física, seleção, anti-aliasing, seleção de desempenho. Enquanto isso, o lado da interface fez uma atualização básica, movendo todo o seu conjunto de componentes de interação para uma implementação mais moderna e estável. Tornar “o que você constrói jogável” de um lado e “a ferramenta com a qual você constrói mais estável” do outro – este é um dia em que o mecanismo e a interface cruzaram um limite de qualidade juntos.

Um grande impulso no motor: física + clique para escolher + anti-aliasing

O motor eliminou três partes inevitáveis ​​da criação de um jogo de uma só vez neste dia. A manchete é física: uma capacidade de suporte a 2D e 3D foi integrada, de modo que os objetos agora respondem à gravidade, colidem e empilham – jogos de plataforma, quebra de tijolos, empilhamento de caixas e rolamento de bolas finalmente têm suporte subjacente real em vez de pretensão falsificada à mão. A seguir vem a seleção de tela: clique em um objeto na tela e selecione-o com precisão - a base compartilhada para "clique para selecionar um objeto" no editor e "jogabilidade baseada em cliques" no jogo. O terceiro é o anti-aliasing: as bordas dos objetos não mostram mais aquela irregularidade da escada, então a imagem parece limpa e profissional. Física para “pode se mover”, escolha para “pode interagir”, anti-aliasing para “parece apresentável” – com todos os três, o mecanismo realmente passa de “pode renderizar” para “pode fazer um jogo jogável”.

Desempenho: seleção de tronco para cenas grandes mais suaves

O mecanismo também adicionou uma otimização de desempenho importante neste dia: seleção de tronco. A idéia é simples: não se preocupe em desenhar objetos que a câmera não consegue ver no momento (aqueles que estão fora da visualização). Antes disso, todos os objetos em uma cena podiam ser processados, estivessem ou não na tela, desperdiçando muito processamento à medida que as cenas cresciam; agora o mecanismo primeiro avalia se cada objeto está dentro do alcance visível da câmera e ignora completamente os invisíveis. Quanto maior a cena e quanto mais objetos, mais isso economiza, de modo que as taxas de quadros se mantêm muito melhor em cenas complexas. Ele complementa o desenho instanciado anteriormente (desenhar um grande lote de objetos idênticos de uma só vez): um corta "desenhando duplicatas", o outro corta "desenhando o invisível". Juntos, o motor está claramente melhor equipado para transportar cenas grandes e densas.

Uma base de UI reconstruída: uma biblioteca de componentes moderna + rede de segurança contra erros de renderização

A interface fez uma atualização de nível “substituir a base” neste dia: movendo todo um conjunto de componentes de interação – caixas de diálogo, menus suspensos, menus, controles de formulário – para uma base de componentes moderna, madura e confiável. Os benefícios são muitos – sensação de interação mais suave, visuais mais unificados, melhor acessibilidade; lugares que costumavam se contentar com os pop-ups nativos do navegador (aquelas caixas de prompt do sistema feias e não personalizáveis) foram atualizados para caixas de diálogo com estilo consistente. Mais importante ainda, uma “rede de segurança contra erros de renderização” foi adicionada abaixo: se um componente de UI for lançado durante a renderização, o sistema o isola em vez de permitir que um erro local congele toda a tela de inicialização em um espaço em branco. Isso parece "apenas trocar uma biblioteca de UI", mas na verdade eleva a interface de "utilizável, mas frágil" para "robusta e durável" - para uma ferramenta que você olha por horas todos os dias, se a interface é estável decide diretamente se usá-la parece seguro.

Leitura de herança material + escolha de um jogo ativa-o

Mais duas melhorias de suavização diária chegaram neste dia. Um: a herança do material tornou-se "lida" - uma propriedade que um material filho não define explicitamente passa automaticamente para o valor do pai - portanto, colocar configurações compartilhadas no pai e substituir apenas as diferenças nos filhos torna um lote de materiais unificados, mas ligeiramente variáveis, gerenciáveis ​​​​e menos propensos a erros. Dois, e um ponto crítico: escolher ou criar um jogo agora o "ativa" genuinamente como o jogo atual, com o diretório de trabalho do agente em segundo plano mudando para corresponder. Antes disso, com vários jogos coexistindo, era fácil ter “você está olhando para este enquanto o agente edita aquele” – uma vez que o que você escolher é o alvo, essa incompatibilidade é eliminada. Um torna os materiais fáceis de manter, o outro mantém as operações sem confusão - ambos detalhes importantes para resolver a complexa questão da "coexistência de múltiplos conteúdos".

Uma nova bancada de carretel + depuração do mecanismo e uma atualização do modelo padrão

A família de ferramentas ganhou mais um membro neste dia: uma bancada de carretel para organização de cutscenes e conteúdo cinematográfico, mais uma ferramenta útil para fazer jogos com narrativa e encenação. O lado do mecanismo adicionou um guia técnico de depuração dedicado, destilando as rotinas para diagnosticar problemas de renderização para que as pessoas e a IA possam localizar os problemas seguindo-os. O back-end atualizou o modelo padrão para um nível mais forte, para que a mesma conversa obtenha respostas mais inteligentes. Individualmente pequenos, eles apontam para uma direção: além dos grandes blocos "jogáveis" e "mais estáveis", avançando um pouco a cobertura das ferramentas, a capacidade de depuração do motor e a capacidade subjacente da IA. A maturidade de uma plataforma depende tanto de alguns grandes avanços quanto desse tipo de pequeno reforço contínuo.

O que este dia significa

Este é o dia em que o mecanismo e a interface "amadureceram". O motor adiciona física, seleção, anti-aliasing e seleção - estes não são efeitos decorativos, mas a linha de passagem para "se uma coisa pode ser chamada de jogo": move-se, é interativo, parece apresentável, executa uma grande cena. A interface passando para uma base moderna com uma rede de segurança contra erros eleva o shell que você usa por horas diariamente de "utilizável" para "robusto". Juntos, eles marcam o início da plataforma para criar "jogos genuinamente jogáveis" - tanto a força do motor que faz um jogo durar quanto a estabilidade da interface que faz as pessoas quererem usá-lo diariamente. A partir de hoje, “fazer um jogo jogável” não é mais uma visão, mas um conjunto de ferramentas realmente disponível.
