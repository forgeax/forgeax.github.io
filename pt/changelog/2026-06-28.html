Um comando – agora também no Windows

Este dia mudou os scripts de instalação e inicialização do bash para o Bun TypeScript multiplataforma: os mesmos comandos são executados de forma idêntica no macOS, Linux e Windows, e o Windows não precisa mais do Git-Bash. Além disso, corrigiu uma série de bloqueadores específicos do Windows, alterou as “sessões” de vinculadas globalmente para escopo por jogo, tornou a importação de ativos mais estável e tornou a CLI subjacente mais rápida, mais controlável e mais auditável.

A maior barreira: não seria instalado se você trocasse de plataforma

Por muito tempo, instalá-lo e executá-lo dependia de uma pilha de scripts bash. Ótimo para macOS e Linux, mas uma barreira rígida para usuários do Windows - o bash não é nativo do Windows, então você tinha que instalar uma camada de compatibilidade como o Git-Bash ou encontrar vários erros enigmáticos. Para uma ferramenta que deseja que “qualquer um transforme ideias em jogos”, “ela não será instalada” é o primeiro desvio mais fatal. Este dia corrigiu exatamente isso: reescrever todos os scripts de instalação e inicialização no atacado, do bash para o TypeScript multiplataforma executado pela Bun. O Bun se comporta de forma idêntica nos três sistemas principais, portanto, os mesmos comandos e a mesma lógica são executados no Windows exatamente como no Mac, sem necessidade de camada de compatibilidade.

Os comandos se resumem em um conjunto memorável

Junto com a mudança, os pontos de entrada foram limpos. Os scripts dispersos por plataforma do passado (.sh, .bat, .ps1 e assim por diante) foram excluídos juntos e unificados em um conjunto simples e memorável: bun run setup para instalar o ambiente uma vez, bun run start para inicializar toda a pilha, bun run stop para interrompê-lo, bun run app para o aplicativo de desktop. Qualquer que seja o sistema em que você esteja, esses poucos são tudo que você precisa lembrar. Para novos usuários, significa "copiar quatro linhas do README e ele será executado", sem mais "Estou no Windows, por qual deles devo trocar"; para os usuários existentes, isso significa que não há mais carga de manutenção de "duas cópias de cada script (uma sh, uma ps1) para editar em sincronia e fácil de perder". Reunir vários scripts equivalentes em uma fonte de verdade multiplataforma é o cerne do trabalho do dia – uma coisa a menos para manter sincronizada é um lugar a menos para dar errado.

Limpando uma série de bloqueadores específicos do Windows

Para realmente tornar o Windows mais suave, os scripts de plataforma cruzada por si só não são suficientes – você também precisa corrigir, uma por uma, as estranhezas que só surgem no Windows. Um caso típico tratado hoje: o Python "falso" do sistema - o Windows envia um espaço reservado python3 que não está realmente instalado e só abre a loja de aplicativos quando invocado, e um script que ingenuamente assume que funciona irá parar misteriosamente durante a configuração. Este dia ensinou o fluxo de instalação a reconhecer e ignorar esse espaço reservado e encontrar um Python que realmente funcione. Detalhes como este - inexistentes em outros sistemas, tropeçando apenas no Windows - são a parte mais desgastante, porém mais necessária, do suporte multiplataforma: eles não adicionam recursos, mas cada um deles corrigido significa que um grupo de usuários do Windows paralisa menos uma vez e pode continuar.

As sessões mudam de globalmente para escopo por jogo

Este dia também tocou em uma estrutura mais interna: a quem pertence uma sessão (uma sessão sendo um trecho de sua conversa com Forge). As sessões costumavam ser globais e separadas de qualquer jogo específico; este dia os aninhou em cada jogo, com escopo por jogo. Significado: sua conversa com Forge para o projeto “space shooter” e aquela para o projeto “farm sim” agora são cada uma delas, nunca se misturando. É mais intuitivo - em primeiro lugar, uma conversa pertence a um jogo específico - e estabelece as bases para um gerenciamento de projeto mais limpo posteriormente: troque de jogo e seu histórico e contexto de bate-papo aparecem, em vez de enfrentar um pote global de sessões mistas. Esse tipo de organização do tipo “arquivar os dados onde eles realmente pertencem” não é glamoroso no dia a dia, mas mantém limpo o modelo mental de todo o sistema.

Importação de ativos mais estável + uma CLI mais rápida e controlável

O dia também trouxe diversas correções que tornam o uso diário mais estável. Nos ativos, ele corrigiu um problema de indexação ao importar modelos maiores (malhas grandes precisam de números inteiros mais amplos para indexar seus vértices, o que costumava falhar aqui) e fez com que os metadados escritos na importação do modelo seguissem um formato canônico – de modo que a importação de um modelo maior e mais complexo não caísse mais facilmente. O núcleo CLI que impulsiona a IA também recebeu vários refinamentos: redução da redundância para que o primeiro turno comece a funcionar mais rápido em alguns casos; consertar um problema na introdução do “código de conduta” de um agente; e adicionar mascaramento opcional das próprias ferramentas externas de um usuário, além de uma trilha de auditoria das chamadas de um agente para ferramentas de host – o último significando “quais ferramentas a IA realmente usou desta vez” torna-se rastreável no registro. Juntos, isso fortalece outra camada em direção a "mais rápido, mais controlável e mais confiável".

O que este dia significa

O protagonista deste dia é “a barreira”. Por mais poderosa que seja uma ferramenta, se um grande grupo for excluído porque seu sistema está errado e não pode ser instalado, metade de seu valor desaparece antes que alguém a utilize. Tornar a instalação e o lançamento totalmente multiplataforma, para que os usuários do Windows também possam executá-lo com um comando, abre essa porta para todos - uma das pré-condições para que "qualquer um possa fazer jogos" seja verdadeira. E no mesmo dia, arquivar as sessões sob seu jogo, consertar a importação de ativos para que fosse estável e polir o núcleo da CLI para ser mais rápido e auditável, arrumaram a sala enquanto a porta era aberta. Abaixe a barreira de entrada e, em seguida, aumente a qualidade interna – este dia fez as duas coisas.
