Modo Play do Windows estabilizado + proxy de depuração LLM para desenvolvedores

O modo Play no Windows agora está estável graças a uma correção na pilha de Socket do editor; uma nova variável de ambiente FORGEAX_DEBUG_PROXY permite que os desenvolvedores capturem e inspecionem todo o tráfego da API LLM em tempo real; o empacotamento do aplicativo desktop no Windows foi corrigido; e a arquitetura do runtime reel-game foi projetada como uma subclasse de runtime de jogo no nível do motor.

Modo Play do Windows: finalmente estável

O modo Play no Windows falhava intermitentemente devido a um problema na pilha de Socket do editor. A exportação WebSocket subjacente estava ausente no caminho de build desktop, fazendo com que o iframe de pré-visualização do motor perdesse a conexão com o host do editor. Isso foi corrigido — o modo Play no Windows agora funciona tão confiavelmente quanto no macOS.

Proxy de depuração LLM para desenvolvedores

Uma nova variável de ambiente opcional FORGEAX_DEBUG_PROXY foi adicionada. Quando definida, ela inicia um proxy HTTP local que captura todas as chamadas de API LLM de saída (Anthropic, OpenAI, Gemini, etc.) e registra os pares de requisição/resposta. Configure no seu .env e o proxy inicia automaticamente com bun fx start.

Empacotamento do app desktop do Windows corrigido

O build desktop Tauri 2 para Windows estava falhando devido a uma exportação de dependência ausente no pacote de interface. Resolvido — bun fx build app agora produz um instalador .exe funcional no Windows.

Arquitetura do runtime reel-game

Uma especificação de design para o runtime reel-game (filme interativo) foi estabelecida, posicionando-o como uma subclasse de runtime de jogo de primeira classe dentro do motor. A implementação seguirá em próximas versões.
