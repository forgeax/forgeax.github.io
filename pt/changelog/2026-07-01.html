Frontend R4 + redesenho da janela de visualização 2×2

Este dia trouxe várias mudanças no Studio que você pode sentir no editor: os aplicativos frontend R4 (chat, ambiente de trabalho, configurações, painel) finalmente conectados à cadeia de inicialização com um armazenamento de interface reduzido; a janela de visualização mudou de alternâncias mutuamente exclusivas de edição/reprodução para uma matriz de execução × exibição 2×2; e o editor não codifica mais os caminhos do jogo – em vez disso, o Studio injeta o layout do jogo. Além disso, o bun fx update ganhou um relatório estruturado com código de cores e o script de empacotamento do desktop foi reforçado para compilações de plataforma cruzada.

Frontend R4: de submódulos independentes até a execução real

Depois de dividir o chat, o ambiente de trabalho, as configurações e o painel em submódulos independentes em 30 de junho, este dia foi para “ligá-los”. O pacote de interface foi reduzido a uma camada AppKit pura (barramento, transmissão, links diretos, sobreposições); cada um dos quatro aplicativos L2 possui preferências do agente e visualização de arquivos por meio do barramento, em vez de lotar uma grande loja. O main.tsx do Studio agora inicializa initAgentPrefs, initFilePreview, bootBroadcast e assinaturas de daemon tick na inicialização - os quatro módulos não são mais "subdiretórios ali", mas partes formais do editor. R4 passou do plano à estrutura que você pode desenvolver diariamente.

Viewport 2×2: modo de execução × modo de exibição

A janela de visualização do editor completou seu redesenho 2×2 neste dia. Antes, Editar e Reproduzir eram dois estados mutuamente exclusivos – mudar significava reconstruir toda a janela de visualização. O novo design divide o "modo de execução" (Editar/Reproduzir) e o "modo de exibição" (Cena/Jogo) em duas dimensões ortogonais formando uma matriz 2×2 — você pode ver tanto a visualização da cena quanto a visualização do jogo ao mesmo tempo, orientadas por diferentes estados de execução. AppMode tornou-se a única fonte de verdade, com a interface e os submódulos do editor alinhados a esta semântica da janela de visualização. É um passo em direção a uma experiência de edição no estilo UE5: edite e visualize em uma tela sem alternar para frente e para trás.

Editor desacopla caminhos de jogo – Studio injeta layout

O submódulo do editor abandonou sua dependência codificada dos diretórios de jogos hoje, tornando-se um pacote independente de layout. Onde os arquivos do jogo ficam e qual é o prefixo da URL não é mais "preparado" pelo editor - o host (Studio) o injeta: o iframe da janela de visualização principal obtém seu caminho via EditSurfaceProps.gameRoot, localStorage mantém os iframes do painel apontados para o mesmo jogo; iniciar o mecanismo passa o diretório de varredura de disco e o prefixo da URL do cliente; O pacote de desktop também prepara o prefixo da URL para que um aplicativo congelado forneça os recursos do jogo corretamente. O editor pode evoluir de forma independente enquanto o Studio possui o layout do projeto – limites mais claros.

atualização bun fx: extraia o código e veja tudo rapidamente

A primeira coisa que um desenvolvedor faz todas as manhãs geralmente é extrair o código mais recente. Antes, bun fx update executava silenciosamente git pull mais sincronização de submódulo - não dizia nada em caso de sucesso e despejava um erro opaco em caso de falha. Este dia adicionou um relatório de atualização estruturado: uma tabela codificada por cores mostrando o resultado do pull de cada submódulo (sucesso, ignorado, conflito), seu branch atual e o resumo do commit mais recente. Se um submódulo tiver alterações locais que precisem de armazenamento, ele informará explicitamente. Após uma atualização, você sabe em que estado está o projeto inteiro - chega de executar git status em cada submódulo, um por um.

Pacote de desktop: script multiplataforma + preparação de versão

O empacotamento de desktop também foi reforçado neste dia: build-desktop.ts tornou-se um script multiplataforma com testes adicionados; empacotar fornecedores platform-io e agent-host no arquivo secundário, inserindo a versão via lib/version.ts no artefato em vez de montá-la em tempo de execução; e bun fx start ganhou uma verificação de porta ocupada que verifica se portas comuns já estão em uso antes do lançamento, para que você não acabe com meia pilha em execução e sem ideia do porquê. Nada disso é chamativo por si só, mas determina se o empacotamento e a inicialização funcionam perfeitamente no Windows e no macOS.

O que este dia significa

O tema deste dia é “aterrissagem nas fronteiras”. A divisão R4 de ontem definiu a direção; hoje, os quatro módulos estão realmente conectados à cadeia de inicialização. A janela de visualização 2×2 transformou a edição e a visualização de mutuamente exclusivas em combináveis. O editor devolveu a propriedade do diretório do jogo ao Studio. Cada peça responde à mesma pergunta: nesta editora, quem é o dono do quê? Depois que os limites estiverem claros, os módulos poderão iterar de forma independente: toque no chat sem reconstruir o ambiente de trabalho, troque o editor sem tocar no layout do projeto do Studio. O Studio está passando de uma grande bola de lama para um conjunto de módulos com responsabilidades claras.
