Forge는 장기 기억을 얻습니다. 더 많이 말할수록 더 많은 것을 알게 됩니다.

이날 가장 큰 변화는 포지에게 '장기 기억'을 부여했다는 점이다. 이전에는 모든 새로운 대화가 첫 만남처럼 시작되었습니다. 이제 이전 세션의 주요 정보를 자동으로 추출하여 새로운 세션에서 다시 불러올 수 있습니다. 즉, 선호도, 프로젝트 규칙, 중간에 수정한 버그 등 모든 것을 기억합니다. 설정 패널에 메모리 토글이 추가되어 계속 제어할 수 있습니다. 편집기 측에서 메시 패널은 이제 개체별 형상 통계를 표시할 수 있습니다. 그 아래에는 새로운 에이전트-호스트 프로세스 감독자가 배치되었습니다. 커서 통합을 방해하는 Windows 인수 길이 제한이 수정되었습니다.

소울 메모리: "매번 새롭게 시작하는 것"에서 "진행하면서 학습하는 것"까지

AI 비서의 가장 답답한 점 중 하나는 '세션 간 기억상실'이다. 어제 20분 동안 프로젝트의 코드 규칙을 설명하고 기본 설정의 이름을 지정하고 피해야 할 함정을 지정한 다음 오늘 새로운 대화를 시작하면 모든 것을 잊어버리고 처음부터 시작합니다. 이날 출시된 소울 메모리 시스템은 이를 해결하기 위해 존재한다. 각 대화가 끝날 때(또는 대화 중 적절한 순간에) "이 프로젝트는 Node가 아닌 Bun을 사용합니다", "사용자는 과도한 설명이 없는 간결한 코드를 선호합니다", "게임의 주인공은 Arin이라고 합니다"와 같은 장기간 보유할 가치가 있는 정보를 자동으로 추출하고 이러한 기억을 디스크에 유지합니다. 새로운 대화가 시작되면 이러한 기억이 Forge의 컨텍스트에 주입되어 "기억으로 시작"됩니다. 기술적으로 메모리 추출은 포크 메커니즘을 사용합니다. 즉, 현재 대화에서 간단한 추출 작업을 포크하고, 진행 중인 채팅을 방해하지 않고 비동기식으로 실행하며, 완료되면 메모리 저장소에 씁니다.

설정 패널: 메모리를 직접 제어할 수 있음

기억은 좋은 것이지만 "AI가 무엇을 기억할지 스스로 결정하는 것"도 불안할 수 있습니다. 그래서 오늘은 설정 패널에 메모리 섹션도 추가했습니다. 자동 메모리 추출을 켜거나 끄고, Forge가 기억한 내용을 확인하고, 보관하고 싶지 않은 항목을 삭제할 수 있습니다. 이 디자인은 원칙을 따릅니다. AI는 사전에 학습할 수 있지만 인간은 항상 거부권을 갖습니다. 메모리 스위치는 기본적으로 켜져 있지만(대부분의 사용자는 즉시 혜택을 누릴 수 있음) 언제든지 한 번의 클릭으로 끌 수 있습니다. 메모리 스위치를 끄면 Forge는 잔여물 없이 "매번 새로 시작" 모드로 되돌아갑니다.

편집기: 메시 패널은 엔터티당 형상 세부정보를 표시합니다.

오늘 편집기의 메시 패널에 편리한 작은 기능이 추가되었습니다. 엔터티 모드에서 각 개체는 정점 수, 삼각형 수, 재질 수 등의 형상 통계를 함께 표시합니다. 이전에는 그것이 얼마나 무거운지 알지 못한 채 "이것은 메쉬입니다"라고만 볼 수 있었습니다. 이제 "이 모델에는 500,000개의 면이 있으므로 데시메이션이 필요할 것입니다." 또는 "이 모델은 200개의 면이므로 여러 개 배치해도 안전합니다."를 한눈에 알 수 있습니다. 이 맥락에서 오해의 소지가 있었던 이전에 표시되었던 "Kind" 필드가 동시에 숨겨졌습니다. 작은 변화처럼 보이지만 장면 최적화를 수행하는 사람에게는 폴리곤 수를 확인하기 위해 더 이상 외부 도구를 열 필요가 없음을 의미합니다.

에이전트-호스트: 에이전트를 위한 전담 관리인

새로운 에이전트-호스트 프로세스 감독자가 인프라 수준에 도착했습니다. 이를 에이전트의 "관리자"로 생각하십시오. 링-0 사이드카로 실행되며 에이전트 프로세스 수명 주기 관리(시작, 모니터링, 다시 시작, 정상적인 종료) 및 IPC(프로세스 간 통신)를 처리합니다. 이전에는 에이전트 프로세스 관리가 통합 감독자 없이 코드베이스 전체에 분산되어 있었습니다. 이제 에이전트-호스트를 사용하면 충돌한 에이전트가 자동으로 다시 시작되고 여러 에이전트 간에 전달되는 메시지에는 표준 채널이 있습니다. 이는 팀 다중 에이전트 협업을 더욱 강력하게 만드는 인프라입니다. 팀은 누군가가 각 구성원을 "감시"할 때만 효율적으로 작업할 수 있습니다.

Windows CLI 수정: 커서 통합이 더 이상 잘리지 않습니다.

Windows 전용 문제도 해결되었습니다. 커서를 통해 Forge CLI를 호출할 때 인수 길이 제한으로 인해 Windows cmd.exe에서 긴 프롬프트가 잘려서 에이전트가 명령의 절반만 수신하게 됩니다. 수정 사항은 명령줄 인수 길이 제한을 우회하여 대신 stdin을 통해 프롬프트를 제공합니다. 이러한 종류의 플랫폼별 엣지 케이스는 교묘합니다. Mac에서는 완벽하게 작동하지만 Windows에서는 이상하게 실패합니다. 그러나 이를 수정하면 Windows 사용자에게 실질적인 안정성이 향상됩니다.

오늘의 의미

이날의 키워드는 '축적'이다. 소울 메모리는 Forge의 기능이 더 이상 매번 0으로 재설정되지 않고 사용함에 따라 축적된다는 것을 의미합니다. 더 많이 사용할수록 Forge는 귀하의 프로젝트, 습관, 선호도를 더 잘 알고 더 효율적이 됩니다. 에이전트-호스트는 다중 에이전트 협업에 안정적인 기반을 제공하고 편집기의 지오메트리 통계는 데이터 기반 최적화를 제공합니다. 모든 변화는 같은 방향을 가리킵니다. Forge를 "각 세션마다 즉흥적으로 작업하는 임시 직원"에서 "기억하고 신뢰할 수 있으며 장기적으로 함께 일할 수 있는 파트너"로 바꾸는 것입니다.
