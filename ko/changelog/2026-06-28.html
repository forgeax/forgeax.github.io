하나의 명령 - 이제 Windows에서도 가능

오늘은 설치 및 시작 스크립트를 bash에서 크로스 플랫폼 Bun TypeScript로 일괄 이동했습니다. 동일한 명령은 macOS, Linux 및 Windows에서 동일하게 실행되며 Windows에는 더 이상 Git-Bash가 필요하지 않습니다. 이와 함께 Windows 관련 차단기 문자열을 수정하고, "세션"을 전역 바인딩에서 게임별 범위 지정으로 변경하고, 자산 가져오기를 더욱 안정적으로 만들고, 기본 CLI를 더 빠르고, 더 제어하기 쉽고, 감사하기 쉽게 만들었습니다.

가장 큰 장벽: 플랫폼을 바꾸면 설치되지 않습니다.

오랫동안 이를 설치하고 실행하는 것은 bash 스크립트 더미에 의존해 왔습니다. macOS 및 Linux에는 적합하지만 Windows 사용자에게는 어려운 벽입니다. bash는 Windows에 기본적으로 제공되지 않으므로 Git-Bash와 같은 호환성 레이어를 설치해야 하거나 여러 가지 암호화된 오류가 발생해야 했습니다. "누구나 아이디어를 게임으로 만들 수 있다"는 도구의 경우 "설치되지 않음"이 가장 치명적인 첫 번째 꺼짐입니다. 오늘 문제가 정확히 해결되었습니다. bash에서 Bun이 실행하는 크로스 플랫폼 TypeScript로 모든 설치 및 실행 스크립트를 일괄적으로 다시 작성하는 것입니다. Bun은 세 가지 주요 시스템에서 동일하게 작동하므로 호환성 레이어가 필요 없이 Mac에서와 마찬가지로 Windows에서도 동일한 명령과 논리가 정확하게 실행됩니다.

명령은 기억에 남는 하나의 세트로 축소됩니다.

이동과 함께 진입점이 정리되었습니다. 과거에 흩어져 있던 플랫폼별 스크립트(.sh, .bat, .ps1 등)가 함께 삭제되어 기억에 남는 하나의 평범하고 기억에 남는 세트로 통합되었습니다. 환경을 한 번 설치하는 bun run setup, 전체 스택을 부팅하는 bun run start, 중지하는 bun run stop, 데스크톱 앱용 bun run app. 어떤 시스템을 사용하든 이 몇 가지만 기억하면 됩니다. 새로운 사용자의 경우 이는 "README에서 네 줄을 복사하면 실행됩니다."를 의미하며 더 이상 "나는 Windows를 사용하고 있습니다. 이것을 무엇으로 바꾸나요"가 아닙니다. 기존 사용자에게는 더 이상 "각 스크립트의 사본 2개(sh 1개, ps1 1개)를 고정적으로 편집해야 하고 놓치기 쉽습니다."라는 유지 관리 부담이 더 이상 발생하지 않음을 의미합니다. 여러 개의 동일한 스크립트를 하나의 크로스 플랫폼 진실 소스로 축소하는 것이 오늘 작업의 핵심입니다. 동기화를 유지해야 할 일이 하나 줄어들면 잘못될 곳도 하나 줄어듭니다.

Windows 관련 차단기 문자열 지우기

Windows를 원활하게 만들려면 크로스 플랫폼 스크립트만으로는 충분하지 않습니다. 또한 Windows에서만 나타나는 이상한 점을 하나씩 수정해야 합니다. 오늘 처리된 일반적인 사례는 다음과 같습니다. 시스템의 "가짜" Python — Windows는 실제로 설치되지 않고 호출될 때만 앱 스토어를 표시하는 python3 자리 표시자를 제공하며, 순진하게 작동한다고 가정하는 스크립트는 설정 중에 신비롭게 정지됩니다. 오늘은 해당 자리 표시자를 인식하고 건너뛰고 실제로 작동하는 Python을 찾는 설치 흐름을 가르쳤습니다. 이와 같은 세부 사항(다른 시스템에는 존재하지 않으며 Windows에서만 문제가 발생함)은 크로스 플랫폼 지원에서 가장 힘들지만 가장 필요한 부분입니다. 기능을 추가하지 않지만 각각의 수정은 Windows 사용자 배치의 지연 시간이 한 번 줄어들고 계속 진행된다는 것을 의미합니다.

세션은 전역 바인딩에서 게임별 범위로 변경됩니다.

이날은 또한 세션이 누구에게 속하는지(Forge와의 대화 중 하나인 세션)와 같은 보다 내부적인 구조에 대해서도 다루었습니다. 세션은 전역적이고 특정 게임과 별개였습니다. 오늘은 게임별로 범위가 지정된 각 게임 아래에 중첩되었습니다. 의미: "Space Shooter" 프로젝트에 대한 Forge와의 대화와 "Farm Sim" 프로젝트에 대한 대화는 이제 서로 고유하며 결코 서로 번지지 않습니다. 더 직관적입니다. 대화는 처음에는 특정 게임에 속하며 나중에 더 깔끔한 프로젝트 관리를 위한 토대를 마련합니다. 단일 글로벌 혼합 세션 포트에 직면하는 대신 게임을 전환하면 채팅 기록과 컨텍스트가 함께 표시됩니다. 이러한 종류의 "진정한 데이터 정리"는 일상적으로는 별 볼일 없는 일이지만 전체 시스템의 정신 모델을 깨끗하게 유지합니다.

안정적인 자산 가져오기 + 더 빠르고 제어 가능한 CLI

또한 그날은 일상적인 사용을 더욱 안정적으로 만드는 몇 가지 수정 사항도 적용되었습니다. 자산의 경우 더 큰 모델을 가져올 때 인덱싱 문제를 해결했고(큰 메시는 정점을 인덱싱하기 위해 더 넓은 정수가 필요했는데 여기서는 실패했습니다) 모델 가져오기에 기록된 메타데이터가 하나의 표준 형식을 따르도록 만들었습니다. 따라서 더 크고 복잡한 모델을 가져오는 것이 더 이상 쉽게 실패하지 않습니다. AI를 구동하는 CLI 코어도 여러 가지 개선을 거쳤습니다. 어떤 경우에는 첫 번째 턴이 더 빠르게 작동하기 시작하도록 중복성을 다듬었습니다. 에이전트의 "행동 강령" 주입 문제를 수정합니다. 사용자 자신의 외부 도구에 대한 선택적인 마스킹과 호스트 도구에 대한 에이전트 호출의 감사 추적을 추가합니다. 후자는 "이번에 AI가 실제로 어떤 도구를 사용했는지"를 의미하며 기록에서 추적 가능해집니다. 함께, 이는 "더 빠르고, 더 제어 가능하고, 더 신뢰할 수 있는" 방향으로 기초를 또 다른 계층으로 강화합니다.

오늘의 의미

오늘의 주인공은 '장벽'이다. 도구가 아무리 강력하더라도 시스템이 잘못되어 설치되지 않아 대규모 그룹이 폐쇄되면 누군가가 도구를 사용하기도 전에 그 가치의 절반이 사라지게 됩니다. 완전한 크로스 플랫폼 설치 및 실행을 구현하여 Windows 사용자도 하나의 명령으로 실행할 수 있도록 하면 모든 사람에게 문이 열려 있습니다. 이는 "누구나 게임을 만들 수 있다"는 전제 조건 중 하나입니다. 그리고 같은 날, 게임 아래에 세션을 정리하고 자산 가져오기를 안정적으로 수정하고 CLI 코어를 더 빠르고 감사하기 쉽게 연마하여 문이 열려 있는 동안 방을 정리했습니다. 진입 장벽을 낮추고 내부 품질을 높이십시오. 오늘은 이 두 가지를 모두 수행했습니다.
