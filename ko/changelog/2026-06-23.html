자산 검사기 + 지연 없는 스위치 + Windows 지원

오픈 소스 릴리스 이후 이날은 다듬고 강화하는 과정을 거쳤습니다. 편집자는 모든 자산 종류를 다루는 검사관을 확보했습니다. 장면 간 전환, 편집과 재생 간 전환 시 더 이상 렌더러를 콜드 재부팅하거나 검은색 화면에서 정지되지 않습니다. 일련의 Windows 호환성 문제가 해결되었습니다. 엔진은 장치 손실을 자가 복구하고 제한된 환경에서 우아하게 성능을 저하시키는 방법을 학습했습니다. 로드 타임 계약 확인이 추가되었습니다. 터미널 버전은 체크포인트 되감기를 얻었습니다.

출시 후 폴리싱으로 전환

오픈 소스를 통해 프로젝트가 대중에게 전달되었으며 실제 테스트는 프로젝트가 전달되는 순간 시작됩니다. 더 많은 사람, 더 다양한 컴퓨터, 더 비판적인 눈을 통해 원활하지 않거나 안정적이지 않은 모든 부분을 노출할 수 있습니다. 오늘은 출시 이후의 차례였습니다. 눈부신 새로운 기능을 쫓는 것이 아니라 기존 경험을 더 매끄럽게 다듬고 기초를 더욱 견고하게 다지기 위해 안주했습니다. 자산 검사기를 통해 제작자는 모든 자료를 명확하게 확인할 수 있습니다. 정지 없는 전환은 일상 사용에서 가장 자주 발생하는 장애를 제거합니다. Windows 호환성을 통해 더 많은 사람들이 참여할 수 있습니다. 엔진 자가 치유 기능은 사고로 인해 사람들이 쉽게 방해를 받지 않도록 해줍니다. 로드 시간 계약 검사는 AI의 코드 편집이 오류로 인해 발생하는 것을 방지합니다. 개별적으로는 소규모이며, 이러한 모든 목표는 "실제로 사용하기 부드럽고 안정적인지 여부"입니다. 이는 대중에게 이제 막 공개된 프로젝트가 즉시 강화해야 하는 목표입니다. 첫인상은 단 한 번만 발생하며, 출시 후 모든 작은 노력이 이를 보호합니다.

자산 검사관: 모든 자산을 명확하게 확인

편집자는 오늘 프로젝트의 모든 종류의 자산을 다루는 자산 검사자 패널을 얻었습니다. 이는 기본적이면서도 오랫동안 간과되었던 요구 사항을 해결합니다. 즉, 프로젝트에 메시, 재료, 텍스처, 애니메이션, 장면 등 많은 재료가 쌓일 때 어떤 것이 실제로 무엇인지 빨리 확인할 수 있는 방법은 무엇입니까? 이전에는 이름만 보는 경우가 많았으며 이름의 모양과 속성을 알려면 실제로 장면에 배치해야 했습니다. 이제 자산을 선택하면 오른쪽에 있는 검사기가 종류에 맞는 미리보기와 세부정보를 제공합니다. 메시를 선택하고 모양, 재질을 확인하고 텍스처 품질을 확인하고, 텍스처를 확인하고 이미지와 애니메이션을 확인하고 해당 정보를 확인하세요. "콘텐츠 브라우저"도 자료 패널에 연결되어 탐색에서 보기, 편집까지 일관된 흐름을 형성했습니다. 제작자에게 있어 중요한 것은 "자신이 가지고 있는 것이 무엇인지 아는 것"입니다. 다소 큰 프로젝트는 쉽게 수십 또는 수백 개의 자산을 보유할 수 있으며, 각 자산을 열어서 명확하게 볼 수 있으면 모호한 이름 더미에서 헤매지 않고 재료 관리 및 재사용의 효율성이 높아집니다.

지연 없이 전환: 렌더링 컨텍스트를 활성 상태로 유지

오늘은 오랜 시간 동안 고통을 주었고 매일 사용할 때 매우 자주 발생하는 오래된 문제인 전환 지연 문제를 해결했습니다. 이전에는 서로 다른 장면을 전환하거나 "편집"과 "재생" 모드를 전환할 때 시스템이 전체 기본 그래픽 렌더링을 해체하고 다시 작성했습니다. 즉, 검은색 플래시, 재초기화 및 가장 느린 속도에서는 완전히 정지되었습니다. 근본 원인: 각 스위치가 렌더 컨텍스트를 재구축하고 그래픽 컨텍스트를 재구축하는 것은 특정 브라우저 환경에서 오류가 발생하기 쉬운 상당히 비용이 많이 드는 작업입니다. 더 자주 전환할수록 중단될 가능성이 더 커집니다. 오늘의 솔루션은 "keep-alive"입니다. 전환은 더 이상 해체 및 재구축되지 않고 렌더링 컨텍스트를 백그라운드에서 활성 상태로 유지하고(파괴되지 않고 화면 밖으로 이동) 필요할 때 직접 재사용합니다. 제자리로 전환하면 장면 간, 편집과 재생 간 전환이 부드럽고 즉각적으로 이루어지며 검은 화면이나 정지 현상이 발생하지 않습니다. 반복적으로 "조정하고, 살펴보고, 다시 조정"하도록 권장하는 생성 도구의 경우 전환은 가장 자주 실행되는 작업 중 하나입니다. 이 경로를 "매번 다시 작성"에서 "언제든지 즉시 전환"으로 전환하면 창의적인 흐름에서 가장 방해가 되는 장애가 직접 제거됩니다.

크로스 플랫폼: 일련의 Windows 수정 사항

이제 오픈 소스이고 가능한 많은 사람들이 이를 사용하기를 원하므로 Windows에 대한 문제를 해결해야 했습니다. 오늘은 일련의 Windows 호환성 문제, 즉 "다른 시스템에서는 문제가 없지만 Windows에서는 설명할 수 없을 정도로 손상되는" 함정과 같은 일반적인 종류의 함정을 휩쓸었습니다. 프로세스가 아직 살아 있는지 확인하는 방법을 Windows 터미널에서 수정하려면 다른 접근 방식이 필요합니다. 새 프로젝트를 만들 때 생성된 심볼릭 링크는 Windows에서 권한 제한에 도달했으며 기본 Windows와 동등한 기능을 회피했습니다. 환경 맵(HDR 형식) 디코딩은 Windows에서도 수정되었습니다. 크로스 플랫폼에서 사용할 수 있도록 시작 스크립트가 강화되었습니다. 각 문제는 눈에 띄지 않지만 해결되지 않은 단일 문제로 인해 설치, 프로젝트 생성 또는 첫 실행 시 Windows 사용자가 차단되어 완전히 반송될 수 있습니다. 설치부터 실행까지 이 전체 경로를 확보하고 Windows에서 작업하면 데스크톱 시장의 대부분을 차지하는 Windows 사용자에게 문이 열리게 됩니다. 그리고 더 많은 사람들이 시도하기를 열망하는 오픈 소스 프로젝트의 경우 이 단계의 실질적인 의미는 특히 큽니다.

엔진 자가 치유: 장치 손실 복구, 한도 내에서 점진적으로 성능 저하

이날 엔진은 '사고 극복'을 위해 큰 발걸음을 내디뎠다. 하나는 장치/표면 자가 치유입니다. 그래픽 장치는 작동 중에 다양한 이유(시스템 리소스 부족, 드라이버 재설정)로 인해 갑자기 작동이 중단될 수 있습니다. 이는 이전에는 종종 화면이 복구되지 않고 검게 변하는 것을 의미했습니다. 이제 엔진은 이러한 하락을 감지하고 렌더링을 자동으로 재설정하여 사진이 죽지 않고 다시 돌아오도록 시도합니다. 두 번째는 한계에 따른 점진적인 성능 저하입니다. 일부 약한 브라우저 환경에서는 엔진의 비디오 메모리 용량 조사가 정확한 값을 얻지 못할 수 있으며, 현재는 그럴 수 없는 경우 안전한 기본 상한으로 돌아갑니다. 렌더링할 콘텐츠가 용량을 초과하면 이제 전체 프레임을 건너뛰는 대신 "잘린 하위 집합을 렌더링"하고 전체 그림을 충돌시키는 것보다 조금 덜 그리는 것을 선호합니다. 낮은 수준의 충돌도 복구 가능한 오류로 격리되었습니다. 공유된 주제는 "탄력성"입니다. 모든 종류의 실제 장치에 직면하고 일반 사람들이 오랫동안 사용하기 위한 엔진은 모든 것이 완벽하다고 가정할 수 없습니다. 진정한 성숙의 특징은 결함이 발생했을 때 첫 번째 사고에서 파업을 시작하기보다는 감소된 수준에서 견디고 회복하며 계속 작동하는 것입니다.

로드 시간 계약 확인 + 장면 쓰기 저장

이날 "AI 작성 코드" 라인에 로드 시간 계약 확인이라는 또 다른 안전 장치가 추가되었습니다. 게임을 로드할 때 시스템은 게임 코드가 엔진의 인터페이스와 일치하는지 자동으로 확인합니다. "계약"은 엔진이 규정하는 호출 규칙입니다. AI가 코드를 편집한 후 일부 지점에서 인터페이스를 오용하거나 파일 간 인터페이스가 일치하지 않는 경우 시스템은 설명할 수 없는 도중에 충돌이 발생하는 대신 화면 오류 오버레이에서 이 "드리프트"를 직접적이고 눈에 띄게 지적합니다. 이는 "작성 완료"와 "실행 중" 사이에 또 ​​다른 자동 체크포인트를 효과적으로 설정하여 인터페이스 수준 오류를 그 자리에서 잡아냅니다. 한편, 엔진은 장면 "쓰기 저장"을 완료했습니다. 즉, 현재 장면의 콘텐츠를 구조화된 자산 팩으로 직렬화하고 콘텐츠에서 역으로 식별자를 조회할 수 있습니다. 이는 "편집기에서 편집하고 즉시 저장"하는 루프의 기본 기반을 마련합니다. 편집은 단지 보고 조정하는 것이 아닙니다. 변경 사항도 안정적으로 지속되어야 합니다. 이 두 가지는 차례로 "창조의 산물"을 더욱 안정적으로 만듭니다. 즉, 코드 정렬을 보장하고 편집 결과가 저장되도록 합니다.

터미널 체크포인트 되감기 + 다중 에이전트 협업 터치

오늘 명령줄/터미널 버전에는 그래픽 인터페이스에 맞는 체크포인트 및 되감기 기능이 추가되었습니다. 대화를 이전 체크포인트로 롤백하고 다시 시도하여 만족스럽지 않으면 취소할 수 있습니다. 세션 복구가 추가되었습니다. 중단 후 하나의 명령이 중단된 부분부터 다시 시작되지 않고 다시 시작됩니다. 질문을 하기 위한 오버레이도 있습니다. 채팅 인터페이스는 다중 에이전트 협업의 실시간 세부 사항을 계속해서 개선했습니다. 하위 에이전트가 다른 에이전트에게 작업을 전달할 때 명확한 릴레이 헤더는 전달 관계를 보여줍니다. 관련 에이전트는 "생산자 가족"별로 그룹화되어 있으며 각각 고유한 범주에 속합니다. 통화가 필요한 민감한 작업에는 전용 권한 확인 카드가 있습니다. 그리고 요원 아바타를 약간 들어올리고 확대하여 "누가 활동 중인지, 누가 당신을 기다리고 있는지"를 한눈에 더 명확하게 알 수 있도록 했습니다. 이것들은 한 가지 역할을 합니다. 서로 다른 작업을 수행하는 AI 팀에게 협업을 지시할 때 전체 프로세스는 명확하고 제어 가능하며 항상 롤백이 가능해야 합니다. 즉, 중단하고 되감기 위한 이니셔티브를 유지하면서 AI가 수행하는 작업을 이해해야 합니다.

오늘의 의미

전날 오픈소스 공개가 '문을 열고 사람들을 초대한다'였다면 이날은 '사람들이 편안하게 생활할 수 있도록 집을 정리하라'였다. 획기적인 새 기능은 없었고 전체적으로 다듬어지고 강화되었습니다. 모든 자산을 명확하게 볼 수 있게 하고, 전환이 끊기지 않게 유지하고, Windows 사용자가 문에 들어갈 수 있도록 하고, 엔진이 사고를 견딜 수 있도록 돕고, AI 코드가 오류로 인해 탈출하는 것을 방지하고, 다중 에이전트 협업을 명확하고 제어 가능하게 만듭니다. 이 모든 것이 가리키는 것은 "유용성"과 "신뢰성"입니다. 이는 바로 수많은 신규 사용자를 환영하는 프로젝트에서 가장 동시에 강화해야 할 두 가지 사항입니다. 새로운 사용자는 눈부신 기능을 계속 사용하지는 않지만 Windows에서 한 번의 정지, 한 번의 충돌, 한 번의 실행 실패로 인해 떠날 수도 있습니다. 이러한 눈에 띄지 않는 경험과 안정성 문제를 하나씩 해결하는 것은 평범해 보이지만 실제로는 오픈 소스에 따른 실제 사용을 위한 기반을 더욱 탄탄하게 다지는 것입니다. 릴리스는 끝이 아니라 시작점입니다. 오늘은 '실제로 사람들이 이용당하고 있다'는 것을 진지하게 받아들이기 시작한 날이었습니다.
