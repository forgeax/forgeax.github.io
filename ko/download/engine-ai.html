ForgeaX Engine + SDK setup for AI

Give this page to an AI coding agent. It defines the safe, repeatable path for installing the published Engine package and the matching SDK carrier, then creating or initializing a game.

Execution contract: probe npm before changing files. @forgeax/engine is the user-facing runtime and CLI package. @forgeax/engine-sdk is a version-matched npm carrier for the built SDK and may still be pending publication. The npm carrier intentionally omits the offline store/pnpm; new and init install the locked Engine dependencies from npm. If npm returns 404 for the carrier, stop and report that state; do not guess a version, use a private GitHub Release, or add the carrier as a game runtime dependency.

Prerequisites

  • Node.js >=22.13.0, pnpm >=10.33.0 <11, and npm registry access.
  • An empty parent directory where the SDK and game can be created as separate sibling directories.
  • No GitHub token is required. The public npm packages are the user download path.

Package roles

PackageUse it forInstall rule
@forgeax/engine The public Engine umbrella, focused package facades, and the forgeax CLI. Install in an existing ForgeaX game, or invoke its CLI with pnpm dlx to install the SDK.
@forgeax/engine-sdk The npm carrier: templates, skills, built packages, source snapshot, and manifests. Do not add it to package.json. The Engine CLI fetches the exact matching version during sdk install; its lockfile is installed from npm.
@forgeax/engine-* Physical focused packages pulled by the umbrella package. Do not discover or install them one by one unless a package README explicitly requires a focused import.

Primary path: create a new game from the SDK

Run this from an empty parent directory. The SDK directory and the game directory must be siblings; forgeax new refuses to create a game inside the SDK.

set -eu

ENGINE_VERSION="$(npm view @forgeax/engine version)"
SDK_VERSION="$(npm view @forgeax/engine-sdk version 2>/dev/null || true)"

if [ -z "$SDK_VERSION" ]; then
  echo "@forgeax/engine-sdk is not published yet; stop and report this state." >&2
  exit 20
fi
if [ "$ENGINE_VERSION" != "$SDK_VERSION" ]; then
  echo "Version mismatch: Engine $ENGINE_VERSION, SDK $SDK_VERSION" >&2
  exit 21
fi

SDK_ROOT="$PWD/forgeax-sdk-$SDK_VERSION"
GAME_ROOT="$PWD/forgeax-game"

pnpm dlx "@forgeax/engine@$ENGINE_VERSION" sdk install "$SDK_ROOT" --version "$SDK_VERSION"
"$SDK_ROOT/bin/forgeax" new "$GAME_ROOT"

cd "$GAME_ROOT"
pnpm forgeax skill verify --json
pnpm forgeax doctor --json
pnpm test
pnpm build
pnpm dev

The SDK install target must be absent or empty. The npm carrier does not contain store/pnpm, so the generated project performs a frozen, registry-backed install using its lockfile. The generated game's AGENTS.md is the next source of truth: read it before editing code or assets. The default template is empty; request --template game-default only when a complete sample is wanted.

Secondary path: install Engine into an existing game

Use this only when the directory already contains a valid forge.json, package.json, and the entry module named by forge.json#entry. It is not a replacement for SDK bootstrap in a blank directory.

cd /path/to/existing-forgeax-game
pnpm add @forgeax/engine@latest
pnpm exec forgeax init
pnpm exec forgeax skill verify --json
pnpm exec forgeax doctor --json

forgeax init adds the standard project scripts and reconciles the Engine dependencies. Keep the package version aligned across the project; use an exact version when reproducing a build.

Failure rules for the agent

  • If npm view @forgeax/engine-sdk version returns 404, stop with a clear “SDK carrier not published” report. Do not continue with a guessed URL or a private repository.
  • If the Engine and SDK versions differ, stop and report the mismatch. The carrier and the CLI are released as one versioned closure.
  • Use an empty SDK target and an empty or absent game target. Never overwrite an existing directory.
  • Do not run forgeax new inside the SDK root. Use a sibling or another external absolute path.
  • After bootstrap, prefer machine-readable checks (skill verify --json, doctor --json) and report the first structured error instead of parsing prose.

Registry and source links

  • @forgeax/engine on npm
  • @forgeax/engine-sdk on npm (availability is checked by the commands above)
