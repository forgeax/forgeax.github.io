확장 페이지를 사용하여 예술 작품 만들기

채팅 외에도 ForgeaX에는 "확장 페이지" 세트가 있습니다. 각 확장 페이지에는 문장을 게임에 바로 사용할 수 있는 자산으로 바꾸는 도구 그룹과 패널이 포함되어 있습니다. 당신은 손으로, AI는 파견으로 동일한 아티팩트를 편집합니다.

✅ 오픈 소스(Apache-2.0). 다음은 확장 페이지 시스템의 개요입니다. 복제 및 설치에 대해서는 다음을 참조하세요.문서.

The four surfaces your agent combines

  • ForgeaX Game — Binds the project, installs Skills and SDK, builds the game and returns preview evidence.
  • Image generation — Creates or edits PNG/JPG assets for concepts, icons, textures, backgrounds and UI.
  • 3D generation — Creates GLB models from text or images and saves them into the active game assets.
  • Engine Skills + SDK — Provides exact authoring guidance and APIs for ECS, rendering, physics, UI, audio, VFX and assets.

A reliable asset-to-game workflow

Generated media is only the beginning. Finish the loop inside the Engine:

  1. Specify — Describe silhouette, style, scale, palette and gameplay purpose.
  2. Generate — Create or edit the source image or GLB in the active game.
  3. Integrate — Use Pack/assets, materials, colliders, animation or UI as needed.
  4. Verify — Run the game and judge readability, scale, collision and performance in context.

Prompts that produce useful artifacts

IMAGE + UI

Generate a transparent 1024×1024 energy-shard icon for this game.
Match the existing cyan/amber palette, keep a readable silhouette at 48 px,
save it in the active game assets, integrate it into the pickup HUD, then run and verify it.

TEXT → 3D → GAMEPLAY

Generate a low-poly sci-fi energy pylon as a GLB, save it in the active game,
then use the Engine asset and physics guidance to place three pylons as solid obstacles.
Run the game and verify scale, collision and camera readability.

ENGINE SYSTEM

Add a dash ability with a short cooldown, a visible recharge indicator and a brief VFX trail.
Read the installed input, ECS, state, UI and VFX guidance first.
Verify keyboard behavior and cooldown timing in the Play build.

Know where the boundaries are

ForgeaX keeps generated content and runtime behavior traceable instead of hiding them behind a one-off editor action:

  • The host agent owns source edits. It changes the active game with normal file tools; MCP stays bounded to setup, status, generation and launch.
  • The Engine owns runtime contracts. The agent reads installed Skills and the version-matched SDK instead of inventing imports from memory.
  • The project owns the result. Images, GLBs, code and Pack declarations remain in your directory and can be versioned, inspected and repaired.
For image-to-3D, the input must be a public HTTPS URL, or a local file when the environment has ForgeaX COS upload configured. Text-to-3D works directly from a prompt.
