按任务使用引擎与创作插件

不要先从产品名或面板开始，先说清楚你要的资产或行为。AI 客户端可以在一条工作流里组合 ForgeaX Game、创作工具与 Engine Skills。

一次对话可以跨越多种能力。例如：生成概念图 → 转成网格 → 作为 Pack 资产接入 → 添加物理与玩法 → 运行并验证。

智能体会组合的四个表面

  • ForgeaX Game — 绑定项目、安装 Skills 与 SDK、构建游戏并返回预览证据。
  • 图片生成 — 生成或编辑 PNG/JPG，用于概念图、图标、纹理、背景和 UI。
  • 3D 生成 — 从文字或图片生成 GLB，并保存到活动游戏资产目录。
  • Engine Skills + SDK — 为 ECS、渲染、物理、UI、音频、VFX 与资产提供准确写法和 API。

你可以让它完成什么任务

你的任务能力路径项目里的结果
制作图标、主视觉、纹理或 UI 面板forgeax_generate_image保存到活动游戏 assets 下的 PNG/JPG。
保留构图，修改风格、颜色或细节给 forgeax_generate_image 传入本地图片不从零重画，得到一份编辑后的资产变体。
制作道具、收集物、环境件或占位角色文字调用 forgeax_generate_3d可继续接入引擎的项目相对路径 .glb。
把确认过的概念图转成网格用公开图片 URL，或已配置本地上传的图片调用 forgeax_generate_3d从视觉参考生成模型，并在真实场景中继续验证。
添加移动、战斗、相机、UI、音频、VFX 或关卡已安装的 forgeax-engine-* Skills + 准确 SDK 声明接入引擎生命周期的游戏代码与创作资产。

可靠的“资产到游戏”工作流

生成媒体只是起点，必须在引擎里完成闭环：

  1. 定义 — 说明轮廓、风格、尺度、配色和玩法用途。
  2. 生成 — 在活动游戏中生成或编辑源图片 / GLB。
  3. 接入 — 按需要使用 Pack / assets、材质、碰撞、动画或 UI。
  4. 验证 — 运行游戏，在上下文里判断可读性、尺度、碰撞和性能。

能产出实用资产的需求写法

图片 + UI

为当前游戏生成一张透明背景的 1024×1024 能量碎片图标。
匹配已有青蓝 / 琥珀色配色，缩到 48 px 时轮廓仍清晰。
保存到活动游戏 assets，接入拾取 HUD，然后运行并验证。

文字 → 3D → 玩法

生成一个低多边形科幻能量塔 GLB，保存到活动游戏。
再按照引擎资产与物理指引，把三个能量塔放进场景作为实体障碍物。
运行游戏，验证尺度、碰撞与相机可读性。

引擎系统

增加冲刺能力：有短冷却、可见的充能指示和短暂 VFX 拖尾。
先阅读已安装的输入、ECS、State、UI 与 VFX 指引。
在 Play 构建里验证键盘操作与冷却计时。

理解能力之间的边界

ForgeaX 不会把生成内容和运行行为藏在一次性编辑器动作里，而是让它们始终可追溯：

  • 宿主智能体负责修改源码。它用普通文件工具改活动游戏；MCP 只负责初始化、状态、生成与启动等有边界操作。
  • 引擎负责运行契约。智能体读取已安装 Skills 与版本匹配 SDK，不凭记忆虚构 import。
  • 项目拥有最终结果。图片、GLB、代码与 Pack 声明都留在你的目录中，可以版本化、检查与修复。
图生 3D 的输入必须是公开 HTTPS URL；如果环境配置了 ForgeaX COS 上传，也可以直接传本地文件。文生 3D 可以直接使用文字描述。
有用的插件不只是生成媒体，还要帮助智能体把媒体放进真正运行的游戏，并在上下文中证明结果。
