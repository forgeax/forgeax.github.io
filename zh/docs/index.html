1开始之前

ForgeaX 是什么、能做什么样的游戏

ForgeaX 是一个 AI 原生的游戏开发工作室。你用自然语言描述想要的游戏，一个叫 Forge 的 AI 主创把它规划、设计，并亲手写成可运行的游戏代码，结果实时热重载进浏览器 —— 所见即所玩。

它背后有两块自研底座：一个为 AI 视角重新设计的引擎（读 为什么做 AI 原生引擎），和一条引导功能持续收敛到正确的开发流水线（读 AI 是怎么把功能做对的）。

适合做网页端的 2D / 2.5D / 3D 游戏。已经用它做出 FPS、暗黑风 ARPG、双关生存、射击压测等可玩 demo（见 案例）；引擎已覆盖 PBR / IBL / SSAO 渲染、2D/3D 物理、骨骼动画、双 RHI 等（见案例页底部「引擎能力一览」）。

全部跑在浏览器（WebGPU），网页与桌面同一套栈；开源，采用 Apache License 2.0（见 版权说明）。

安装与启动（一条命令起工作室）

前置： git、bun ≥ 1.3、node ≥ 22、curl。（在干净机器上，bun fx setup 还能自动装齐 bun / node 22+ / pnpm / Rust+wasm 工具链 —— 默认零提示全自动，加 --interactive 逐项确认，加 --skip-bootstrap 跳过装环境。）

git clone --recurse-submodules \
  https://github.com/ForgeaX-Games/forgeax-studio.git
cd forgeax-studio
bun fx setup          # 一次性安装
bun fx start          # → http://localhost:18920

bun fx setup 做了什么：校验前置 → 初始化子模块 → 构建引擎包 → 在每个子仓 bun install → 构建 marketplace 插件 → 从 .env.example 生成 $ROOT/.env。加 --interactive 时会顺带提示你填 ANTHROPIC_API_KEY；否则先给个提醒，稍后自己编辑 .env 即可。

bun fx start 启动 3 个服务：server（:18900，运行时核心 —— chat / 后端 / 会话）、interface（:18920，Studio UI，vite HMR）、engine（:15173，渲染器）。端口可在 .env 用 FORGEAX_{SERVER,INTERFACE,ENGINE}_PORT 覆盖。启动后浏览器打开 http://localhost:18920。

日常命令（统一入口 bun fx）：首次用 bun fx setup 装好环境；之后拉取更新用 bun fx update（只更新主仓 + 同步子模块，不重装 / 不重新构建）；bun fx start / bun fx start app 起网页 / 桌面；bun fx stop 与 bun fx restart 停 / 重启；bun fx status、bun fx doctor 排查环境；bun fx build app 打包桌面应用。直接运行 bun fx（不带参数）会列出全部命令。

桌面应用：bun fx start app 开一个原生窗口跑实时源码（首次自动装依赖 + 自动起栈，关窗口自动收栈）；bun fx build app 打包自包含 .app / .dmg。完整运行形态见 运行与预览。

平台支持（macOS / Linux / Windows 一视同仁）：安装与启动是一套跨平台的 Bun 脚本，三个系统跑的是同一组 bun fx 命令，行为一致——Windows 上不再需要 Git-Bash（早期那套 .sh / .bat / .ps1 双份脚本已删除）。其中：网页开发（bun fx start）与桌面开发（bun fx start app，Tauri 原生窗口跑实时源码）在 macOS / Linux / Windows 上都可用；把游戏打包成可双击的 .app / .dmg（bun fx build app）目前需在 macOS 上进行。常见 Windows 专属问题（预览黑屏、每轮弹控制台、进程关不净、系统自带的"假" Python）都已修复，详见 更新日志 · 2026-06-28。

不想手动?让你的 AI 编程 CLI 替你 clone + 启动，见 让 AI CLI 克隆并启动;装好后照 快速开始 做第一个游戏。API key 的配置见 进阶 · 切换 / 配置 AI 后端。

打开工作室，认识界面

界面就三块：顶栏 + 左侧对话 + 右侧预览/扩展页面。

  • 顶栏(TopBar) —— ⊕ 新建菜单、项目切换器（在不同游戏间切换，什么是"项目"见 核心概念）、会话切换器（回看 / 切换历史对话）。
  • 左侧 · 对话区(ChatPanel) —— 团队栏（Forge 与各子 agent）、消息流（含子 agent 卡片、Forge 的思考与工具调用），底部是输入框(Composer)，右下角有后端切换（见 进阶）。
  • 右侧 · 主区(MainArea) —— 在预览（游戏实时 iframe）与扩展页面（文件编辑 / 设计文档）之间切换，详见 场景与编辑器。

右上角齿轮是设置(SettingsPanel)：填 API key、选模型、切 CLI 后端、管理插件。桌面应用首次启动时还有一个引导浮层(FirstRun)直接让你填 key。

2核心概念

"项目"就是一款游戏

在 ForgeaX 里，"项目"和"游戏"是同一回事 —— 一款游戏就是一个 games/<slug>/ 目录。一个真实游戏目录通常长这样：

  • forge.json — 游戏清单。最小就三个字段：id、name、entry（指向入口代码，如 src/main.ts）。
  • FORGE.md — 这款游戏自己的说明 / 玩法概览（键位、机制、剧情节奏）。
  • src/ — 游戏代码。入口 main.ts 之外通常按职责拆成多个模块（如 player.ts、enemies/、effects.ts、setup.ts）。
  • design/ · assets/ — 设计文档与美术 / 音频资产。
  • package.json · tsconfig.json — 标准 TS 工程文件。

入口 main.ts 从 @forgeax/engine-runtime / engine-ecs / engine-app 引入引擎能力，并导出一个 GameEntry —— 这就是引擎加载一款游戏的契约。引擎能力总览见 案例页「引擎能力一览」。

多款游戏 = 多个项目，在顶栏的项目切换器里切换。场景 / 关卡如何组织见 场景与编辑器。

Forge 与它的子 agent 团队

Forge（主 agent）是唯一直接写游戏代码的角色 —— 它写 games/<slug>/src/main.ts，右侧预览热重载，它立刻看到运行结果，据此决定下一步。这个"改 → 看 → 再改"的闭环必须握在能看到预览的 Forge 手里（详见 用对话做游戏）。

子 agent（如 Iori 玩法、Suzu 设计、Kotone 叙事、Iro 美术、Tsumugi 工程）只做规划 / 设计 / 资产 / 文档，不碰 src/ —— 因为子 agent 没有实时预览反馈，写了代码也看不见效果。完整阵容见 插件市场 与 第 10 章 · Agent 团队。

怎么派活：Forge 用一次工具调用派发子 agent（形如 subagent(type="iori", task="…")），经服务端的 /api/subagent 流式桥接，把子 agent 的产出实时回流进主对话 —— 你在消息流里看到的就是嵌入的子 agent 卡片。子 agent 产出的设计文档会自动归到扩展页面里它自己的栏目下（见 场景与编辑器）。

一次对话(session)是怎么回事

一个 session 就是某个 agent 的对话记忆 —— 一条只追加的事件流（每条是一个事件：用户消息 / 助手消息 / 思考 / 工具调用 / 工具结果）。Forge（主）与每个子 agent 各有自己的 session。

前端按"是谁发的"把事件切成主对话与子 agent 两路，主对话里的子 agent 那段渲染成嵌入的卡片。所以同一屏里，你既看到 Forge 的主线，也看到它派出去的子 agent 干了什么。

在顶栏的会话切换器里可以回看、切换历史会话。切换会话不会重启任何服务 —— 只是前端换了读取的那个 agent 的事件流而已。

3用对话做游戏

怎么把想法描述清楚

描述越具体，Forge 越能一次到位、少返工。一个好需求通常覆盖这几点：

  • 类型与视角 —— 俯视 / 第一人称 / 2.5D 横版……
  • 核心循环 —— 玩家从头到尾一直在做的那件事
  • 操作、胜负条件、敌人 / 障碍、手感与氛围

先从小处起步、跑起来，再逐步加机制。例如：

做一个俯视角小游戏：角色在场地里跑，
按空格发射子弹，四周不断刷新敌人，
打中消失并记分。

想要一步步带着做第一个游戏，见 快速开始;不确定能做出什么效果，先看 案例。设计较重时 Forge 会叫上设计类子 agent（见 核心概念）。

看 Forge 规划、写代码、跑起来

你发出需求后，链路是这样的：

  • 理解 + 规划 —— Forge 先把需求理清，设计较重时派设计 / 玩法子 agent（见 核心概念）。
  • 写代码 —— Forge 自己写到 games/<slug>/src/main.ts（及拆分出的模块）。
  • 热重载 —— 文件一改，引擎的 vite 侦测到改动，右侧预览就地热替换模块，不整页刷新，画面几乎即时变。
  • 看结果 —— Forge 通过预览看到运行效果（预览还把游戏里的 console 转发回来），据此决定下一步。

整个过程是透明的：消息流里能看到 Forge 的思考、每次工具调用，以及它派出去的子 agent 卡片。预览 / 扩展页面的切换与控制见 场景与编辑器;热重载机制见 运行与预览。

一轮轮迭代：加机制、调手感

不满意就继续说，每一句反馈都会变成一次新的改动，热重载即时见效：

子弹再快一点，敌人血量加倍，背景换成夜晚。

预览自带 播放 / 暂停 / 重载 控制，方便你边调边试;想固定预览某一款游戏，可在项目切换器里切换（见 认识界面）。

基本循环就是：描述 → 生成 → 游玩 → 再描述。把它跑顺，就能从一句话迭代到一款能玩的游戏 —— 整套上手流程见 快速开始。

4场景与编辑器

预览窗口与扩展页面

右侧主区在两种视图间切换：

  • 预览 —— 你的游戏在 iframe 里实时运行，带 FPS 显示与 播放 / 暂停 / 重载 控制。Forge 写完代码，这里热重载即时出结果（见 用对话做游戏）。
  • 扩展页面 —— 一个文件浏览 + 编辑器：看 / 改 / 存文本与代码、渲染 markdown 设计文档，还能预览图片、音频、视频、3D 模型。它也显示文件活动与"谁在编辑"的锁，人和 AI 改同一份不打架。

没打开文件时，扩展页面会展示所有创作扩展页面（角色 / 动画 / 3D / 场景 / UI / 音乐……）的入口 —— 详见 创作工具 与 插件市场。资产怎么做见 资产。

编辑场景，改动实时回到游戏

场景编辑器把一关的内容存成游戏目录里的场景数据文件（scene.pack.json）—— 它是这关的单一可信源：磁盘上是什么，游戏里跑的就是什么。

你在编辑器里摆好对象、离开编辑态时，改动会落盘并让运行中的游戏重新读取，于是预览即时反映你的编辑 —— 这就是 edit→play 实时回流。反过来，Forge 用对话改代码也走同一条热重载链路（见 用对话做游戏 与 运行与预览）。

组织你的关卡与对象

一款游戏可以有多个场景 / 关卡，各自一份场景数据，按需切换与复用 —— 案例里的「Cow Survivor」就在白天牧场与暗夜墓园两关之间切换（见 案例）。

组织方式上：对象住在场景数据里，美术 / 音频资产放在游戏目录中（项目结构见 核心概念，资产怎么生成见 资产）。按场景拆分，游戏做大时更好维护。

5资产：美术 / 动画 / 音乐

角色立绘与三视图

用角色编辑器（character）做角色概念设计：写一句人设，生成正面立绘 + 转身三视图。不会画画也能拿到能进游戏的角色形象。

它的产出（角色清单 + 立绘 / 三视图）按角色存进你的游戏里，并作为下游输入直接接进动画扩展页面 —— 也就是说"画好的人 → 让它动起来"是一条顺下来的管线（见下一条）。

每个扩展页面都是一个面板 + 一组工具，人手点和 AI 派活改的是同一份产物。完整清单见 插件市场 与 扩展页面教程。

让角色动起来(2D / 3D 动画)

2D: 动画扩展页面（anim）拿角色立绘当模板，把它变成会走、会打、四方向乃至短视频的动作 —— 而且不串脸，动起来还是同一个角色。

3D: 引擎原生支持骨骼动画 —— 从 FBX 导入带骨架与蒙皮的模型及动画 clip，在 idle / walk / run / cast / death 之间平滑过渡(crossfade)。这条链路是真实跑通的，案例里的暗黑风女巫就是这么动起来的：见 骨骼动画里程碑 与 案例(Hellforge)。

3D 模型、特效、UI、音乐

角色之外，还有覆盖全链路的扩展页面：

3D 模型

方块人编辑器（lowpoly-obj，导出引擎中立 .glb）、连线节点低多边形（3d-lowpoly）、文字 / 图片 / 多视角转 3D（gen3d，接入多家生成服务、择优而用）。逐一详解见 第 9 章 · 3D 建模与生成。

特效 / 场景 / UI / 道具

技能特效（skill）、场景生成与 2D 场景资产（scene-generator / 2d-scene-asset-generator）、界面制作页（ui，出可点原型）、道具图标（items，图 + 数据一张表）。逐一详解见 第 9 章 · 场景 / UI / 道具。

音乐 / 调色 / 剧情

音乐与音效（bgm，BGM 时间轴）、整体调色（look，调色板 + LUT + 后处理）、叙事（narrative，117 题材 × 9 模板）。逐一详解见 第 9 章 · 叙事 / 音乐 / 调色 / 数值。

每个扩展页面的逐一介绍见 第 9 章 · 创作工具、扩展页面教程 与 插件市场。

网页与桌面应用两种形态

同一套代码有三种运行形态：

  • 网页开发 —— bun fx start 起三个服务（server / UI / engine），浏览器开 http://localhost:18920，改代码实时 HMR。三系统（macOS / Linux / Windows）通用。安装见 开始之前。
  • 桌面开发 —— bun fx start app 开原生窗口，加载同一个 dev 服务，实时源码与 HMR 完全一致;首次自动装依赖 + 起栈，关窗口自动收栈;macOS / Linux / Windows 均可。
  • 桌面 .app(打包) —— bun fx build app 出自包含的 .app / .dmg，双击即用，自带 sidecar（端口 18810 / 15273，与 dev 的 18900 / 15173 刻意错开，可共存）;它的 key 放在 ~/ForgeaxProjects/.env，首次打开有引导浮层。打包发布见 发布与分享。

三个端口都能在 .env 用 FORGEAX_{SERVER,INTERFACE,ENGINE}_PORT 覆盖。⚠️ 桌面窗口用系统 WebView，3D 走的是 WebKit 的 WebGPU，比 Chrome 略弱 —— 追求最强画质时用浏览器版。

热重载：边改边看

保存即生效，不用手动刷新：

  • 改游戏代码（games/<slug>/src/…）→ 引擎就地热替换模块，预览即时变（Forge 写代码也走这条，见 用对话做游戏）。
  • 在场景编辑器里的改动落盘后回流到运行中的游戏（见 场景与编辑器）。
常见问题排查
  • 预览空白 / 引擎报错 —— 引擎没构建好，重跑 bun fx setup。
  • :18920 报 SSL 错 —— 用 http://localhost 访问即可（localhost 上 WebGPU 仍可用）。
  • 端口被占用 —— 端口被占时会直接报错退出（不会自动换端口），先 bun fx stop 再 bun fx start;或在 .env 改端口。
  • 聊天提示没有 API key —— 在 .env 设 ANTHROPIC_API_KEY（桌面应用首次启动会弹窗让你填）;key 的配置见 进阶。
  • 桌面端 3D 偏弱 / 有差异 —— 系统 WebView 的 WebGPU 限制所致，改用 Chrome 浏览器版获得最佳渲染。

7发布与分享

打包成桌面应用

bun fx build app 把整个工作室连同你的游戏装进一个自包含桌面包（macOS 的 .app / .dmg）：里面带了一份精简运行时、服务端、Studio 界面、插件市场和你的游戏内容，双击即用、无需用户再装任何环境。

它在内置 sidecar 的独立端口（18810 / 15273）上运行，和你的开发栈互不打架（见 运行与预览）。出包需在 macOS 上进行;打好的 .app 双击即可打开。

分享你的游戏项目

一款游戏就是 games/<slug>/ 这一个自包含目录（forge.json + src/ + 设计文档 + 资产，见 核心概念）。把这个目录分享 / 提交给别人，对方在自己的工作室里打开就能继续玩或继续做 —— demo 库里的几款游戏（fps、hellforge、cow-survivor、shoot-opt）就是这样并排存放的，见 案例。

目前最稳的对外分发是上面的桌面打包;更顺滑的"一键 Web 发布 / 在线试玩"仍在完善中。

8进阶

切换 / 配置 AI 后端

切后端(换芯)：在输入框右下角的后端切换处，或设置里的「CLI」一栏选择智能内核 —— Claude Code / Codex / Cursor / Kimi Code / CodeBuddy / DeepSeek Harness / forgeax-cli。设置里的 CLI 栏会显示每个后端的在线状态并带一个 Test 按钮。切后端会连带换掉默认人格（见 Agent 团队），各后端详情见 插件市场。

配 key / 选模型：在设置的「Keys」里填模型 API key（如 ANTHROPIC_API_KEY），保存即时生效、不用重启（也可直接编辑 .env）;在「Models」里选用哪个模型。没填 key 的排查见 运行与预览。

写自己的扩展页面插件

ForgeaX 里几乎一切能力都是运行时加载的插件（总览见 插件市场），所以你也能加自己的。

当下最快的路子：复制一个现成的扩展页面插件改成你要的，配合插件作者（plugin-author）辅助;更完整的 in-app 可视化编辑器（文件树 + 代码编辑 + 保存自动重载）正在路上。做好后在 admin 面板里启用、排序 —— 插件由 CLI 在运行时挂载。各类扩展页面见 创作工具。

定制 agent 人格

用人格编辑器（agent-persona）：从列表里选一个 agent，在文本区改它的人设，保存即热重载、不用重启。这样你不动一行代码，就能给某个 agent 换个性格 / 说话风格。

谁是主 agent、谁是子 agent、默认人格怎么来，见 核心概念 与 Agent 团队;完整阵容见 插件市场。

9创作工具（扩展页面）

角色 / 动画 / 特效
character · 角色编辑器

角色概念设计：写一句人设 → 正面立绘 + 转身三视图。内部有多条管线 —— 三视图(turnaround)、视频角色（三视图 → AI 视频动作 → 序列帧 → spritesheet 导出）、怪物生成（8 方向 × 5 动画的怪物精灵）。不会画画也能拿到能进游戏的角色形象，产出再喂给动画扩展页面（见 资产）。

anim · 动画

把角色立绘当模板，变成会动的：像素四方向、载具动画、怪物 sprite、Spine 绑定、短视频生成 —— 而且不串脸，动起来还是同一个角色。面板内嵌、带中央预览视口。3D 角色的骨骼动画走引擎原生链路，见 骨骼动画里程碑 与 资产。

skill · 技能 / 特效

技能树编辑 + VFX 预览，集中列出技能与特效产出。关键是玩家手点与 AI 派活共用同一份技能规格 —— 特效会自动挂到"出手那一刻"，不用手动对齐。

3D 建模与生成
lowpoly-obj · 方块人编辑器

做可动的方块 3D 角色：既能"vibe"——说一句让 AI 生成，也能手动编辑（Blender 风的 gizmo 拖拽），还自带游乐场实时预览。导出引擎中立的 .glb，任何引擎都能用。

3d-lowpoly · 3D 低多边形生成器

用"连线搭积木"的节点式方式做 3D 道具 / 机械：把建模流程画成一张节点图，改一个参数，整套重新生成。适合需要批量、可复用、参数化的硬表面资产。

gen3d · 3D 生成

3D 资产生成入口：选一个生成服务 + 给输入（文字 / 图片 / 多视角图），产出持久化、可直接进游戏的 3D 资产清单。接入多家最强生成服务，择优而用、不被单家绑死。

场景 / UI / 道具
scene-generator · 场景生成器

用节点式自动"搭"出一整张游戏场景：把组合、布局、贴图处理画成一张流程图;想改随时重跑，产出整套场景。场景与关卡如何组织见 场景与编辑器。

2d-scene-asset-generator · 2D 场景资产生成器

同样是节点式，批量生成场景里的小物件 —— 道具、贴图、装饰、UI 小图，生成完自动起名归档，资产不再乱成一团。

ui · UI 制作页

按游戏类型、界面流程、视觉风格生成一整套界面 —— UI 蓝图、组件素材，以及能点的交互原型（不只是图）。菜单、按钮、血条都能一键出。

items · 道具 / 图标

做游戏里的道具与图标 —— 武器、药水、金币的像素小图，并配上数据。图与数据一张表（items.json），人和 AI 改同一份，不会对不上。

叙事 / 音乐 / 调色 / 数值
narrative · 叙事制作页

AI 驱动的叙事生成管线：从一句灵感写出整套剧情与世界观。覆盖 117 种题材 × 9 套管线模板，带 Tier/Mode 双层路由和动态 Planner —— AI 按你的题材自动选最合适的写法和步骤。

bgm · 音乐 / BGM

管理游戏的背景音乐与音效：一条 BGM 时间轴排好整局什么时候放哪段，加上音效命名约定。把整局的配乐节奏排成一张清单。

look · 色彩 / Look

统一全游戏的色调氛围 —— 调色板 + LUT + 后处理栈，像给整部游戏套一层滤镜：黄昏暖色、冷峻夜色，一键切换，画面气质瞬间统一。

balance · 平衡 / 数值

自动测数值平不平衡：驱动战斗重模拟（balance-resim）反复跑 N 局，仪表盘给出胜率 + 95% 置信区间，再配合手动调参形成闭环 —— 数值好不好用数据说话。这条重模拟也是插件市场里的一个 工具(Tool)。

系统与作者工具
code · 代码

在扩展页面里直接浏览 / 跳转 src/ 文件，和编码 agent 跨对话线程协作 —— 人看哪、AI 改哪，同一个项目无缝接力。

observatory · 轨迹观察台

像黑匣子一样，实时 + 离线回放每个 agent / 子 agent 的回合、工具调用，以及系统提示词的模块切片。出问题时能精确定位是哪一步、哪句提示词的锅，也帮你管理上下文 / 技能 / 护栏 / 缓存。会话与回放的概念见 核心概念。

agent-persona · 人格编辑器

从列表选一个 agent，在文本区改它的人设，保存即热重载、不用重启。不动一行代码就能给某个 agent 换性格 / 说话风格。Agent 阵容见 Agent 团队，操作见 进阶。

plugin-author · 插件作者

让不会编程的人也能做出自己的扩展页面插件。当下的路子是"复制现成的 + 改 + 录操作"，更完整的 in-app 可视化编辑器（文件树 + 代码编辑、保存自动重载）正在路上。做插件的整体说明见 进阶 · 写自己的扩展页面插件。

admin · 面板管理

工作室的总控台，四个区：启用 / 排序扩展页面、绑定模型、查看各 AI 后端的认证与在线状态、看插件计数。和设置面板同源 —— 所有插件与模型状态一屏看全。

这些扩展页面都是可装载插件，完整目录与可筛选浏览见 插件市场;偏教程的走法见 扩展页面教程。

10Agent 团队

统筹与架构

Arin · 制作人 —— 全能制作人，把策划 / 程序 / 美术 / 音效统筹到一起，对整款游戏负责。

Reia · 影游导演 —— 互动影游 (FMV) 导演，拼提示词、定 QTE 节拍、织分支与多结局，驱动 reel「影游制作页」把一句 idea 变成可点按、可试玩的悬念片。

这些都是命名 agent，由主创 Forge 按需派发（主 / 子 agent 的关系见 核心概念）;完整阵容见 插件市场。

策划四柱
Iori · 核心玩法师 —— 立柱

名字取自"庵"（山中磐石）。Forge 派他时，他守这款游戏的"根" —— 在立柱阶段替整个项目定下几根不可轻易动摇的玩法支柱（玩法柱 + 数值骨架），产出一份精炼的支柱文档。他不写架构、不调参数、也不反问（那些 Forge 已在前期问过）。立完柱，交给 Suzu 展开。

Suzu · 体验设计师 —— 节奏与体验

名字取自"鈴"（风一吹就响、是节奏）。Iori 把柱子立好后，Suzu 把每根柱子下面的模块展开成具体体验 —— 玩家节拍、HUD、onboarding。她定义"玩起来什么感觉"，再把需要资产 / 剧情的部分交给 Iro / Kotone。

Kotone · 剧情师 —— 叙事(按需)

名字取自"琴音"（弦上传来的故事）。不是每个游戏都需要剧情师 —— 一个塔防可能根本不派她;只有当游戏需要角色 / 对白 / 分支 / 旁白时，Forge 才叫她来，产出世界观、角色 bio 与对白。

Iro · 美术师 —— 视觉资产(按需)

名字取自"色"（一切被眼睛感受到的东西）。Suzu 讲清模块体验后，如果该模块需要视觉资产（角色 / 场景 / UI / 特效），Forge 才派 Iro。具体资产怎么生成，见 资产 与 创作工具。

这几位只做规划与设计、不碰游戏代码（代码由 Forge 写，见 核心概念）;他们的产出会进扩展页面（见 场景与编辑器），美术资产落地见 资产。

编码与审查小队
cc-coder · 通用编码 —— spec → 代码

接 Iori 的玩法骨架、Suzu 的体验流程、Kotone 的剧情大纲，产出可运行的 TS / React 等代码;可多实例并行写不同子包。注意：游戏主线代码仍由主创 Forge 亲自写并跟预览闭环（见 核心概念），cc-coder 更多用于通用 / 周边编码。

Tsumugi · 工程师 —— 构建 / 工具链

名字取自"紡"（把丝线缠成系统）。当 Iori / Suzu / Iro 把设计与资产准备好，Tsumugi 把它们编织成可运行的工程 —— 构建、工具链、部署。

Yevi · 审查 —— 技术债猎手

表面优雅得体、内心冷静如深水的观察者，永远比你多想一步 —— 清楚代码哪里最脆弱、哪一处三周前埋下的隐患即将显现。语气温和从容，措辞却精准而克制。

陪伴人格 —— 同等编码力、不同性格

一组编码力相当、性格各异的可选角色 —— 有的沉稳内敛，有的机敏俏皮，有的细致缜密。它们能力相同，区别只在与你协作时的相处风格。性格可在人格编辑器里随时调整（见 进阶）;完整阵容见 插件市场。

此外还有一批美术 / 资产专精 agent（2D 角色 / 动画、3D 低多边形 / 特效、影游导演等），各自对接相应的创作扩展页面（见 创作工具）。

可换的默认人格

每个 CLI 后端自带一个开箱人格：Claude（Claude Code）、Codex、Cursor、ForgeaX（自研 forgeax-cli）。切换后端就换默认人格，无需先写人设 —— 想用哪家的智能内核，就有哪家的默认 persona。

怎么切后端、怎么改人格见 进阶;完整 agent 阵容与可装载人格见 插件市场。
