一条命令,从此 Windows 也能跑

这天把安装和启动脚本从 bash 整体搬到了跨平台的 Bun TypeScript:同一套命令在 macOS、Linux、Windows 上一致运行,Windows 上不再需要 Git-Bash。配套修掉了一串 Windows 专属的拦路问题,把"会话"从绑死全局改成跟着每个游戏走,资产导入更稳,底层 CLI 也更快、更可控、更可审计。

最大的一道门槛:换平台就装不起来

长期以来,装好、跑起来这一步是靠一堆 bash 脚本完成的。这对 macOS 和 Linux 用户没问题,但对 Windows 用户就是一道硬门槛——bash 不是 Windows 的原生环境,要么得先装 Git-Bash 这类兼容层,要么各种诡异报错。对一个想让"任何人都能把想法变成游戏"的工具来说,"装不起来"是最致命的第一道劝退。这一天解决的就是这件事:把所有安装与启动脚本,从 bash 整体重写成用 Bun 跑的跨平台 TypeScript。Bun 在三大系统上行为一致,于是同一套命令、同一套逻辑,在 Windows 上和在 Mac 上跑得一模一样,不再需要任何兼容层。

命令收敛成一组好记的

搬迁的同时,入口也清理干净了。过去散落的、平台各异的脚本(.sh、.bat、.ps1 等)被一并删掉,统一成一组直白好记的命令:bun run setup 一次性装好环境、bun run start 起整套服务、bun run stop 停掉、bun run app 开桌面应用。不管你在哪个系统上,记住这几条就够了。对新用户,这意味着"照着 README 抄四行就能跑起来",不用再分辨"我是 Windows,这条该换成哪个";对老用户,这意味着不再有"两份脚本(一份 sh、一份 ps1)各改一遍、还容易改漏"的维护负担。把多份等价脚本收敛成一份跨平台的真源,正是这天工作的核心——少一份要同步的东西,就少一处会出错的地方。

顺手修掉一串 Windows 专属拦路虎

真正让 Windows 顺起来,光有跨平台脚本还不够,还得逐个修掉那些只在 Windows 上冒头的怪问题。这天处理的一类典型是:系统里那个"假"的 Python——Windows 自带一个其实没装、点了只会弹应用商店的 python3 占位程序,脚本如果天真地以为它能用,就会在装环境时莫名其妙地卡住。这天让安装流程学会识别并跳过这个占位、去找一个真正能用的 Python。类似这种"在别的系统上根本不存在、只在 Windows 上才会绊一跤"的细节,是跨平台支持里最磨人也最必要的一环——它们不增加任何功能,但每修掉一个,就有一批 Windows 用户能少卡一次、顺利往下走。

会话从"绑死全局"变成"跟着游戏走"

这天还动了一处更内在的结构:会话(也就是你和 Forge 的一段对话过程)的归属。此前会话是全局的、和具体游戏分离的;这天把它改成嵌套进每个游戏之下、按游戏来划分。意思是:你为"太空射击"这个项目和 Forge 的对话,和你为"农场模拟"那个项目的对话,从此各归各的、互不串味。这更符合直觉——一段对话本就属于某一个具体的游戏;也为后面更清晰的项目管理打底:切换游戏时,连同它的对话历史、上下文一起切过去,而不是面对一锅混在一起的全局会话。这类"把数据归到它真正所属的地方"的整理,平时不显眼,却让整个系统的心智模型更干净。

资产导入更稳 + 底层 CLI 更快更可控

这天还落了几项让日常更稳的修复。资产这边,修好了较大模型导入时的一个索引问题(大网格需要用更宽的整数来索引顶点,过去会在这里出错),并让模型导入时写出的元数据走统一的规范格式——导入一个大一点、复杂一点的模型不再容易"翻车"。底层驱动 AI 的 CLI 内核也做了多项打磨:让某些场景下的首轮响应去掉冗余、更快开始干活;修正了一处给 agent 注入"行为准则"的问题;并新增了可选地屏蔽用户自带外部工具、以及对 agent 调用宿主工具的审计记录——后者意味着"这次 AI 到底动用了哪些工具"变得有据可查。这些合起来,是把地基往"更快、更可控、更可信"的方向又夯实了一层。

这一天意味着什么

这一天的主角,是"门槛"。一个再强大的工具,如果一大批人因为系统不对、装不起来就被挡在门外,它的价值就先打了对折。把安装与启动彻底跨平台、让 Windows 用户也能一条命令跑起来,等于把这扇门向所有人敞开——这是"任何人都能做游戏"这句话能成立的前提之一。而同一天里,把会话归到游戏名下、把资产导入修稳、把 CLI 内核打磨得更快更可审计,则是在敞开门的同时,把屋里也收拾得更整洁。降低进入的门槛,再提高里面的质量——这一天两件事都做了。
