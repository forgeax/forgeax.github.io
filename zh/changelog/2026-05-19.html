断电也能恢复的后端地基 + 引擎第一次点灯

这天三条线都"扒到地基重浇":后端运行时重写成一套分层、能断电恢复的多 agent 架构;引擎第一次点亮基于物理的光照——方向光、点光、聚光、色调映射、带贴图的立方体全部到位;AI 开发流程也大幅瘦身,同一个改动少绕好几圈。

三条线,同一种决心:扒到地基重浇

这一天的三件大事有一个共同特征:都不是在原有基础上小修小补,而是"扒到地基重浇"。后端把整套运行时推倒,按一套清晰分层重写;引擎把渲染从只能清屏推进到真正点亮物理光照;连构建这一切的 AI 开发流程本身,也被大幅精简。敢在产品已经能演示之后,还回头把地基重做,背后是一种判断:有些早期为了快而欠下的结构性债务,越往后拖代价越大,不如趁现在还来得及,一次性还清。这天体现的,正是"在正确的时机做正确的重写"这种工程上的成熟。

后端推倒重盖:能"断电恢复"的多 agent 地基

后端运行时这天从地基重浇成一套更稳、更清晰的多 agent 架构。最关键的变化是"断电恢复":每个 agent 都自己写一本只追加的事件日志(账本),记录它经历的每一件事;一旦进程崩溃、甚至机器断电,重新打开时系统能从这本账本把事件完整回放,把 agent 恢复到崩溃前那一刻的状态。这条命脉被一个端到端的烟雾测试反复验证过——从产生事件、写入账本、重新打开、到完整回放,整条路径都跑通。对一个要让 agent 在后台长时间干活的平台,这是从"出意外就前功尽弃"到"出意外也能原地复活"的根本性升级。

分层架构:为什么把后端拆成清晰的几层

这次重写不是简单换个写法,而是把后端拆成了职责单一、自底向上的若干层:最底是类型与默认值的骨架,往上是事件总线与队列、共享黑板(临时状态)、可恢复的事件账本、监听磁盘的 agent 列表、上下文窗口、agent 本体与驱动它一回合思考的循环、每个会话各自的调度器,最顶是会话与会话管理。每一层只依赖它下面那层、只暴露明确的接口,这样任何一层都能独立理解、独立测试、独立替换。配套还把 agent 列表改成直接盯着磁盘上的文件变化来感知增删,不再维护一份容易写歪的索引。分层的真正价值,是让一个会越来越复杂的系统始终"拆得开、看得懂、改得动"——这正是它值得花大力气重浇的原因。

引擎第一次"点灯":基于物理的光照

引擎渲染这天迈过一道象征性的门槛:第一次点亮了一束基于物理的光。"基于物理"意味着材质对光的反应遵循真实世界的能量规律——而不是简单地把颜色乘个亮度。亮起这第一束方向光,看似只是屏幕上多了点明暗,实则是引擎从"能把形状涂上颜色"跨进了"能模拟光和物体之间真实交互"的世界。这是所有真实感画面的起点:有了正确的光照模型,后面金属的反光、布料的柔和、表面的凹凸才谈得上可信。把这件最基础也最关键的事第一步走对,等于给后面所有画质提升定了正确的基调。

投光体、衰减与色调映射

点亮第一束方向光之后,引擎紧接着补上了更丰富的光照类型:点光源(从一个点向四面八方发光,像灯泡)和聚光灯(打出一个光锥,像手电),并且都带物理上正确的"距离衰减"——离光越远越暗,符合直觉。光多了之后,新的问题是高光容易"爆白"成一片死白,于是又接上了"色调映射":把超出屏幕显示范围的强光优雅地压回可见区间,让明暗过渡自然、亮部仍有细节,而不是糊成一团。这几样合起来,意味着你现在可以用不同类型的灯去布置一个场景的氛围——一盏暖色的点光、一束聚光打在角色身上——而画面不会因为光强而失控。

带贴图的立方体端到端跑通

这天还把"一个贴着纹理的立方体"从头到尾正确地渲染了出来——听起来简单,实则要把好几处底层细节同时对齐才行:颜色空间要走正确的处理链(不然贴图会偏色),背面要被正确剔除(不然会看到本该藏起来的内壁),三角形的环绕方向要修对(不然某些面会朝里翻、整个物体看着破洞百出)。这些都是 3D 渲染里典型的"魔鬼在细节"——任何一处没对齐,画面就会以各种诡异的方式出错。把一个带图的立方体完整、正确地画对,等于把这条从模型数据到屏幕像素的完整管线验证了一遍,为后面渲染真正的复杂模型扫清了一批最常见的坑。

让 AI 开发流程少绕几圈

这天还把"AI 是怎么把这一切建出来的"那套开发流程做了一次大幅精简。此前一个改动要走的内部流程偏重:有两套各自独立的审查环节、小改动还要在不同模板之间分岔。这天把重复的审查合并成一次、只产出一份统一的产物,小改动也收进同一条更轻的快路,删掉了一道多余的转手。结果是:同样一个改动,跑完整套流程时少绕好几圈,该快的小事真的快了下来,而该严谨的把关又没有丢。这条线虽然用户看不见,但它直接决定了团队(以及越来越多由 AI 承担的开发)能以多快的节奏稳定产出——把"造东西的流水线"本身打磨顺,和打磨产品同样重要。

这一天意味着什么

这一天没有一件是"加个新按钮"式的浅层功能,三条线全在做最不讨好却最要紧的事:把后端重写得能扛住意外、把渲染推进到能模拟真实光影、把开发流程本身改得更利落。它们共同回答了一个问题——这个东西到底能不能撑住长期、严肃的使用?后端有了断电恢复,意味着把活交给它不再提心吊胆;引擎点亮了物理光照,意味着它真的在往"做得出好看的游戏"那条路上走;流程瘦身,意味着这种快速演进还能持续下去。趁早把地基重浇好,是为了之后能在上面盖得更高、更放心——这正是这一天留给未来开发的那句话。
