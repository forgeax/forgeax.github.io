一键整理对话 + WebGPU 软件兜底

这天围绕"让长会话和各种机器都不掉链子"做功夫:一键压缩对话、上下文用量看得见、斜杠命令可补全;3D 在没有硬件加速时自动软件兜底。新游戏从干净的 ECS 模板起步,引擎还补上 2D 精灵图集动画与一批健壮性修复。

把"长期、广泛地用"这件事做扎实

能力齐了之后,下一个问题是:它能不能被长期、广泛地用?长期,指的是一次对话能不能撑很久而不被上下文塞爆;广泛,指的是它能不能在各种各样的机器上都跑得起来,而不只是开发者那台高配电脑。这天的几件事,正好分别回答这两个问题:一键整理对话解决"聊久了会卡上限",WebGPU 软件兜底解决"没有好显卡就黑屏"。再加上新游戏的干净起点、2D 动画和一批健壮性修复——主线很清楚:不是加新花活,而是把"日常长时间、在更多机器上用"这件事做扎实。

一键整理对话:/compact + 上下文用量环

和大模型长时间来回,它能记住的"上下文"会越堆越满;一旦接近上限,响应会变慢、质量也会下滑,甚至开始忘事。这天加了一个 /compact 命令:一键把此前的来回压缩成一份精炼的摘要,腾出空间继续聊,而且这次压缩本身不占用一整轮对话——它是直接在后端完成的。输入框里还多了一个"上下文用量环",像油表一样直观显示当前还剩多少额度,快满了你一眼就能看见,从而主动决定该不该整理一下。配合斜杠命令的自动补全,打一个 / 就能看到所有可用命令并快速选用。这一组改动直面"和 AI 长期协作"绕不开的核心约束——上下文是有限的;把它的管理交到用户手里、而且做得轻巧,长会话才真正可持续。

WebGPU 软件兜底:更多机器能跑起 3D

3D 渲染依赖现代显卡的能力,但现实里总有一些机器或环境拿不到硬件加速——可能是显卡太旧、可能是运行环境受限。以前遇到这种情况就是一片黑屏,等于直接把这部分用户挡在门外。这天加了一层软件兜底:当拿不到硬件加速的渲染设备时,系统会自动退一步,改用软件实现把画面渲出来——虽然慢一些,但至少能跑、能看、能继续做。底层还做了多级回退(一条路不通就试下一条,实在不行才报错),并补上了更清楚的诊断提示,告诉你为什么没走上硬件加速(比如运行在非安全来源下)。这件事的意义在于覆盖面:一个面向大众、希望谁都能上手的平台,不能假设每个人都有一台高配电脑;能在更弱的机器上也跑起来,门槛才真正降了下来。

新游戏从干净的 ECS 模板起步

新建一个游戏时,现在会从一份结构清晰、按正规架构组织的精简模板生成。这天把这份默认模板重写成了"正规 ECS 架构"的写法,并把它从内嵌字符串提取成一个受版本控制的独立文件、行数还砍掉了一半——也就是说,你一建好游戏,拿到的就是一份干净、紧凑、能直接往上加东西的好底子,而不是一堆需要先读懂再删改的样板代码。配套也把模板和喂给 AI 的系统说明一起更新到了最新的引擎接口。这件事对"AI 来写游戏"尤其重要:AI 是照着模板的样子继续写的,模板越干净、越规范,AI 生成的代码就越大概率写对、越容易被你看懂和复用。一个好的起点,能省下后面无数纠偏的功夫。

2D 精灵图集动画

引擎这天补上了 2D 精灵图集动画:把一张"精灵图集"(把一连串动作帧排在同一张图里)里的多帧按顺序播放,角色和特效的 2D 动画就有了一套现成、规范的做法。这是 2D 游戏里最常用的动画方式——一个小人走路、一团火焰跳动,本质上就是几帧画面快速轮播。在此之前 2D 内容只能是静态精灵;有了图集动画,2D 这条线才算真正能动起来。它和此前的精灵图层一起,把引擎做 2D 的基本功补齐:既能正确分层叠放,又能让每个精灵动起来。对想做 2D 游戏的人来说,这是把"能摆图"升级成"能做动画"的关键一步。

引擎健壮性:回归测试 + 一批渲染修复

这天引擎还做了一批不显眼但要紧的健壮性工作。补上了针对几类容易出问题的情形的回归测试——比如渲染查询、父子层级、以及"场景里一盏灯都没有"这种边界,把它们用测试钉死,防止以后改别的地方时把它们悄悄改坏。还把一些含义模糊的字段做了更准确的命名,让代码读起来更不容易误解;并修了几处合并后才暴露的兼容问题。这些都属于"把刚加进来的新能力焊牢"的工作:前面几天密集加了很多东西,这天回头给它们补测试、清边角,确保它们不只是"能跑一次",而是"以后也一直靠得住"。快速迭代和稳扎稳打交替进行,是这条产品线能一直跑下去的原因。
