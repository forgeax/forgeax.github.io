资产检视器 + 切换不再卡顿 + Windows 兼容

开源发布之后,这天是一轮扎实的打磨与硬化:编辑器新增了覆盖所有资产类型的检视器;在场景之间、编辑与试玩之间切换不再冷重启渲染器、不再黑屏卡顿;一批 Windows 兼容问题被扫清;引擎学会了从设备掉线中自愈、在受限环境下优雅降级;载入期还加了自动合约校验,终端版也补上了检查点回退。

发布之后,转身打磨

开源发布把项目交到了公众手里,而真正的考验从交出去那一刻才开始——更多的人、更多样的电脑、更挑剔的眼光,会把每一处不够顺、不够稳的地方都照出来。这一天就是发布之后的转身:不追新的炫目功能,而是沉下心来把已有的体验打磨得更顺、把底层硬化得更稳。资产检视器让创作者能看清自己手里的每一份素材;切换不卡顿消除了日常使用中最高频的一处顿挫;Windows 兼容让更多人连得进门;引擎自愈让意外不再轻易把人打断;载入期合约校验让 AI 改的代码错不出门。这些改动单看都不大,但它们瞄准的都是"用起来到底顺不顺、稳不稳"——而这恰恰是一个刚刚走向公众的项目最该立刻补强的地方。第一印象只有一次,发布之后的每一处打磨,都是在守护它。

资产检视器:任何资产都能看清

编辑器这天新增了一个资产检视面板,覆盖项目里所有类型的资产。它解决的是一个很基础却一直缺位的需求:当你的项目里堆了一大堆素材——网格、材质、纹理、动画、场景——你怎么快速看清某一个到底是什么样?以前往往只能看到一个名字,具体长什么样、有哪些属性,得真把它放进场景才知道。现在选中任意一个资产,右侧的检视面板就会按它的类型给出对应的预览和详情:选个网格能看到它的形状,选个材质能看到它的质感,选个纹理能看到那张图,选个动画能看到它的信息。配套还把"内容浏览器"和材质面板联动起来,从浏览到查看到编辑形成连贯的动线。这件事对创作者的意义是"心里有数"——一个稍大的项目动辄几十上百份资产,能随手点开看清每一份,才不至于在一堆模糊的名字里抓瞎,管理和复用素材的效率也随之提升。

切换不再卡顿:渲染上下文后台保活

这天修好了一个折磨人很久、且在日常使用中极高频的老问题:切换时的卡顿。此前,无论是在不同场景之间切换、还是在"编辑"和"试玩"两种模式之间来回切,系统都会把底层那套图形渲染整个推倒重来——画面先黑一下,重新初始化一遍,慢的时候甚至直接卡死。根因在于:每次切换都会重建渲染上下文,而重建一个图形上下文是一件相当昂贵、且在某些浏览器环境下容易出错的操作,你切得越频繁、它越容易出问题。这天的解法是"保活":切换时不再推倒重建,而是把渲染上下文留在后台继续活着(只是移出可见区域而不是销毁),需要时直接复用。改成原地切换之后,在场景之间、在编辑与试玩之间切来切去都变得顺滑、即时,不再有黑屏和卡顿。对一个鼓励你反复"改一下、看一眼、再改"的创作工具来说,切换正是被触发得最频繁的动作之一;把这条路径从"每次都重来"改成"随时秒切",直接消除了创作心流里最碍事的一处顿挫。

跨平台:Windows 兼容性修一批

既然已经开源、想让尽可能多的人用上,Windows 这块就必须啃下来。这天集中扫了一批 Windows 上的兼容问题,都是那种"在另一个系统上没事、到了 Windows 就莫名其妙坏掉"的典型坑:判断一个进程是否还活着的方式,在 Windows 的终端环境里得换一种写法才正确;创建新工程时要建的软链接,在 Windows 上会遇到权限限制,改用 Windows 原生的等价机制绕开;环境贴图(HDR 格式)的解码在 Windows 上也修对了。配套还把启动脚本做了跨平台加固。这些问题一个个都不起眼,但只要有一个没解决,Windows 用户就可能在安装、建工程、或第一次运行时被卡住,直接劝退。把这条从安装到跑起来的链路在 Windows 上完整跑通,等于向占据大半桌面市场的 Windows 用户敞开了大门——对一个刚开源、急需被更多人试用的项目,这一步的现实意义格外大。

引擎自愈:设备掉线能恢复,受限环境优雅降级

引擎这天在"出意外也能扛住"上推进了一大步。其一是设备/表面自愈:图形设备在运行中可能会因为各种原因突然掉线(比如系统资源紧张、显卡驱动重置),以前这往往意味着画面直接黑掉、无法恢复;现在引擎能侦测到这种掉线,并尝试自动把渲染重新建立起来,让画面缓过来,而不是就此死掉。其二是受限环境下的优雅降级:在某些能力较弱的浏览器环境里,引擎对显存容量的探测可能拿不到准确值,这天改成了在拿不到时退回一个安全的默认上限;当要渲染的内容超出容量时,也改成"截断渲染一部分"而不是整帧跳过,宁可少画一点也不让整个画面崩掉;底层的崩溃也被隔离成可恢复的错误。这些改动的共同主题是"韧性":一个要面向各种各样真实设备、被普通人长时间使用的引擎,不可能假设一切都完美;真正成熟的标志,是在不完美发生时,它能扛住、能恢复、能退而求其次地继续工作,而不是一遇意外就彻底罢工。

载入期合约校验 + 场景回写

这天还给"AI 写代码"这条线又加了一道保险:载入期合约校验。当载入一个游戏时,系统会自动检查游戏代码与引擎接口是否对得上——所谓"合约",就是引擎规定的那套调用约定;如果 AI 改完代码后,某处用错了接口、或者跨文件之间的接口对不上了,系统会把这种"漂移"用画面上的报错浮层直接、显眼地指出来,而不是等运行到一半才莫名其妙地崩。这等于在"写完"和"跑起来"之间,又设了一道自动门岗,把接口层面的错误当场拦下。与此同时,引擎打通了场景的"回写":能把当前场景里的内容序列化保存成一份结构化的资产包,并支持从内容反查回它的标识。这为"在编辑器里改完、立刻能存下来"这条闭环打下了底层基础——编辑不只是看和调,改动还得能可靠地落盘保存。这两件事一前一后,都是在让"创作的产物"更可靠:既保证代码层面对得上,也保证编辑成果存得住。

终端版检查点回退 + 多 agent 协作细节

这天命令行/终端版也补上了和图形界面对齐的能力:检查点与回退。你可以把一段对话回退到此前某个检查点重新来过,不满意就退回去;还新增了会话恢复——中断之后,用一条命令就能接着上次的进度继续,不必从头再来;以及一个用来向你提问的浮层。聊天界面这边则继续打磨多 agent 协作的临场细节:当一个子 agent 把任务交接给另一个时,会显示清晰的接力标头让你看清交接关系;相关的 agent 会按"出品家族"分组,一屋子人各归各类;需要你拍板的敏感操作有了专门的权限确认卡片;agent 的头像也做了轻微的抬升和放大,让"谁在动、谁在等你"更一目了然。这些改动共同服务于一件事:当你同时指挥一群各有分工的 AI 协作时,整个过程要清楚、可控、随时退得回来——既看得懂它们在做什么,也始终握着叫停和回退的主动权。

这一天意味着什么

如果说前一天的开源发布是"把门打开、请人进来",那这一天就是"把屋里收拾得让人住得舒服"。它没有惊天动地的新功能,通篇都是打磨与硬化:让你看清每一份资产、让切换不再卡你一下、让 Windows 用户进得了门、让引擎在意外面前扛得住、让 AI 的代码错不出门、让多 agent 协作清楚可控。这些事的共同指向,是"可用性"和"可靠性"——而这恰恰是一个刚刚迎来大量新用户的项目,最需要立刻补强的两件事。新用户不会因为某个炫目功能而留下,却很可能因为一次卡顿、一次崩溃、一次在 Windows 上跑不起来而转身离开。把这些不起眼的体验和稳定性问题一个个解决掉,看似平淡,实则是在为开源之后接踵而来的真实使用,把地基夯得更实。发布是起点,而不是终点;这一天,正是认真对待"被人真正用起来"这件事的开始。
