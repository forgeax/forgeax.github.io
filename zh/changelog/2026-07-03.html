更新2026-07-03

Windows Play 模式稳定化 + 开发者 LLM 调试代理

编辑器 Socket 栈修复后，Windows 上的 Play 模式终于稳定了；新增 FORGEAX_DEBUG_PROXY 环境变量让开发者可以实时捕获和检查所有 LLM API 流量；Windows 桌面 app 打包问题已修复；影游 runtime 架构设计落地，作为引擎级 game runtime 子类。

Windows Play 模式：终于稳定了

Windows 上的 Play 模式之前一直间歇性失败，原因是编辑器的 Socket 栈有问题。底层的 WebSocket 导出在桌面构建路径中缺失，导致引擎预览 iframe 与编辑器宿主断开连接。现在已修复——Windows 上的 Play 模式和 macOS 一样稳定了。

开发者 LLM 调试代理

新增了一个可选的环境变量 FORGEAX_DEBUG_PROXY。设置后，它会启动一个本地 HTTP 代理，捕获所有外发的 LLM API 调用（Anthropic、OpenAI、Gemini 等），并记录请求/响应对。这对调试 agent 行为非常有价值——你能看到发送了什么 prompt、模型返回了什么、每次调用花了多长时间。在 .env 里设置即可，代理会随 bun fx start 自动启动。

Windows 桌面 app 打包修复

Windows 的 Tauri 2 桌面构建之前因 interface 包缺少一个依赖导出而失败。现已修复——bun fx build app 能在 Windows 上正常生成 .exe 安装包了。

影游 runtime 架构设计

影游（互动电影）runtime 的设计文档落地，将它定位为引擎内的一等公民 game runtime 子类。这意味着互动电影将共享与普通游戏相同的 ECS 管线、场景图和资产系统，而不再是独立的 sidecar。实现将在后续版本中跟进。
