骨骼动画 + 场景工作台与观测台

这天角色第一次真正"动"了起来:引擎补上骨骼蒙皮动画。工具家族也扩到三件——场景工作台(还带一个工程多游戏)、观测台、叙事工具补上真本事;聊天界面更清爽、凭据更安全,引擎也瘦了样板代码、能在浏览器里干净运行。

从"静态物体"到"活的角色"

在这天之前,引擎能渲染被光照亮、贴着图、投着影的物体,但它们都是"静"的——再精致也只是摆件。这天补上的骨骼动画,是让这些物体"活过来"的关键一环;而工具侧又一口气添了场景、观测、叙事几件能力。把"让角色动起来"和"把做游戏要用的工具补齐"放在同一天,正是这个平台一贯的节奏:引擎管"做出来的东西够不够生动",工具管"做这件事顺不顺手",两头一起往前。下面分别看这几件事。

引擎:角色骨骼蒙皮动画

引擎这天补上了游戏里最关键的一块——骨骼蒙皮动画。它的原理是:给角色模型搭一副"骨架",再把表面的网格"蒙"在骨架上;当骨架按动画数据摆出姿势时,网格会跟着自然地拉伸、弯折,于是角色就走、跑、挥手起来,而不是僵在原地。这是从"渲染一个静态物体"跨进"渲染一个活的角色"的分水岭——一个不会动的角色再好看也只是雕像,而能动的角色才撑得起角色扮演、动作、冒险这些真正的游戏类型。把这块基础能力做对,意味着引擎从"能展示场景"开始具备"能承载有生命的主角"的资格,这是后面所有有人物、有战斗的游戏的前提。

新增"场景"工作台 + 一个工程多个游戏

工具家族再添一位实打实的成员:场景工作台,作为第一个"真正能干活"的此类插件落地,用来搭建和组织一个游戏里的场景。配套平台开始支持"一个工程里管理多个游戏",并做了按游戏隔离的数据存放——每个游戏的内容各自归各自,互不污染。这意味着你可以在同一个工程里做一个系列、拆出多个关卡分支、或者并行试几个不同的想法,而不必每次都另起炉灶。对一个想长期经营自己作品的创作者来说,"多游戏共处一个工程、互不干扰"是把零散尝试沉淀成体系的基础——挑哪个游戏来跑、来改,从此是顺手的一步,而不是一次搬家。

新增"观测台":实时看 agent 在做什么

新增了一个"观测台"工作台,把 agent 的活动实时摊开:谁在跑、在调用哪个工具、产出了什么事件,一目了然。它由专门的后端接口和一条事件桥支撑,把后台正在发生的事源源不断地送到这个面板上。它解决的是"放手让一群 agent 自己干活"时最矛盾的一对需求——既想撒手不管、又怕完全失控。观测台给了你一个折中:平时让它们自己跑,你扫一眼面板就知道全局态势;一旦哪里不对劲,你能立刻看清是谁、在哪一步出了问题,及时介入。对多 agent 协作越来越重的平台,这种"看得见的掌控感"是敢于把更多事交给 AI 的心理底气。

叙事工具补上真本事 + 叙事 agent 激活

叙事这条线这天从"有个空壳"走到了"真能用"。后端补上了一组面向大模型的叙事工具定义——也就是给 agent 配上了几把能真正编排剧情与文本的"趁手家伙",而不只是一个没法动手的界面;与此同时,负责叙事的那个专门 agent 也从占位状态正式激活,可以接活了。两件事合起来,意味着"写故事"这件事在平台里第一次有了能实际驱动它的角色和工具。做游戏从来不只是堆玩法,剧情、对白、节奏同样是作品的灵魂;把叙事工具和叙事 agent 一起补齐,是平台朝"一个人就能做出一个有血有肉的完整游戏"这个目标迈出的实在一步。

聊天更清爽 + 凭据更安全

这天界面与安全上也各收一笔。聊天界面做了一轮精简:去掉多余的发光与模糊效果、把边框统一,装了很多 agent 时列表会自动分页,悬停时高度也更稳,长时间盯着看更省眼、更专注于内容本身。预览窗也放开了所需的图形与全屏等权限,让里面的游戏跑得更完整。安全方面,后端开始把模型密钥从一个独立保险库迁向"只走环境变量"的方式管理,并加了一份文件活动账本——既简化了凭据的管理路径,也让"什么时候动了哪个文件"有迹可循。界面更清爽是为了少打扰,凭据更规整是为了更可信,两者都在让平台朝"能放心长期使用"再靠近一点。

引擎:样板代码瘦身 + 浏览器里干净运行

引擎这天在"好用、好跑"上各做了一处底层功夫。其一是样板代码瘦身:给常用的数据结构补上合理的默认值与便捷的创建函数,并统一了一些常用工具的引出方式——结果是写游戏内容时要敲的样板代码更少,意图更直接。其二是"浏览器安全子导出":把那些只能在本机环境(而非浏览器)里用的依赖,从引擎的主入口里剥离出去,确保引擎在浏览器里加载时不会误拉进跑不动的东西、干净利落地运行。前者降低了"写"的负担,后者保障了"跑"的稳定;它们都不是亮眼功能,却实实在在地让这台自研引擎对使用它的人(以及生成代码的 AI)更友好。
