文字生 3D 落进游戏 + agent 自己验证再继续

这天文字 / 图生成的 3D 模型真正打通,产物按游戏单独存储、直接落进你的游戏,而不再停在一个看看而已的展示台;agent 写完代码会自己跑验证、失败就接着改,不再卡着反问用户;引擎把一个大型场景的冷启动从约 2GB 压到约 45MB,角色骨骼动画的链路继续推进;游戏库还新增了一款弹幕生存样例。

两条线同时收口:产物落地与自主可靠

这一天最值得说的两件事,正好对应"AI 造游戏"这条路上最关键的两个问题:做出来的东西怎么真正用上,以及 AI 怎么少给人添麻烦。前一天那款"文字生成 3D 模型"的工作台还停在"评测台"阶段——能生成,但产物未必能顺畅地接进游戏;这天它走完了最后一公里,生成的模型按游戏单独存储、并能直接落进你的关卡。另一条线上,前几天给 AI 装的"验车线"还需要平台在背后盯着,这天则更进一步,让 agent 自己把"写代码 → 验证 → 继续"这个循环闭合起来,不再动不动停下来反问用户。再加上引擎对大型场景的提速、骨骼动画的推进、以及一款新样例游戏,这一天的主题是:让能力真正可用、让自动化真正省心。

文字 / 图生 3D 真打通,产物直接进你的游戏

3D 生成工作台这天从"评测台"正式走到了"真能用"。此前它能凭文字或图片生成 3D 模型,但生成只是第一步——一个模型如果不能顺畅地保存、并接进你正在做的那个游戏,它就只是个孤立的展示品。这天补齐的正是"落地"这后半程:每个游戏拥有自己独立的一份 3D 资产存储,生成的模型会按游戏单独归档;生成走的是一条公网可达的上传链路,接入外部的图生 3D 服务后,用文字 / 图片生成模型已经在真实环境里完整跑通;后端还专门开了一条按游戏分发 3D 资产的通道,把每个游戏的生成产物单独发出来。配套工具编辑界面也做了重构,对齐了统一的视觉风格、按生成的阶段组织侧边栏。把这些串起来,"想要一个石头 / 箱子 / 小怪的模型"到"这个模型已经在我的关卡里"之间的距离一下子缩短了——生成不再是一个需要你手动搬运产物的独立环节,而是创作流程里顺畅的一步。对没有美术能力的创作者来说,这是把"获取素材"这道最高的门槛,实打实地踏平了一截。

Agent 写完自己验证再继续,不再卡着问你

延续前几天"验车线"的思路,这天把 agent 的"写完→验证→继续"闭环真正收紧了一步。此前的痛点很微妙也很常见:agent 写完一段代码,既不主动跑测试、也不主动看构建有没有报错,而是直接停下来反问用户"这样对吗?"——可用户往往根本没法判断,只能含糊地回一句"应该行吧",于是错误就这么溜过去了。这其实是把本该由机器承担的验证责任,错误地推给了人。这天的改动让 agent 写完代码后自动跑一遍验证:通过了才往下走,没通过就拿着具体的报错自己继续改,直到真的对了为止——它不再为了一个自己就能确认的问题去白白占用你的一个对话回合。这和前几天的"构建不过不许说做完"是同一条逻辑的延伸:前者保证最终交付是对的,这一条则让中间的每一步都尽量自我闭环、少打扰人。配合聊天界面新增的"跳到最新"浮标、以及你翻看旧记录时不再被自动滚动硬拽到底部,长对话回看起来也舒服多了。一个真正好用的 AI 协作者,应该是"自己能搞定的就别问",这天正是朝这个方向迈进。

大场景冷启动从约 2GB 压到约 45MB

引擎这天给大型复杂场景做了一次力度惊人的冷启动瘦身。此前的痛点是:一个细节丰富的室内大场景,首次加载时要读取约 2GB 的网格几何数据——这不仅启动慢得让人难以忍受,在开发时反复重启更是煎熬。这天的做法是把网格数据预先二进制化、并打包成一个紧凑的缓存产物:同样的场景,首次加载读取的数据从约 2GB 压缩到了约 45MB,启动速度快了整整一个数量级。这件事的意义在于,它直接决定了"这个引擎到底能不能跑严肃规模的场景"——一个动辄要等几十秒甚至卡死的加载,会让大场景在实践中变得不可用;而把它压到秒级之后,真正有规模、有细节的场景才第一次变得"开发起来不痛苦"。配套引擎还能在同一个场景里同时点亮数百盏灯而保持高效、把清晰锐利的文字真正烤进画面,这些能力合在一起,意味着引擎的演示这条线终于开始能承载严肃的、接近真实游戏体量的场景了。

骨骼动画链路推进:为"角色真动起来"铺路

引擎这天还在角色动画这条线上扎实推进了一步:打通了骨骼蒙皮动画所需的顶点数据链路。这听起来很底层,但它对应的是游戏里最重要的一类表现——一个角色之所以能自然地跑、跳、挥手,靠的是"骨骼"驱动"皮肤":模型内部有一副看不见的骨架,每根骨头摆动时,贴在它上面的网格表面("皮肤")就跟着变形,于是角色就动了起来。要让这套机制正确运转,引擎必须能正确地把"每个顶点受哪几根骨头影响、各影响多少"这串数据一路传递并计算到位。这天落地的正是这条链路的关键环节,并配了一个让同一个带骨骼的角色同时出现多个实例的演示,以及一个能识别多种格式的模型导入器和处理骨骼层级的解析器。它本身还不是"角色已经动起来了",而是让那一步成为可能的前置工程——把这条链路铺好,后面真正的角色动画才能稳稳地接上去。对一个以做游戏为目标的引擎来说,角色动画是绕不开的硬骨头,这天啃下了其中关键的一块。

游戏库新增一款弹幕生存样例

这天游戏库里新增了一款"弹幕生存"风格的 3D 样例游戏:成群的小怪从四面八方扑过来,角色自动开火、不断清场、在越来越密的包围中尽量活得久一点。这类玩法近年很受欢迎,规则简单、节奏爽快、容易上手又耐玩。把它做成一个现成的样例,价值有两层:一是它本身就是一个可玩的成品,任何人都能打开玩、也能照着改成自己的版本;二是它作为一个真实的、有完整玩法循环的游戏,反过来检验了平台和引擎的各项能力是否真的扛得住——大量同屏敌人考验渲染容量、自动战斗考验逻辑、生存节奏考验整体手感。用一个真游戏来压测平台,比任何抽象的测试都更能暴露问题。每多一款风格不同的样例,就等于给后来的创作者多提供了一个可以直接站上去的起点。

这一天意味着什么

这一天把"能力"和"可靠"两件事又各自往前推了一程,而它们恰恰是一个 AI 创作平台的两条腿,缺哪条都走不稳。"能力"这条腿上,文字生 3D 真正落地、大场景跑得动、骨骼动画铺好路、新样例补进库——平台能做的事更多、更大、更真实了。"可靠"这条腿上,agent 学会了自己验证再继续——平台做事更让人省心、更不容易出岔子、更不需要人时时盯着。一个值得长期信赖的工具,从来不是只在某一条腿上拼命发力,而是让这两条腿协调地交替向前:能力越强,就越需要可靠性来兜住它,否则强大反而意味着更大的翻车风险;而可靠性越扎实,就越敢于把能力推向更难、更大的目标。这一天,正是这两条腿一起向前迈出的一步。
