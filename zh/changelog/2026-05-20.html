聊天接回新后端 + 设置里管模型与密钥

前一天重浇的后端地基,这天接回了聊天界面:新建、切换、删除会话都顺,历史能完整回放,过程里还分出"来信/出信/警告/报错"几类系统行。模型和密钥都搬进了设置面板,可视化管理;引擎则补齐了贴图光照、多光源,并修好了第一人称相机漫游。

从"重写完"到"接回来"

前一天后端被推倒重浇成一套分层、能断电恢复的新架构,但重写完只是完成了一半——新地基必须被真正接回界面、跑通完整的一条链路,才算落地。这天的主线就是"接回来":让聊天界面对接到新的后端运行时,把会话的新建、切换、删除、回放这些日常动作在新架构上一一打通,并顺势把模型与密钥的管理也搬进界面。换句话说,前一天证明了"新地基立得住",这一天证明了"新地基用得上"。一次大重写最危险的时刻往往不是重写本身,而是重写之后能不能平滑地把上层接回去而不留一地碎玻璃——这天迈过的正是这一关。

聊天接回新后端,会话管理更顺

聊天界面这天对接上了新的后端运行时,日常的会话操作随之变得规整顺手。新建会话有了一个统一的入口,不再是几处入口各行其是;切换会话时会自动打开对应的标签页,你的注意力跟着内容走;删除也一步到位。重新打开一个会话,能从持久记录里完整回放此前的来回,上下文不丢。过程里还把系统消息按"来信 / 出信 / 警告 / 报错"分门别类地显示出来——当一次运行出问题时,你能一眼看出是卡在哪一步、属于哪一类,而不是对着一团混在一起的输出干瞪眼。这些都是"会话"作为日常单位该有的基本盘,这天把它们在新架构上稳稳兑现了。

会话与历史走规整接口

在"接回来"的同时,后端把会话与历史的相关能力都收敛成了一套规整的接口。会话的创建与删除走标准的增删接口,默认 agent 会被自动准备好;顶层创建一个 agent、或者把它连同附属一锅端地删掉,也都有对应的明确命令;历史则通过专门的取数接口按需读取,而不是把一切都塞进实时流里。底层的 agent 列表改成"无状态地扫一遍磁盘 + 监听文件变化"来维护,所有 agent 的变动事件都落进一份全局日志。把这些能力都规整成清晰、单一职责的接口,好处是上层(界面、命令行、甚至将来别的客户端)都能用同一套规矩去操作,而不必各写各的——这正是前一天那套分层架构开始兑现红利的地方。

在设置里直接管模型与密钥

这天把"用哪个模型、填什么密钥"这两件高频却以前很麻烦的事,搬进了界面。模型选择器现在读取真实的可用模型清单——你选的就是会真正生效的那一个,而不是一个可能早已过时的写死列表;而且可以为每个 agent 分别指定它用哪个模型,让不同角色用不同档位的模型成为可能。密钥输入也搬进了常驻的设置面板,配一个"眼睛"按钮在显示与隐藏之间切换,既方便核对又不至于一直明文晾着。对用户来说,这意味着填 key、换模型不再需要退到命令行、去翻配置文件——这些本就该在界面里完成的事,现在真的在界面里完成了。降低这类操作的门槛,正是让非专业开发者也能上手的关键一环。

引擎:贴图光照 + 多光源同场

引擎的光照能力这天继续往实用方向补。其一是"贴图驱动的光照":用一张纹理去控制物体表面不同部位对光的反应强弱——比如让金属嵌条比周围的木头更亮、让磨损处更暗,材质细节因此丰富很多,而不必把整块表面当成均匀的一种材质。其二是"多光源同场":一个场景里可以同时点亮好几盏灯,并把点光、聚光等不同投光体组合起来用。这两件事合起来,意味着布光从"只能打一盏灯"进入了"能像真实场景那样布置多光源、营造层次"的阶段。对想做出有氛围、有质感画面的人来说,这是从"亮着"到"好看"之间最关键的一段路。

引擎:第一人称相机漫游修好 + 带图场景

这天还修好了第一人称相机的漫游——此前 WASD 走位失灵,根因是一个很典型的小坑:键盘事件读的是"物理按键位置"还是"字符",两种口径没对齐,导致按了没反应。修对之后,你可以用 WASD 在场景里自由走动、转动视角去观察,这是任何"能逛的 3D 场景"最基本的交互。配套还把一个贴着纹理的场景跑通,并修正了外部素材的地址处理,让纹理在各种部署路径下都能被正确找到。能自由走进一个被多盏灯照亮、贴着图的场景去四处看看——这天把"搭一个能逛的世界"这件事又往前推了实打实的一步。

这一天意味着什么

这一天把前一天的"重写"真正变成了"可用"。后端新地基接回了界面,会话、模型、密钥这些日常操作都在新架构上跑顺并收敛成规整接口;引擎则在光照与相机上同步推进,让画面更有层次、场景更能走动。一边是把底层的大手术平滑地接回上层、不留后遗症,一边是持续往用户能直接感知的体验上添砖加瓦——两者并行,说明这个团队既敢做伤筋动骨的重构,又没忘记每天都要让产品对用户更好用一点。大重写之后还能当天就把界面接回来、把模型密钥这种贴身体验补上,本身就是"重写做对了"的最好证明。
