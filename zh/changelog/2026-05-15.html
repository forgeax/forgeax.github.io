聊天界面进阶:可调布局、嵌套工具调用、子 agent 卡片

这天有两条主线:界面长大了——可调布局、工具调用嵌套在待办下、子 agent 有了独立卡片、实时与回放统一成一条流水线;后端则在悄悄浇一块大地基——一套插件运行时(事件总线、权限引擎、沙盒文件接口、插件清单),为"任何能力都能作为插件接进来"铺路。引擎也扩展了组件词汇并引入了场景资产。

一明一暗:界面长大 + 后端浇地基

这天的工作分成看得见和看不见的两半。看得见的一半,是聊天界面集中长大了一截——这是用户每天都要面对的地方,体验上的每一点进步都立竿见影。看不见的一半,是后端在默默浇一块影响深远的地基:一套让"第三方能力作为插件被安全地装进来"的运行时。后者当天几乎没有任何用户能直接感知的产出,却决定了这个平台未来能不能从"一个写死了功能的应用",长成"一个可以被不断扩展、甚至被用户二次开发的平台"。把这两件事放在同一天看,正好体现了一种平衡:既要持续打磨眼前的体验,也要为长远的可扩展性下注。

聊天界面进阶:可调布局 + 工具调用嵌套在待办下

界面这天的进步集中在"信息怎么组织得更清楚"。其一,侧栏、聊天区、底部面板都能拖拽调整大小,你可以按当下在做的事自由分配屏幕——看代码时把聊天收窄,盯输出时把底部拉高。其二,也是更关键的一处:工具调用现在会嵌套显示在它所属的那个待办事项之下,而不是平铺成一长串。当 agent 在执行一个多步任务时,你能清楚看到"为了完成这一步,它调用了哪些工具",层级关系一目了然。长对话、多步骤任务最怕的就是信息糊成一团让人看不清进展;这两处改动,正是把"看得清谁在做什么、做到哪一步"这件事落到实处。

子 agent 有了独立卡片

随着多 agent 协作越来越常见,"一个主 agent 派活给多个子 agent"成了日常场景。这天给子 agent 的活动做了一个独立的卡片呈现:子任务不再混在主对话的字流里,而是各自有一张能折叠展开、带自己上下文的卡片。这让"谁在替谁干活、各自进展如何"在视觉上立刻分得清。对一个把"一个人指挥一支 AI 团队"当成核心场景的平台来说,这种"把每个成员的工作各自归位"的呈现方式至关重要——否则团队一大,屏幕就会变成一锅看不懂的乱炖。子 agent 卡片是把"多 agent"这件抽象的事,变成你眼睛能直接看懂的画面的第一步。

实时与回放统一到一条流水线

在此之前,"实时看着 agent 干活"和"事后回放一段历史"很可能是两套各自为政的渲染逻辑——结果就是同一段内容,实时看到的和回放出来的细节常常对不上。这天把它们统一到了同一条流水线上,共享同一套处理回调:无论内容是正在实时流进来,还是从历史账本里重放出来,都走完全相同的解析与呈现路径。意义在于一致性:你重新打开一段历史,看到的就是它当时真实发生的样子,一个细节都不会变形。这种"单一真相路径"的设计,既省去了维护两套逻辑的负担,也从根上杜绝了"实时和回放对不上"这类最让人困惑的 bug。

后端插件运行时地基:总线、权限、沙盒

后端这天最重的活,是开始浇一套插件运行时的地基,目标是让"第三方能力作为插件被安全地装进来跑"。它由几块咬合的部件组成:一条进程内的事件总线,让各部件以发布/订阅的方式松耦合地通信;一份插件清单的解析与校验,并对清单里声明的"作用域"做防伪造处理(防止一个插件谎报自己的权限);一个权限引擎,用规则约束每个插件能碰什么、不能碰什么;一套沙盒化的文件接口,配上协作式的文件锁,让多个插件读写时不互相破坏;再加上一份只追加的文件账本来记录发生过什么。这一整套当天几乎没有面向用户的产出,但它是"全插件化"这个长远方向的真正起点——有了它,以后无论是新工具、新工作台还是新 agent,都能以统一、可控、可沙盒的方式接进来,而不必每加一样东西就改一遍内核。

引擎:组件词汇扩展 + 场景资产

引擎这天继续扩充它描述游戏世界的"词汇"。组件系统新增了对字符串、以及定长/变长数组这类数据形态的支持,并内置了一个"名字"组件——这样场景里的每个对象都能有个可读的名称,而不只是一串内部编号,无论是调试还是将来在编辑器里查看都方便得多。更重要的是引入了"场景资产":把一整个场景作为一种可被引用、可被实例化的资产对象来管理,并提供了把场景实例化到世界里的机制。这意味着场景从此可以像模型、纹理一样被结构化地保存、引用和复用——这是后面"在编辑器里搭场景、把场景拼成关卡"等一切能力的底层前提。

引擎质量门:双通道把关

引擎这天还立了一道双通道的质量门,从两个互补的角度自动把关代码质量:一条通道做常规的代码风格与规范检查,另一条通道专门盯着"内部接口"的使用边界——确保那些只该在内部使用的东西不会被无意间当成公开接口暴露出去。两条通道都接进了持续集成,每次提交都自动跑。它的价值和此前那道渲染基准是一脉相承的:把"代码质量对不对"从靠人评审、靠自觉,变成一道自动、客观、绕不过去的关卡。一个要长期演进、还要面向越来越多协作者的引擎,正是靠这一道道自动门,才能在快速迭代的同时不至于慢慢腐坏。

这一天意味着什么

这一天的两条线,恰好代表了一个成熟产品必须同时握住的两端:一端是用户当下的体感,另一端是平台长远的骨架。聊天界面的进阶让人现在就用得更舒服,而后端那套几乎无人能直接看见的插件运行时,则是在为"这个平台将来能不能被无限扩展"埋下伏笔。能在同一天里既照顾眼前、又投资长远,靠的是清晰的分工和对优先级的判断——哪些是要立刻见效的体验,哪些是宁可慢一点也要先打牢的地基。这正是值得留给未来开发的一条经验:别只顾着加看得见的功能,也别只埋头打看不见的地基,真正难的是两者都不偏废。
