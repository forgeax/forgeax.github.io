1开始之前Before you start

ForgeaX 是什么、能做什么样的游戏What ForgeaX is and what games it makes

ForgeaX 是一个 AI 原生的游戏开发工作室。你用自然语言描述想要的游戏,一个叫 Forge 的 AI 主创把它规划、设计,并亲手写成可运行的游戏代码,结果实时热重载进浏览器 —— 所见即所玩。ForgeaX is an AI-native game development studio. You describe the game in plain language; an AI lead called Forge plans it, designs it, and writes it into running game code itself, hot-reloading the result into your browser — what you say is what you play.

它背后有两块自研底座:一个为 AI 视角重新设计的引擎(读 为什么做 AI 原生引擎),和一条引导功能持续收敛到正确的开发流水线(读 AI 是怎么把功能做对的)。Two in-house foundations sit underneath: an engine redesigned for the AI's point of view (see Why an AI-native engine) and a development loop that converges features on a correct result (see How AI gets a feature right).

适合做网页端的 2D / 2.5D / 3D 游戏。已经用它做出 FPS、暗黑风 ARPG、双关生存、射击压测等可玩 demo(见 案例);引擎已覆盖 PBR / IBL / SSAO 渲染、2D/3D 物理、骨骼动画、双 RHI 等(见案例页底部「引擎能力一览」)。It suits 2D / 2.5D / 3D web games. Playable FPS, Diablo-style ARPG, two-level survival and shooter demos already exist (see the showcase); the engine covers PBR / IBL / SSAO rendering, 2D/3D physics, skeletal animation and dual RHI (see "Engine capabilities" at the bottom of the showcase).

全部跑在浏览器(WebGPU),网页与桌面同一套栈;开源,采用 Apache License 2.0(见 版权说明)。Everything runs in the browser (WebGPU), web and desktop on one stack; open source under Apache License 2.0 (see the license).

安装与启动(一条命令起工作室)Install & launch

前置: git、bun ≥ 1.3、node ≥ 22、curl。(在干净机器上,install.sh 还能自动装齐 bun / node 22+ / pnpm / Rust+wasm 工具链 —— 默认零提示全自动,加 --interactive 逐项确认,加 --skip-bootstrap 跳过装环境。)Prerequisites: git, bun ≥ 1.3, node ≥ 22, curl. (On a clean host, install.sh can also bootstrap bun / node 22+ / pnpm / the Rust+wasm toolchain — zero-prompt by default; --interactive asks per tool, --skip-bootstrap skips it.)

git clone --recurse-submodules \
  https://github.com/ForgeaX-Games/forgeax-studio.git
cd forgeax-studio
bash install.sh        # 一次性安装 / one-time setup
bash start.sh          # → http://localhost:18920

install.sh 做了什么:校验前置 → 初始化子模块 → 构建引擎包 → 在每个子仓 bun install → 构建 marketplace 插件 → 从 .env.example 生成 $ROOT/.env。加 --interactive 时会顺带提示你填 ANTHROPIC_API_KEY;否则先给个提醒,稍后自己编辑 .env 即可。What install.sh does: verifies prereqs → inits submodules → builds the engine packages → runs bun install in each sub-repo → builds the marketplace plugins → scaffolds $ROOT/.env from .env.example. With --interactive it also prompts for ANTHROPIC_API_KEY; otherwise it warns and you edit .env later.

start.sh 启动 3 个服务:server(:18900,运行时核心 —— chat / 后端 / 会话)、interface(:18920,Studio UI,vite HMR)、engine(:15173,渲染器)。端口可在 .env 用 FORGEAX_{SERVER,INTERFACE,ENGINE}_PORT 覆盖。启动后浏览器打开 http://localhost:18920。start.sh boots three services: server (:18900, the runtime core — chat / backends / sessions), interface (:18920, the Studio UI with vite HMR), and engine (:15173, the renderer). Override ports in .env via FORGEAX_{SERVER,INTERFACE,ENGINE}_PORT. Then open http://localhost:18920.

桌面应用:bash app.sh 开一个原生窗口跑实时源码(首次自动装依赖 + 自动起栈,关窗口自动收栈);bash app.sh build 打包自包含 .app / .dmg。完整运行形态见 运行与预览。Desktop app: bash app.sh opens a native window on the live source (first run auto-installs and starts the stack; closing it stops the stack); bash app.sh build packages a self-contained .app / .dmg. See Run & preview for all modes.

不想手动?让你的 AI 编程 CLI 替你 clone + 启动,见 让 AI CLI 克隆并启动;装好后照 快速开始 做第一个游戏。API key 的配置见 进阶 · 切换 / 配置 AI 后端。Prefer not to do it by hand? Let your AI coding CLI clone & launch it — see Have your AI CLI clone & launch it; then build your first game with Quick start. For API keys, see Advanced · Switch / configure the AI backend.

2核心概念Core concepts

"项目"就是一款游戏A "project" is a game

在 ForgeaX 里,"项目"和"游戏"是同一回事 —— 一款游戏就是一个 games/<slug>/ 目录。一个真实游戏目录通常长这样:In ForgeaX, "project" and "game" are the same thing — a game is one games/<slug>/ folder. A real game folder usually looks like this:

  • forge.json — 游戏清单。最小就三个字段:id、name、entry(指向入口代码,如 src/main.ts)。the game manifest. Minimally three fields: id, name, and entry (pointing at the entry code, e.g. src/main.ts).
  • FORGE.md — 这款游戏自己的说明 / 玩法概览(键位、机制、剧情节奏)。the game's own readme / gameplay overview (controls, mechanics, story beats).
  • src/ — 游戏代码。入口 main.ts 之外通常按职责拆成多个模块(如 player.ts、enemies/、effects.ts、setup.ts)。the game code. Besides the main.ts entry, it's usually split into modules by concern (e.g. player.ts, enemies/, effects.ts, setup.ts).
  • design/ · assets/ — 设计文档与美术 / 音频资产。design documents and art / audio assets.
  • package.json · tsconfig.json — 标准 TS 工程文件。standard TS project files.

入口 main.ts 从 @forgeax/engine-runtime / engine-ecs / engine-app 引入引擎能力,并导出一个 GameEntry —— 这就是引擎加载一款游戏的契约。引擎能力总览见 案例页「引擎能力一览」。The main.ts entry imports engine capabilities from @forgeax/engine-runtime / engine-ecs / engine-app and exports a GameEntry — the contract by which the engine loads a game. For the full capability set, see "Engine capabilities" on the showcase.

多款游戏 = 多个项目,在顶栏的项目切换器里切换。场景 / 关卡如何组织见 场景与编辑器。Multiple games = multiple projects, switched in the top-bar project switcher. For how scenes / levels are organized, see Scenes & editor.

Forge 与它的子 agent 团队Forge and its team of sub-agents

Forge(主 agent)是唯一直接写游戏代码的角色 —— 它写 games/<slug>/src/main.ts,右侧预览热重载,它立刻看到运行结果,据此决定下一步。这个"改 → 看 → 再改"的闭环必须握在能看到预览的 Forge 手里(详见 用对话做游戏)。Forge (the main agent) is the only one that writes game code directly — it writes games/<slug>/src/main.ts, the preview hot-reloads, and it sees the running result to decide the next step. That edit → see → edit loop has to stay with whoever can see the preview, i.e. Forge (see Build by chatting).

子 agent(如 Iori 玩法、Suzu 设计、Kotone 叙事、Iro 美术、Tsumugi 工程)只做规划 / 设计 / 资产 / 文档,不碰 src/ —— 因为子 agent 没有实时预览反馈,写了代码也看不见效果。完整阵容见 插件市场 与 第 10 章 · Agent 团队。Sub-agents (e.g. Iori gameplay, Suzu design, Kotone narrative, Iro art, Tsumugi build) only plan / design / make assets / write docs and never touch src/ — they have no live-preview feedback, so any code they wrote would have nothing to steer it. See the full cast in the marketplace and Chapter 10 · The agent team.

怎么派活:Forge 用一次工具调用派发子 agent(形如 subagent(type="iori", task="…")),经服务端的 /api/subagent 流式桥接,把子 agent 的产出实时回流进主对话 —— 你在消息流里看到的就是嵌入的子 agent 卡片。子 agent 产出的设计文档会自动归到工作台里它自己的栏目下(见 场景与编辑器)。How dispatch works: Forge dispatches a sub-agent with one tool call (shaped like subagent(type="iori", task="…")); the server's /api/subagent stream bridges its output back into the main conversation in real time — that's the embedded sub-agent card you see in the message stream. A sub-agent's design docs are filed under its own section in the workbench (see Scenes & editor).

一次对话(session)是怎么回事What a session is

一个 session 就是某个 agent 的对话记忆 —— 一条只追加的事件流(每条是一个事件:用户消息 / 助手消息 / 思考 / 工具调用 / 工具结果)。Forge(主)与每个子 agent 各有自己的 session。A session is an agent's memory — an append-only stream of events (each one is a user message / assistant message / thinking / tool call / tool result). Forge (main) and each sub-agent each keep their own.

前端按"是谁发的"把事件切成主对话与子 agent 两路,主对话里的子 agent 那段渲染成嵌入的卡片。所以同一屏里,你既看到 Forge 的主线,也看到它派出去的子 agent 干了什么。The UI splits events by who emitted them into the main thread vs sub-agents, rendering each sub-agent's slice as an embedded card. So on one screen you see both Forge's main thread and what the sub-agents it dispatched actually did.

在顶栏的会话切换器里可以回看、切换历史会话。切换会话不会重启任何服务 —— 只是前端换了读取的那个 agent 的事件流而已。Use the top-bar session switcher to review and switch past sessions. Switching a session restarts nothing — the UI just reads a different agent's event stream.

3用对话做游戏Build by chatting

怎么把想法描述清楚How to describe your idea clearly

描述越具体,Forge 越能一次到位、少返工。一个好需求通常覆盖这几点:The more specific you are, the better Forge nails it first try with fewer redos. A good prompt usually covers:

  • 类型与视角 —— 俯视 / 第一人称 / 2.5D 横版……Genre & view — top-down / first-person / 2.5D side-scroller…
  • 核心循环 —— 玩家从头到尾一直在做的那件事Core loop — the one thing the player keeps doing
  • 操作、胜负条件、敌人 / 障碍、手感与氛围Controls, win/lose, enemies / obstacles, and the feel

先从小处起步、跑起来,再逐步加机制。例如:Start small, get it running, then layer mechanics on. For example:

做一个俯视角小游戏:角色在场地里跑,
按空格发射子弹,四周不断刷新敌人,
打中消失并记分。A top-down game: a character runs around an arena,
space fires bullets, enemies keep spawning,
hits remove them and add score.

想要一步步带着做第一个游戏,见 快速开始;不确定能做出什么效果,先看 案例。设计较重时 Forge 会叫上设计类子 agent(见 核心概念)。For a step-by-step first game, see Quick start; for what's achievable, browse the showcase. For heavier design, Forge pulls in design sub-agents (see Core concepts).

看 Forge 规划、写代码、跑起来Watch Forge plan, code, and run it

你发出需求后,链路是这样的:Once you send a request, the chain is:

  • 理解 + 规划 —— Forge 先把需求理清,设计较重时派设计 / 玩法子 agent(见 核心概念)。Understand + plan — Forge clarifies the requirement, dispatching design / gameplay sub-agents for heavier work (see Core concepts).
  • 写代码 —— Forge 自己写到 games/<slug>/src/main.ts(及拆分出的模块)。Write code — Forge writes itself into games/<slug>/src/main.ts (and its split-out modules).
  • 热重载 —— 文件一改,引擎的 vite 侦测到改动,右侧预览就地热替换模块,不整页刷新,画面几乎即时变。Hot-reload — on save, the engine's vite detects the change and the preview hot-replaces the module in place — no full reload, the picture updates almost instantly.
  • 看结果 —— Forge 通过预览看到运行效果(预览还把游戏里的 console 转发回来),据此决定下一步。See the result — Forge sees the running result through the preview (which also forwards the game's console back), and decides the next step.

整个过程是透明的:消息流里能看到 Forge 的思考、每次工具调用,以及它派出去的子 agent 卡片。预览 / 工作台的切换与控制见 场景与编辑器;热重载机制见 运行与预览。The whole process is transparent: the message stream shows Forge's thinking, each tool call, and the cards of the sub-agents it dispatched. For switching/controlling preview vs workbench, see Scenes & editor; for how hot-reload works, see Run & preview.

一轮轮迭代:加机制、调手感Iterate: add mechanics, tune the feel

不满意就继续说,每一句反馈都会变成一次新的改动,热重载即时见效:Not happy? Keep talking — each bit of feedback becomes another change, visible instantly via hot-reload:

子弹再快一点,敌人血量加倍,背景换成夜晚。Faster bullets, double enemy health, night background.

预览自带 播放 / 暂停 / 重载 控制,方便你边调边试;想固定预览某一款游戏,可在项目切换器里切换(见 认识界面)。The preview has play / pause / reload controls for testing as you go; to pin the preview to a specific game, switch in the project switcher (see Open the studio, learn the interface).

基本循环就是:描述 → 生成 → 游玩 → 再描述。把它跑顺,就能从一句话迭代到一款能玩的游戏 —— 整套上手流程见 快速开始。The basic loop is describe → generate → play → describe again. Run it smoothly and you go from a sentence to a playable game — the full onboarding is in Quick start.

4场景与编辑器Scenes & editor

预览窗口与工作台Preview window & workbench

右侧主区在两种视图间切换:The right-hand main area toggles between two views:

  • 预览 —— 你的游戏在 iframe 里实时运行,带 FPS 显示与 播放 / 暂停 / 重载 控制。Forge 写完代码,这里热重载即时出结果(见 用对话做游戏)。Preview — your game runs live in an iframe, with an FPS readout and play / pause / reload controls. When Forge writes code, it hot-reloads here instantly (see Build by chatting).
  • 工作台 —— 一个文件浏览 + 编辑器:看 / 改 / 存文本与代码、渲染 markdown 设计文档,还能预览图片、音频、视频、3D 模型。它也显示文件活动与"谁在编辑"的锁,人和 AI 改同一份不打架。Workbench — a file browser + editor: view / edit / save text & code, render markdown design docs, and preview images, audio, video and 3D models. It also surfaces file activity and "who's editing" locks, so you and the AI edit the same files without clobbering.

没打开文件时,工作台会展示所有创作工作台(角色 / 动画 / 3D / 场景 / UI / 音乐……)的入口 —— 详见 创作工具 与 插件市场。资产怎么做见 资产。With no file open, the workbench shows entries for every creation workbench (character / animation / 3D / scene / UI / music…) — see Creation tools and the marketplace. For making assets, see Assets.

编辑场景,改动实时回到游戏Edit the scene, changes flow back live

场景编辑器把一关的内容存成游戏目录里的场景数据文件(scene.pack.json)—— 它是这关的单一可信源:磁盘上是什么,游戏里跑的就是什么。The scene editor saves a level's contents to a scene data file in the game folder (scene.pack.json) — the single source of truth for that level: what's on disk is what runs in the game.

你在编辑器里摆好对象、离开编辑态时,改动会落盘并让运行中的游戏重新读取,于是预览即时反映你的编辑 —— 这就是 edit→play 实时回流。反过来,Forge 用对话改代码也走同一条热重载链路(见 用对话做游戏 与 运行与预览)。When you place objects and leave edit mode, the changes are flushed to disk and the running game re-reads them, so the preview reflects your edits immediately — the edit→play round-trip. Conversely, when Forge changes code by chat it rides the same hot-reload path (see Build by chatting and Run & preview).

组织你的关卡与对象Organize your levels and objects

一款游戏可以有多个场景 / 关卡,各自一份场景数据,按需切换与复用 —— 案例里的「Cow Survivor」就在白天牧场与暗夜墓园两关之间切换(见 案例)。A game can have multiple scenes / levels, each its own scene data, switched and reused as needed — the "Cow Survivor" demo switches between a day pasture and a night graveyard (see the showcase).

组织方式上:对象住在场景数据里,美术 / 音频资产放在游戏目录中(项目结构见 核心概念,资产怎么生成见 资产)。按场景拆分,游戏做大时更好维护。How to organize: objects live in the scene data, while art / audio assets live in the game folder (project layout in Core concepts, asset generation in Assets). Splitting by scene keeps a growing game maintainable.

5资产:美术 / 动画 / 音乐Assets: art / animation / audio

角色立绘与三视图Character portraits & turnarounds

用角色编辑器(wb-character)做角色概念设计:写一句人设,生成正面立绘 + 转身三视图。不会画画也能拿到能进游戏的角色形象。Use the character editor (wb-character) for character concept design: write a one-line brief, get a portrait + turnaround. No drawing skills needed to get a game-ready character.

它的产出(角色清单 + 立绘 / 三视图)按角色存进你的游戏里,并作为下游输入直接接进动画工作台 —— 也就是说"画好的人 → 让它动起来"是一条顺下来的管线(见下一条)。Its outputs (a character manifest + portrait / turnaround) are stored per character inside your game and feed straight into the animation workbench as downstream input — so "design the character → make it move" is one continuous pipeline (see the next item).

每个工作台都是一个面板 + 一组工具,人手点和 AI 派活改的是同一份产物。完整清单见 插件市场 与 工作台教程。Each workbench is a panel plus a set of tools; you-by-hand and AI-by-dispatch edit the same artifact. Full list in the marketplace and the workbenches tutorial.

让角色动起来(2D / 3D 动画)Make characters move (2D / 3D)

2D: 动画工作台(wb-anim)拿角色立绘当模板,把它变成会走、会打、四方向乃至短视频的动作 —— 而且不串脸,动起来还是同一个角色。2D: the animation workbench (wb-anim) uses the character portrait as a template and turns it into walking, attacking, four-direction motion, even short clips — without face drift, so it stays the same character once it moves.

3D: 引擎原生支持骨骼动画 —— 从 FBX 导入带骨架与蒙皮的模型及动画 clip,在 idle / walk / run / cast / death 之间平滑过渡(crossfade)。这条链路是真实跑通的,案例里的暗黑风女巫就是这么动起来的:见 骨骼动画里程碑 与 案例(Hellforge)。3D: the engine natively supports skeletal animation — import a rigged, skinned model plus animation clips from FBX, with smooth crossfades between idle / walk / run / cast / death. This pipeline is real and shipped — it's how the dark-fantasy witch in the showcase moves: see the skeletal-animation milestone and the showcase (Hellforge).

3D 模型、特效、UI、音乐3D models, VFX, UI, music

9创作工具(工作台)Creation tools (workbenches)

角色 / 动画 / 特效Character / animation / VFX
wb-character · 角色编辑器character editor

角色概念设计:写一句人设 → 正面立绘 + 转身三视图。内部有多条管线 —— 三视图(turnaround)、视频角色(三视图 → AI 视频动作 → 序列帧 → spritesheet 导出)、怪物生成(8 方向 × 5 动画的怪物精灵)。不会画画也能拿到能进游戏的角色形象,产出再喂给动画工作台(见 资产)。Character concept design: a one-line brief → portrait + turnaround. It has several pipelines — turnaround (three views), video character (turnaround → AI video motion → frame extraction → spritesheet export), and monster generation (8-direction × 5-animation monster sprites). No drawing skills needed; the output then feeds the animation workbench (see Assets).

wb-anim · 动画animation

把角色立绘当模板,变成会动的:像素四方向、载具动画、怪物 sprite、Spine 绑定、短视频生成 —— 而且不串脸,动起来还是同一个角色。面板内嵌、带中央预览视口。3D 角色的骨骼动画走引擎原生链路,见 骨骼动画里程碑 与 资产。Uses a character portrait as a template and makes it move: four-direction pixel, vehicle animation, monster sprites, Spine binding, short-video generation — without face drift, so it stays the same character. Embedded panel with a center viewport. 3D characters use the engine's native skeletal pipeline — see the skeletal-animation milestone and Assets.

wb-skill · 技能 / 特效skill / VFX

技能树编辑 + VFX 预览,集中列出技能与特效产出。关键是玩家手点与 AI 派活共用同一份技能规格 —— 特效会自动挂到"出手那一刻",不用手动对齐。Skill-tree editing + VFX preview, listing your skill and effect outputs in one place. The key idea: the player's clicks and AI dispatch share one skill spec — effects auto-attach to "the moment of cast", no manual alignment.

3D 建模与生成3D modeling & generation
wb-lowpoly-obj · 方块人编辑器blocky-character editor

做可动的方块 3D 角色:既能"vibe"——说一句让 AI 生成,也能手动编辑(Blender 风的 gizmo 拖拽),还自带游乐场实时预览。导出引擎中立的 .glb,任何引擎都能用。Build rigged blocky 3D characters: either "vibe" it (say a line, AI generates) or edit by hand (Blender-style gizmo), with a built-in playground for live preview. wb-3d-lowpoly · 3D 低多边形生成器low-poly generator

用"连线搭积木"的节点式方式做 3D 道具 / 机械:把建模流程画成一张节点图,改一个参数,整套重新生成。适合需要批量、可复用、参数化的硬表面资产。Build 3D props / mechanical assets with node-programming ("wire up blocks"): model the process as a node graph, change one parameter, regenerate the whole set. Great for batch, reusable, parametric hard-surface assets.

wb-gen3d · 3D 生成3D generation

3D 资产生成入口:选一个生成服务 + 给输入(文字 / 图片 / 多视角图),产出持久化、可直接进游戏的 3D 资产清单。接入多家最强生成服务,择优而用、不被单家绑死。A 3D asset generation entrypoint: pick a generation service and give an input (text / image / multi-view), and get a durable, game-ready 3D asset manifest. Plugged into several top generators so you pick whichever's best — no single-vendor lock-in.

wb-scene-generator · 场景生成器scene generator

用节点式自动"搭"出一整张游戏场景:把组合、布局、贴图处理画成一张流程图;想改随时重跑,产出整套场景。场景与关卡如何组织见 场景与编辑器。Assemble a whole game scene with node-programming: lay out composition, placement and texturing as a graph; re-run anytime to regenerate the full scene. For how scenes / levels are organized, see Scenes & editor.

wb-2d-scene-asset-generator · 2D 场景资产生成器2D scene assets

wb-ui · UI 工坊UI workshop

按游戏类型、界面流程、视觉风格生成一整套界面 —— UI 蓝图、组件素材,以及能点的交互原型(不只是图)。菜单、按钮、血条都能一键出。Generate a full interface set by genre, screen flow and visual style — UI blueprints, component assets, and clickable interactive prototypes (not just images). Menus, buttons and health bars in one go.

wb-items · 道具 / 图标items / icons

做游戏里的道具与图标 —— 武器、药水、金币的像素小图,并配上数据。图与数据一张表(items.json),人和 AI 改同一份,不会对不上。Make the game's items and icons — pixel art for weapons, potions, coins — with their data attached. Art and data in one table (items.json) that you and the AI edit together, so they never drift apart.

He doesn't write architecture, tune parameters, or ask questions back (Forge handled those up front). Once pillared, Suzu takes over.

Suzu · 体验设计师 —— 节奏与体验 — pacing & experience

名字取自"鈴"(风一吹就响、是节奏)。Iori 把柱子立好后,Suzu 把每根柱子下面的模块展开成具体体验 —— 玩家节拍、HUD、onboarding。她定义"玩起来什么感觉",再把需要资产 / 剧情的部分交给 Iro / Kotone。Named after "鈴" (a wind-chime — rhythm). After Iori sets the pillars, Suzu expands each pillar's modules into concrete experience — player pacing, HUD, onboarding. She defines how it feels to play, then hands the parts needing assets / story to Iro / Kotone.

Kotone · 剧情师 —— 叙事(按需) — narrative (on demand)

名字取自"琴音"(弦上传来的故事)。不是每个游戏都需要剧情师 —— 一个塔防可能根本不派她;只有当游戏需要角色 / 对白 / 分支 / 旁白时,Forge 才叫她来,产出世界观、角色 bio 与对白。Named after "琴音" (a story carried on strings). Not every game needs a narrative designer — a tower-defense might never call her; only when the game needs characters / dialogue / branches / narration does Forge bring her in to produce world, character bios and lines.

Iro · 美术师 —— 视觉资产(按需) — visual assets (on demand)

名字取自"色"(一切被眼睛感受到的东西)。Suzu 讲清模块体验后,如果该模块需要视觉资产(角色 / 场景 / UI / 特效),Forge 才派 Iro。具体资产怎么生成,见 资产 与 创作工具。Named after "色" (everything the eye perceives). Once Suzu has framed a module's experience, Forge dispatches Iro only if it needs visual assets (characters / scenes / UI / VFX). How those assets are actually made: see Assets and Creation tools.

这几位只做规划与设计、不碰游戏代码(代码由 Forge 写,见 核心概念);他们的产出会进工作台(见 场景与编辑器),美术资产落地见 资产。These specialists only plan and design — they never touch game code (Forge writes code, see Core concepts); their output lands in the workbench (see Scenes & editor), and art assets are produced as in Assets.

编码与审查小队Coding & review crew
cc-coder · 通用编码 —— spec → 代码 — spec → code

接 Iori 的玩法骨架、Suzu 的体验流程、Kotone 的剧情大纲,产出可运行的 TS / React 等代码;可多实例并行写不同子包。注意:游戏主线代码仍由主创 Forge 亲自写并跟预览闭环(见 核心概念),cc-coder 更多用于通用 / 周边编码。Takes Iori's gameplay pillars, Suzu's UX flows and Kotone's narrative outlines and turns them into runnable TS / React etc.; can run multiple instances on different packages in parallel. Note: the game's main code is still written by Forge itself, closed-loop with the preview (see Core concepts); cc-coder is more for general / surrounding code.

Tsumugi · 工程师 —— 构建 / 工具链 — build / toolchain

名字取自"紡"(把丝线缠成系统)。当 Iori / Suzu / Iro 把设计与资产准备好,Tsumugi 把它们编织成可运行的工程 —— 构建、工具链、部署。Named after "紡" (weaving threads into a system). Once Iori / Suzu / Iro have the design and assets ready, Tsumugi weaves them into a working build — build, toolchain, deployment.

Yevi · 审查 —— 技术债猎手 — tech-debt hunter

表面优雅得体、内心冷静如深水的观察者,永远比你多想一步 —— 清楚代码哪里最脆弱、哪一处三周前埋下的隐患即将显现。语气温和从容,措辞却精准而克制。A gracefully composed observer, calm as deep water, always one step ahead — she knows where the code is weakest and which three-week-old issue is about to surface. A measured, gentle tone, with precise and incisive wording.

陪伴人格 —— 同等编码力、不同性格 — same skill, different character

一组编码力相当、性格各异的可选角色 —— 有的沉稳内敛,有的机敏俏皮,有的细致缜密。它们能力相同,区别只在与你协作时的相处风格。性格可在人格编辑器里随时调整(见 进阶);完整阵容见 插件市场。A set of optional characters with comparable coding skill but distinct personalities — some measured, some playful, some meticulous. They have the same ability; the only difference is how it feels to work alongside them. Personalities are editable any time in the persona editor (see Advanced); the full cast is in the marketplace.

此外还有一批美术 / 资产专精 agent(2D 角色 / 动画、3D 低多边形 / 特效、影游导演等),各自对接相应的创作工作台(见 创作工具)。There's also a set of art / asset specialist agents (2D character / animation, 3D low-poly / VFX, interactive-film director, and more), each wired to its matching creation workbench (see Creation tools).

可换的默认人格Swappable default personas

每个 CLI 后端自带一个开箱人格:Claude(Claude Code)、Codex、Cursor、ForgeaX(自研 forgeax-native)。切换后端就换默认人格,无需先写人设 —— 想用哪家的智能内核,就有哪家的默认 persona。Each CLI backend ships with an out-of-the-box persona: Claude (Claude Code), Codex, Cursor, and ForgeaX (the self-built forgeax-native). Switching the backend swaps the default persona — no setup needed; whichever kernel you pick comes with its default persona.

怎么切后端、怎么改人格见 进阶;完整 agent 阵容与可装载人格见 插件市场。How to switch backends and edit personas is in Advanced; the full agent cast and loadable personas are in the marketplace.
