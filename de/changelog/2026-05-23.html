Bestätigen Sie vor riskanten Aktionen + Motorumgebungslicht und -schatten

An diesem Tag wurden echte Sicherheitsmaßnahmen eingeführt, um „die KI agieren zu lassen“: Riskante Aktionen erfordern jetzt eine Bestätigung, und Plugins können signiert, verifiziert und vertrauenswürdig sein. Plugins können auch in der App bearbeitet werden und die Workbench wurde vollständig mit Plugins ausgestattet; Die Engine fügte bildbasiertes Umgebungslicht, Schatten und die Möglichkeit hinzu, eine komplexe Szene im Spielmaßstab zu laden.

Installieren Sie die Sicherheitsvorrichtungen, bevor Sie loslassen

Je mehr Sie „die KI für sich arbeiten lassen“ möchten, desto mehr müssen Sie zunächst eine Frage beantworten: Wird sie etwas tun, was sie nicht tun sollte, während Sie nicht zuschauen? Die Hauptaufgabe dieses Tages bestand darin, das „Loslassen“ mit Schutzmaßnahmen auszustatten – riskante Handlungen von Ihrer Zustimmung abhängig zu machen und die Quellen von Drittanbieter-Plugins überprüfbar zu machen. Gleichzeitig wurde die Workbench vollständig mit Plugins ausgestattet, Plugins konnten innerhalb des Produkts bearbeitet werden und die Bildqualität der Engine wurde immer realistischer. Sicherheit, Erweiterbarkeit, gutes Aussehen – Teile gleichzeitig in drei Richtungen platziert; Aber durch sie zieht sich ein Wort: Vertrauen. Erst wenn Sie sicher sind, dass kein Amok läuft und dass das, was Sie installieren, vertrauenswürdig ist, trauen Sie sich wirklich, die Arbeit abzugeben.

Eine Sicherheitsabfrage vor riskanten Aktionen

Beim Aufrufen von Werkzeugen erhielten die Agenten eine Sicherheitstür. Jedes Tool kann seine Bestätigungsrichtlinie festlegen: immer bestätigen, niemals bestätigen oder nur bestätigen, wenn es als gefährlich eingestuft wird. Wenn ein Agent im Begriff ist, eine gefährliche Aktion auszuführen (z. B. das Löschen oder Überschreiben einer wichtigen Datei), sendet das Backend in Echtzeit eine „Bestätigung erforderlich“-Anfrage an die Schnittstelle. Oben wird eine Bestätigungsleiste angezeigt. Die Aktion wird nur ausgeführt, wenn Sie dies zulassen, und wird sofort blockiert, wenn Sie dies ablehnen. Jede Entscheidung wird protokolliert. Dieses Tor befasst sich mit dem beunruhigendsten Risiko: „Der Agent hat im Hintergrund stillschweigend etwas Schlimmes getan, und Sie hatten keine Ahnung.“ Damit haben Sie die Möglichkeit, loszulassen, während Sie bei kritischen Aktionen immer das letzte Vetorecht haben. Dies ist die konkrete Umsetzung des Prinzips „Der Mensch ist die letzte Autorität“ im Produkt.

Bearbeiten Sie Plugins direkt in der App

Eine neue „Plugin-Autor“-Workbench ist da: links ein Dateibaum, rechts ein Editor, Änderungen werden sofort wirksam. Seine Bedeutung besteht darin, dass die Messlatte für die „selbst erweiterte Erweiterung“ nahezu auf Null sinkt – um die Eingabeaufforderung eines Tools zu optimieren, einen Parameter zu ändern oder eine Idee auszuprobieren, verlassen Sie nicht das Produkt, wechseln zu einem Code-Editor und blättern hin und her, sondern bearbeiten direkt in der Benutzeroberfläche und sehen die Wirkung sofort. Dies spiegelt eine langfristige Ausrichtung der Plattform wider: Nicht-professionelle Entwickler, sogar Benutzer selbst, können die Plattform praktisch erweitern und anpassen, anstatt nur die Voreinstellungen der Entwickler zu verwenden. Im Moment handelt es sich zwar um einen einfachen Dateibaum und ein Bearbeitungsfeld, aber sobald „Sie können das Produkt innerhalb des Produkts ändern“ gilt, öffnet sich der Raum dessen, was vorstellbar ist.

Plugins können signiert, verifiziert und vertrauenswürdig sein

Da sich die Plattform auf ein Ökosystem zubewegt, in dem „jeder Plugins erstellen und teilen kann“, muss die Sicherheit an erster Stelle stehen. Dieser Tag gab Plugin-Paketen einen vollständigen Vertrauensmechanismus: eine digitale Signatur beim Export, automatische Überprüfung beim Import, um zu bestätigen, dass ein Paket tatsächlich vom Autor stammt, den es vorgibt, und nicht während der Übertragung manipuliert wurde; Das System führt eine Vertrauensliste, in der aufgezeichnet wird, welche Quellen vertrauenswürdig sind. und sobald die Signatur einer Quelle widerrufen wird, wird die Neuinstallation ihrer Plugins komplett blockiert. Dies basiert auf dem ausgereiften Ansatz „Signierung + Vertrauenskette“ in der Softwareverteilung mit einem klaren Ziel: Wenn Sie das Plugin einer anderen Person installieren, müssen Sie nicht blind vertrauen. Ein offenes Plugin-Ökosystem ohne diese Vertrauensbasis wird früher oder später von böswilligen oder manipulierten Plugins heimgesucht; Es zu etablieren, während das Ökosystem noch klein ist, ist der verantwortungsvolle Schritt.

Engine: Umgebungshimmellicht + Schatten + Szenen im Spielmaßstab

Die Bildqualität der Engine hat sich an diesem Tag noch einmal verbessert. Durch die Hinzufügung von bildbasiertem Umgebungslicht werden Objekte durch ihre Umgebung sanft beleuchtet – schattige Bereiche sind nicht mehr völlig schwarz, glatte Oberflächen reflektieren die Farbe der Umgebung und das Licht der gesamten Szene wird natürlich und verfeinert; Zusammen mit den vorhandenen Richtungsschatten ist die Hell-Dunkel-Beziehung vollständiger und glaubwürdiger. Noch aussagekräftiger: Heutzutage konnte die Engine eine komplexe, große Indoor-Szene im Spielmaßstab laden und vollständig rendern, wobei mehrere Lichter gleichzeitig leuchten. Das Ausführen einer Szene in solch einem realen Maßstab ist ein harter Test für die „Bereitschaft für die reale Welt“ eines Renderers. Dies bedeutet, dass die Engine von der Demophase „Kann einen Würfel drehen“ in die Phase „Kann echten Spielinhalten standhalten“ übergegangen ist.

Eine vollständig mit Plugins ausgestattete Workbench: viele Tools auf einer Architektur

An diesem Tag wurde die Workbench vollständig mit Plugins ausgestattet: Tools wie Charakter, Erzählung und Plugin-Autor laufen nun alle als eigene eingebettete Seiten auf derselben Split-Surface-Plugin-Architektur, nicht mehr als Sonderfälle fest in die Hauptschnittstelle einprogrammiert. Auf der Schnittstellenseite wurde auch geändert, „welche Plugins geladen werden sollen“ von einer hartcodierten Tabelle auf das Abonnieren einer dynamischen Plugin-Registrierung – was installiert ist, ist das, was angezeigt wird, ohne Änderungen am Hauptprogrammcode. Chat kann die Funktion eines Plugins auch direkt mit einem /tool-Befehl aufrufen. Die weitreichende Bedeutung: Es bringt „integrierte Funktionen“ und „Drittanbieter-Plugins“ auf die gleiche Ausgangslinie – die eigenen Tools der Plattform und die Tools anderer folgen den gleichen Integrationsregeln. Nur wenn die Kernfunktionen eines Systems selbst als Plugins vorhanden sind, besteht tatsächlich das Potenzial für unbegrenzte Erweiterungen.

Was dieser Tag bedeutet

Das Schlüsselwort dieses Tages ist „Vertrauen“. Riskante Aktionen, bei denen Ihr Nicken erforderlich ist und Plugin-Quellen überprüfbar sind: „Wage ich es, es wirken zu lassen, wage ich es, die Dinge anderer zu installieren“; die vollständig mit Plugins ausgestattete Workbench und Bearbeitungs-Plugins innerhalb der Produktadresse „Kann diese Plattform unbegrenzt erweitert werden, können Benutzer dies selbst tun“; Die Engine, die Umgebungslicht und Schatten hinzufügt und realistische Szenen abspielt, ist „das, was sie wirklich gut aussehend und realistisch genug macht“. Sicherheit, Offenheit und Bildqualität scheinen drei Dinge zu sein, aber alle ebnen den Weg für eine Zukunft: eine Plattform, auf der man sich wirklich traut, eigene Ideen zu verwirklichen, und die vorzeigbare Arbeiten hervorbringt. Nur wenn Sie eine solide Vertrauensbasis schaffen, können Sie davon sprechen, den Benutzern mehr Freiheit zu geben.
