Update2026-06-28

Ein Befehl – ​​jetzt auch unter Windows

An diesem Tag wurden die Installations- und Startskripte vollständig von Bash auf plattformübergreifendes Bun TypeScript verschoben: Dieselben Befehle werden auf macOS, Linux und Windows identisch ausgeführt, und Windows benötigt Git-Bash nicht mehr. Daneben wurde eine Reihe von Windows-spezifischen Blockern behoben, „Sitzungen“ von „global gebunden“ auf „pro Spiel begrenzt“ geändert, der Asset-Import stabiler gestaltet und die zugrunde liegende CLI schneller, kontrollierbarer und überprüfbarer gemacht.

Das größte Hindernis: Es ließe sich nicht installieren, wenn Sie die Plattform wechseln würden

Lange Zeit war für die Installation und Ausführung ein Haufen Bash-Skripte erforderlich. Gut für macOS und Linux, aber eine harte Hürde für Windows-Benutzer – Bash ist nicht nativ in Windows enthalten, sodass Sie entweder eine Kompatibilitätsebene wie Git-Bash installieren mussten oder auf verschiedene kryptische Fehler stoßen. Für ein Tool, das möchte, dass „jeder Ideen in Spiele umwandelt“, ist „es lässt sich nicht installieren“ die fatalste erste Abschreckung. An diesem Tag wurde genau das behoben: Alle Installations- und Startskripte wurden komplett neu geschrieben, von Bash in plattformübergreifendes TypeScript, das von Bun ausgeführt wird. Bun verhält sich auf allen drei Hauptsystemen identisch, sodass unter Windows dieselben Befehle und dieselbe Logik genauso ausgeführt werden wie auf dem Mac, ohne dass eine Kompatibilitätsschicht erforderlich ist.

Die Befehle werden zu einem einprägsamen Satz zusammengefasst

Mit dem Umzug wurden auch die Einstiegspunkte bereinigt. Die verstreuten, plattformspezifischen Skripte der Vergangenheit („.sh“, „.bat“, „.ps1“ usw.) wurden zusammen gelöscht und in einem einfachen, einprägsamen Satz vereint: „bun run setup“ zum einmaligen Installieren der Umgebung, „bun run start“ zum Starten des gesamten Stapels, „bun run stop“ zum Stoppen, „bun run app“ für die Desktop-App. Welches System Sie auch verwenden, diese wenigen sind alles, was Sie sich merken müssen. Für neue Benutzer bedeutet es: „Kopieren Sie vier Zeilen aus der README-Datei und es wird ausgeführt“, ohne mehr: „Ich verwende Windows, gegen welches tausche ich das aus“; Für bestehende Benutzer bedeutet es keinen Wartungsaufwand mehr, da „zwei Kopien jedes Skripts (eine SH, eine PS1) im Gleichschritt bearbeitet werden müssen und leicht zu übersehen sind.“ Das Zusammenfassen mehrerer gleichwertiger Skripte in einer plattformübergreifenden Quelle der Wahrheit ist das Herzstück der täglichen Arbeit – eine Sache weniger, die synchron gehalten werden muss, bedeutet eine Stelle weniger, an der Fehler passieren können.

Eine Reihe von Windows-spezifischen Blockern wird gelöscht

Um Windows wirklich reibungslos zu machen, reichen plattformübergreifende Skripte allein nicht aus – Sie müssen auch die Kuriositäten, die nur unter Windows auftauchen, nach und nach beheben. Ein typischer Fall, der heute behandelt wird: Das „falsche“ Python des Systems – Windows liefert einen Python3-Platzhalter aus, der nicht wirklich installiert ist und nur beim Aufruf den App Store öffnet, und ein Skript, das naiv annimmt, dass es funktioniert, bleibt während der Installation auf mysteriöse Weise stehen. An diesem Tag lernte der Installationsablauf, diesen Platzhalter zu erkennen und zu überspringen und ein Python zu finden, das tatsächlich funktioniert. Details wie diese – die auf anderen Systemen nicht vorhanden sind und Sie nur unter Windows stolpern lassen – sind der mühsamste und zugleich notwendigste Teil der plattformübergreifenden Unterstützung: Sie fügen keine Funktionen hinzu, aber jedes einzelne Problem bedeutet, dass eine Gruppe von Windows-Benutzern einmal weniger ins Stocken geraten und weitermachen können.

Die Sitzungen ändern sich von „global gebunden“ zu „pro Spiel begrenzt“.

Dieser Tag berührte auch eine eher interne Struktur: wem eine Sitzung gehört (eine Sitzung ist ein Teil Ihres Gesprächs mit Forge). Früher waren Sitzungen global und von einem bestimmten Spiel getrennt; An diesem Tag wurden sie unter jedem Spiel verschachtelt, je nach Spiel. Das heißt: Ihr Gespräch mit Forge für das „Weltraum-Shooter“-Projekt und das für das „Farm-Sim“-Projekt sind jetzt jeweils für sich und gehen nie ineinander über. Es ist intuitiver – ein Gespräch gehört in erster Linie zu einem bestimmten Spiel – und legt den Grundstein für ein späteres, saubereres Projektmanagement: Wechselspiele und der dazugehörige Chat-Verlauf und -Kontext kommen mit, anstatt sich mit einem globalen Topf gemischter Sitzungen auseinandersetzen zu müssen. Diese Art des Aufräumens „Daten dort ablegen, wo sie wirklich hingehören“ ist im Alltag unscheinbar, hält aber das mentale Modell des gesamten Systems sauber.

Stabilerer Asset-Import + eine schnellere, besser kontrollierbare CLI

An diesem Tag wurden auch mehrere Fehlerbehebungen vorgenommen, die die tägliche Nutzung stabiler machen. Bei Assets wurde ein Indizierungsproblem beim Importieren größerer Modelle behoben (große Netze benötigen breitere Ganzzahlen, um ihre Scheitelpunkte zu indizieren, was hier früher fehlschlug) und dafür gesorgt, dass die beim Modellimport geschriebenen Metadaten einem kanonischen Format folgen – so fällt der Import eines größeren, komplexeren Modells nicht mehr so ​​leicht ins Stocken. Auch der CLI-Kern, der die KI antreibt, wurde mehrfach verfeinert: Reduzierung der Redundanz, damit die erste Runde in manchen Fällen schneller funktioniert; Behebung eines Problems bei der Einführung des „Verhaltenskodex“ eines Agenten; und das Hinzufügen einer optionalen Maskierung der eigenen externen Tools eines Benutzers sowie eines Audit-Trails der Anrufe eines Agenten an Host-Tools – letzteres bedeutet „Welche Tools hat die KI dieses Mal tatsächlich verwendet?“ wird aktenkundig nachvollziehbar. Zusammengenommen legt dies den Grundstein für eine weitere Ebene in Richtung „schneller, kontrollierbarer, vertrauenswürdiger“.

Was dieser Tag bedeutet

Der Protagonist dieses Tages ist „die Barriere“. So leistungsfähig ein Tool auch ist, wenn eine große Gruppe ausgeschlossen wird, weil ihr System fehlerhaft ist und es sich nicht installieren lässt, ist die Hälfte seines Werts verloren, bevor jemand es verwendet. Durch die vollständige plattformübergreifende Installation und den Start, sodass auch Windows-Benutzer es mit einem Befehl ausführen können, wird diese Tür für alle geöffnet – eine der Voraussetzungen dafür, dass „Jeder kann Spiele erstellen“ gilt. Und am selben Tag wurde der Raum aufgeräumt, während die Tür geöffnet wurde, indem Sitzungen unter ihrem Spiel abgelegt, der Asset-Import stabilisiert und der CLI-Kern schneller und überprüfbarer gemacht wurde. Senken Sie die Eintrittsbarriere und erhöhen Sie dann die Qualität im Inneren – an diesem Tag gelang beides.
