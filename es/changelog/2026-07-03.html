Modo Play de Windows estabilizado + proxy de depuración LLM para desarrolladores

El modo Play en Windows ahora es estable gracias a una corrección del stack de Socket del editor; una nueva variable de entorno FORGEAX_DEBUG_PROXY permite a los desarrolladores capturar e inspeccionar todo el tráfico de la API LLM en tiempo real; se ha corregido el empaquetado de la aplicación de escritorio en Windows; y la arquitectura del runtime reel-game se ha diseñado como una subclase de runtime de juego a nivel de motor.

Modo Play de Windows: finalmente estable

El modo Play en Windows fallaba intermitentemente debido a un problema en el stack de Socket del editor. La exportación WebSocket subyacente faltaba en la ruta de compilación de escritorio, causando que el iframe de vista previa del motor perdiera la conexión con el host del editor. Esto se ha corregido — el modo Play en Windows ahora funciona tan fiablemente como en macOS.

Proxy de depuración LLM para desarrolladores

Se ha añadido una nueva variable de entorno opcional FORGEAX_DEBUG_PROXY. Cuando se establece, inicia un proxy HTTP local que captura todas las llamadas salientes a la API LLM (Anthropic, OpenAI, Gemini, etc.) y registra los pares solicitud/respuesta. Configúralo en tu .env y el proxy se inicia automáticamente con bun fx start.

Empaquetado de la aplicación de escritorio de Windows corregido

La compilación de escritorio Tauri 2 para Windows fallaba debido a una exportación de dependencia faltante en el paquete de interfaz. Esto se ha resuelto — bun fx build app ahora produce un instalador .exe funcional en Windows.

Arquitectura del runtime reel-game

Se ha establecido una especificación de diseño para el runtime reel-game (película interactiva), posicionándolo como una subclase de runtime de juego de primera clase dentro del motor. La implementación seguirá en próximas versiones.
