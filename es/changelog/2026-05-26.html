Compactación de contexto con un solo toque + respaldo del software WebGPU

Este día se trabajó para "evitar que las conversaciones largas y todo tipo de máquinas se estropeen": compactación de conversaciones con un solo toque, un indicador de contexto visible, comandos de barra diagonal que se completan automáticamente; y un software alternativo para 3D cuando falta la aceleración de hardware. Los juegos nuevos comienzan a partir de una plantilla ECS limpia y el motor agregó animación de hoja de sprites 2D y una serie de correcciones de solidez.

Hacer sólido el "uso amplio y a largo plazo"

Una vez que se cuenta con la capacidad, la siguiente pregunta es: ¿se puede utilizar a largo plazo y de manera amplia? Largo plazo significa si una sola conversación puede durar sin que el contexto se desborde; amplio significa si se ejecuta en todo tipo de máquinas, no sólo en la de gama alta del desarrollador. Los elementos del día responden a estos dos respectivamente: direcciones de compactación de conversaciones con un solo toque "charlar lo suficiente llega al techo" y direcciones de respaldo del software WebGPU "no una buena GPU significa una pantalla negra". Agregue el punto de partida limpio del nuevo juego, la animación 2D y un lote de correcciones de robustez, y la línea es clara: no nuevos trucos, sino hacer que el "uso diario de larga duración en más máquinas" sea sólido.

Compactación con un toque: /compact + un anillo de uso de contexto

Tras largos intercambios con un modelo grande, el "contexto" que puede contener se acumula; cerca del límite, las respuestas son lentas, la calidad disminuye e incluso comienza a olvidar. Este día se agregó un comando /compact: un toque comprime los intercambios anteriores en un resumen conciso, liberando espacio para continuar, y la compactación en sí no consume un turno completo de conversación: se realiza directamente en el backend. El compositor también obtuvo un "anillo de uso de contexto" que, como un indicador de combustible, muestra de un vistazo cuánto presupuesto queda, de modo que cuando se esté llenando puedas verlo y decidir proactivamente si ordenar o no. Con el autocomando de barra diagonal, escribir / mostrar todos los comandos disponibles para una selección rápida. Este conjunto de cambios enfrenta de frente la limitación central de la "colaboración a largo plazo con la IA": el contexto es finito; poner su gestión en manos del usuario, hecho a la ligera, es lo que hace que las sesiones largas sean realmente sostenibles.

Una alternativa al software WebGPU: el 3D se ejecuta en más máquinas

La renderización 3D depende de las capacidades de una GPU moderna, pero en realidad algunas máquinas o entornos no pueden obtener aceleración de hardware; tal vez la GPU sea demasiado antigua, tal vez el tiempo de ejecución esté limitado. Anteriormente, esto significaba una pantalla negra, que excluía por completo a esos usuarios. Este día se agregó una alternativa de software: cuando no se puede obtener un dispositivo de renderizado acelerado por hardware, el sistema da un paso atrás y utiliza una implementación de software para renderizar la imagen, más lento, pero al menos se ejecuta, muestra y le permite seguir trabajando. Debajo, se agregó un respaldo de varios niveles (pruebe la siguiente ruta cuando una falla, error solo como último recurso), con diagnósticos más claros que explican por qué no se tomó la aceleración de hardware (por ejemplo, ejecutar bajo un origen no seguro). La importancia es la cobertura: una plataforma para el mercado masivo, que quiere que cualquiera pueda comenzar, no puede dar por sentado que todos tengan una máquina de alta gama; correr en máquinas más débiles también es lo que realmente baja el listón.

Los nuevos juegos comienzan desde una plantilla ECS limpia

La creación de un nuevo juego ahora se genera a partir de una plantilla limpia y bien estructurada organizada según una arquitectura adecuada. Este día reescribió esa plantilla predeterminada en un estilo de "arquitectura ECS adecuada", la extrajo de una cadena en línea a un archivo independiente con control de versión y redujo a la mitad su número de líneas, lo que significa que en el momento en que creas un juego, obtienes una base limpia y compacta lista para construir, no un montón de texto estándar que debes comprender primero antes de editarlo. La plantilla y las instrucciones del sistema enviadas a la IA se actualizaron a las últimas interfaces del motor. Esto es importante especialmente para los "juegos de escritura de IA": la IA continúa a partir de la forma de la plantilla, por lo que cuanto más limpia y estándar sea la plantilla, más probable es que el código de la IA sea correcto y más fácil le resultará leerlo y reutilizarlo. Un buen punto de partida ahorra innumerables correcciones posteriores.

Animación de hoja de sprites 2D

El motor agregó animación de hoja de sprites 2D este día: reproduce múltiples fotogramas de una "hoja de sprites" (una serie de fotogramas de acción dispuestos en una imagen) en secuencia, dando a la animación de efectos y personajes 2D un enfoque estándar ya hecho. Este es el método de animación más común en juegos 2D: una pequeña figura caminando, una llama parpadeando, son esencialmente unos pocos cuadros que se mueven rápidamente. Antes de esto, el contenido 2D sólo podía ser sprites estáticos; Con la animación en hoja, la línea 2D realmente puede moverse. Junto con las capas de sprites anteriores, completa los fundamentos 2D del motor: capas y apilamiento correctos, además de hacer que cada sprite se mueva. Para cualquiera que quiera crear un juego en 2D, este es el paso clave desde "poder colocar imágenes" hasta "poder hacer animaciones".

Robustez del motor: pruebas de regresión + un lote de correcciones de renderizado

El motor también realizó un trabajo de robustez poco glamoroso pero importante este día. Se agregaron pruebas de regresión para varias situaciones propensas a fallas (consultas de renderizado, jerarquía padre-hijo y el caso límite de "ni una sola luz en la escena"), fijándolas con pruebas para que cambios futuros en otros lugares no puedan romperlas silenciosamente. A algunos campos con nombres vagos se les cambió el nombre con mayor precisión para que sea más difícil leer mal el código; y se solucionaron algunos problemas de compatibilidad que surgieron solo después de la fusión. Este es el trabajo de "soldar capacidades recién agregadas": después de agregar intensamente muchas cosas durante los días anteriores, este día volvió a agregar pruebas y limpiar bordes, asegurando que no solo "se ejecuten una vez" sino que "se mantengan confiables en el futuro". Alternar una iteración rápida con una consolidación constante es la razón por la que esta línea de productos puede seguir funcionando.
