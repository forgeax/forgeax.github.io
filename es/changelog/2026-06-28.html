Actualización2026-06-28

Un comando, ahora también en Windows

Este día se trasladaron los scripts de instalación y lanzamiento al por mayor de bash a Bun TypeScript multiplataforma: los mismos comandos se ejecutan de manera idéntica en macOS, Linux y Windows, y Windows ya no necesita Git-Bash. Además, arregló una serie de bloqueadores específicos de Windows, cambió las "sesiones" de vinculadas globalmente a con alcance por juego, hizo la importación de activos más estable y hizo que la CLI subyacente fuera más rápida, más controlable y más auditable.

La mayor barrera: no se instalaría si cambiaras de plataforma

Durante mucho tiempo, instalarlo y ejecutarlo dependió de un montón de scripts bash. Está bien para macOS y Linux, pero es un muro duro para los usuarios de Windows: bash no es nativo de Windows, por lo que tenías que instalar una capa de compatibilidad como Git-Bash o sufrir una variedad de errores crípticos. Para una herramienta que quiere que "cualquiera convierta ideas en juegos", "no se instala" es el primer desvío más fatal. Este día solucionó exactamente eso: reescribir todos los scripts de instalación y lanzamiento al por mayor, desde bash hasta TypeScript multiplataforma ejecutado por Bun. Bun se comporta de manera idéntica en los tres sistemas principales, por lo que los mismos comandos y la misma lógica se ejecutan en Windows exactamente como en Mac, sin necesidad de capa de compatibilidad.

Los comandos se agrupan en un conjunto memorable.

Junto con la mudanza, se limpiaron los puntos de entrada. Los scripts dispersos por plataforma del pasado (.sh, .bat, .ps1, etc.) se eliminaron juntos y se unificaron en un conjunto simple y memorable: bun run setup para instalar el entorno una vez, bun run start para iniciar toda la pila, bun run stop para detenerlo, bun run app para la aplicación de escritorio. Cualquiera que sea el sistema en el que esté, estos pocos son todo lo que necesita recordar. Para los nuevos usuarios significa "copiar cuatro líneas del README y se ejecuta", sin más "Estoy en Windows, ¿por cuál cambio esto?"; para los usuarios existentes significa no más carga de mantenimiento de "dos copias de cada script (una sh, una ps1) para editar al mismo tiempo y es fácil pasar por alto". Reunir varios scripts equivalentes en una fuente de verdad multiplataforma es el corazón del trabajo diario: una cosa menos que mantener sincronizada es un lugar menos donde fallar.

Limpiar una serie de bloqueadores específicos de Windows

Para que Windows sea realmente fluido, los scripts multiplataforma por sí solos no son suficientes: también hay que corregir, una por una, las rarezas que sólo aparecen en Windows. Un caso típico manejado hoy: el Python "falso" del sistema: Windows incluye un marcador de posición python3 que en realidad no está instalado y solo aparece en la tienda de aplicaciones cuando se invoca, y un script que ingenuamente asume que funciona se detendrá misteriosamente durante la instalación. Este día enseñó el flujo de instalación a reconocer y omitir ese marcador de posición y encontrar un Python que realmente funcione. Detalles como este (inexistentes en otros sistemas y que solo lo hacen tropezar en Windows) son la parte más exigente pero más necesaria del soporte multiplataforma: no agregan funciones, pero cada una de ellas arreglada significa que un grupo de usuarios de Windows se detiene una vez menos y puede continuar.

Las sesiones cambian de un ámbito global a un ámbito por juego

Este día también tocó una estructura más interna: a quién pertenece una sesión (una sesión es un tramo de su conversación con Forge). Las sesiones solían ser globales y separadas de cualquier juego específico; este día los anidó debajo de cada juego, con un alcance por juego. Significado: su conversación con Forge para el proyecto "disparador espacial" y la del proyecto "simulación de granja" ahora son propias y nunca se mezclan entre sí. Es más intuitivo (una conversación pertenece a un juego específico en primer lugar) y sienta las bases para una gestión de proyectos más limpia en el futuro: cambia de juego y aparece su historial y contexto de chat, en lugar de enfrentarse a una olla global de sesiones mixtas. Este tipo de orden de "archivar los datos donde realmente pertenecen" no es atractivo en el día a día, pero mantiene limpio el modelo mental de todo el sistema.

Importación de activos más estable + una CLI más rápida y controlable

El día también se implementaron varias correcciones que hacen que el uso diario sea más estable. En cuanto a los activos, solucionó un problema de indexación al importar modelos más grandes (las mallas grandes necesitan números enteros más anchos para indexar sus vértices, lo que solía fallar aquí) e hizo que los metadatos escritos en la importación de modelos siguieran un formato canónico, por lo que importar un modelo más grande y complejo ya no falla fácilmente. El núcleo CLI que impulsa la IA también recibió varias mejoras: recortar la redundancia para que el primer turno comience a funcionar más rápido en algunos casos; solucionar un problema al introducir el "código de conducta" de un agente; y agregar un enmascaramiento opcional de las propias herramientas externas de un usuario más un seguimiento de auditoría de las llamadas de un agente a las herramientas del host; este último significa "qué herramientas usó realmente la IA esta vez" y se puede rastrear en el registro. En conjunto, esto empuja la base hacia otra capa hacia "más rápido, más controlable, más confiable".

que significa este dia

La protagonista de este día es "la barrera". Por poderosa que sea una herramienta, si un grupo grande queda excluido porque su sistema es incorrecto y no se instala, la mitad de su valor desaparece antes de que alguien la use. Hacer que la instalación y el lanzamiento sean totalmente multiplataforma, para que los usuarios de Windows también puedan ejecutarlo con un solo comando, abre esa puerta a todos: una de las condiciones previas para que "cualquiera pueda crear juegos" sea cierta. Y el mismo día, archivar sesiones bajo su juego, arreglar la importación de activos para que fuera estable y pulir el núcleo CLI para que fuera más rápido y auditable, arregló la sala mientras se abría la puerta. Bajar la barrera de entrada y luego aumentar la calidad del interior: este día hizo ambas cosas.
