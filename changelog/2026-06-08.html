编辑器一波大整合:右键菜单、引用进对话、专业视口A big editor integration: context menu, reference-to-chat, a pro viewport

编辑器这天一次性补齐了一大批让它"顺手"的交互。统一的右键菜单,让常用操作在任何地方右键就能就近取用,不必满界面找按钮。"把选中对象引用进对话":在场景里选中某个东西,一键就能把它作为引用带进与 AI 的对话里,这样你说"把这个放大一点"时,AI 精确知道"这个"指的是哪一个,而不用你费力描述。多个工作区用标签页切换,做不同的活有不同的布局,互不打扰。视口里移动 / 旋转 / 缩放的操作手柄和相机的推拉旋转,采用了业界主流三维软件那一套通行的操作习惯——任何用过专业三维工具的人几乎零成本就能上手。画布上还加了错误浮层:一旦出问题,直接在画面里弹出提示,而不是把错误闷在看不见的控制台里让你一头雾水。这一整波整合,把编辑器从"功能能用"明确推向了"用着顺手、看着专业"。The editor filled in a large batch of natural-feeling interactions at once this day. A unified right-click menu puts common actions within reach anywhere — right-click nearby instead of hunting the interface for a button. "Reference a selected object into chat": select something in the scene and, in one click, carry it as a reference into the conversation with the AI, so when you say "scale this up a bit," the AI knows exactly which "this" you mean without your laboring to describe it. Multiple workspaces switch via tabs, with different layouts for different work that don't disturb each other. The viewport's move/rotate/scale handles and the camera's pan/zoom/orbit adopt the common operating conventions of mainstream professional 3D software — anyone who has used a pro 3D tool picks it up at almost zero cost. An error overlay was added on the canvas: the moment something goes wrong, a prompt pops up right in the view, instead of burying the error in an unseen console and leaving you mystified. This whole wave of integration clearly pushed the editor from "the features work" toward "natural to use and professional to look at."

模型在编辑和试玩里都能带材质实时渲染Models render live with materials, in edit and play alike

这天补上了"所见即所得"长期缺的最后一块视觉拼图:导入的 3D 模型现在能在运行时带着完整材质正确渲染。具体包含几样:纹理(贴在模型表面的那层图案与色彩)、多级纹理细节(让物体在远处不再出现细碎的闪烁噪点)、双面材质(薄片状的物体两面都能正确显示而不穿帮);再配上基于环境贴图的天光照明,模型在场景里看起来真实、有质感,而不再是一团没有表面细节的灰模型。比单点能力更关键的是一致性:这套运行时渲染让编辑态和试玩态看到的完全是同一个样子——你在编辑器里摆好、看到的效果,就是真正玩起来时的效果,中间不再有"编辑时一个样、跑起来另一个样"的落差。示例射击游戏已经整体切到这条运行时渲染链路上,编辑与试玩两边的画面严丝合缝。对创作者而言,这意味着你终于可以"放心地照着编辑器里的样子去打磨",因为它就是最终成品的样子。This day filled in the last visual piece long missing from "what-you-see-is-what-you-get": imported 3D models now render correctly with full materials at runtime. Specifically: textures (the pattern and color laid on the model's surface), mipmaps (so objects no longer show fine shimmering noise in the distance), and double-sided materials (so thin, sheet-like objects display correctly on both faces without breaking). Combined with image-based environment-map sky lighting, models look real and tactile in a scene rather than a lump of gray model with no surface detail. More crucial than any single capability is consistency: this runtime rendering makes edit and play look exactly the same — what you arranged and saw in the editor is what it is when actually played, with no more "looks one way editing, another way running" gap. The sample shooter has moved wholesale onto this runtime rendering path, with its edit and play views matching seamlessly. For creators this means you can finally "polish confidently against what the editor shows," because that is what the final product looks like.

实时控制台抛光:盯着 AI 干活更踏实Live console polish: watching the AI work, more reassuring

这天有一阵密集的抛光集中在那个"实时盯着 AI agent 干活"的控制台界面上——它是你观察后台多个 AI 任务进展、随时介入的窗口。此前它每一处都还有点硌手,这天被一项项磨平。关掉浏览器再回来,后台的 agent 还活着、状态不丢;在里面跑那种占满整屏的终端程序时,鼠标滚轮终于能直接滚动了;多个任务卡片在切换焦点时,变亮变暗改成了平滑过渡而不是生硬地"啪"地一跳;当前聚焦的那张卡片有了清晰的高亮边框,不再是浏览器默认的难看白边;全屏的卡片会正确地盖在顶栏之上而不被挡住;还消除了一个会反复误报"历史记录丢失"的烦人循环。这些改动没有一个是"新功能",但合起来,这个控制台从"勉强能用"变成了"可以盯着看一整天而不心烦"。对一个以 AI agent 为核心的平台来说,"能舒服地观察 AI 在干什么"本身就是一项关键能力——看得清、盯得住,人才放心把活交给它。This day had a dense burst of polish concentrated on the console for "watching the AI agents work live" — your window into the progress of multiple background AI tasks and stepping in at any time. Previously it was a bit grating in every corner; this day those were smoothed one by one. Close the browser and come back, and the background agents are still alive with state intact; when running a full-screen terminal program inside it, the mouse wheel can finally scroll directly; as multiple task cards switch focus, their brightening and dimming became a smooth transition instead of a jarring jump; the currently-focused card gained a clear highlight border instead of the browser's default ugly white edge; a full-screen card correctly covers above the top bar instead of being blocked; and an annoying loop that kept falsely reporting "history lost" was eliminated. None of these is a "new feature," but together the console went from "barely usable" to "you can watch it all day without irritation." For a platform centered on AI agents, "comfortably observing what the AI is doing" is itself a key capability — only when you can see clearly and watch steadily will you confidently hand the work to it.

动画工坊统一界面 + 抠图与标注新工具A unified animation workbench + cutout and annotation tools

动画相关的几个工具此前各自一套界面,图标、按钮主次、侧栏布局、提示风格都不一致,几个工坊放在一起像是几个不同团队拼出来的东西。这天把它们一口气标准化到同一套设计语言上:统一的图标库、清晰的按钮层级(主操作和次操作一眼分得清)、一致的侧栏布局、统一的提示样式、统一的"完成"状态配色。除了视觉统一,2D 骨骼动画的处理管线还新增了几样实用能力:从多个候选结果里挑选、自动抠掉背景、以及一个用来标注的模式;另一个用来搭 2D 场景的工作台也被正式开放出来。视觉一致看似只是"好看",实则关乎信任——当一个产品的各个角落长得像同一个东西时,用户才会本能地相信它们背后是同一套靠谱的逻辑。对不写代码、只用界面的创作者来说,这天是 Studio 第一次"看起来像一个完整的产品",而不是一堆工具的拼盘。Several animation-related tools each had their own interface before — icons, button priority, sidebar layout and toast styles all inconsistent, so the workbenches together looked like things stitched from different teams. This day standardized them onto one design language in a single pass: a unified icon set, clear button hierarchy (primary and secondary actions distinguishable at a glance), consistent sidebar layout, unified toast style, and unified "complete"-state colors. Beyond visual unity, the 2D skeletal-animation pipeline gained several practical abilities: choosing among multiple candidate results, automatic background removal, and an annotation mode; another workbench for building 2D scenes was also formally opened up. Visual consistency seems like just "looking nice," but it's really about trust — when every corner of a product looks like the same thing, users instinctively believe the same reliable logic sits behind them. For creators who don't write code and only use the interface, this day was the first time Studio "looked like a complete product" rather than a platter of assorted tools.

引擎:天空不再倒着画 + 进阶渲染教学示例Engine: the sky no longer renders upside-down + advanced rendering demos

引擎这天修了一个很典型的小而扰人的 bug:天空盒的立方体贴图之前在竖直方向上被画反了,导致天空是上下颠倒的。这天把这个翻转去掉,立方体贴图终于正着画了——天空回归正常。同一波还做了一批进阶渲染技法的教学示例并直接跑在引擎里:立方体环境贴图、着色器里高效共享数据的方式、以及前面提到的实例化渲染(用一个行星环的场景来验证大量重复物体的高效绘制)。这些示例有双重作用:一方面它们是引擎能力的"活文档",任何人想知道某项技法怎么用,看这个能跑的示例最直观;另一方面,做示例的过程本身就在不断地把渲染管线里残留的小坑暴露出来、就地补掉——天空倒置这个 bug 正是这样被顺手发现并修掉的。一边教自己、一边修脏,是让一台引擎持续保持健康的好习惯。The engine fixed a textbook small-but-irritating bug this day: the skybox's cube map was previously drawn flipped vertically, leaving the sky upside-down. This day removed that flip, and the cube map finally renders right-side-up — the sky is back to normal. The same wave produced a batch of advanced rendering-technique demos running directly in the engine: cube environment maps, efficient ways to share data in shaders, and the instanced rendering mentioned earlier (using a planet-ring scene to validate efficient drawing of many repeated objects). These demos serve a dual purpose: on one hand they are "living documentation" of the engine's capabilities — anyone wanting to know how a technique is used finds a runnable demo most intuitive; on the other, the very act of building demos continually exposes residual little pitfalls in the rendering pipeline and patches them on the spot — the upside-down-sky bug was found and fixed exactly this way. Teaching yourself while cleaning up is a good habit for keeping an engine continuously healthy.
