六月第一天:桌面应用第一次从安装到游玩全程跑通,首启就引导你填 key。引擎一天连击——3D 世界里能挂清晰文字、物体关系双向同步、加了每帧缓存提性能、修好抗锯齿与贴图朝向;还新增了一个低多边形建模助手。June's first day: the desktop app ran end to end from install to play for the first time, with first-launch key onboarding. The engine landed a streak — crisp text in the 3D world, bidirectional object relations, a per-frame cache for performance, anti-aliasing and texture-orientation fixes; plus a new low-poly modeling assistant.

前几天桌面应用的外壳刚立起来,但"立起来"和"能用"之间还隔着一整条链路:后端要打进包、预览要内嵌、示例游戏要自动放好、第一次启动还得让用户顺利填上 key。这天把这整条链路从头到尾打通,桌面应用第一次能从"安装"一路走到"游玩"。与此同时,引擎单日推进了一长串(文字、关系、性能、画质修复),协作侧还添了一个新助手。一边把"能装能跑"的桌面体验做闭环,一边持续给引擎和工具加料,这天是把六月开局稳稳铺在"既能用、又在长"的双轨上。The desktop shell had just stood up the prior days, but between "stands up" and "usable" lies a whole chain: the backend must be bundled in, the preview embedded, sample games seeded, and the first launch must let users enter a key smoothly. This day connected that whole chain end to end, and the desktop app could go all the way from "install" to "play" for the first time. Meanwhile the engine advanced a long streak in a single day (text, relations, performance, image-quality fixes), and the collaboration side added a new assistant. Closing the loop on an "installable and runnable" desktop experience while continuing to feed the engine and tools, this day laid June's opening firmly on the dual track of "usable and still growing."

桌面 App 端到端跑通 + 首启引导填 keyThe desktop app runs end to end + first-launch key onboarding

桌面应用这天第一次从头跑到尾。它把后端服务直接打进安装包、把引擎预览内嵌进窗口、把示例游戏在首次启动时自动放好,连第一人称游戏需要的鼠标指针捕获(把光标锁进窗口里转视角)也接上了。最贴心的是首次启动体验:会弹出一个引导层让你填入 API key,填完立即生效、不用重启应用——后端会把新填的 key 实时应用到运行环境里。端口也能用环境变量覆盖以适配不同机器,装配前还会自愈一类常见的依赖摆放问题,避免打包失败。从这天起,把它当一个能安装、能打开、能直接玩的桌面软件来用,整条路真正通了——这是从"开发者在源码里跑"到"普通人装个 app 就能用"的关键一步。The desktop app ran from start to finish for the first time this day. It bundles the backend service directly into the installer, embeds the engine preview into the window, seeds sample games automatically on first launch, and even wires up the mouse pointer capture (locking the cursor into the window to turn the view) that first-person games need. Most thoughtful is the first-launch experience: an onboarding overlay prompts you to enter your API key, which takes effect immediately with no app restart — the backend applies the newly entered key to the running environment live. Ports can be overridden via environment variables to fit different machines, and a common dependency-placement issue self-heals before assembly to avoid build failures. From this day, using it as a desktop application you can install, open and play directly genuinely works end to end — the key step from "developers running in source" to "ordinary people installing an app and using it."

引擎:3D 世界里能挂清晰文字Engine: crisp text in the 3D world

引擎这天落地了"世界空间文字渲染":现在能把清晰、放大也不糊的文字直接挂在 3D 场景里的任意位置。这件事比听起来重要——游戏里到处都需要立在世界里的文字:招牌、路牌、角色头顶的名字、血条数字、漂浮的伤害跳字、互动提示。它用的是一种特殊的字形表达方式,让文字无论被拉近拉远、放大缩小,边缘都保持锐利,而不是变成一团模糊的像素糊。在此之前,引擎只能画几何与贴图,文字是个明显的空缺;补上这一块,意味着做带 UI、带提示、带数值反馈的游戏第一次有了正经的文字能力。对几乎任何类型的游戏来说,这都是从"能渲染世界"到"能在世界里传达信息"的必备一步。The engine landed "world-space text rendering" this day: you can now place crisp text, sharp even when enlarged, directly anywhere in a 3D scene. This matters more than it sounds — games need text standing in the world everywhere: signs, road markers, names above characters, health-bar numbers, floating damage popups, interaction prompts. It uses a special glyph representation that keeps edges sharp whether the text is moved near or far, scaled up or down, instead of turning into a blurry pixel mush. Before this, the engine could only draw geometry and textures, and text was a glaring gap; filling it means making games with UI, prompts and numeric feedback has proper text capability for the first time. For almost any genre, this is an essential step from "can render a world" to "can convey information in the world."

引擎:物体关系双向同步 + 实体生命周期统一 + 性能缓存Engine: bidirectional relations + unified entity lifecycle + a performance cache

引擎这天在底层的"对象组织"上做了几处加固。其一是物体之间的"关系"做成了双向自动同步:当你建立或解除一对父子、归属之类的关联时,关系的两端会自动保持一致——不会出现"父亲说有这个孩子、孩子却不认这个父亲"的脏状态,组合与拆解都更省心。其二是把场景实例的生命周期统一了:分离、销毁、整体清除走同一套规整的语义,避免边角情况下漏删、残留。其三是性能:加了一层每帧的渲染状态缓存,把每帧都要重算的东西缓存起来复用,减少无谓开销。这些都是看不见的内功,但它们决定了一个复杂场景在频繁增删、组合对象时会不会越来越乱、越来越慢。把"对象之间怎么连、怎么生、怎么灭"这套规矩立稳,是引擎能扛住真实游戏复杂度的根基。The engine reinforced several things in low-level "object organization" this day. One: relationships between objects became bidirectionally auto-synced — when you create or break a parent-child or ownership link, both ends stay consistent automatically, with no dirty state where "the parent claims this child but the child doesn't recognize the parent," making composition and teardown easier. Two: scene-instance lifecycle was unified — detach, destroy and full clear follow one orderly semantics, avoiding missed deletions and leftovers in edge cases. Three, performance: a per-frame render-state cache was added, caching and reusing what would otherwise be recomputed every frame, cutting needless overhead. These are invisible inner work, but they decide whether a complex scene grows messier and slower as objects are frequently added, removed and combined. Establishing the rules for "how objects connect, are born and die" is the foundation for the engine to withstand real game complexity.

引擎画质修复:抗锯齿 + 贴图朝向Engine image-quality fixes: anti-aliasing + texture orientation

这天还修了几处直接影响观感的画质问题。抗锯齿修了两处:一处是采样偏移的数学算错,导致边缘平滑得不准;另一处更隐蔽——颜色被错误地做了两次空间转换,使得画面平坦区域整体偏亮、发灰。两处修对之后,边缘更干净、色彩更准。还修了一个程序化生成几何体的贴图上下颠倒问题:根因是贴图坐标的方向和图形采样器的原点约定没对齐(一个从上数、一个从下数),典型的"差一个翻转"的坑——草地之类的贴图原本是倒着贴的,现在正过来了。这些都不是新功能,而是把已有能力的细节抠到"看着就是对的"。画质这种东西,往往就赢在这些一眼能看出对错、却很容易被忽略的细节上。This day also fixed several image-quality issues that directly affect look and feel. Anti-aliasing got two fixes: one was wrong math in the sampling offset, making edge smoothing inaccurate; the other more subtle — colors were wrongly converted through a space twice, making flat areas of the image overall brighter and washed out. With both fixed, edges are cleaner and colors more accurate. A texture upside-down issue on procedurally-generated geometry was also fixed: the root cause was that the texture coordinate's direction and the graphics sampler's origin convention didn't align (one counts from the top, the other from the bottom), the classic "off by one flip" pitfall — textures like grass were applied upside down and are now right-side up. None of these are new features but carving the details of existing capability to "it just looks right." Image quality often wins exactly on these glance-obvious-yet-easily-overlooked details.

新增低多边形建模助手 + 外部插件自动启动A new low-poly modeling assistant + auto-starting external plugins

协作阵容这天再添一员:一个专做低多边形(low-poly)3D 建模的助手,带无头渲染能力,可以帮你生成那种面数少、棱角分明、清爽风格的 3D 模型——这是很多独立游戏偏爱的美术风格,做起来又快又有辨识度。平台这边还让外部工作台插件能随系统自动启动:装好的第三方工具开机即用,不必每次手动去拉起,接入体验更顺。同时修好了一个会让某些工具被误报"未知工具"的同步问题——根因是工具注册的同步不够及时、不够幂等,修对之后工具调用更稳。一个负责造型的新助手、一个让插件更省心的接入改进、一个让工具调用更可靠的修复,合起来继续把"用一群各有专长的 AI 协作做游戏"这件事打磨得更顺手。The collaboration roster gained another member this day: an assistant specialized in low-poly 3D modeling, with headless rendering, to help you generate those low-face-count, sharp-edged, clean-styled 3D models — an art style many indie games favor, fast to make and distinctive. The platform also lets external workbench plugins auto-start with the system: installed third-party tools work from boot without manual launching each time, smoothing the integration experience. A sync issue that made some tools wrongly report "unknown tool" was also fixed — the root cause was tool-registration sync not being timely or idempotent enough, and once fixed, tool calls are steadier. A new modeling assistant, an integration improvement that makes plugins lower-maintenance, and a fix making tool calls more reliable — together they keep polishing "collaborating with a team of specialized AIs to make games" into something smoother.

这一天意味着什么What this day means

六月以这样一天开局,信号很明确:一边把"普通人装个 app 就能用"这件事做到真正端到端,一边让引擎在画面表达力(文字)、底层秩序(对象关系与生命周期)、性能与画质细节上同时往前推。桌面端从"能开"走到"能用",意味着这个工具开始具备走向真实用户的形态;引擎补上世界文字、把对象关系理顺,意味着它能承载的游戏越来越接近"完整作品"。一个面向大众的创作平台,既要让人轻松进得来(桌面 app + 首启引导),又要让人做得出像样东西(引擎能力持续补强)——这一天在这两条最根本的线上,都各自扎实地走了一步。June opening with a day like this sends a clear signal: making "ordinary people install an app and use it" genuinely end to end, while pushing the engine forward at once on visual expressiveness (text), low-level order (object relations and lifecycle), and performance and image-quality detail. The desktop side moving from "can open" to "usable" means the tool begins to have the form to reach real users; the engine adding world text and straightening out object relations means the games it can carry get closer to "complete works." A mass-market creation platform must both let people in easily (a desktop app plus first-launch onboarding) and let them make presentable things (continual engine reinforcement) — and this day took a solid step on each of these two most fundamental lines.
