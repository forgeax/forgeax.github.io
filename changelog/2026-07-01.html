R4 前端落地收官 + 视口 2×2 重设计R4 frontend lands + viewport 2×2 redesign

这天 Studio 侧交付了几块能直接改变编辑体验的改动:R4 四大前端模块（聊天、工作台、设置、仪表盘）真正接上启动链并完成 interface 瘦身;视口从互斥的 Edit/Play 切换升级为运行模式 × 显示模式的 2×2 矩阵;编辑器不再自己写死游戏路径,改由 Studio 注入游戏目录布局。另外,bun fx update 加上了彩色结构化更新报告,桌面端打包脚本也做了跨平台加固。This day shipped several Studio changes you can feel in the editor: the R4 frontend apps (chat, workbench, settings, dashboard) finally wired into the boot chain with a slimmed interface store; the viewport moved from mutually exclusive Edit/Play toggles to a 2×2 run × display matrix; and the editor no longer hard-codes game paths — Studio injects the game layout instead. On top of that, bun fx update gained a color-coded structured report, and the desktop packaging script was hardened for cross-platform builds.

R4 前端:从独立子模块到真正跑起来R4 frontend: from standalone submodules to actually running

6 月 30 日把聊天、工作台、设置、仪表盘拆成独立子模块后,这天做的是"接上电"。interface 包瘦身成纯 AppKit 层（总线、广播、深链、浮层）,四个 L2 应用各自接管 agent 偏好和文件预览,通过 bus 通信而不是挤在一个大 store 里。Studio 的 main.tsx 启动时初始化 initAgentPrefs、initFilePreview、bootBroadcast 和 daemon tick 订阅——四大模块不再是"挂在那里的子目录",而是编辑器的正式组成部分。R4 从计划变成了能日常开发的结构。After splitting chat, workbench, settings and dashboard into standalone submodules on June 30, this day was about "turning them on." The interface package was slimmed to a pure AppKit layer (bus, broadcast, deep links, overlays); the four L2 apps each own agent preferences and file preview via the bus instead of crowding one big store. Studio's main.tsx now initializes initAgentPrefs, initFilePreview, bootBroadcast and daemon tick subscriptions at boot — the four modules are no longer "subdirectories sitting there" but formal parts of the editor. R4 went from plan to structure you can develop against daily.

视口 2×2:运行模式 × 显示模式Viewport 2×2: run mode × display mode

编辑器视口这天完成了 2×2 重设计。之前 Edit 和 Play 是两种互斥状态,一切换就要重建整个视口。新方案把"运行模式"（Edit / Play）和"显示模式"（Scene / Game）拆成两个正交维度,合成 2×2 矩阵——你可以同时看到场景视图和游戏视图,用不同的运行状态驱动。AppMode 成为单一数据源,interface 和 editor 子模块都对齐到这套 viewport 语义。这是朝 UE5 式编辑体验迈的一步:在一个屏幕上同时编辑和预览,不用来回切。The editor viewport completed its 2×2 redesign this day. Before, Edit and Play were two mutually exclusive states — switching meant rebuilding the entire viewport. The new design splits "run mode" (Edit / Play) and "display mode" (Scene / Game) into two orthogonal dimensions forming a 2×2 matrix — you can see both the scene view and the game view at once, driven by different run states. AppMode became the single source of truth, with the interface and editor submodules aligned to this viewport semantics. It's a step toward a UE5-style editing experience: edit and preview on one screen without toggling back and forth.

编辑器解耦游戏目录,Studio 注入布局Editor decouples game paths — Studio injects layout

编辑器子模块这天去掉了对游戏目录的硬编码依赖,变成布局无关的独立包。游戏文件该放哪、URL 前缀是什么,不再由编辑器自己"烘焙",而是由宿主（Studio）注入:主视口 iframe 通过 EditSurfaceProps.gameRoot 拿到路径,localStorage 让各面板 iframe 指向同一游戏;启动引擎时传入磁盘扫描目录和客户端 URL 前缀;桌面打包也会烘焙 URL 前缀,让冻结的应用能正确提供游戏资源。编辑器可以独立演进,Studio 掌控项目布局——职责边界更清晰了。The editor submodule shed its hard-coded dependency on game directories this day, becoming a layout-agnostic standalone package. Where game files live and what the URL prefix is no longer gets "baked" by the editor — the host (Studio) injects it: the main viewport iframe gets its path via EditSurfaceProps.gameRoot, localStorage keeps panel iframes pointed at the same game; launching the engine passes the disk scan dir and client URL prefix; desktop packaging also bakes the URL prefix so a frozen app serves game assets correctly. The editor can evolve independently while Studio owns project layout — clearer boundaries.

bun fx update:拉完代码一目了然bun fx update: pull code and see everything at a glance

开发者每天早上做的第一件事通常是拉最新代码。之前 bun fx update 就是安静地跑一遍 git pull 加子模块同步,成功了就什么也不说,失败了就丢一段难懂的报错。这天给它加上了结构化的更新报告:用彩色的表格显示每个子模块的拉取结果（成功、跳过、冲突）、当前分支、最新 commit 摘要。如果某个子模块有本地修改需要 stash,也会明确告诉你。一次 update 结束后,你对整个项目现在什么状态心里有数——不用再挨个子模块去 git status。The first thing a developer does each morning is usually pull the latest code. Before, bun fx update would silently run git pull plus submodule sync — say nothing on success, and dump an opaque error on failure. This day added a structured update report: a color-coded table showing each submodule's pull result (success, skipped, conflict), its current branch, and the latest commit summary. If a submodule has local changes that needed stashing, it tells you explicitly. After one update you know what state the entire project is in — no more running git status in each submodule one by one.

桌面端打包:跨平台脚本 + 版本烘焙Desktop packaging: cross-platform script + version baking

桌面端构建这天也做了加固:build-desktop.ts 改成跨平台脚本并补上测试;打包时把 platform-io 和 agent-host 打进 sidecar,版本号通过 lib/version.ts 烘焙进产物,不再依赖运行时拼凑;bun fx start 还新增了端口占用检查,启动前会探测常用端口是否已被占用,避免起了半个栈却不知道。这些改动单个看都不 flashy,但决定了 Windows 和 macOS 上能不能顺畅打包、启动。Desktop packaging was hardened this day too: build-desktop.ts became a cross-platform script with tests added; packaging vendors platform-io and agent-host into the sidecar, baking the version via lib/version.ts into the artifact instead of assembling it at runtime; and bun fx start gained a port-busy check that probes whether common ports are already in use before launch, so you don't end up with half a stack running and no idea why. None of these are flashy on their own, but they determine whether packaging and launching work smoothly on Windows and macOS.
