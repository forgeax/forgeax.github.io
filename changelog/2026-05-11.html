从零到「对话生成一个旋转立方体」From zero to a chat-made spinning cube

24 小时,四条线并行,把整个产品最核心的假设变成了眼见为实:对它说一句话,它改代码,浏览器立刻热更出结果。这天交付的是一个能自我验证的"对话→旋转立方体"端到端闭环,以及托起这个闭环的分层架构、真正的 agent 运行时、三栏界面和上百次体验打磨。In 24 hours, four parallel tracks turned the product's core bet into something you can see: say a sentence, it writes code, and the browser hot-reloads the result. The day delivered a self-verifying "chat → spinning cube" end-to-end loop, plus the layered architecture, real agent runtime, three-column interface and hundreds of polish passes that hold it up.

北极星:为什么是"一个旋转立方体"The north star: why "a spinning cube"

这一天所有的工作都对着同一个验收点:在一台干净的机器上,克隆、填一个密钥、一条命令跑起来,然后在界面里对 agent 说"做一个旋转立方体",它去改代码、引擎热重载、浏览器里立刻出现一个转动的立方体。立方体本身毫不起眼,但它是整个产品最核心假设的最小证明——"用对话就能做出真正能跑的东西",这条链路上任何一环断了,这个平台就不成立。把目标收敛成这样一个能被一张截图证明的、不可含糊的验收点,意味着团队不是在"感觉有进展",而是在追一个要么通、要么不通的硬指标。这一天,它通了。Everything this day aimed at one acceptance point: on a clean machine, clone, drop in a key, run one command, then tell the agent in the interface "make a spinning cube" — it edits code, the engine hot-reloads, and a turning cube appears in the browser at once. The cube itself is unremarkable, but it's the minimal proof of the product's core bet — "you can build something genuinely runnable just by talking" — and if any link in that chain breaks, the platform doesn't hold. Collapsing the goal into one unambiguous acceptance point a single screenshot can prove means the team isn't "feeling progress" but chasing a hard pass/fail target. This day, it passed.

端到端闭环跑通:说一句话,画面就变The end-to-end loop runs: say a sentence, the picture changes

这条闭环由六个环节首尾相接:你在对话框里说出需求 → agent 把对应的代码写进游戏文件 → 文件监听器察觉到改动 → 通过实时通道通知前端 → 引擎动态加载新代码 → 画面立刻更新。这天第一次把这六环完整、稳定地串通,并且用自动化浏览器截图实测到了那个正在旋转中、带着倾斜角度的立方体,全程除了一个无害的图标缺失提示,没有任何报错。这意味着"所见即所得"不再是愿景里的一句话,而是一条真实存在、可重复触发的流水线。后面所有"边聊边做、立刻看到效果"的体验,都建立在这条闭环之上;它通了,产品才算真正"活"了一次。This loop chains six links end to end: you state a requirement in the chat box → the agent writes the corresponding code into the game file → a file watcher notices the change → a real-time channel notifies the front end → the engine dynamically loads the new code → the picture updates instantly. This day connected those six links completely and stably for the first time, and an automated browser screenshot actually captured the cube mid-rotation at a tilt, with no errors the whole way except one harmless missing-icon notice. That means "what you see is what you get" is no longer a line in a vision deck but a real, repeatably-triggered pipeline. Every later experience of "build while chatting and see the result immediately" rests on this loop; with it working, the product truly came alive once.

三层架构落地:各司其职、可替换The three layers land: clear roles, replaceable

为了让这条闭环长期站得住,这天把系统切成了几层职责清晰、可独立替换的部件:一层是真正驱动 agent 思考与行动的运行时内核(管模型调用、工具、会话、记忆);一层是纯粹的编排与界面桥接(负责把文件改动广播给前端,自己完全不碰大模型);一层是引擎(把游戏代码渲染成画面);再加上用户直接面对的三栏界面。这套划分写进了内部的接口约定,并被定为不可随意重议的铁律——内核就是内核、编排就是编排,边界不许含糊。它的价值在于:每一层都能独立演进、独立替换,某一层出问题不会牵连全局,也让"换一个引擎、换一种界面"在未来成为可能,而不是从头重写。To make this loop stand the long haul, the system was sliced into parts with clear, independently-replaceable responsibilities: a runtime kernel that actually drives the agent's thinking and acting (handling model calls, tools, sessions, memory); a pure orchestration-and-interface bridge (broadcasting file changes to the front end, never touching the large model itself); an engine (rendering game code into a picture); plus the three-column interface the user faces. This split was written into an internal interface contract and set as an iron rule not to be relitigated lightly — the kernel is the kernel, orchestration is orchestration, boundaries stay unambiguous. Its value: each layer can evolve and be swapped on its own, a problem in one layer doesn't drag down the whole, and "swap the engine, swap the interface" becomes possible later rather than a rewrite.

把"占位壳"换成真正的 agent 运行时内核Replacing the "placeholder shell" with a real agent runtime

凌晨那版闭环里,驱动 agent 的还只是个临时占位的空壳;这天分三十多个步骤,把它替换成了一套真正"类专业编码助手"的 agent 运行时内核。这套内核具备一个真实 agent 该有的东西:能调用大模型、能使用工具、能维护会话与记忆、能在一个"思考—行动"的循环里自主推进。替换之后,系统第一次拿到了真实的大模型回复,并跑通了"真模型 + 真工具"的完整闭环。这一步把产品从"看起来能聊"推进到"真的能干活"——之前的对话只是表演,现在背后是一个能读、能写、能调工具去真正改动你项目的引擎。In the pre-dawn version of the loop, what drove the agent was still a temporary placeholder shell; this day, in some thirty-plus steps, it was replaced with a real "professional coding-assistant-class" agent runtime. This kernel has what a real agent needs: it can call the large model, use tools, maintain sessions and memory, and drive itself forward in a "think–act" loop. After the swap, the system received genuine model replies for the first time and ran a full "real model + real tools" loop. This step pushed the product from "looks like it can chat" to "can actually do the work" — earlier conversations were a performance; now behind them is an engine that can read, write and use tools to genuinely change your project.

不重复造轮子:复用标准而非抄千行代码Don't reinvent: reuse standards instead of copying thousands of lines

在补全 agent 能力时,有两块本来可以"照着别处抄上千行"来做:一是把工具能力接进来的协议层,二是一套标准的对话事件协议。这天的判断很明确——凡是已经有成熟开放标准、且能直接装来用的,就不自己重抄一遍。于是这两块各自用官方提供的标准实现替换掉了早前的手写版本:工具协议那一处代码从一百多行缩到八十行,还顺带白拿到了更完整的传输方式和能力变更通知;对话事件协议那一处则直接引入标准库、转出三十多个标准事件,几乎没写新代码。两步加起来净增不到两百行,换来的却是企业级的能力。这背后是一条会反复出现的工程纪律:把力气花在别人没替你解决的难题上,而不是重造已经躺在公共标准里的轮子。While filling in agent capability, two pieces could have been done by "copying a thousand lines from elsewhere": the protocol layer that brings tool capability in, and a standard conversation-event protocol. This day's judgment was clear — wherever a mature open standard already exists and can be installed and used directly, don't re-copy it by hand. So both were replaced with official standard implementations of the earlier hand-written versions: the tool-protocol code shrank from a hundred-odd lines to eighty and got more complete transports and capability-change notifications for free; the conversation-event protocol pulled in a standard library and re-exported thirty-plus standard events with almost no new code. Together the two steps added under two hundred net lines yet delivered enterprise-grade capability. Behind it is a discipline that recurs: spend effort on the hard problems no one solved for you, not on reinventing wheels already sitting in public standards.

聊天界面上百次打磨:从裸字符到接近桌面级Hundreds of chat-UI passes: from raw text to near desktop-grade

一旦闭环真通了,界面的体感缺陷就成了最痛的地方。这天用极小的步长、上百次迭代,把聊天面板从"裸字符 + 占位框"打磨到接近成熟桌面助手的质感。这里面有一整套手写的 Markdown 渲染(代码块、列表、表格、任务清单都支持),有逐字打字的流式动画且速率会随内容长短自适应,有把工具调用浓缩成一枚信息密度很高的"药丸"标签、点开还能看完整结果,有把 agent 的"自我纠正/反思"用视觉上分隔出来,还有按无障碍标准把气泡与背景的对比度调到达标、并为偏好减少动效的用户关掉循环动画。每一拍都只动一处、改完自测、再记一笔。这条线说明的事很朴素:能力再强,如果读起来费劲、看着廉价,用户也不会信任它;把日常最常盯着的那块界面抠到顺眼,本身就是核心功能的一部分。Once the loop truly worked, the interface's experience gaps became the sorest spot. This day, in tiny steps over a hundred iterations, polished the chat panel from "raw text and placeholder boxes" to something near a mature desktop assistant. It includes a whole hand-written Markdown renderer (code blocks, lists, tables, task lists all supported), a character-by-character streaming animation whose speed adapts to content length, tool calls condensed into a high-density "pill" tag that expands to the full result, the agent's "self-correction/reflection" set off visually, contrast between bubbles and background tuned to meet accessibility standards, and looping animations turned off for users who prefer reduced motion. Each pass touched one thing, self-tested, and logged a note. The point is plain: however strong the capability, if it reads laboriously or looks cheap users won't trust it; polishing the surface you stare at most into something pleasant is itself part of the core feature.

扁平化重构 + 零构建直跑源码A flat restructure + zero-build, run-from-source dev

下午做了一次工程结构上的扁平化重构,把原本层层嵌套的目录拍平,让各个部件以更直接的方式并列。配套确立了"零构建"的开发方式:克隆下来之后,一条命令就能直接拉起源码运行,不必先经过一长串编译打包。对开发者来说,这意味着改一行代码、几乎立刻就能在浏览器里看到效果,迭代速度直接上一个台阶;对想上手的新人来说,"从克隆到看见画面"这段路被压到最短。结构上的简化看不见摸不着,却决定了后面几周能不能维持"每天一大步"的节奏——地基越简单清楚,在上面盖得就越快越稳。In the afternoon came a structural flattening: the once deeply-nested directories were laid flat so the parts sit side by side in a more direct way. Alongside it, a "zero-build" dev mode was established: after cloning, one command runs the source directly, with no long compile-and-bundle step first. For developers, that means changing a line and seeing the result in the browser almost immediately, stepping iteration speed up a level; for newcomers, the road "from clone to seeing the picture" is squeezed to its shortest. The structural simplification is intangible, yet it decides whether the coming weeks can keep a "a big step a day" cadence — the simpler and clearer the foundation, the faster and steadier you build on top.

Studio 三栏界面成形:文件、预览、控制台、各种切换器The three-column Studio takes shape: files, preview, console, switchers

晚间集中把 Studio 的三栏界面铺了出来,一口气补上一批真正能用的面板:左侧的文件树接上了真实的项目文件、点一下产物就能预览;中间是直连引擎的实时预览窗,带帧率显示、暂停、重载、全屏,以及桌面/移动两种设备模式;还有把引擎控制台输出接进来的面板、能列出并回放历史会话的切换器、以及项目与游戏的切换入口和一个"新建"菜单。值得一提的是,这天还顺应一个直觉把"项目"和"游戏"两个概念合二为一——用户说它们本来就是一回事,界面就不该硬分。至此,"左侧管理、中间预览、右侧对话"的基本格局定了下来,Studio 从一堆能力开始收拢成一个能用的产品形态。In the evening the three-column Studio was laid out, with a batch of genuinely usable panels at once: the files tree on the left wired to real project files, click a product to preview it; a live preview window in the center connected straight to the engine, with a frame-rate readout, pause, reload, fullscreen and desktop/mobile device modes; plus a panel that pipes in the engine's console output, a switcher that lists and replays past sessions, and entries to switch projects and games with a "new" menu. Notably, this day also followed an instinct and merged the two concepts "project" and "game" into one — the user said they were the same thing, so the interface shouldn't force them apart. With that, the "manage-left / preview-center / chat-right" layout settled, and the Studio began converging from a pile of capabilities into a usable product form.

这一天意味着什么What this day means

把四条线连起来看,这一天的分量在于:它不是某个单点功能上线,而是整个产品的核心命题第一次被端到端地证明成立。从一句话到一个会动的立方体,中间的渲染、运行时、编排、界面每一环都真实跑通,并且是在一台干净机器上、被一张截图实证的。立方体之后的所有复杂——真实的游戏、复杂的场景、整支 agent 团队——都是在这条已经接通的主干上继续生长。也正因如此,这一天值得被当成范本记下来:先把那条最关键、最能证伪的主链路打通,再谈枝叶;能跑通一次,就有第二次、第一百次的底气。Seen together, the weight of this day is this: it wasn't a single feature shipping, but the product's core thesis being proven end to end for the first time. From a sentence to a moving cube, every link in between — rendering, runtime, orchestration, interface — genuinely ran, on a clean machine, evidenced by a screenshot. Everything complex after the cube — real games, complex scenes, a whole agent team — grows on this already-connected trunk. That's exactly why this day is worth recording as a model: connect the most critical, most falsifiable main chain first, then talk about the branches; running once is what gives you the confidence for the second time, and the hundredth.
