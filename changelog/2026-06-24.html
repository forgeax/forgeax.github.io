全新资产浏览器 + 更省心的首次引导A new asset browser + smoother first-run onboarding

这天围绕"刚进来的新人"和"已经在干活的创作者"两头同时发力:全新的双栏资产浏览器带缩略图、还能把一批资产整批交给 AI;第一次启动的设置引导做成两步、三种接入任选、全程不阻塞;编辑器补上了"打开工程→改→存回磁盘"的完整创作闭环;还新增了遥测与日志面板让整个系统更透明,引擎也把句柄统一、把大量相同物体的绘制做了实例化优化。This day pushed on both ends at once — the newcomer just arriving and the creator already at work: a new dual-pane Content Browser with thumbnails that can hand a batch of assets to the AI at once; a first-run setup made two-step, three-path and never-blocking; an editor that completes the "open project → edit → save back to disk" creative loop; plus a telemetry/log panel making the whole system more transparent, and an engine that unified handles and instanced the drawing of many identical objects.

两头同时使劲:接住新人,也撑住老手Pushing on both ends: catching newcomers, supporting veterans

这一天的工作可以分成两个朝向,各对应一类用户。一头是"接住新人":第一次打开的引导被重做得更省心,让一个素未谋面的访客最快地从"打开"走到"能跟 AI 聊起来做游戏"。另一头是"撑住老手":全新的资产浏览器、能把改动可靠存回磁盘的编辑流程、让一切运行状态可观测的遥测面板,都是为那些已经认真在做项目的人准备的——他们需要的不再是"能不能上手",而是"工具够不够趁手、够不够可靠"。一个刚刚开源、正迎来形形色色用户的平台,恰恰需要在这两头同时使劲:既要把门口的台阶削平,也要把屋里的工作台备齐。这一天,正是这样一次双向的发力。This day's work splits into two directions, each for a kind of user. One end is "catching newcomers": the first-run guide was redone to be smoother, getting a never-before-seen visitor fastest from "open it" to "chatting with the AI to make a game." The other end is "supporting veterans": a new asset browser, an editing flow that reliably saves changes back to disk, a telemetry panel making all runtime state observable — all for those already seriously working on projects, who need not "can I get started" but "is the tool handy and reliable enough." A platform just open-sourced and welcoming all sorts of users needs exactly to push on both ends: shaving the entry steps flat and equipping the workbench inside. This day was just such a two-way push.

全新资产浏览器:双栏 + 缩略图 + 一批资产直接交给 AIA new asset browser: dual-pane + thumbnails + hand a batch to the AI

资产浏览器这天升级到了第二代,并被设为默认。它是一个完整的、专业工具水准的素材管理面板:左侧是收藏夹加文件夹树,方便你按目录组织、把常用的钉起来;右侧是带缩略图和详细悬浮提示的内容区,一眼就能认出每份素材是什么;新增、导入、删除、全部保存等操作一应俱全,还配了键盘快捷键,熟练之后双手不离键盘就能高效整理。最有想象力的一点,是它和 AI 打通了:你可以在浏览器里框选一批资产,然后一键把它们整批作为引用递给聊天里的 AI——以前要让 AI"把这几个模型和这张贴图用进场景",你得一个个描述清楚是哪些;现在直接在浏览器里选好、一键递过去,AI 立刻精确知道你指的是哪些资产。这把"管理素材"和"指挥 AI"这两件原本分开的事缝在了一起,让"我手里有这些东西 → 你帮我用起来"成为一个顺滑的连续动作。The asset browser was upgraded to a second generation this day and made the default. It's a complete, professional-grade material-management panel: favorites and a folder tree on the left for organizing by directory and pinning frequently-used items; a content area with thumbnails and rich hover tooltips on the right so you recognize each material at a glance; add, import, delete and save-all all in place, plus keyboard shortcuts so, once practiced, you can organize efficiently without leaving the keyboard. The most imaginative part is that it's wired to the AI: you can select a batch of assets in the browser and hand them all to the chat AI as references in one click — where you previously had to describe one by one which models and which texture you wanted the AI to "use in the scene," now you pick them in the browser and pass them over, and the AI knows exactly which assets you mean. This stitches together "managing materials" and "directing the AI," two previously separate things, making "I have these things in hand → help me use them" one smooth continuous action.

首次启动引导更省心:两步、三种接入任选A smoother first run: two steps, three ways to connect

第一次打开时的设置引导这天重做了,核心目标是把新人最容易卡住的那一步变得尽可能轻松。新引导只有两步,提供三种接入方式任你选择:默认走一个聚合模型入口,因为它对新人最友好、配置最少就能跑起来;同时也保留了其他方式给有需要的人。最关键的设计是"全程不阻塞"——你不必在第一屏就被强制填完所有东西才能进门,可以先跳过、先进去逛逛,之后想用了再回来填。引导本身也做了中英双语。为什么一个"设置引导"值得专门打磨?因为对一个素未谋面的访客来说,第一次打开的那几分钟是去留的分水岭:流程一旦繁琐、一旦在某处卡住、一旦看不懂下一步该干嘛,人就走了。把这道门槛削到"两步、可跳过、有默认推荐",等于尽最大努力让每一个愿意点进来的人,都能顺利走到"开始用"这一步。The first-run setup guide was redone this day, its core goal to make the step newcomers most easily get stuck on as effortless as possible. The new guide is only two steps, offering three connection paths to choose from: it defaults to an aggregated model entry, the friendliest to newcomers and runnable with the least configuration, while keeping other paths for those who need them. The key design is "never blocking" — you needn't be forced to fill everything on the first screen before entering; you can skip first, look around inside, and come back to fill it in when you want. The guide itself is bilingual. Why is a "setup guide" worth deliberate polish? Because for a never-before-seen visitor, the first few minutes after opening are the watershed of staying or leaving: once the flow is cumbersome, once it stalls somewhere, once you can't tell what the next step is, people leave. Shaving this threshold to "two steps, skippable, with a default recommendation" is the utmost effort to let everyone willing to click in smoothly reach the "start using" step.

编辑器补上"打开工程 → 改 → 存回磁盘"的完整闭环The editor completes the "open project → edit → save to disk" loop

编辑器这天补上了一个让它从"能看能调"真正变成"能用来创作"的关键闭环:打开工程、修改、再把改动可靠地存回磁盘。具体落地了几件事:支持"打开一个工程"的创作流程,把游戏的入口和场景资产正确地装载进来;改成了"手动保存"——去掉了之前那种自动定时保存,改用一个清晰的"未保存"标记,让你明确知道当前改动存没存、由你决定什么时候落盘;打通了从编辑器内的改动到磁盘文件的回写链路,并配了热重载,改完能即时看到效果又能稳妥保存。此外还给编辑器加了"系统面板"(可以开关游戏里各个逻辑系统)和检视器里的"添加组件"菜单。这些拼在一起,意味着编辑器不再只是一个用来微调的辅助视图,而是一个能独立承载"打开 → 编辑 → 保存"完整创作循环的真正工具。对创作者来说,最根本的安全感就是"我改的东西存得住、找得回"——这天把这份安全感坐实了。The editor completed this day a key loop that turns it from "can view and tune" into genuinely "usable for creation": open a project, edit, and reliably save changes back to disk. Several things landed: support for an "open a project" authoring flow that correctly loads the game's entry and scene assets; a switch to "manual save" — dropping the previous automatic timed save for a clear "unsaved" marker, so you know whether current changes are saved and decide when to persist; a writeback chain from in-editor changes to disk files, with hot reload so changes show instantly yet save safely. The editor also gained a "systems panel" (toggling each logic system in the game) and an "add component" menu in the inspector. Together these mean the editor is no longer just an auxiliary view for fine-tuning but a real tool that independently carries the full "open → edit → save" creative loop. The most fundamental sense of security for a creator is "what I change is saved and recoverable" — and this day made that security real.

可观测性:遥测与日志面板 + 聊天防卡死Observability: a telemetry/log panel + a chat anti-freeze

这天给整个系统增添了"可观测性"——让你能看清它内部到底在发生什么。新增了一个遥测面板,把"追踪 + 日志"两类信息汇成一条可观测的信息流:某个 agent 此刻在干什么、每一步花了多长时间、中间出了什么状况,都能在这个面板里看到。后端配了对应的遥测汇集与上报通路,前端也加了一层监控脚手架。为什么要专门做这个?因为当越来越多的工作由 AI 自主推进时,"它到底在干什么、慢在哪、错在哪"就成了一个必须能被看见的问题——看不见,就既无法信任,也无法优化。与此同时,聊天这边修了一个真实的卡死风险:当 AI 输出超长的、带格式的 Markdown 内容时,前端会不停地重新解析渲染,频繁到一定程度就会把内存吃爆、整个界面卡死;这天给它加了节流,让长回答能边输出边稳定显示。一个透明、且扛得住长时间高强度使用的系统,才能让人放心地把大任务交给它跑。This day added "observability" to the whole system — letting you see what's actually happening inside it. A telemetry panel was added, gathering "traces + logs" into one observable feed: what an agent is doing at the moment, how long each step took, and what went wrong are all visible in it. The backend got a matching telemetry sink and reporting route, and the front end gained a monitoring scaffold. Why build this deliberately? Because as more work is pushed autonomously by AI, "what is it actually doing, where is it slow, where did it err" becomes a question that must be visible — invisible, it can be neither trusted nor optimized. Meanwhile, the chat fixed a real freeze risk: when the AI outputs very long, formatted Markdown, the front end keeps re-parsing and rendering, frequently enough to blow up memory and freeze the whole interface; this day throttled it so long answers stay stable as they stream. A transparent system that withstands long, intense use is what lets people confidently hand it big tasks to run.

引擎:统一句柄 + 实例化绘制 + 插件协议归一Engine: unified handles + instanced drawing + a unified plugin protocol

引擎这天在底层做了几件影响深远的事。其一是把"句柄"统一:句柄是程序里对实体和资产的引用(相当于一个指向某个东西的把手),这天把实体和资产的句柄统一成同一套带"代际"信息的编码——所谓代际,就是给每个句柄盖一个版本戳,这样当它指向的东西已经被销毁、那个位置又被新东西占用时,系统能立刻识别出"这是个过期的旧引用",而不是误以为还有效。这从源头上消除了"引用到一个已经没了的东西"这类极其隐蔽、极难排查的 bug。其二是实例化绘制优化:当场景里有大量长得一模一样的物体(一片树、一群兵)时,以前是逐个发出绘制指令,这天改成把同类的合并成一桶、一次画出来,绘制调用大幅减少——这对大规模场景的性能是质变,并用上万个独立物体的压力测试验证了效果。其三是把插件协议统一成一种写法,让扩展更一致;还提供了一个无界面的纯净后端用于测试。这些都是用户看不见、却决定平台"能跑多大、扩多远、错多少"的底层功夫。The engine did several far-reaching low-level things this day. One: unifying "handles." A handle is a program's reference to an entity or asset (a grip pointing at something), and this day unified entity and asset handles into one encoding carrying "generational" info — a generation being a version stamp on each handle, so when the thing it points to has been destroyed and its slot reused by something new, the system immediately recognizes "this is a stale old reference" rather than mistaking it as valid. This eliminates at the source the extremely subtle, hard-to-diagnose class of bugs where you "reference something that's already gone." Two: instanced-drawing optimization — when a scene has many identical objects (a forest, a crowd of soldiers), drawing commands used to be issued one by one, and this day merged the identical ones into a bucket drawn in one call, sharply cutting draw calls — a qualitative change for large-scene performance, verified with a stress test of tens of thousands of independent objects. Three: unifying the plugin protocol into one form for more consistent extension, plus a headless clean backend for testing. These are under-the-hood work users don't see yet that decides how big the platform can run, how far it extends, and how few errors it makes.

这一天意味着什么What this day means

这一天最值得记住的,是它同时照顾到了一个用户旅程的两端。对刚刚因为开源而第一次点进来的新人,它把"进门"的门槛削到了最低——两步引导、可跳过、有默认推荐,尽量让每个愿意尝试的人都能顺利开始。对那些已经在认真做项目的创作者,它把"干活"的工具备得更齐——专业的资产浏览器、能可靠存盘的编辑闭环、看得清内部的遥测面板。而引擎层面的句柄统一、实例化绘制、插件协议归一,则在更深处为这一切的"大规模、可扩展、可靠"提供着支撑。一个产品要想真正立住,光接住新人不够,还得让留下来的人越用越顺;光让老手满意也不够,还得让新人进得来。这一天,正是难得地把这两件事放在一起做——既敞开了门,也备好了屋。What's most memorable about this day is that it attended to both ends of a user journey at once. For the newcomer clicking in for the first time because of the open-sourcing, it shaved the "entry" threshold to the lowest — a two-step guide, skippable, with a default recommendation, doing its best to let everyone willing to try start smoothly. For creators already seriously working on projects, it equipped the "work" tools more fully — a professional asset browser, an editing loop that reliably saves, a telemetry panel that sees inside. And the engine-level handle unification, instanced drawing and unified plugin protocol provide, deeper down, the support for all of this to be "large-scale, extensible, reliable." For a product to truly hold, catching newcomers isn't enough — those who stay must find it smoother the more they use it; satisfying veterans isn't enough — newcomers must be able to get in. This day rarely did both together — opening the door and equipping the house alike.
