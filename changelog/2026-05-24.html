分水岭:跑你游戏的,从此是自己的引擎A watershed: from now, your game runs on our own engine

这是一个真正的分水岭。在此之前,预览里实际驱动你游戏跑起来的,还是一套早期为了快速起步而借用的通用渲染方案;而引擎团队这些天自研的那套能力,虽然一直在长,却还没真正成为"跑游戏的那台发动机"。这天把运行时整体切换到了自研引擎——从今天起,你聊出来的每一个游戏,真正跑在自己的引擎上。它的意义不只是"换了个底",而是把前面这些天分散积累的能力(基于物理的光照、阴影、环境天光、资产系统、2D 图层)第一次收进同一套引擎里协同工作,不再各管一摊。下面几件事,都是围绕这次切换展开或被它带动的。This is a genuine watershed. Before it, what actually drove your game in the preview was still a general-purpose rendering approach borrowed early for a fast start; and the capabilities the engine team had been building these days, though steadily growing, hadn't truly become "the engine that runs games." This day switched the runtime wholesale to the in-house engine — from today, every game you chat into being truly runs on our own engine. Its significance isn't just "swapping the base," but bringing the scattered capabilities built up over the past days (physically-based lighting, shadows, ambient sky light, the asset system, 2D layers) together inside one engine for the first time, no longer each on its own. The items below either revolve around this switch or were driven by it.

为什么自研引擎是值得的选择Why an in-house engine is the choice worth making

换掉一套现成、能用的方案,自己从头造一台引擎,代价显然不小;那为什么值得?核心在于"掌控力"。借用通用方案时,画质、性能、特性都受制于那套方案的取舍,想做点它没设计的事就很别扭;而自研之后,渲染表现完全可控、出了问题能一路查到底、要加的新特性可以一处实现处处生效,不必绕着别人的限制走。更重要的是,这台引擎是专门为"AI 来写游戏"而设计的——它的接口、它的资产体系、它的默认行为,都可以围绕"让 AI 容易写对、让生成的代码容易复用"来打磨,这是任何通用第三方方案给不了的。这天的切换,等于把产品最核心的那块基础,从"租来的"变成了"自己的"。Replacing a ready-made, working approach to build an engine from scratch clearly costs a lot; so why is it worth it? The core is control. Borrowing a general approach leaves image quality, performance and features constrained by that approach's trade-offs, and doing something it wasn't designed for is awkward; in-house, rendering is fully controllable, problems can be traced all the way down, and new features can be built once and take effect everywhere, without working around someone else's limits. More importantly, this engine is designed specifically for "AI writing games" — its interfaces, asset system and default behavior can all be polished around "making it easy for AI to write correctly and easy to reuse generated code," which no general third-party approach can offer. This day's switch turns the product's most core foundation from "rented" to "our own."

材质支持自定义着色器Materials gain custom shaders

借着引擎切换,材质系统也分成了"模板 + 实例"两层。一层是开箱即用的标准物理材质,满足大多数普通物体;另一层允许某个物体挂上它自己的自定义着色器,去做独特的视觉效果——发光、扭曲、脉动、能量场之类,不再受标准材质的束缚。为了不让"花样多了就变卡",引擎会按材质各自缓存对应的渲染管线,相同材质复用、不同材质各管各的,既灵活又高效。配套做了一个会"脉动发光"的示例来验证整条路打通了。对想让某个物体看起来与众不同的人来说,这一步给了一条正路:既能享受标准材质的省心,又保留了在需要时彻底自定义的自由。Riding the engine switch, the material system also split into two layers — template and instance. One is a ready-to-use standard physically-based material that covers most ordinary objects; the other lets an object carry its own custom shader for a distinctive visual effect — glow, distortion, pulsing, energy fields — no longer bound by the standard material. To keep "more variety" from "getting slow," the engine caches a render pipeline per material, reusing the same material and keeping different ones separate, both flexible and efficient. A "pulsing glow" demo proved the path works end to end. For anyone wanting an object to look unlike the rest, this gives a proper route: the ease of the standard material, plus the freedom to fully customize when needed.

网格上传更严格:坏数据当场报错Stricter mesh upload: bad data errors on the spot

这天还给"把网格数据传上显卡"这条底层链路加了一道严格的入口检查:如果传进来的网格数据格式不对(比如每个顶点的数据量对不上预期),引擎会当场快速报错,而不是默默吞下、等到画面以诡异方式出错时才让人去猜。配套还做了一次数据格式上的统一迁移,把相关的顶点数据格式对齐到一致的标准。这看似只是"加了个检查",其实体现了一条重要的工程原则:让错误尽早、尽近地暴露在它真正发生的地方,而不是顺着管线往下漂、最后变成一个难以追查的怪现象。对一个要让 AI 大量生成网格数据的引擎来说,这种"坏数据进不来"的把关,能省下后面无数排查时间。This day also added a strict entry check to the low-level path of "uploading mesh data to the GPU": if incoming mesh data is malformed (say, the per-vertex data count doesn't match expectations), the engine fails fast on the spot rather than silently swallowing it and leaving you to guess when the image later breaks in some uncanny way. A unified data-format migration came alongside, aligning the relevant vertex data formats to one consistent standard. This looks like "just adding a check," but it embodies an important engineering principle: surface errors as early and as close as possible to where they actually occur, rather than letting them drift down the pipeline into a hard-to-trace oddity. For an engine that will have AI generate mesh data in bulk, this "bad data can't get in" gatekeeping saves countless hours of later debugging.

更多专家 agent + 工具里直接挑人More specialist agents + picking them in-tool

协作阵容这天又充实了一批:新增了若干各有专长的 agent,你可以按任务挑合适的那个来接手,而不是所有事都丢给同一个通才。工具窗的顶栏还加了一个 agent 选择器,可以直接在某个工作台里指定由哪个 agent 来干,并一键打开它的详情看看它擅长什么。后端也补上了对 agent 的统一增删改查能力和角色配套,让"管理你这支 AI 团队"本身变得规整。让对的人做对的事,是协作效率的关键——一个画美术的需求交给擅长美术的 agent,远比交给一个什么都会一点的通才更靠谱。这天把"挑人"这件事做得既方便又顺手。The collaboration roster filled out again this day: several new agents with distinct specialties arrived, so you can pick the right one to take a task rather than dumping everything on one generalist. The tool window's top bar gained an agent picker to assign which agent works inside a given workbench and open its details in one click to see what it's good at. The backend also added unified create/read/update/delete for agents with role support, making "managing your AI team" itself orderly. Getting the right agent on the right job is key to collaboration efficiency — handing an art need to an art-specialized agent is far more reliable than to a jack-of-all-trades. This day made "picking the person" both convenient and smooth.

让文档别骗人:文档与代码自动对账Don't let docs lie: automatic doc-vs-code reconciliation

这天还立了一道很特别的闸门:自动检查"设计文档"和"实际代码"是否还对得上。任何长期演进的项目都有一个通病——文档写的是当初的设想,代码却一直在变,时间一长两者就悄悄脱节,文档反而开始误导人。这道对账闸门会在代码里那些被文档引用的关键位置发生变化时报警,逼着你要么更新代码、要么更新文档,不许它们偷偷分家。它解决的是"文档可信度"这个最容易被忽视、却长期侵蚀团队效率的问题。对一个把"AI 也要靠文档来理解系统"当回事的平台来说,保证文档不骗人,本身就是一项核心基础设施——因为骗了人的文档,会同时把人类和 AI 一起带偏。This day also raised a special gate: automatically checking whether the "design docs" and the "actual code" still line up. Every long-evolving project has a common ailment — docs describe the original intent while code keeps changing, and over time the two quietly diverge until the docs start misleading. This reconciliation gate alarms when key code locations referenced by docs change, forcing you to update either the code or the doc, not letting them secretly part ways. It addresses "doc trustworthiness," the most easily overlooked yet long-term efficiency-eroding problem. For a platform that takes "AI also relies on docs to understand the system" seriously, keeping docs honest is itself core infrastructure — because lying docs mislead humans and AI alike.

这一天意味着什么What this day means

这一天的重量,几乎全压在那次运行时切换上:把跑你游戏的引擎,从"租来的"换成"自己的"。它不是一个能立刻让画面变漂亮的功能,而是一个关于"未来主动权在谁手里"的根本决定——从此画质、性能、为 AI 优化的方向,都掌握在自己手中。围绕这次切换,材质能自定义了、坏数据进不来了、团队更好挑人了、文档不再骗人了,每一件都在让这台"自己的引擎"更可控、更可信。一个平台敢在能用之后还把最核心的底层换成自研,图的不是一时的好看,而是长久的自主——这正是这一天最该被记住的判断。The weight of this day rests almost entirely on that runtime switch: changing the engine that runs your game from "rented" to "our own." It's not a feature that instantly makes the image prettier, but a fundamental decision about "who holds the initiative for the future" — from now, image quality, performance and the direction of AI optimization are all in our own hands. Around this switch, materials became customizable, bad data can't get in, the team is easier to staff, and docs no longer lie — each making this "own engine" more controllable and trustworthy. A platform daring, after it already works, to replace its most core foundation with an in-house one isn't after momentary good looks but lasting autonomy — and that's the judgment this day most deserves to be remembered for.
