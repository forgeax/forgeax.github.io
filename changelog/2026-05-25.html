骨骼动画 + 场景工作台与观测台Skeletal animation + scene & observatory workbenches

这天角色第一次真正"动"了起来:引擎补上骨骼蒙皮动画。工具家族也扩到三件——场景工作台(还带一个工程多游戏)、观测台、叙事工具补上真本事;聊天界面更清爽、凭据更安全,引擎也瘦了样板代码、能在浏览器里干净运行。This day characters genuinely "moved" for the first time: the engine added skinned skeletal animation. The tool family grew too — a scene workbench (with multi-game per project), an observatory, and narrative tools with real teeth; chat got cleaner, credentials safer, and the engine slimmed boilerplate and ran cleanly in the browser.

从"静态物体"到"活的角色"From "static objects" to "living characters"

在这天之前,引擎能渲染被光照亮、贴着图、投着影的物体,但它们都是"静"的——再精致也只是摆件。这天补上的骨骼动画,是让这些物体"活过来"的关键一环;而工具侧又一口气添了场景、观测、叙事几件能力。把"让角色动起来"和"把做游戏要用的工具补齐"放在同一天,正是这个平台一贯的节奏:引擎管"做出来的东西够不够生动",工具管"做这件事顺不顺手",两头一起往前。下面分别看这几件事。Before this day, the engine could render objects that were lit, textured and shadowed, but they were all "static" — however refined, just ornaments. The skeletal animation added this day is the key piece that brings these objects "to life"; and on the tool side, several capabilities — scene, observatory, narrative — arrived at once. Putting "make characters move" and "fill in the tools for making games" on the same day is this platform's consistent rhythm: the engine governs "is what you make vivid enough," the tools govern "is making it smooth," advancing both ends together. Below, each in turn.

引擎:角色骨骼蒙皮动画Engine: skinned skeletal animation

引擎这天补上了游戏里最关键的一块——骨骼蒙皮动画。它的原理是:给角色模型搭一副"骨架",再把表面的网格"蒙"在骨架上;当骨架按动画数据摆出姿势时,网格会跟着自然地拉伸、弯折,于是角色就走、跑、挥手起来,而不是僵在原地。这是从"渲染一个静态物体"跨进"渲染一个活的角色"的分水岭——一个不会动的角色再好看也只是雕像,而能动的角色才撑得起角色扮演、动作、冒险这些真正的游戏类型。把这块基础能力做对,意味着引擎从"能展示场景"开始具备"能承载有生命的主角"的资格,这是后面所有有人物、有战斗的游戏的前提。The engine added one of the most essential pieces for games this day — skinned skeletal animation. How it works: build a "skeleton" for a character model, then "skin" the surface mesh onto it; when the skeleton poses according to animation data, the mesh stretches and bends along with it naturally, so the character walks, runs and waves rather than standing frozen. This is the watershed from "rendering a static object" to "rendering a living character" — a motionless character, however good-looking, is just a statue, while a moving character can carry real genres like role-playing, action and adventure. Getting this foundational capability right means the engine, from "can display scenes," becomes qualified to "carry a living protagonist" — the precondition for every later game with characters and combat.

新增"场景"工作台 + 一个工程多个游戏A new scene workbench + multiple games in one project

工具家族再添一位实打实的成员:场景工作台,作为第一个"真正能干活"的此类插件落地,用来搭建和组织一个游戏里的场景。配套平台开始支持"一个工程里管理多个游戏",并做了按游戏隔离的数据存放——每个游戏的内容各自归各自,互不污染。这意味着你可以在同一个工程里做一个系列、拆出多个关卡分支、或者并行试几个不同的想法,而不必每次都另起炉灶。对一个想长期经营自己作品的创作者来说,"多游戏共处一个工程、互不干扰"是把零散尝试沉淀成体系的基础——挑哪个游戏来跑、来改,从此是顺手的一步,而不是一次搬家。The tool family gained a solid member: a scene workbench, landing as the first plugin of its kind that "actually does work," for building and organizing a game's scenes. The platform began supporting "managing multiple games in one project," with per-game isolated data storage — each game's content belongs to itself, with no cross-contamination. This means you can make a series in one project, branch out multiple levels, or try several different ideas in parallel without starting over each time. For a creator who wants to cultivate their own works long-term, "multiple games coexisting in one project without interference" is the basis for settling scattered attempts into a system — picking which game to run or edit is now a smooth step rather than a move.

新增"观测台":实时看 agent 在做什么A new observatory: watch what agents are doing, live

新增了一个"观测台"工作台,把 agent 的活动实时摊开:谁在跑、在调用哪个工具、产出了什么事件,一目了然。它由专门的后端接口和一条事件桥支撑,把后台正在发生的事源源不断地送到这个面板上。它解决的是"放手让一群 agent 自己干活"时最矛盾的一对需求——既想撒手不管、又怕完全失控。观测台给了你一个折中:平时让它们自己跑,你扫一眼面板就知道全局态势;一旦哪里不对劲,你能立刻看清是谁、在哪一步出了问题,及时介入。对多 agent 协作越来越重的平台,这种"看得见的掌控感"是敢于把更多事交给 AI 的心理底气。A new "observatory" workbench lays out agent activity in real time: who's running, which tool they're calling, what events they've produced — all at a glance. It's backed by a dedicated backend interface and an event bridge that streams what's happening in the background onto this panel. It addresses the most conflicting pair of needs when "letting a team of agents work on their own" — wanting to be hands-off yet fearing total loss of control. The observatory gives you a middle ground: let them run by themselves normally, and a glance at the panel tells you the overall state; the moment something's off, you can immediately see who and at which step the problem is and step in. For a platform leaning ever more on multi-agent collaboration, this "visible sense of control" is the psychological footing to dare hand more to the AI.

叙事工具补上真本事 + 叙事 agent 激活Narrative tools get teeth + the narrative agent activates

叙事这条线这天从"有个空壳"走到了"真能用"。后端补上了一组面向大模型的叙事工具定义——也就是给 agent 配上了几把能真正编排剧情与文本的"趁手家伙",而不只是一个没法动手的界面;与此同时,负责叙事的那个专门 agent 也从占位状态正式激活,可以接活了。两件事合起来,意味着"写故事"这件事在平台里第一次有了能实际驱动它的角色和工具。做游戏从来不只是堆玩法,剧情、对白、节奏同样是作品的灵魂;把叙事工具和叙事 agent 一起补齐,是平台朝"一个人就能做出一个有血有肉的完整游戏"这个目标迈出的实在一步。The narrative line moved this day from "an empty shell" to "actually usable." The backend added a set of large-model-facing narrative tool definitions — equipping the agent with handy implements that genuinely arrange story and text, not just an interface that can't act; meanwhile, the dedicated agent responsible for narrative was formally activated from placeholder status and can take work. Together, "writing the story" has, for the first time, both a role and tools that can actually drive it in the platform. Making a game was never only piling up gameplay; plot, dialogue and pacing are equally a work's soul. Filling in the narrative tools and the narrative agent together is a concrete step toward "one person can make a complete, fully-fleshed game."

聊天更清爽 + 凭据更安全A cleaner chat + safer credentials

这天界面与安全上也各收一笔。聊天界面做了一轮精简:去掉多余的发光与模糊效果、把边框统一,装了很多 agent 时列表会自动分页,悬停时高度也更稳,长时间盯着看更省眼、更专注于内容本身。预览窗也放开了所需的图形与全屏等权限,让里面的游戏跑得更完整。安全方面,后端开始把模型密钥从一个独立保险库迁向"只走环境变量"的方式管理,并加了一份文件活动账本——既简化了凭据的管理路径,也让"什么时候动了哪个文件"有迹可循。界面更清爽是为了少打扰,凭据更规整是为了更可信,两者都在让平台朝"能放心长期使用"再靠近一点。Interface and security each got a touch this day. The chat interface had a pass of simplification: redundant glow and blur removed, borders unified, the list paginates when many agents are installed, and hover heights are steadier — easier on the eyes over a long session and more focused on content itself. The preview window also opened the graphics and fullscreen permissions it needs, so games inside run more completely. On security, the backend began migrating model keys from a separate vault toward "environment-variable only" management, and added a file-activity ledger — both simplifying the credential path and making "when which file was touched" traceable. A cleaner interface is to disturb less, tidier credentials to be more trustworthy — both bringing the platform a step closer to "safe to use long-term."

引擎:样板代码瘦身 + 浏览器里干净运行Engine: slimmer boilerplate + clean in-browser runs

引擎这天在"好用、好跑"上各做了一处底层功夫。其一是样板代码瘦身:给常用的数据结构补上合理的默认值与便捷的创建函数,并统一了一些常用工具的引出方式——结果是写游戏内容时要敲的样板代码更少,意图更直接。其二是"浏览器安全子导出":把那些只能在本机环境(而非浏览器)里用的依赖,从引擎的主入口里剥离出去,确保引擎在浏览器里加载时不会误拉进跑不动的东西、干净利落地运行。前者降低了"写"的负担,后者保障了"跑"的稳定;它们都不是亮眼功能,却实实在在地让这台自研引擎对使用它的人(以及生成代码的 AI)更友好。The engine did low-level work on both "easy to use" and "easy to run" this day. One is boilerplate slimming: giving common data structures sensible defaults and convenient factory functions, and unifying how some common utilities are exported — so writing game content takes less boilerplate and expresses intent more directly. The other is "browser-safe sub-exports": stripping dependencies usable only in the local environment (not the browser) out of the engine's main entry, ensuring the engine, when loaded in the browser, doesn't accidentally pull in things that can't run, and runs cleanly. The former lowers the burden of "writing," the latter safeguards the stability of "running"; neither is a flashy feature, but both genuinely make this in-house engine friendlier to the people using it (and the AI generating code).
