角色终于有影子了:一整天的死磕The character finally casts a shadow: a whole day of grinding

前一天出炉的暗黑风格 ARPG 样例有个一眼就能看出的破绽:女巫主角脚下没有影子,整个人像一张贴图浮在半空,毫无"踩在地上"的实感。这天就专门跟这个影子死磕了一整天,过程非常曲折:先试着给带骨骼的角色专门写投影用的着色器、再用一个隐形的代理几何体来代替角色投影、又退而求其次做了一个贴在脚下的椭圆形"假影子"作为兜底;同时反复调整投射阴影所需的各个参数——给场景材质补上投影通道、把方向光调斜让影子拉长、调级联阴影的精度、压低天光强度让方向光的对比显出来、调月光的强度和方位。一路试下来,最后才定位到真正的症结:阴影的级联层数从 4 改成 1 才能稳定投出来——这其实牵出了引擎里一个更深的 bug(在试玩模式下,4 层级联的方向光阴影路径有问题),并被整理成一份详细的报告留给引擎团队。配套还把夜晚氛围调到位:昏暗的月光加上营地周围的几支火炬,营造出暗黑风格里"夜里围着篝火清怪"的气氛。这一整天的较真,换来的是一个看似微小、实则至关重要的效果:角色终于"落了地"。The dark-fantasy ARPG sample from the day before had an at-a-glance flaw: the witch hero cast no shadow underfoot, the whole figure like a texture floating in midair, with no sense of "standing on the ground." This day grinded against that shadow for a whole day, a winding process: first trying to write a dedicated shadow-casting shader for the rigged character, then using an invisible proxy geometry to cast the shadow in its place, then falling back to an oval "fake shadow" pinned under the feet as a backstop; while repeatedly tuning the parameters shadow casting needs — adding a casting pass to scene materials, tilting the directional light to lengthen shadows, adjusting cascaded-shadow precision, lowering sky-light intensity so the directional light's contrast shows, tuning the moonlight's intensity and angle. After all that trial, the real crux was finally pinned down: the shadow's cascade count had to change from 4 to 1 to cast reliably — which actually surfaced a deeper engine bug (the 4-cascade directional-shadow path misbehaves in play mode), organized into a detailed report for the engine team. Night atmosphere was tuned to match: dim moonlight plus a few torches around the camp, evoking the dark-fantasy mood of "clearing monsters around a fire at night." A whole day's persistence bought a seemingly tiny yet crucial effect: the character finally "landed."

编辑器能完全独立运行The editor runs fully standalone

编辑器的独立入口这天被整体重写成了一套真正自包含的外壳。此前虽然一直在朝"独立"努力,但那个独立访问入口其实还和主聊天界面藕断丝连——必须挂在主界面里才能跑起来,算不上真正独立。这天把它彻底拆开重写:自带一套可停靠的多面板布局,编辑器需要的九个面板都自己渲染、自己组织,完全不依赖主界面那一套。还加了一个一键引导脚本,在一台新机器上能自动把运行所需的各种构件准备好——包括底层渲染所需的二进制件,做到开箱就能编。这件事的意义,是让编辑器从"主 Studio 的一个内嵌部分"彻底变成了"一个能单独打开、单独使用的完整应用"。它既是模块化设计的一次彻底兑现,也为将来把编辑器嵌进其他产品、或者作为独立工具单独分发,铺平了道路。The editor's standalone entry was rewritten this day into a truly self-contained shell. It had been working toward "standalone" for a while, but that standalone entry was still entangled with the main chat interface — it had to run inside the main interface, not truly independent. This day it was fully separated and rewritten: it brings its own dockable multi-panel layout, renders and organizes all nine panels the editor needs itself, depending not at all on the main interface's setup. A one-click bootstrap script was added that, on a fresh machine, automatically prepares the various build artifacts needed to run — including the binary pieces low-level rendering needs — so it's ready to edit out of the box. The significance is turning the editor from "an embedded part of the main Studio" fully into "a complete application you can open and use on its own." It's both a thorough fulfillment of modular design and a paving of the way to later embed the editor in other products or distribute it as a standalone tool.

整个代码库第一次有了 CI 闸门The whole codebase gets its first CI gate

这天给整个代码库装上了第一道自动化的质量闸门。所谓 CI(持续集成)闸门,就是每当有人提交一处改动,系统会自动跑一遍检查——这次上线的基础检查包含三关:类型检查(确认代码各部分的接口对得上)、构建(确认代码真能编译出来)、以及冒烟测试(跑一遍确认基本功能没崩)。三关全过,改动才被允许并入主干。这道闸门一立,立刻照出了之前在几个子项目里"默默漂移"了一阵的二十多处类型不一致问题——它们平时不报错,但其实已经埋下了隐患;当天就被分批清理干净。这件事的深远意义在于:从今天起,任何新的改动都不能再悄悄把这类问题带进主干了——机器会在门口自动拦下。对一个由大量 AI agent 高频并行改动的代码库来说,这种自动化的"守门人"尤其关键:人不可能盯住每一处改动,但闸门可以,而且它从不疲劳、从不徇私。把质量的底线交给自动化来守,正是一个项目从"快速生长"走向"可持续生长"的标志。This day fitted the whole codebase with its first automated quality gate. A CI (continuous integration) gate means that whenever someone submits a change, the system automatically runs a check — this initial check has three parts: type checking (confirming the interfaces between code parts line up), build (confirming the code actually compiles), and smoke testing (a run confirming basic functionality didn't break). Only if all three pass is the change allowed into the mainline. The gate, once up, immediately surfaced over twenty type inconsistencies that had been "quietly drifting" in a few sub-projects — they didn't error in normal use but had already planted hazards; they were cleaned up in batches that same day. The far-reaching significance: from this day, no new change can quietly carry such problems into the mainline — the machine automatically stops them at the door. For a codebase changed at high frequency in parallel by many AI agents, this automated "gatekeeper" is especially crucial: a person can't watch every change, but a gate can, and it never tires and never plays favorites. Handing the floor of quality to automation to guard is exactly the mark of a project moving from "fast growth" to "sustainable growth."

接专业模型格式 + 角色动作平滑过渡Professional model formats + smooth animation blending

引擎这天在角色与资产上补了两块实打实的能力。一是正式接入了专业建模工具直出的模型格式:这种格式能完整携带动画、骨骼乃至物理参数,而此前要把它用进来必须先转换成另一种网页通用格式,转换过程难免丢细节;现在引擎能直接读它,从专业工具流出的资产可以原汁原味地搬进游戏。二是让角色动作之间能平滑交叉过渡:以前从"走"切到"跑"、从"待机"切到"攻击",往往是生硬的瞬间切换,看着很跳;现在多段动作之间能按比例混合、平滑衔接,角色的动作连贯自然了许多——这对动作类游戏的手感至关重要。此外还加了一个即时调试绘制工具,能在画面上直接画出辅助线、包围盒之类的标记,排查问题时所见即所得,比对着数字猜直观得多。这几样合起来,让"做一个会动、且动得自然的角色"这件事的工具链又完整了一截。The engine added two solid capabilities on characters and assets this day. One: it formally ingests the model formats that professional modeling tools output directly. This format fully carries animation, skeleton and even physics parameters, whereas using it before required converting to another web-common format first, inevitably losing detail; now the engine reads it directly, so assets flowing from professional tools come into the game faithfully. Two: it makes character actions cross-fade smoothly: where switching from "walk" to "run" or "idle" to "attack" used to be a hard instant cut that looked jumpy, now several clips can blend proportionally and transition smoothly, making a character's motion far more coherent and natural — crucial to the feel of action games. An immediate debug-draw tool was also added, drawing helper lines and bounding boxes right on the picture, what-you-see-is-what-you-get for diagnosis, far more intuitive than guessing from numbers. Together these complete another stretch of the toolchain for "making a character that moves, and moves naturally."

引擎落地完整的 2D 瓦片地图系统A complete 2D tile-map system lands in the engine

引擎这天还系统性地把 2D 瓦片地图这一整类能力补齐落地了。瓦片地图是 2D 游戏最经典的搭建方式——把世界铺成一格一格的方块网格,每格放一张小图,拼出整张关卡。这天落地的不只是"能显示",而是一整套完整的机制:瓦片集资产、瓦片图层、按区块高效提取渲染、瓦片的水平/垂直翻转与锚点处理、精灵的正确剔除与排序,以及一连串严格的数据校验在出错时快速报错。它还配了可运行的演示和自动化测试一路兜底。这件事把平台的 2D 能力从前些天的初步基础,推进到了"能认真做一个 2D 游戏"的程度。很多创作者心里的第一个游戏恰恰是 2D 的——一个横版、一个俯视角、一个像素风的世界;把 2D 这条路认真铺扎实,等于向这一大批创作者敞开了一扇门。3D 与 2D 两条腿都硬,平台能承接的游戏类型才足够宽。The engine also systematically completed and landed the whole 2D tile-map category this day. Tile maps are the most classic way to build 2D games — paving the world into a grid of square cells, each holding a small picture, assembled into a whole level. What landed this day isn't just "can display" but a complete set of mechanisms: tileset assets, tile layers, efficient chunk-based extraction and rendering, horizontal/vertical flipping and anchor handling for tiles, correct sprite culling and sorting, and a string of strict data validations that fail fast on error. It came with runnable demos and automated tests backing it the whole way. This pushes the platform's 2D capability from the preliminary basics of recent days to the level of "you can seriously make a 2D game." The first game in many creators' minds is precisely a 2D one — a side-scroller, a top-down view, a pixel-art world; paving the 2D road solidly throws open a door to that large body of creators. With both 3D and 2D legs strong, the range of game types the platform can carry is wide enough.

The process of grinding a whole day over one shadow best represents this team's attitude: a character without a shadow may seem an inconsequential flaw to many, but it directly decides whether the image is believable — and fully solving it required not fudging past it but trying layer by layer, ruling out layer by layer, until finding the true crux hidden deep in the engine, and honestly recording it. Meanwhile, the editor's full independence, the establishment of the first CI gate, and the hardening of cross-platform deployment provide sustainable soil for this kind of diligence — when the floor of quality is guarded by automation and modules can evolve independently, the team is freed to polish every shadow. Doing the immediate experience to the utmost while setting the long-term foundation firm — this day achieved both.
