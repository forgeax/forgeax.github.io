编辑器模式收官Editor mode, complete

前一天刚跑通的编辑器,这天一口气把所有可实施的功能补齐收官:面板能拖、能分组、能弹成独立窗口、能一键重置;移动 / 旋转 / 缩放三种 gizmo 全到位并配上快捷键;属性面板跟着你拖动实时刷新;一键飞到选中对象、历史与能力面板齐备。引擎这边还让网格的拓扑类型能直接在视口里看出来,内容工具也收了一批界面统一。The editor that had just run the day before reached completion this day, with every implementable feature filled in: panels drag, group, pop out into separate windows and reset with one click; the move/rotate/scale gizmos are all in place with shortcuts; the property inspector refreshes live as you drag; one-key fly-to-selection plus history and capabilities panels are ready. The engine also made a mesh's topology type directly visible in the viewport, and the content tools got a batch of interface unification.

从"能用"到"像个真编辑器"From "usable" to "feels like a real editor"

前一天,编辑器第一次能选对象、拖 gizmo、存盘,迈出了"动手"的第一步;但那时它还更像一个能用的雏形,而不是一个让人愿意整天待在里面干活的成熟工具。这天做的,就是把"能用"补成"好用":一个专业编辑器之所以让人顺手,靠的是无数件看似细碎、实则缺一不可的事——面板能不能按你的习惯摆、变换工具全不全、改一下数值能不能立刻看到反馈、找一个物体快不快、做错了能不能回退。这天把这些事一次性补齐,等于给编辑器装上了"专业工具该有的全部基本功"。这不是堆功能,而是把一个工具打磨到"上手没有别扭感"的程度——而正是这种没有别扭感,决定了一个创作者愿不愿意长期用它。The day before, the editor could select objects, drag gizmos and save for the first time, taking the first "hands-on" step; but at that point it was more a usable prototype than a mature tool you'd happily spend all day working in. This day's work fills "usable" out into "pleasant": what makes a professional editor feel natural is countless seemingly-trivial yet indispensable things — whether panels arrange to your habits, whether the transform tools are complete, whether a value change shows feedback at once, how fast you can find an object, whether a mistake can be undone. Filling all of these in at once equips the editor with "the full basics a professional tool should have." This isn't piling on features but polishing a tool to the point of "no awkwardness on first use" — and it's exactly that lack of awkwardness that decides whether a creator will use it for the long haul.

可停靠面板:界面随你摆,乱了一键复位Dockable panels: arrange the interface your way, reset in one click

这天给编辑器接入了一套可停靠的面板系统,并配了一个统一的面板管理器来掌管它。具体能做什么:每一块面板——场景树、属性检视、材质、时间轴、材质图等等——都可以用鼠标拖到界面的任意区域重新摆放,可以把几个面板叠成一组标签页(拖到一起就成组、点标签就切换),可以把某个面板弹成一个独立的浮动窗口单独看,布局被你折腾乱了还能一键重置回默认。为什么这件事重要?因为不同的人、不同的活,需要的界面布局完全不同:调材质时想把材质面板放大,做动画时想让时间轴占满底部。一套写死的固定布局永远只能照顾一种人;而可停靠面板把"界面长什么样"的决定权交还给了用户。同一天还首发了材质、时间轴、材质图三个新面板,加上已有的检视器和场景树一起接进这套系统——编辑器的"骨架"自此成型。This day wired a dockable panel system into the editor, with a unified panel manager to govern it. What it can do: every panel — scene tree, property inspector, material, timeline, material graph and so on — can be dragged with the mouse to any region to rearrange, can stack several panels into one tab group (drag together to group, click a tab to switch), can pop a panel out into its own floating window to view alone, and if you mess the layout up you can reset to default in one click. Why does this matter? Because different people and different tasks need entirely different layouts: tuning materials you want the material panel enlarged, animating you want the timeline filling the bottom. One hardcoded fixed layout can only ever serve one kind of person; dockable panels hand the decision of "what the interface looks like" back to the user. The same day debuted three new panels — material, timeline and material graph — joined with the existing inspector and scene tree into this system, and the editor's "skeleton" took shape from here.

三种变换工具全到位:移动、旋转、缩放The full transform toolset: move, rotate, scale

前一天能拖的只有"移动"一种 gizmo,这天把"旋转"和"缩放"也补齐了,并配上了一组与业界通行约定一致的快捷键来快速切换这三种模式——这样上手过任何专业三维工具的人,几乎不用学就知道怎么用。三种变换是摆放任何东西的最基本动作:把一个箱子挪到墙边(移动)、让它斜着放(旋转)、把它放大一倍当作障碍(缩放),缺一不可。配套还让引擎正确渲染出物体的旋转,保证你在视口里看到的姿态和数据完全一致。此外还加了"一键飞到选中对象"——按一个键或双击,相机立刻平滑地飞过去把选中的东西框在画面中央,在一个大场景里再不用费劲手动找视角。把这套最基础的操作做齐、做到符合直觉,是编辑器从"演示品"变成"生产工具"的分界线。The day before, the only gizmo you could drag was "move"; this day "rotate" and "scale" were filled in, with a set of shortcuts matching industry-standard convention to switch quickly between the three modes — so anyone who has used any professional 3D tool knows how to use it almost without learning. The three transforms are the most basic actions for placing anything: move a crate to the wall (move), set it at an angle (rotate), double its size as an obstacle (scale) — none dispensable. The engine was also made to render an object's rotation correctly, ensuring the pose you see in the viewport exactly matches the data. On top of that, "one-key fly-to-selection" was added — press a key or double-click and the camera smoothly flies over to frame the selected thing in the center, so in a big scene you no longer struggle to find the viewpoint by hand. Completing this most basic toolset and making it intuitive is the dividing line where an editor turns from a "demo" into a "production tool."

改一下立刻看到:检视器跟着拖动实时刷新See it at once: the inspector refreshes live as you drag

这天还接通了编辑里最关键的一条反馈回路:属性检视面板会跟着你在视口里的拖动实时更新。也就是说,当你用 gizmo 拖动一个物体时,右侧检视面板里那些表示位置、旋转、缩放的数字会同步跳动,你能一边拖、一边精确地看到当前数值;反过来,这条回路也保证了你在面板里输入一个精确数值时,视口里的物体立刻随之改变。这种"双向、即时"的一致性,是所有专业编辑器的灵魂——它消除了"我刚才那一拖到底改成了多少"这种不确定感,让粗调(拖 gizmo)和精调(填数值)能无缝衔接。同一天还上线了历史面板和能力面板:历史面板让你能看清并回退做过的每一步操作,能力面板则把当前可用的操作集中呈现。有了实时反馈和可回退的历史,编辑这件事才真正变得"放心大胆"——错了能撤,改了能看见。This day also wired up the most crucial feedback loop in editing: the property inspector refreshes live with your dragging in the viewport. That is, as you drag an object with a gizmo, the numbers for position, rotation and scale in the right-hand inspector jump in sync, so you can drag while seeing the exact current values; conversely, this loop also guarantees that when you type a precise value in the panel, the viewport object changes with it at once. This "bidirectional, instant" consistency is the soul of every professional editor — it eliminates the uncertainty of "just how much did that drag change," letting coarse adjustment (dragging gizmos) and fine adjustment (typing values) seamlessly connect. The same day brought a history panel and a capabilities panel: the history panel lets you see and undo each operation you performed, and the capabilities panel surfaces the currently available operations in one place. With live feedback and an undoable history, editing finally becomes "confident and bold" — mistakes can be undone, changes can be seen.

引擎:一眼看出网格的拓扑类型Engine: see a mesh's topology type at a glance

引擎这天补的一项很实用:把网格的"拓扑类型"做成了能直接在视口里画出来的调试视图,五种基本的几何拓扑(点、线段、连续折线、三角面、连续三角带)都能被可视地标注出来。这是什么意思?一个三维模型说到底是由一堆点和它们之间的连接关系拼成的,而"拓扑"就是描述"这些点是怎么连起来的"——是孤立的点、是一根根线段、还是拼成的三角面。当一个模型显示不正常时,问题常常就出在拓扑类型不对,但以前你只能对着代码或数据瞎猜。现在能在视口里直接把它画出来看,定位坏掉的几何就直观多了。这项能力主要服务于调试和资产排查,它和编辑器是一条线上的——编辑器让你能摆放和调整,而这种调试视图让你在出问题时能看清底层到底怎么了。把"看不见的内部状态"变得可见,是工具走向成熟的一个标志。A very practical engine addition this day: a mesh's "topology type" was made into a debug view that can be drawn directly in the viewport, with all five basic geometry topologies (points, line segments, continuous polylines, triangle faces, continuous triangle strips) visibly annotated. What does this mean? A 3D model is, at bottom, a pile of points and the connections between them, and "topology" describes "how those points are connected" — isolated points, individual line segments, or assembled triangle faces. When a model displays wrong, the problem is often a wrong topology type, but you used to only guess at the code or data. Now you can draw it directly in the viewport and look, making it far more intuitive to locate broken geometry. This capability mainly serves debugging and asset inspection, and it's on the same line as the editor — the editor lets you place and adjust, while this debug view lets you see what's really happening underneath when something goes wrong. Making "invisible internal state" visible is a hallmark of a tool maturing.

游戏与内容工具:对齐编辑器这条线Games and content tools: aligning to the editor line

编辑器收官的同时,周边也在往同一个方向靠拢。游戏这边,把示例射击游戏的"可玩体验"写成了正经文档,并给另一个射击示例做了"场景文件种子化"——也就是把它的场景预先存成那份以文档为准的场景文件,让它和编辑器走的是同一套磁盘场景机制;还顺手清理掉了之前用编辑器做测试时留下的痕迹,保证种子场景是干净的。内容创作工具这边,梳理了技能工作台的侧边栏工作流,并把各个插件的侧边栏标题样式一次性对齐统一,让它们看起来是同一个产品的不同模块;叙事工具也继续推进,加上了关键节点的校验和角色时间线。这些改动单看都不大,但它们共同确保了一件事:当编辑器这条主线收官时,它周围的游戏示例和创作工具不是各走各的,而是被一起拉到了同一套机制、同一套视觉语言上。As the editor reached completion, its surroundings converged in the same direction. On the games side, the sample shooter's "playable experience" was written into a proper document, and another shooter sample got "scene-file seeding" — pre-saving its scene as that document-driven scene file so it runs the same disk-scene mechanism as the editor; the artifacts left from earlier editor-testing were also cleaned up to keep the seed scene clean. On the content-tools side, the skill workbench's sidebar workflow was streamlined, and the sidebar header styles across plugins were unified at once so they look like different modules of one product; the narrative tool also kept advancing, adding validation of key nodes and a character timeline. Individually small, these together ensure one thing: when the editor's main line reached completion, the game samples and creation tools around it weren't each going their own way but were pulled together onto the same mechanism and the same visual language.

The period drawn this day means Studio formally has a feature-complete, awkwardness-free visual editor — no longer an auxiliary demo beside the AI but a second creative main line on equal footing with conversation. What's worth savoring is the rhythm of these three days: not leaving a pile of half-finished pieces to rush a schedule, but honestly filling in a professional tool's basics one by one until "every implementable feature landed." Whether a tool is ultimately pleasant to use is never decided by how many dazzling big features it has, but by whether these unglamorous basics were earnestly completed. With the editor line wrapped, human and AI finally stand before the same canvas: the AI paints with code and conversation, you revise with mouse and gizmo, two brushes on one image.
