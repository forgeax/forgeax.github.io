整个界面能切中英文 + 开发者工具齐活Full bilingual UI + complete devtools panels

这天做了一次彻底的国际化:整个工作室界面实现中英双语、可一键切换、跨窗口实时同步,编辑器也同步全量双语化;开发者工具的控制台 / 网络 / 日志面板从空壳补成真功能;界面层叠、表单对比度、无障碍标题等老毛病一并理顺;引擎困扰多日的方向光阴影终于修对,游戏逻辑获得声明式系统编排,引擎资源也用上了规范的生命周期与故障隔离。This day did a thorough internationalization: the whole studio interface becomes bilingual, switchable in one click, synced live across windows, with the editor fully bilingual too; the Console / Network / log devtools panels went from empty shells to real features; UI stacking, form contrast and accessibility titles were straightened out; the engine's multi-day directional-shadow bug was finally fixed; game logic gained declarative system scheduling; and engine resources got disciplined lifecycle and fault isolation.

面向世界,也面向调试Facing the world, and facing debugging

这一天有两个朝向。一个朝外:把整个界面彻底双语化,让它不再只服务于中文用户,而是能面向全世界——这是一个产品想走向更广阔人群的必经一步。另一个朝内:把开发者工具补齐,让创作者在调试自己游戏时,能清楚看到控制台输出、网络请求、运行日志——这是让人能"看清自己在做什么"的底气。一外一内,看似不相干,内核却一致:都是在消除"看不见 / 看不懂"的障碍。语言不通,界面就是一堵墙;调试无门,问题就是一团雾。这天同时拆掉了这两类障碍。与此同时,引擎也把困扰多日的阴影问题从根上修对、给游戏逻辑添了更有条理的编排方式、并为自己的资源管理立了更严的规矩。对外更可达,对内更透明,底层更扎实——这是这一天的三个侧面。This day faced two directions. One outward: fully bilingualizing the whole interface so it no longer serves only Chinese users but can face the whole world — a necessary step for a product reaching a broader audience. The other inward: completing the devtools so creators debugging their own games can clearly see console output, network requests and runtime logs — the confidence of being able to "see what you're doing." Outward and inward seem unrelated, but the core is the same: both remove the barrier of "can't see / can't understand." A language barrier makes the interface a wall; no way to debug makes a problem a fog. This day tore down both kinds of barrier at once. Meanwhile, the engine fixed the multi-day shadow problem at the root, added a more orderly way to schedule game logic, and set stricter rules for its own resource management. More reachable outward, more transparent inward, more solid underneath — these are the day's three facets.

整个界面能一键切中英文Switch the whole interface between English and Chinese in one click

这天做了一次彻底的国际化,而且做法很讲究。第一步是先搭起一套轻量的多语言内核:以英文为基准源(所有文案以英文为权威)、中文作为覆盖层(在英文之上替换成中文),两者可随时切换。第二步是把整个界面逐文件、分批迁移进这套体系——顶栏、仪表盘、聊天面板、设置抽屉、侧边栏、各种切换器,几十个面板和组件一个不落。为什么要"逐文件"而不是一次性全改?因为界面里硬编码的文案散落在成百上千处,只有一处处过、才能不漏。迁完之后,界面默认英文、自动跟随系统语言,还做了一个很贴心的细节:跨窗口实时同步——你在一个窗口里把语言切成中文,另一个开着的窗口会立刻跟着变,不必各切一遍。编辑器那边也同步完成了全量双语化并通过了运行验证。对一个想被全世界创作者使用的平台来说,语言这堵墙是必须先拆掉的——这一天,把它彻底拆掉了。This day did a thorough internationalization, and did it carefully. Step one was a lightweight multilingual core: English as the baseline source (all copy authoritative in English), Chinese as an overlay (replacing English where present), switchable anytime. Step two migrated the whole interface into this system file by file, in batches — top bar, dashboard, chat panel, settings drawer, sidebar, the various switchers, dozens of panels and components, none left out. Why "file by file" rather than all at once? Because hardcoded copy is scattered across hundreds or thousands of spots in the interface, and only going through each one misses nothing. After migration, the interface defaults to English, follows the system language automatically, and got a thoughtful detail: live cross-window sync — switch the language to Chinese in one window and another open window follows immediately, no switching each one. The editor completed full bilingualization too and passed runtime verification. For a platform that wants to be used by creators worldwide, the language wall must be torn down first — and this day tore it down completely.

开发者工具面板齐活:控制台 + 网络 + 日志落盘Devtools panels completed: Console + Network + on-disk logs

开发者工具区此前有几个面板要么空着、要么是点不动的占位,这天一次性补成了真功能。控制台面板接通了游戏与编辑器的完整输出流——你的游戏里打印的每一条日志、报的每一个错,都会实时汇到这里。网络面板从一个死占位变成了真东西,能抓到你正在试玩的游戏里发出的各种网络请求:普通请求、异步请求、长连接都能看到。更进一步,控制台、网络、信息这三条流不只是显示在面板里,还会被镜像保存到本地的日志文件,方便事后回溯——出问题时不必非得在现场抓到,事后翻日志也能复盘。同时删掉了一个和监控台职能重复的页签,避免两处显示同样的东西让人困惑。这件事的意义在于:调试是创作中绕不开的一环,而调试的前提是"看得见"。当一个游戏行为不对时,能在面板里直接看到完整的控制台报错和网络往来,排错就从"凭感觉猜"变成了"照着证据查"。The devtools area previously had panels that were either empty or unclickable placeholders; this day completed them into real features at once. The Console panel wired up the full output streams of the game and editor — every log your game prints and every error it throws now flows here in real time. The Network panel went from a dead placeholder to the real thing, capturing the various network requests your play-tested game makes: regular requests, async requests and long-lived connections all visible. Further, the console, network and info streams aren't just shown in a panel but mirrored to local log files for later review — you needn't catch a problem live; you can replay it from the logs afterward. A tab redundant with the monitoring view was removed to avoid the confusion of showing the same thing in two places. The significance: debugging is an unavoidable part of creation, and the prerequisite for debugging is "being able to see." When a game behaves wrong, seeing the full console errors and network traffic directly in a panel turns debugging from "guessing by feel" into "checking against evidence."

界面打磨:层叠、对比度、无障碍UI polish: stacking, contrast, accessibility

借着这次大改,界面上几处积压已久的老毛病也一并理顺了。一是层叠次序:此前一些弹窗、下拉菜单、语言选择器会错误地盖住顶栏、或者藏到对话框底下,这天把它们的层级关系重新排清楚,该在上面的稳稳在上面。二是表单控件的对比度:某些原生的输入框、按钮之前因为样式没接上,显示的是浏览器默认的黑色文字,在深色背景上几乎看不清;这天让它们都用上了可读的主题色。三是无障碍:给提示弹窗补上了规范要求的标题,消除了无障碍方面的报错,也让用辅助阅读工具的人能正确理解弹窗内容。这些改动每一个都很小,小到大多数人不会专门注意;但它们共同决定了一件事——界面是不是处处都"正常"。一个到处有小别扭的界面,会持续地、隐隐地消耗用户的耐心;把这些别扭一个个抹平,换来的是一种"用着哪儿都对劲"的踏实感。Taking the chance of this big change, several long-standing UI issues were straightened out together. One is stacking order: previously some dialogs, dropdowns and the language selector would wrongly cover the top bar or hide beneath a dialog, and this day re-ordered their layering clearly, so what should be on top stays firmly on top. Two is form-control contrast: certain native input boxes and buttons previously showed the browser's default black text because styles weren't wired up, nearly unreadable on a dark background; this day gave them readable theme colors. Three is accessibility: prompt dialogs got the titles the standard requires, eliminating accessibility errors and letting people using assistive readers understand dialog content correctly. Each of these is small, small enough that most people won't specifically notice; but together they decide one thing — whether the interface feels "normal" everywhere. An interface with little awkwardnesses everywhere continuously and subtly drains a user's patience; smoothing them one by one buys a solid sense that "everything feels right to use."

引擎方向光阴影修对 + ECS 系统声明式编排Directional shadows fixed + declarative system scheduling

引擎这天把一个困扰了好几天的问题从根上修对了:方向光的阴影。前几天做样例游戏时,曾不得不靠"把阴影的级联层数从 4 改成 1"这种临时绕法才能让影子稳定投出来——那只是症状层面的回避,真正的病根在引擎里。这天把它彻底治好:多级联阴影在某些配置下失效、以及单层时的错位,几个根因被一起收掉。上游一稳,下游所有游戏的方向光阴影就都能正常工作,不再需要那种治标不治本的绕法。同一天,游戏逻辑这层还获得了一个很有价值的能力:声明式的系统编排。一个游戏由许多"系统"(各管一摊的逻辑模块,比如移动、碰撞、AI)组成,以前它们的运行时机和顺序得手工安排;现在可以按条件、按标签、按当前状态来声明式地编排——比如"只在战斗状态下运行这套系统""这几个系统打上同一个标签一起调度"。这让复杂的游戏行为逻辑写起来更有条理、更不容易乱。底层还顺手加了故障隔离(把底层崩溃转成可恢复的错误并自动重试)和一个离线的渲染帧查看器,让排查图形问题更顺手。The engine fixed, at the root, a problem that had nagged for several days: directional-light shadows. While building sample games over the preceding days, there'd been no choice but the stopgap of "changing the shadow's cascade count from 4 to 1" to get shadows casting reliably — that only dodged the symptom, with the real disease in the engine. This day cured it fully: the root causes of cascaded shadows failing under certain configurations, and of misalignment at a single level, were cleared together. With the upstream stable, every downstream game's directional shadows work properly, no more symptom-only workaround. The same day, game logic gained a valuable capability: declarative system scheduling. A game is composed of many "systems" (logic modules each minding one area, like movement, collision, AI), whose run timing and order used to be arranged by hand; now they can be scheduled declaratively by condition, by label, by current state — "run this set of systems only in combat state," "schedule these systems together under one label." This makes complex game behavior logic more orderly to write and less prone to chaos. Underneath, fault isolation (turning a low-level crash into a recoverable error with automatic retry) and an offline render-frame viewer were added for smoother graphics debugging.

引擎给资源立规矩:用完即收、坏了不崩The engine disciplines resources: reclaim when done, don't crash when broken

引擎这天还在"资源管理"上下了不少功夫,而这恰是一个长时间运行的程序最容易出问题的地方。一方面是显卡资源和音频资源的生命周期:每一块显存、每一个声音通道,在不再被任何东西引用时,都能被准确地识别出来并及时回收,而不是悄悄堆积、越占越多——这天专门做了"释放不再被引用的资源"的机制,并用一个长时间运行的压力测试验证它确实能维持在一个稳定、有界的占用水平,而不会一路膨胀。另一方面是故障隔离:当底层出现严重错误时,引擎能把它转成一个可以被妥善处理的错误、而不是直接整个崩掉,必要时还能重试。这两件事都属于用户看不见、却直接决定"能不能长时间稳定运行"的底层功夫。一个游戏可能要连续跑上几个小时,期间不断地创建和销毁各种资源;只有把"用完就还、坏了能扛"这两条做扎实,长时间游玩才不会越来越卡、或者莫名崩溃。The engine also put real work into "resource management" this day, exactly where a long-running program is most prone to trouble. One part is the lifecycle of GPU and audio resources: every chunk of video memory and every sound channel, when no longer referenced by anything, can be accurately identified and reclaimed in time rather than quietly piling up — this day specifically built a "release no-longer-referenced resources" mechanism and verified with a long-running stress test that it indeed holds at a stable, bounded usage level instead of ballooning. The other part is fault isolation: when a serious low-level error occurs, the engine can turn it into a properly-handleable error rather than crashing wholesale, retrying when needed. Both are under-the-hood work users don't see yet that directly decides "whether it can run stably for a long time." A game might run for several hours straight, constantly creating and destroying resources; only by making "return when done, withstand when broken" solid does long play avoid getting laggier or crashing inexplicably.

这一天意味着什么What this day means

这一天的关键词是"打通障碍"。双语化打通的是语言的障碍,让这个平台第一次具备了面向全球用户的基本条件——一个工具要走多远,首先取决于它能被多少人看懂、用上。开发者工具的补全打通的是调试的障碍,让创作者在出问题时能看清真相、而不是对着黑箱干着急。引擎阴影的修复打通的是"治标"到"治本"的障碍,把一个反复出现、只能绕过的顽疾从根上解决。而声明式编排和资源管理,则是在为更复杂、更长时间的游戏打通可能性的障碍。把这些障碍一道道拆掉,平台就同时变得更可达、更透明、更可靠。一个真正想被广泛使用、被长期信赖的工具,做的往往就是这样朴素的事:不断地发现障碍、然后认真地把它拆掉。The day's keyword is "clearing barriers." Bilingualization clears the language barrier, giving the platform, for the first time, the basic conditions to face a global audience — how far a tool goes depends first on how many people can understand and use it. Completing the devtools clears the debugging barrier, letting creators see the truth when problems arise rather than fretting at a black box. Fixing the engine shadows clears the barrier from "treating symptoms" to "treating the root," resolving at the source a recurring ailment that could only be worked around. And declarative scheduling and resource management clear the barrier of possibility for more complex, longer-running games. Tearing down these barriers one by one makes the platform simultaneously more reachable, more transparent and more reliable. A tool that genuinely wants to be widely used and trusted long-term often does exactly this plain thing: continually finding barriers, then earnestly tearing them down.
