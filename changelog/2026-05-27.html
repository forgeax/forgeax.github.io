引擎完全自立 + 更真实的材质The engine stands fully on its own + richer materials

里程碑日:引擎拔掉最后一个外部渲染库依赖,从此完全靠自己跑、还能自检每帧的像素级精度。材质升到自发光 + 环境光遮蔽 + 多种色调映射;更多老设备也能画得出;预览有了原生"播放器",五十行就能写个游戏;再加上全程 HTTPS 与预览自动恢复。A milestone: the engine removed its last external rendering-library dependency, now running entirely on its own and self-verifying every frame's pixel accuracy. Materials rose to emissive + ambient occlusion + tone-mapping looks; more older devices can render; the preview got a native "player" where a game starts in fifty lines; plus HTTPS everywhere and preview auto-recovery.

自立的分水岭:从"借壳"到"自己站住"The watershed of standing alone: from "borrowed shell" to "standing on its own"

这是引擎发展史上的一个分水岭日。一直以来,引擎在底层还留着对一个成熟的外部通用渲染库的依赖——用它当"标准答案"来对照自己画得对不对。这天把这最后一个依赖整个拔掉,引擎从此完全靠自己的渲染管线运行。这不是一次普通的删依赖,而是一个姿态上的转变:从"站在别人肩膀上、随时要参照别人"的状态,变成"自己就是那个标准"。下面几件事——自检基准、材质升档、设备兼容、原生预览——都是围绕这次"自立"展开的配套,合起来宣告:这台引擎已经长成一个能独立站住的成熟渲染器。This is a watershed day in the engine's history. All along, the engine had kept a low-level dependency on a mature external general-purpose rendering library — using it as the "reference answer" to check whether its own rendering was correct. This day removed that last dependency entirely, and the engine now runs solely on its own rendering pipeline. This isn't an ordinary dependency removal but a shift in posture: from "standing on others' shoulders, always referencing someone else" to "being the standard itself." The items below — a self-check benchmark, richer materials, device compatibility, a native preview — are all the accompaniment around this "standing alone," together declaring that this engine has grown into a mature renderer that stands on its own.

自带像素级对齐基准:自己给自己验真A built-in pixel-parity benchmark: verifying itself

拔掉外部库之后,一个现实问题随之而来:以前靠那个库当对照来确认"画得对不对",现在没有它了,拿什么保证质量?答案是引擎自带了一套"像素级对齐"的基准——它能自己给自己出标准答案,逐像素核对每一帧渲染的结果,差一点就报警。这等于把"质量裁判"从外部请来的,变成了引擎自己内置的。它的深远意义在于:从此引擎的画质、性能、特性演进都完全掌握在自己手里,不再被外部库的能力边界和取舍牵着走——想加什么、想怎么优化,不必绕开别人的限制。一个能自我验真的引擎,才真正具备了长期独立演进的资格。After removing the external library, a practical problem followed: previously that library was the reference to confirm "is the rendering correct," and without it, what guarantees quality? The answer: the engine carries its own "pixel-parity" benchmark — it generates its own reference answer and checks each rendered frame pixel by pixel, alarming on any deviation. That turns the "quality judge" from externally borrowed into built into the engine itself. Its far-reaching significance: from now, the engine's image quality, performance and feature evolution are fully in its own hands, no longer led by an external library's capability boundaries and trade-offs — whatever you want to add or optimize, no working around someone else's limits. An engine that can verify itself is truly qualified to evolve independently long-term.

Tier-1 PBR 材质:自发光 + 环境光遮蔽 + 多种色调映射Tier-1 PBR materials: emissive + ambient occlusion + tone-mapping looks

材质系统这天统一并升了一档。底层把原本分成几种变体的材质合并成一套统一的、基于"渲染通道"的材质模型,既简化了概念,也为加新能力腾出了空间。在这套统一模型上,加了几样让画面更真实的能力:自发光,让物体能自己"亮"起来,做霓虹灯、发光符文、能量核心这类效果;环境光遮蔽,让缝隙、转角、接触处自然变暗,大大增强立体感;还有多种色调映射风格,让你能挑画面的整体观感(冷峻、温暖、电影感等)。为了不让"材质花样一多就掉帧",这些复杂材质会被串进渲染管线的缓存里,相同的复用、不同的各管各的。综合起来,场景里的东西看上去更"对"、更有质感——这是从"画得出"迈向"画得好看"的关键升级。The material system was unified and stepped up a level this day. The low level merged what had been several material variants into one unified "render-pass"-based material model, simplifying concepts and making room to add new capabilities. On this unified model, several realism-boosting abilities were added: emissive, letting objects glow on their own for neon signs, glowing runes and energy cores; ambient occlusion, naturally darkening crevices, corners and contact points to greatly strengthen depth; and several tone-mapping looks to choose the overall feel of the image (cool, warm, cinematic, etc.). To keep "more material variety" from "costing frame rate," these complex materials are threaded through a render-pipeline cache, reusing the same and keeping different ones separate. All told, things in a scene look more "right" and more tactile — the key upgrade from "can render" to "renders beautifully."

更广的设备兼容:渲染设备层补齐 + 无高级特性也能兜底Wider device support: the device layer completed + fallback without advanced features

这天把"让引擎在更多机器上跑得起来"也往前推了一截。底层的"渲染设备层"补齐了关键的一整组能力,让引擎在浏览器里能完整地申请并使用渲染所需的设备资源,不再缺胳膊少腿;在没有最新显卡能力的退路上,也把离"能正常出图"仅剩的几个缺口逐一接通。更贴心的是,对那些缺少某些现代显卡特性的设备,专门做了材质上的兼容方案,让它们即便走简化路径也能把物体正确画出来。综合下来,能正常跑起 3D 的机器范围又宽了一截。对一个面向大众的平台来说,"在更弱的机器上也能跑"和"画得更好看"同样重要——前者决定有多少人进得来,后者决定他们留不留得住。This day also pushed "letting the engine run on more machines" forward. The low-level "rendering device layer" completed a key full set of capabilities, so the engine can fully request and use the device resources rendering needs in the browser, no longer missing pieces; on the fallback path without the latest GPU features, the remaining gaps to "renders properly" were wired up one by one. Even more thoughtfully, for devices missing certain modern GPU features, a material-compatibility route was built so they can draw objects correctly even on a simplified path. Net result: the range of machines that can run 3D properly widened another notch. For a mass-market platform, "runs on weaker machines" matters as much as "looks better" — the former decides how many can get in, the latter whether they stay.

预览有了原生"播放器",五十行就能写个游戏A native preview player — a game in fifty lines

预览游戏这天用上了平台自己的原生运行宿主:一套清爽的游戏入口与加载器,负责把一个游戏正确地装载、跑起来,不必再绕一个外部宿主。配套把游戏模板压缩到了约五十行——也就是说,写一个能跑的游戏,从五十行起步就够了。这件事的价值在于"起点足够轻":一个新手或一个 AI,面对的不是一大坨需要先读懂的框架代码,而是一份极简、清晰、能立刻往上加东西的骨架。起点越轻、越标准,"聊出一个游戏"这条路就越顺——AI 照着这个干净起点生成代码,出错更少;人接手时,也更容易看懂和修改。原生宿主 + 极简模板,是把"做游戏"的入门台阶削到最低的一步。Preview games this day moved to the platform's own native runtime host: a clean game entry and loader responsible for loading and running a game correctly, with no detour through an external host. The game template was compressed to about fifty lines — meaning writing a runnable game starts from fifty lines. The value here is "a light enough starting point": a beginner or an AI faces not a big lump of framework code to understand first, but a minimal, clear skeleton ready to build on immediately. The lighter and more standard the start, the smoother the road of "chatting a game into being" — AI generating code from this clean start makes fewer errors, and a human taking over finds it easier to read and edit. A native host plus a minimal template is a step toward cutting the entry bar of "making a game" to the lowest.

稳定性:全程 HTTPS + 预览自动恢复Stability: HTTPS everywhere + preview auto-recovery

这天还在稳定性上补了两笔。其一是支持"全程 HTTPS"的开发模式——某些现代浏览器能力(包括部分图形与设备特性)只在安全来源下才放开,走 HTTPS 能让这些能力正常可用,也更贴近真实部署环境。其二是预览的自动恢复:当预览因为后端的临时抖动而出错时,它会自己尝试重连、自愈,而不是停在一个错误页面等你手动刷新。这两件事都属于"让你不被打断"的功夫——开发时最破坏心流的,往往不是某个大 bug,而是这种隔三差五要手动救一下的小毛病。把它们自动化掉,长时间坐着做游戏才真正顺畅。This day also added two stability touches. One is support for a "HTTPS everywhere" dev mode — some modern browser capabilities (including certain graphics and device features) are only granted under a secure origin, and HTTPS makes them properly available while better matching a real deployment environment. The other is preview auto-recovery: when the preview errors due to a transient backend hiccup, it tries to reconnect and self-heal on its own, rather than sitting on an error page waiting for a manual refresh. Both are the work of "not interrupting you" — what most breaks flow during development is often not some big bug but these small recurring issues needing a manual rescue every so often. Automating them away is what makes sitting down to make a game for hours truly smooth.

这一天意味着什么What this day means

这一天的核心,是引擎完成了"自立"。拔掉最后一个外部渲染依赖、自带像素级基准,意味着它从一个"借别人壳跑、要参照别人"的状态,长成了一个能独立站住、自己给自己验真的成熟渲染器。在这个底气之上,材质升到了能做真实质感、设备兼容覆盖到了更弱的机器、预览有了极简的原生起点、稳定性也更经得起折腾——每一项都是这次自立之后才更有意义的延伸。一个平台敢把最核心的渲染底座做成完全自研、不依赖任何外部库,图的是把命运攥在自己手里:从此画质能走多远、性能能优化到什么程度、要支持什么新特性,都不再受制于人。这正是这一天最该被记住的分量。The core of this day is the engine completing its "independence." Removing the last external rendering dependency and carrying its own pixel-parity benchmark means it grew from "running on a borrowed shell, referencing others" into a mature renderer that stands on its own and verifies itself. On that footing, materials rose to real tactile quality, device compatibility reached weaker machines, the preview got a minimal native starting point, and stability became more resilient — each an extension that means more after this independence. A platform daring to make its most core rendering foundation fully in-house, depending on no external library, is after holding its own fate: from now, how far image quality can go, how much performance can be optimized, and what new features to support are no longer at others' mercy. That's the weight this day most deserves to be remembered for.
