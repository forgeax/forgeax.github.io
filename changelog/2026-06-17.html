角色撞墙会滑的标准移动 + 编辑器独立窗成熟Slide-along-walls movement + a matured standalone editor

引擎给出"撞墙会滑、不卡死"的标准角色移动与类型安全状态机;编辑器独立窗口推到日常可用;样例关卡修通并把经验反哺模板。The engine ships standard "slide along walls, don't get stuck" movement and a typed state machine; the standalone editor window matures into daily use; sample levels are fixed with lessons fed back into the template.

引擎给了"撞墙会滑、不卡死"的标准移动 + 状态机Standard "slide, don't stick" movement + a state machine

引擎落地了一个做任何"能跑能跳"游戏都要用到的基础:运动学角色控制器(移动并滑动),2D 和 3D 都支持。角色撞到墙后会沿着墙面顺滑滑行,而不是直接卡死或者穿模——这是手感能不能及格的关键一环。配套还做了类型安全的状态机:把"待机 / 跑动 / 跳跃 / 攻击"这类状态规范地表达出来,而且实体的生命周期能跟状态绑定(进入某状态时生成、离开时自动清理)。两件加在一起,意味着下一个游戏的角色控制和行为逻辑,不必每次从零手搓。The engine landed a building block every "run and jump" game needs: a kinematic character controller (move-and-slide), for both 2D and 3D. When a character hits a wall it slides smoothly along the surface instead of jamming or clipping through — a key part of whether movement feels right. Alongside it came a type-safe state machine: states like idle / run / jump / attack are expressed cleanly, and entity lifecycles can bind to states (spawn on entering a state, auto-clean on leaving). Together, the next game's character control and behavior logic no longer have to be hand-rolled from scratch.

编辑器独立窗口成熟可用The standalone editor window is ready for daily use

前一天重写的编辑器独立窗口,这天推到了能日常用的成熟度:停靠面板用弹性布局铺满整个视口,移除了一个遗留的"幽灵空画布",斩断了模块之间的循环依赖,独立窗口自己注入编辑与预览两套渲染。控制台健康度也修到只剩正常的资源缺失提示,不再红字满屏。还补齐了双语说明和启动文档,配上结构图,新人照着就能把它单独跑起来。编辑器作为一个独立工具,真正站稳了。The standalone editor window rewritten the day before reached daily-use maturity: docked panels use a flexible layout to fill the whole viewport, a leftover "ghost empty canvas" was removed, a circular dependency between modules was broken, and the standalone window injects its own edit and preview rendering. Console health was fixed down to just the normal missing-resource notices, no more screens of red. Bilingual docs and startup instructions with a structure diagram were added too, so a newcomer can stand it up on its own by following along. The editor truly holds its own as a standalone tool.

样例关卡修通,经验反哺模板Sample levels fixed, lessons fed back into the template

一个样例关卡之前连环踩了三个坑,这天一次扫干净:场景对象的内部编号不连续,导致走位和视角操作失灵——重排成连续编号修好;阴影用的是旧配置——迁到新的阴影方案并锁定稳定的渲染配置;最后把整个翻车与排查过程写成复盘文档,并据此修订了相关的使用约定。更重要的是,这些教训被反哺进新建游戏的默认模板"易踩坑清单",让后来的游戏不会再栽进同一个坑。同时也把样例主角的蒙皮动画接通,让它真正动起来。A sample level had hit three pitfalls in a row, all cleared this day: the scene objects' internal IDs weren't contiguous, which broke movement and camera controls — fixed by renumbering them consecutively; shadows used an old configuration — migrated to the new shadow approach with a stable render config locked in; and the whole derailment and diagnosis was written up as a retrospective, with the relevant usage conventions revised accordingly. More importantly, these lessons were fed back into the default new-game template's "common pitfalls" list, so later games won't fall into the same trap. The sample hero's skinned animation was also wired up so it genuinely moves.
