Git 凭据弹窗:一个小问题,大干扰The credential popup: a small problem, a big disruption

在 Windows 上开发时,IDE 里时不时弹出一个"GitHub — Select an account"的窗口,要你选 x-access-token 还是 service-account——然后点 Continue 才能继续操作。这个弹窗来自 Windows 的 Git Credential Manager,根源是之前为了解决 CI 中的认证问题,在本地 .git/config 里加了一条 insteadOf 规则,把所有 github.com 的 URL 自动替换成了带 token 的格式。这导致系统凭据管理器检测到多个身份,每次操作都弹窗确认。修法三步:第一,删掉 insteadOf 规则,恢复干净的 remote URL;第二,在 ~/.git-credentials 里存好 token,让 credential.helper=store 静默提供认证;第三,全局设置 credential.interactive=never,彻底禁止 Credential Manager 弹出任何交互窗口。从此 git 操作全部静默认证,不再打断工作流。When developing on Windows, an "GitHub — Select an account" popup would appear in the IDE from time to time, asking you to pick x-access-token or service-account — and you had to click Continue before anything could proceed. This popup came from the Windows Git Credential Manager. The root cause: to fix a CI auth issue earlier, an insteadOf rule had been added to the local .git/config, automatically rewriting all github.com URLs into a token-embedded format. This made the system credential manager detect multiple identities and prompt on every operation. The fix was three steps: first, remove the insteadOf rule and restore clean remote URLs; second, store the token in ~/.git-credentials so credential.helper=store provides auth silently; third, globally set credential.interactive=never to stop the Credential Manager from ever showing an interactive window. From then on, all git operations authenticate silently without breaking the workflow.
