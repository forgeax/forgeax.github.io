3D 生成会绑骨配动作 + 编辑器自动体检Generated 3D gets rigged and animated + automated editor QA

3D 生成能在插件里填密钥、生成、绑骨、配动作;编辑器有了自动化端到端体检与保活地基;引擎对称回收 GPU 与音频资源。3D generation can configure keys, generate, rig and animate inside the plugin; the editor gains automated end-to-end QA and keep-alive groundwork; the engine reclaims GPU and audio resources symmetrically.

3D 生成全面"会自己干活":填密钥、生成、绑骨、配动作3D generation takes on the whole job: keys, generate, rig, animate

3D 生成工作台往"端到端能用"又推了一大步。生成方式改成多视图,出模型更稳;你可以直接在插件里配置多家生成服务的密钥,并用一个"真实模式"总开关决定是真出还是先试。更关键的是接上了"绑骨 + 动画":生成出来的模型能自动绑定骨骼,再从一个动作浏览器里挑现成动作给它用。也就是说,"用文字生成一个角色 → 给它骨架 → 让它动起来",第一次能在同一个工作台里一条龙走完,而不用导出去别的工具折腾。The 3D-generation workbench pushed another big step toward end-to-end usable. Generation switched to a multi-view approach for steadier models; you can configure the keys for several generation services right in the plugin, and a "real mode" master switch decides whether to actually generate or just try. The key addition is rigging plus animation: a generated model can be auto-rigged with a skeleton, then assigned ready-made motions picked from a motion browser. In other words, "generate a character from text → give it a skeleton → make it move" can now be done end to end in one workbench, without exporting to other tools.

编辑器有了自动化体检 + 切换不被掐死Automated editor QA + it isn't killed on switching

给编辑器立了一套自动化端到端体检:一组冒烟测试会自动把几个样例游戏跑一遍,确认它们在编辑与试玩里都能正常加载、不退化——以后改动有没有把现成游戏弄坏,机器会先替你查一遍。同时对"嵌入式编辑器"做了加固,并为"保活"打下地基:当你在浏览器标签或宿主之间切来切去时,正在运行的编辑器会话更不容易被悄悄回收掐死。底层还把"设备掉线后自动恢复"做进了引擎,意外更少打断你。An automated end-to-end health check was set up for the editor: a set of smoke tests automatically runs several sample games and confirms they load correctly in both edit and play without regressing — so whether a change broke an existing game gets checked by the machine first. The embedded editor was hardened too, with groundwork laid for "keep-alive": as you switch between browser tabs or hosts, a running editor session is far less likely to be quietly reclaimed and killed. Underneath, "auto-recover after a device drop" was built into the engine, so accidents interrupt you less.

引擎资源对称回收:GPU 与音频不再悄悄泄漏Symmetric resource reclaim: no more quiet GPU and audio leaks

引擎给资源管理立了"有借有还"的对称规则:显卡资源(纹理、缓冲等)有了配套的释放原语,用完能干净回收;音频资源也做了确定性回收(到点该清就清,不靠运气)。意义在于——长时间玩、反复切场景时,显存和音频内存不会越积越多、越跑越卡。这类"悄悄泄漏"是大型场景和长会话最隐蔽的杀手,从根上收住了,游戏跑得更久也更稳。The engine established a symmetric "borrow it, return it" rule for resources: GPU resources (textures, buffers and the like) got matching release primitives so they're cleanly reclaimed when done; audio resources got deterministic reclaim too (cleaned up exactly when they should, not by luck). The point — over long play sessions and repeated scene switches, video and audio memory no longer pile up and bog things down. This kind of "quiet leak" is the most insidious killer of large scenes and long sessions, and tackling it at the root keeps games running longer and steadier.
