让能力更自主,让运行更可靠Making capability more autonomous, and running more reliable

这一天有两条彼此呼应的线。一条关于"自主":让 3D 生成从一个需要人盯着、一步步操作的工具,变成一条能自己把"生成 → 绑骨 → 配动作"一气呵成走完的产线,而且密钥、模式都能由用户在插件里自行配置。另一条关于"可靠":给编辑器立自动化体检、给嵌入式运行打保活地基、给引擎的资源管理立"有借有还"的对称规矩。前者拓展了"能做到什么",后者保障了"做出来的东西稳不稳、能不能长时间用"。一个工具越是想让用户放手交给它自己跑,就越要在可靠性上下足功夫——能力越自主,对底层稳健的要求就越高。这一天,恰好是这两件事一起往前推。This day had two mutually-echoing lines. One is about "autonomy": turning 3D generation from a tool you must watch and operate step by step into a pipeline that runs "generate → rig → animate" through in one breath, with keys and modes configurable by the user in the plugin. The other is about "reliability": setting up automated QA for the editor, laying keep-alive groundwork for embedded running, and establishing a symmetric "borrow it, return it" rule for the engine's resource management. The former expands "what can be done"; the latter ensures "whether what's made is stable and usable long-term." The more a tool wants users to hand it work to run on its own, the more it must invest in reliability — the more autonomous the capability, the higher the demand on underlying robustness. This day pushed both forward together.

3D 生成全面"会自己干活":填密钥、生成、绑骨、配动作3D generation takes on the whole job: keys, generate, rig, animate

3D 生成工作台这天往"端到端能用"又推了一大步,几件事合起来形成了一条完整的产线。其一,生成方式改成多视图——从多个角度去引导生成,出来的模型形态更稳、更符合预期。其二,你可以直接在插件里配置多家生成服务的密钥,并用一个"真实模式"总开关来决定是真正调用服务出模型、还是先用占位试跑流程;把密钥和开关交到用户手里,意味着每个人都能用自己的额度、按自己的节奏来生成。其三也是最关键的一步:接上了"绑骨 + 配动作"。一个刚生成出来的模型只是一具静态的躯壳,要让它能动,得先给它绑上一副骨架(绑骨),再给这副骨架套上具体的动作。现在这两步都能在工作台里完成——绑骨可以自动做,动作则从一个内置的"动作浏览器"里直接挑选现成的套上去。把这几样串起来,"用一句话生成一个角色 → 给它骨架 → 让它动起来",第一次能在同一个工作台里一条龙走完,而不必把模型导出去、在别的专业工具里来回折腾。对没有建模和动画功底的创作者来说,这条产线把原本需要好几款专业软件、好几道工序才能完成的事,压缩成了在一个面板里点几下。The 3D-generation workbench pushed another big step toward end-to-end usable this day, with several things together forming a complete pipeline. First, generation switched to a multi-view approach — guiding generation from several angles for a steadier, more on-target model shape. Second, you can configure the keys for several generation services right in the plugin, with a "real mode" master switch deciding whether to actually call a service and produce a model or first try the flow with placeholders; handing keys and the switch to the user means everyone can use their own quota at their own pace. Third, and most key: rigging plus animation. A freshly-generated model is just a static shell; to make it move, you first fit it with a skeleton (rigging), then put concrete motions on that skeleton. Both steps can now be done in the workbench — rigging can be automatic, and motions are picked ready-made from a built-in "motion browser." Stringing these together, "generate a character from a sentence → give it a skeleton → make it move" can be done end to end in one workbench for the first time, without exporting the model and fussing back and forth in other professional tools. For creators without modeling or animation skills, this pipeline compresses what used to take several professional programs and several stages into a few clicks in one panel.

编辑器有了自动化体检 + 切换不被掐死Automated editor QA + it isn't killed on switching

这天给编辑器立了一套自动化的端到端体检。具体说,是一组冒烟测试会自动把几个不同类型的样例游戏都跑一遍——纯代码的、带场景包的、需要在桌面环境走兜底路径的——逐一确认它们在编辑和试玩里都能正常加载、不出退化。这件事的价值在于:平台每天都有大量改动,任何一处改动都可能不经意地把某个现成的游戏弄坏;有了这套自动体检,机器会在改动合入前先替你把这些样例都验一遍,把"改 A 坏了 B"这类回归挡在门外。与此同时,还对"嵌入式编辑器"做了加固,并为"保活"打下地基:编辑器是嵌在一个内嵌页面里运行的,当你在不同标签页或不同宿主之间切来切去时,浏览器有时会把暂时看不见的它悄悄回收掉,导致你切回来时正在跑的会话已经被掐死。这天的加固和保活地基,正是为了让这种切换不再打断你正在进行的工作。底层还把"图形设备意外掉线后自动恢复"做进了引擎,让这类底层意外更少地打断创作。This day set up an automated end-to-end health check for the editor. Specifically, a set of smoke tests automatically runs several different types of sample game — pure-code ones, ones with scene packs, ones that take the fallback path in a desktop environment — confirming each loads correctly in both edit and play without regressing. The value: the platform sees many changes every day, any of which could inadvertently break an existing game; with this automated check, the machine verifies all these samples before a change merges, keeping "changing A broke B" regressions out at the door. Meanwhile, the embedded editor was hardened, with groundwork laid for "keep-alive": the editor runs inside an embedded page, and when you switch between tabs or hosts, the browser sometimes quietly reclaims the temporarily-invisible one, so on returning your running session is already dead. This day's hardening and keep-alive groundwork are precisely to keep such switching from interrupting your in-progress work. Underneath, "auto-recover after a graphics device unexpectedly drops" was built into the engine, so such low-level accidents interrupt creation less.

引擎资源对称回收:GPU 与音频不再悄悄泄漏Symmetric resource reclaim: no more quiet GPU and audio leaks

引擎这天给资源管理立了一条"有借有还"的对称规矩,并以此标志着一整个底层基础层的收口。所谓对称,就是每一种"申请资源"的操作,都必须有一个配套的、明确的"释放资源"操作与之对应——显卡资源(纹理、缓冲等)有了成套的释放原语,用完能被干净地回收;音频资源也做了确定性回收,即到了该清理的时候就准确地清理,而不是靠垃圾回收的运气。为什么这件事这么重要?因为一个游戏可能要连续跑很久,期间不停地创建、又不停地丢弃各种资源;如果"申请"了却没人负责"释放",这些用不到的资源就会在显存和音频内存里悄悄堆积,越积越多,直到把游戏拖得越来越卡、最终崩溃。这种"悄悄泄漏"是大型场景和长时间会话最隐蔽、最难排查的杀手,因为它平时不报错,只在跑得够久之后才发作。把资源的生命周期做成严格对称、可确定地回收,等于从制度上杜绝了这类泄漏。这天还把引擎规划中的这一整层基础工作正式标记为完成——意味着引擎的底层资源治理告一段落,可以放心地在它之上搭更复杂的东西。The engine established a symmetric "borrow it, return it" rule for resource management this day, marking the closure of a whole underlying foundation layer. Symmetric means every "request a resource" operation must have a matching, explicit "release the resource" operation — GPU resources (textures, buffers and the like) got a full set of release primitives so they're cleanly reclaimed when done; audio resources got deterministic reclaim too, cleaned up exactly when they should be rather than by garbage-collection luck. Why does this matter so much? Because a game may run for a long stretch, constantly creating and discarding resources; if something is "requested" but no one is responsible for "releasing" it, these unused resources quietly pile up in video and audio memory, accumulating until the game grows laggier and finally crashes. This "quiet leak" is the most insidious, hardest-to-diagnose killer of large scenes and long sessions, because it doesn't error in normal use and only erupts after running long enough. Making resource lifecycles strictly symmetric and deterministically reclaimable institutionally eliminates this class of leak. This day also formally marked this whole foundation layer of the engine's roadmap as complete — meaning the engine's low-level resource governance reached a milestone, and more complex things can confidently be built atop it.

游戏改用更干净的统一加载方式Games move to a cleaner unified loading model

这天还顺手把示例游戏的加载方式做了一次整理,统一到一个更干净的模型上。此前不同的游戏在"如何加载自己的场景资源"上各有各的做法——有的自己去抓、自己解析、自己维护一份目录,逻辑分散且容易各自走偏。这天把它们改成由"宿主"统一喂入:游戏不再自己去张罗加载,而是由承载它的运行环境把场景资源准备好、直接递给它。配套还把各游戏的场景资源文件挪到了一个能被自动扫描发现的统一位置。这类改动用户完全看不见,但它消除了"每个游戏一套加载逻辑"的重复和分歧,让所有游戏走同一条加载路径。好处是双重的:一是后面再做加载相关的改进时,改一处就能让所有游戏受益,不必逐个适配;二是问题更好排查——既然大家走同一条路,出了岔子就只需要查那一条路。把分散的做法收敛成统一的一条,正是让整个游戏库能被一致地维护和演进的前提。This day also tidied the sample games' loading approach, unifying them onto a cleaner model. Previously different games each had their own way of "loading their own scene resources" — some fetched, parsed and maintained their own catalog, logic scattered and prone to diverging. This day changed them to be fed uniformly by the "host": a game no longer arranges its own loading but has the runtime environment carrying it prepare the scene resources and hand them over directly. Each game's scene-resource files were also moved to a unified location that can be auto-discovered by scanning. Such changes are entirely invisible to users, but they eliminate the duplication and divergence of "a loading logic per game," putting all games on the same loading path. The benefit is twofold: later loading-related improvements need be made in just one place to benefit all games, no per-game adaptation; and problems are easier to diagnose — with everyone on the same path, a glitch means checking only that one path. Converging scattered approaches into one unified path is exactly the precondition for the whole game library to be consistently maintained and evolved.

这一天意味着什么What this day means

这一天体现了一个 AI 创作平台成熟过程中两股力量的并进:一股是让能力更"自主"——3D 生成从一个需要人逐步操作的工具,变成一条能自己走完"生成、绑骨、配动作"全程、且让用户自主掌控密钥与模式的产线;另一股是让系统更"可靠"——给编辑器立自动体检、为嵌入式运行保活、给引擎资源立对称回收、把游戏加载收敛成统一路径。这两股力量看似一进一守,实则相辅相成:正因为有了自动体检和稳健的资源治理兜底,才敢把越来越多的环节交给 AI 自主完成;而越是把环节交出去,这些底层保障就越显得不可或缺。一个真正可靠的自动化系统,从来不是"放手不管",而是"放手之前先把网织密"。这一天,既在织密那张网,也在把更多的事放心地交了出去。This day embodied two forces advancing together as an AI creation platform matures: one making capability more "autonomous" — 3D generation going from a tool requiring step-by-step human operation into a pipeline that runs the whole "generate, rig, animate" course on its own, with users controlling their own keys and modes; the other making the system more "reliable" — setting up automated QA for the editor, keep-alive for embedded running, symmetric reclaim for engine resources, and a unified loading path for games. These two forces seem one advancing and one guarding, but they're complementary: precisely because automated QA and robust resource governance back it up can more and more steps be handed to the AI to do autonomously; and the more steps handed over, the more indispensable these underlying safeguards become. A truly reliable automated system is never "let go and ignore" but "weave the net tight before letting go." This day both wove that net tighter and confidently handed more over.
