引擎学会投影:方向光阴影The engine learns to cast: directional-light shadows

引擎渲染这天迈过一道关键门槛——方向光阴影。物体现在会在一束方向光(类似太阳光)下投下影子,也会接住别的物体投来的影子。阴影看似只是地上多了一片暗,实则是画面"立体感"的重要来源:人眼很大程度上靠阴影来判断物体之间的高低、远近和接触关系——没有影子,一个角色会像贴纸一样浮在地面之上;有了影子,它才真正"站"在那里。把方向光阴影做对,是从"物体被照亮"走向"物体存在于一个空间里"的关键一步,也是任何要做出真实感场景的游戏都绕不开的基础能力。Engine rendering crossed a key threshold this day — directional-light shadows. Objects now cast shadows under a directional light (like sunlight) and receive shadows from others. A shadow looks like just a dark patch on the ground, but it's a major source of an image's "depth": human eyes largely use shadows to judge height, distance and contact between objects — without a shadow, a character floats above the ground like a sticker; with one, it truly "stands" there. Getting directional-light shadows right is a key step from "objects are lit" to "objects exist in a space," and a foundational capability no game aiming for realistic scenes can avoid.

基于环境的天光 + 逐物体贴图Image-based sky light + per-object textures

在方向光阴影之外,这天还补上了两块让画面更真实的能力。其一是"基于环境的天光":用一张环境贴图作为光源,让物体被四周环境柔和地照亮——暗部不再死黑,金属与光滑表面会映出环境的样子,整个场景的光感一下子自然、高级很多,这是接近真实感渲染的关键一环。其二是修好了"逐物体的材质贴图绑定":同一个场景里不同的物体现在能各自贴各自的图,不再出现"改了一个物体的贴图、结果影响到另一个"的串台问题。方向光阴影 + 环境天光 + 逐物体贴图,这三样凑齐,引擎离能渲染一个"看上去就是对"的完整场景,又近了一大步。Beyond directional-light shadows, this day added two more capabilities that make images more real. One is "image-based sky light": using an environment image as a light source so objects are softly lit by their surroundings — shadowed areas no longer go dead black, and metal and smooth surfaces reflect the look of their environment, making the whole scene's light suddenly far more natural and refined, a key part of approaching realistic rendering. The other is fixing "per-object material texture binding": different objects in the same scene can now each carry their own texture, with no more crosstalk where "changing one object's texture affects another." With directional shadows + ambient sky light + per-object textures together, the engine is much closer to rendering a complete scene that simply "looks right."

新增叙事工作台A new narrative workbench

工具家族这天迎来一位新成员:叙事工作台。它借着前一天确立的分屏插件架构,以嵌入式工具窗的形态住进工作台,占满主区域来组织一个游戏的剧情与文本。它解决的是一个真实的割裂——做游戏不只是写玩法代码,还要编剧情、写对白、设计分支;以前这些往往得在另外的工具里做,再想办法搬回来。现在"做玩法"和"写故事"被放进了同一个平台里推进,你不用在不同工具之间来回切换、来回复制。这也印证了那套分屏架构的价值:它让平台能像搭积木一样,把一个又一个不同职能的工作台稳稳接进来。The tool family welcomed a new member this day: a narrative workbench. Riding the split-surface plugin architecture established the day before, it lives in the workbench as an embedded tool window filling the main area to organize a game's story and text. It solves a real fragmentation — making a game isn't just writing gameplay code but also scripting plot, writing dialogue, designing branches; these often had to be done in another tool and then somehow brought back. Now "building gameplay" and "writing the story" advance inside one platform, with no switching and copying between separate tools. It also confirms the value of that split-surface architecture: it lets the platform plug in workbench after workbench of different functions, like building blocks, steadily.

角色工作台:生成的素材会留住,还能上传自己的Character workbench: keeps your assets, takes your uploads

角色工作台这天从"试着玩玩"往"真能拿来做项目"迈了一大步。最关键的是资产持久化:生成出来的立绘、素材现在会被保存下来,关掉工作台再回来它们还在,不必每次都重新生成一遍——这对一个要反复打磨角色的人是质的区别。分屏里左右两侧的内容也会保持同步,改一边另一边跟着更新,不会各说各话。你还能把自己已有的素材上传进来一起用,而不必所有东西都靠生成;并且生成可以按需路由到不同的外部服务,挑合适的那一家来出图。这些改动合起来,让这个工作台从一个有趣的演示,变成一个能真正承载日常创作的工具。The character workbench took a big step this day from "fun to try" toward "actually usable on a project." The key is asset persistence: generated portraits and assets are now saved, still there when you close the workbench and come back, with no regenerating each time — a qualitative difference for someone refining a character repeatedly. The two sides of a split view stay in sync, so editing one updates the other rather than them disagreeing. You can also upload your own existing assets to use alongside, not relying on generation for everything; and generation can route to different external services on demand, picking the right one for the image. Together these turn the workbench from an interesting demo into a tool that can genuinely carry everyday creation.

新增 UI 工坊 + 跨平台与界面打磨A new UI workshop + cross-platform and interface polish

这天还多了一个 UI 工坊工作台,继续扩充工具矩阵;界面则按设计稿把工具切换栏、折叠态宽度等细节对齐,让视觉更规整。底层也清理了一批东西:删掉了几个不再需要的构建期插件、把一些示例的命名空间归整统一,并修好了一个在 Windows 上路径处理出错的跨平台问题——让更多系统上的开发者都能顺利跑起来。这些改动单看零碎,但它们和前面那些大特性一样重要:大特性决定平台能做什么,这些打磨决定平台在你的机器上、你的日常里到底好不好用。两者都做扎实,产品才立得住。This day also added a UI workshop workbench, continuing to expand the tool matrix; the interface aligned details like the tool switcher bar and collapsed-state width to the design spec for a tidier look. The low level cleaned up a batch of things too: removing a few build-time plugins no longer needed, consolidating some examples' namespaces, and fixing a cross-platform path-handling bug on Windows — so developers on more systems can run smoothly. Individually these look minor, but they matter as much as the big features above: big features decide what the platform can do, while these polishes decide whether it's actually pleasant on your machine, in your day. Doing both solidly is what lets the product hold up.
