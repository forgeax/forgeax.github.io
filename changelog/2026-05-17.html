让协作"看得见、点得到"Making collaboration visible and clickable

前几天平台搭好了"多 agent 后台长跑 + 事件总线"的能力,但这些都还藏在系统内部。这天的主线,是把这套能力彻底推到界面前台:你不仅能看见 agent 之间在总线上的往来,还能直接 @ 点名某个 agent、把素材就地预览出来、用引用胶囊把对象带进对话。换句话说,这天补的不是某个孤立功能,而是"让一群 agent 协作"这件事真正可被一个普通人操控的那层交互。当后台的复杂被翻译成你看得懂、点得到的界面元素,多 agent 才从"技术上能跑"变成"用起来顺手"。In the prior days the platform built the capability of "multiple agents running long in the background + an event bus," but all of it was still hidden inside the system. This day's through-line was pushing that capability fully to the interface foreground: you can not only see the traffic between agents on the bus, but @ a specific agent by name, preview assets in place, and bring objects into the conversation as reference pills. In other words, what this day added isn't an isolated feature but the interaction layer that makes "a team of agents collaborating" something an ordinary person can actually operate. Once the backend's complexity is translated into interface elements you can read and click, multi-agent goes from "technically runs" to "comfortable to use."

直接 @ 一个 agent 跟它对话@ an agent to talk to it directly

这天多 agent 协作迈出关键一步:你可以在对话里直接用 @ 点名某个 agent,让它接住这条消息并回复,而不再是只能跟那个主控对话、由它转述给别人。配套上线了一个 agent 中枢面板,把当前这支"团队"里有哪些成员、各自在忙什么集中呈现出来。这件事改变的是协作的"指挥方式":以前你像是只能对项目经理说话,现在你可以越过项目经理,直接找那个负责美术、或负责关卡的成员把话说清楚。对"一个人带一支 AI 团队"这个核心场景来说,能点名沟通是从"群发"走向"精确指挥"的分水岭——你终于能把对的话说给对的成员听。Multi-agent collaboration took a key step this day: you can @ a specific agent by name in the conversation so it picks up that message and replies, rather than only talking to the lead and having it relay to others. A companion agent-hub panel went live, presenting at a glance which members are in the current "team" and what each is busy with. What this changes is the "command style" of collaboration: where you used to be able to speak only to the project manager, you can now go past the manager and address the member handling art, or the one handling levels, directly. For the core scenario of "one person leading a team of AIs," named communication is the watershed from "broadcast" to "precise command" — you can finally say the right thing to the right member.

总线状态铺满界面:处处看得见能力健康度Bus status spread across the UI: capability health everywhere

承接前一天把总线接进界面,这天把"系统里有哪些能力、各自健不健康"这件事铺到了界面的各个角落。顶栏多了一排状态灯,分别对应工具、技能、agent 等几类能力,各自显示数量和健康状态;聊天面板、侧栏、总线管理面板里也到处是这种"小灯 + 计数 + 可点深链"的呈现,点一下就能跳到对应的详情。它的价值在于把"系统现在到底有什么、状态如何"这件事变成一种环境信息——你不用专门去查,扫一眼界面就知道。对一个能力越来越多、还能被插件不断扩展的系统来说,这种无处不在的健康可视化,是让人始终对"它现在是什么状态"心里有底的关键。Building on the prior day's wiring of the bus into the interface, this day spread "which capabilities exist in the system and how healthy each is" into every corner of the UI. The top bar gained a row of status lamps for categories like tools, skills and agents, each showing a count and health; the chat panel, sidebar and bus admin panel are likewise dotted with this "little lamp + count + clickable deep-link" presentation, where one click jumps to the matching detail. Its value is turning "what does the system have right now and how is it doing" into ambient information — you don't go look it up; a glance at the interface tells you. For a system with ever more capabilities, extensible by plugins, this omnipresent health visualization is key to always having a feel for "what state it's in."

聊天里就地预览素材 + 引用 pillInline asset preview + reference pills in chat

这天还让"素材"在对话里变得可见、可引用。聊天能就地预览附件:贴一张图片直接出缩略图,丢一个模型文件会渲染成一个可看的小预览,不必先塞进游戏里跑一遍才能看到它长什么样。讨论一个角色或一张贴图时,双方看到的是同一个具体的东西,而不是各自脑补。配套的"引用胶囊"则让你在输入框里打个 @ 就能把一个 agent 或一份资源做成一枚可点的标签——记得你最近用过哪些、悬停能看说明、插入后还能点回去。这两件事合起来,把"把素材带进对话"这件以前要靠复制长路径、靠文字描述的事,变成了一拖、一点的直接操作。This day also made "assets" visible and referenceable in conversation. Chat can preview attachments in place: paste an image and get a thumbnail; drop a model file and it renders as a small viewable preview, without first wiring it into a running game to see what it looks like. When discussing a character or a texture, both sides see the same concrete thing rather than imagining their own. The companion "reference pills" let you type @ in the composer to turn an agent or a resource into a clickable tag — remembering what you used recently, showing a tooltip on hover, clickable back after insertion. Together, these turn "bringing an asset into the conversation" — which used to mean copying long paths and describing in words — into a direct drag-and-click action.

引擎:统一的网格渲染器 + 材质句柄 + 默认值回退Engine: a unified mesh renderer + material handle + default-value fallback

引擎这天在渲染与组件这两层做了重要收敛。渲染上,统一成了单一的网格渲染器,并用"材质句柄"来引用材质——也就是一个物体怎么被画出来,统一由"网格 + 一个指向材质的句柄"来描述,既清楚又便于复用同一份材质。组件这边,给"创建实体"和"添加组件"补上了一条默认值回退链:当你没显式给某个字段赋值时,系统会沿着多层规则去找一个合理的默认值,而不是报错或留空。这意味着写游戏内容时可以"只写关心的部分,其余交给合理默认",大大减少样板和出错面。这类收敛不是新功能,而是让引擎在被越来越多人(和 AI)使用时,依然保持"少惊讶、好预期"的关键。The engine made important convergences at the rendering and component layers this day. In rendering, it unified to a single mesh renderer that references materials by a "material handle" — that is, how an object is drawn is uniformly described by "a mesh plus a handle pointing to a material," both clear and easy to reuse one material across objects. On components, "creating an entity" and "adding a component" gained a default-value fallback chain: when you don't explicitly set a field, the system walks layered rules to find a sensible default rather than erroring or leaving it blank. This means writing game content can be "write only the parts you care about, leave the rest to sensible defaults," greatly cutting boilerplate and error surface. Such convergence isn't a new feature but the key to the engine staying "low-surprise, predictable" as more people (and AI) use it.

引擎:截图能力统一 + 控制台依赖反转 + 教学示例铺开Engine: unified capture + console dependency inversion + tutorial examples

引擎这天还清理了几处"重复"与"耦合"。其一,把原本散落在多个示例里、各写一套的"截屏"逻辑统一成渲染器的一个标准能力,一处实现、处处可用,既减少重复又让视觉验证更一致。其二,对"控制台"这条调试通道做了依赖反转:它不再直接依赖具体的内部模块,而是通过一个抽象接口来工作,从而把彼此解耦——这让控制台能更独立地演进,也让插件能以统一方式接进来。其三,落地了一整套循序渐进的渲染教学示例(从最基础的三角形、纹理到输入处理),并把图像、纹理、输入这些通用能力内化进引擎本身。这些示例既是引擎能力的活文档,也是新人(和 AI)学习怎么用这套引擎的最好入口。The engine also cleaned up several spots of "duplication" and "coupling" this day. One: the "screenshot" logic once scattered across multiple examples, each its own copy, was unified into a standard renderer capability — one implementation usable everywhere, cutting duplication and making visual verification more consistent. Two: the "console" debug channel got dependency inversion — it no longer depends directly on concrete internal modules but works through an abstract interface, decoupling them — letting the console evolve more independently and letting plugins plug in a uniform way. Three: a full set of progressive rendering tutorial examples landed (from the most basic triangle and textures to input handling), and common capabilities like images, textures and input were internalized into the engine itself. These examples are both living documentation of the engine's capabilities and the best entry point for newcomers (and AI) to learn how to use it.

这一天意味着什么What this day means

这一天的两条线——界面上把多 agent 协作彻底"显形",引擎里把渲染与组件大幅"收敛"——表面无关,内里却是同一种追求:让一个正在快速变复杂的系统,始终对人保持清楚。界面这边,@ 提及、能力健康灯、素材预览、引用胶囊,合起来让"指挥一支 AI 团队"从抽象变得具体可操作;引擎这边,统一渲染器、统一截图、依赖反转、教学示例,合起来让底层在功能膨胀的同时不至于越长越乱。一个能长期演进的系统,既要往外长出能力,也要往内保持秩序——这一天,正好同时在做这两件事。The day's two lines — fully "revealing" multi-agent collaboration in the interface, and heavily "converging" rendering and components in the engine — seem unrelated but inside share one pursuit: keeping a rapidly-complicating system clear to people. On the interface side, @-mentions, capability health lamps, asset preview and reference pills together turn "directing a team of AIs" from abstract into concretely operable; on the engine side, the unified renderer, unified capture, dependency inversion and tutorial examples together keep the low level from growing messier as features balloon. A system that can evolve long-term must both grow outward in capability and keep order inward — and this day did exactly both at once.
