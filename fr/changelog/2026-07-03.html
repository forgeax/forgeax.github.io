Mise à jour2026-07-03

Mode Play Windows stabilisé + proxy de débogage LLM pour développeurs

Le mode Play sur Windows est désormais stable grâce à une correction du stack Socket de l'éditeur ; une nouvelle variable d'environnement FORGEAX_DEBUG_PROXY permet aux développeurs de capturer et d'inspecter tout le trafic API LLM en temps réel ; l'empaquetage de l'application de bureau sur Windows a été corrigé ; et l'architecture du runtime reel-game a été conçue comme une sous-classe de runtime de jeu au niveau du moteur.

Mode Play Windows : enfin stable

Le mode Play sous Windows échouait par intermittence en raison d'un problème dans le stack Socket de l'éditeur. L'export WebSocket sous-jacent manquait dans le chemin de build desktop, causant la perte de connexion de l'iframe de prévisualisation du moteur avec l'hôte éditeur. Cela a été corrigé — le mode Play sous Windows fonctionne désormais aussi fiablement que sous macOS.

Proxy de débogage LLM pour développeurs

Une nouvelle variable d'environnement optionnelle FORGEAX_DEBUG_PROXY a été ajoutée. Lorsqu'elle est définie, elle lance un proxy HTTP local qui capture tous les appels API LLM sortants (Anthropic, OpenAI, Gemini, etc.) et enregistre les paires requête/réponse. Configurez-la dans votre .env et le proxy démarre automatiquement avec bun fx start.

Empaquetage de l'application de bureau Windows corrigé

Le build desktop Tauri 2 pour Windows échouait en raison d'un export de dépendance manquant dans le package interface. Résolu — bun fx build app produit maintenant un installateur .exe fonctionnel sous Windows.

Architecture du runtime reel-game

Une spécification de conception pour le runtime reel-game (film interactif) a été établie, le positionnant comme une sous-classe de runtime de jeu de première classe au sein du moteur. L'implémentation suivra dans les prochaines versions.
