1Avant de commencer

Qu'est-ce que ForgeaX et quels jeux il crée

ForgeaX est un studio de développement de jeux natif d'IA. Vous décrivez le jeu dans un langage simple ; un responsable de l'IA appeléForge le planifie, le conçoit et l'écrit lui-même dans le code du jeu en cours d'exécution, rechargez à chaud le résultat dans votre navigateur – ce que vous dites est ce que vous jouez.

Deux fondations internes se trouvent en dessous : unmoteur repensé pour le point de vue de l'IA(voirPourquoi un moteur natif d'IA) et unboucle de développement qui fait converger les fonctionnalités vers un résultat correct(voirComment l'IA réussit à créer une fonctionnalité).

Ça convient2D / 2,5D / 3Djeux sur Internet. Des FPS jouables, des ARPG façon Diablo, des démos de survie et de shooter à deux niveaux existent déjà (voir levitrine); le moteur couvre le rendu PBR / IBL / SSAO, la physique 2D/3D, l'animation squelettique et le double RHI (voir "Capacités du moteur" en bas duvitrine).

Tout fonctionne dans le navigateur (WebGPU), sur le Web et sur le bureau sur une seule pile ; open source sous Apache License 2.0 (voir lelicence).

Ouvrez le studio, apprenez l'interface

L'interface est composée de trois parties : une barre supérieure, le chat à gauche et l'aperçu/workbench à droite.

  • Barre supérieure- le⊕nouveau menu, unsélecteur de projet(passer d'un jeu à l'autre - ce qu'est un "projet" est couvert dansConcepts de base), et uncommutateur de session(réviser/changer les conversations passées).
  • Gauche · chat (ChatPanel)— un rail d'équipe (Forge et les sous-agents), un flux de messages (cartes de sous-agents, réflexions et appels d'outils de Forge), et un compositeur en bas avec uncommutateur principalen bas à droite (voirAvancé).
  • Droite · zone principale (MainArea)— bascule entre lesaperçu(votre jeu vit dans une iframe) et leétabli(édition de fichiers / documents de conception) ; voirScènes et éditeur.

Le rouage en haut à droite s'ouvreParamètres: Clés API, choix du modèle, backend CLI et gestion des plugins. L'application de bureau affiche également une superposition de première exécution qui vous demande la clé la première fois que vous l'ouvrez.

2Concepts de base

Un "projet" est un jeu

Dans ForgeaX,"projet" et "jeu" sont la même chose— un jeu en est unjeux//dossier. Un vrai dossier de jeu ressemble généralement à ceci :

  • forge.json — le manifeste du jeu. Au minimum trois champs :identifiant,nom, etentrée(en pointant le code d'entrée, par ex.src/main.ts).
  • FORGE.md — le fichier readme/aperçu du gameplay du jeu (commandes, mécanismes, rythmes de l'histoire).
  • src/ — le code du jeu. Outre lemain.tsentrée, il est généralement divisé en modules par préoccupation (par ex.joueur.ts,ennemis/,effets.ts,configuration.ts).
  • design/ · assets/ — documents de conception et actifs artistiques/audio.
  • package.json · tsconfig.json — fichiers de projet TS standard.

Lemain.tsl'entrée importe les capacités du moteur depuis@forgeax/moteur-runtime/moteur-ecs/application moteuret exporte unEntrée de jeu— le contrat par lequel le moteur charge un jeu. Pour connaître l'ensemble complet des fonctionnalités, voir « Capacités du moteur » sur levitrine.

Plusieurs jeux = plusieurs projets, commutés dans le sélecteur de projet de la barre supérieure. Pour savoir comment les scènes/niveaux sont organisés, voirScènes et éditeur.

Forge et son équipe de sous-agents

Forge (l'agent principal)est le seul à écrire directement le code du jeu — il écritjeux//src/main.ts, l'aperçurecharges à chaud, et il voit le résultat en cours pour décider de l'étape suivante. Cette boucle édition → voir → édition doit rester avec quiconque peut voir l'aperçu, c'est-à-dire Forge (voirConstruisez en discutant).

Sous-agents(par exemple, gameplay Iori, conception Suzu, récit Kotone, art Iro, construction Tsumugi) uniquement planifier/concevoir/créer des actifs/écrire des documents etne jamais touchersrc/- ils n'ont pas de retour d'aperçu en direct, donc tout code qu'ils ont écrit n'aurait rien pour le guider. Retrouvez le casting complet dansmarchéetChapitre 10 · L'équipe d'agents.

Comment fonctionne l'expédition :Forge envoie un sous-agent avec un seul appel d'outil (en formesous-agent(type="iori", tâche="…")); celui du serveur/api/sous-agentstream relie sa sortie à la conversation principale en temps réel : il s'agit de la carte de sous-agent intégrée que vous voyez dans le flux de messages. Les documents de conception d'un sous-agent sont classés dans sa propre section dans l'atelier (voirScènes et éditeur).

Qu'est-ce qu'une séance

UNsessionest la mémoire d'un agent - unajout uniquementflux d'événements (chacun est un message utilisateur / un message d'assistant / une réflexion / un appel d'outil / un résultat d'outil). Forge (principal) et chaque sous-agent gardent chacun le sien.

L'interface utilisateur divise les événements selon celui qui les a émis dans le thread principal par rapport aux sous-agents, rendant la tranche de chaque sous-agent sous la forme d'une carte intégrée. Ainsi, sur un écran, vous voyez à la fois le fil principal de Forge et ce que les sous-agents qu'il a envoyés ont réellement fait.

Utilisez le sélecteur de session dans la barre supérieure pour consulter et basculer entre les sessions passées.Changer de session ne redémarre rien- l'interface utilisateur lit simplement le flux d'événements d'un autre agent.

3Construisez en discutant

Comment décrire clairement votre idée

Plus vous êtes précis, plus Forge réussit à essayer en premier avec moins de reprises. Une bonne invite couvre généralement :

  • Genre et vue— vue de haut en bas / première personne / défilement latéral 2,5D…
  • Boucle centrale- la seule chose que le joueur continue de faire
  • Contrôles,gagner/perdre,ennemis / obstacles, et lesentir

Commencez petit, faites-le fonctionner, puis superposez la mécanique. Par exemple:

Un jeu descendant : un personnage court dans une arène, l'espace tire des balles, les ennemis continuent d'apparaître, les frappes les suppriment et ajoutent des points.

Pour un premier jeu étape par étape, voirDémarrage rapide; pour savoir ce qui est réalisable, parcourez levitrine. Pour une conception plus lourde, Forge fait appel à des sous-agents de conception (voirConcepts de base).

Regardez Forge planifier, coder et exécuter

Une fois que vous envoyez une demande, la chaîne est :

  • Comprendre + planifier— Forge clarifie l'exigence en envoyant des sous-agents de conception/gameplay pour des travaux plus lourds (voirConcepts de base).
  • Écrire du code— Forge écritlui-mêmedansjeux//src/main.ts(et ses modules split-out).
  • Rechargement à chaud— lors de la sauvegarde, le vite du moteur détecte le changement et l'aperçuremplacement à chaud du moduleen place – pas de rechargement complet, l’image se met à jour presque instantanément.
  • Voir le résultat— Forge voit le résultat en cours d'exécution via l'aperçu (qui transmet également leconsoleretour) et décide de l'étape suivante.

L'ensemble du processus est transparent : le flux de messages montre la pensée de Forge, chaque appel d'outil et les cartes des sous-agents qu'il a envoyés. Pour basculer/contrôler l'aperçu par rapport au Workbench, voirScènes et éditeur; pour savoir comment fonctionne le rechargement à chaud, voirExécuter et prévisualiser.

Itérer : ajouter des mécanismes, ajuster la sensation

Pas content ? Continuez à parler : chaque élément de retour devient un autre changement, visible instantanément via un rechargement à chaud :

Balles plus rapides, double santé de l'ennemi, fond nocturne.

L'aperçu alecture/pause/rechargementdes contrôles pour tester au fur et à mesure ; pour épingler l'aperçu à un jeu spécifique, activez le sélecteur de projet (voirOuvrez le studio, apprenez l'interface).

La boucle de base estdécrire → générer → jouer → décrire à nouveau. Exécutez-le en douceur et vous passez d'une phrase à un jeu jouable - l'intégration complète est en coursDémarrage rapide.

4Scènes et éditeur

Fenêtre d'aperçu et établi

La zone principale de droite bascule entre deux vues :

  • Aperçu— votre jeu s'exécute en direct dans une iframe, avec une lecture FPS et des commandes de lecture/pause/rechargement. Lorsque Forge écrit du code, il se recharge instantanément à chaud (voirConstruisez en discutant).
  • Établi— un navigateur de fichiers + un éditeur : affichez/modifiez/enregistrez du texte et du code, restituez des documents de conception markdown et prévisualisez des images, des modèles audio, vidéo et 3D. Il fait également apparaître l'activité des fichiers et les verrous « qui édite », de sorte que vous et l'IA modifiez les mêmes fichiers sans vous encombrer.

En l'absence de fichier ouvert, l'atelier affiche les entrées pour chaque atelier de création (personnage / animation / 3D / scène / UI / musique…) — voirOutils de créationet lemarché. Pour créer des actifs, voirActifs.

Modifiez la scène, les modifications reviennent en direct

L'éditeur de scène enregistre le contenu d'un niveau dans unfichier de données de scènedans le dossier du jeu (scène.pack.json) - lesource unique de véritépour ce niveau : ce qui est sur le disque est ce qui s'exécute dans le jeu.

Lorsque vous placez des objets et quittez le mode édition, les modifications sontvidés sur le disque et le jeu en cours les relit, de sorte que l'aperçu reflète immédiatement vos modifications - l'aller-retour édition → lecture. À l'inverse, lorsque Forge modifie le code par chat, il emprunte le même chemin de rechargement à chaud (voirConstruisez en discutantetExécuter et prévisualiser).

Organisez vos niveaux et vos objets

Un jeu peut avoirplusieurs scènes / niveaux, chacun ses propres données de scène, commutées et réutilisées selon les besoins — la démo "Cow Survivor" bascule entre un pâturage de jour et un cimetière de nuit (voir levitrine).

Comment organiser :objetsvivre dans les données de la scène, tandis queressources artistiques/audiolive dans le dossier du jeu (disposition du projet dansConcepts de base, génération d'actifs dansActifs). La division par scène permet de maintenir un jeu en pleine croissance.

5Atouts : art / animation / audio

Portraits et retournements de personnages

Utilisez leéditeur de personnages(caractère wb) pour la conception du concept de personnage : rédigez un brief d'une ligne, obtenez unportrait + retournement. Aucune compétence en dessin n'est nécessaire pour obtenir un personnage prêt à jouer.

Ses sorties (un manifeste de personnage + un portrait/revirement) sont stockées par personnage dans votre jeu etalimenter directement l'atelier d'animation en tant qu'entrée en aval- donc "concevoir le personnage → le faire bouger" est un pipeline continu (voir l'élément suivant).

Chaque établi est un panneau plus un ensemble d'outils ; vous-même et l'IA par expédition modifiez le même artefact. Liste complète dans lemarchéet letutoriel sur les établis.

Faire bouger les personnages (2D / 3D)

2D :l'atelier d'animation (wb-anim) utilise le portrait du personnage comme modèle et le transforme en mouvements de marche, d'attaque, dans quatre directions, voire en clips courts -sans dérive du visage, donc il reste le même personnage une fois qu'il bouge.

3D :le moteur prend en charge nativementanimation squelettique- importez un modèle truqué et skinné ainsi que des clips d'animation depuis FBX, avec des fondus enchaînés fluides entre ralenti/marche/course/cast/mort. Ce pipeline est réel et expédié — c'est ainsi que se déplace la sorcière dark-fantasy de la vitrine : voirle jalon de l'animation squelettiqueet levitrine (Hellforge).

Modèles 3D, VFX, UI, musique

Au-delà des personnages, il existe des ateliers tout au long du pipeline :

Modèles 3D

Éditeur de caractères en blocs (wb-lowpoly-obj, exporte sans moteur.glb), graphe de nœuds low-poly (wb-3d-lowpoly), et texte/image/multi-vue en 3D (wb-gen3d, indépendant du fournisseur). Détaillé dansChapitre 9 · Modélisation et génération 3D.

VFX / scènes / UI / éléments

VFX de compétence (wb-compétence), la génération de scènes et les ressources de scène 2D (générateur de scène wb/wb-2d-scene-asset-générateur), l'atelier UI (wb-ui, prototypes cliquables) et icônes d'éléments (articles wb, art + données dans un seul tableau). Détaillé dansChapitre 9 · Scènes / UI / éléments.

Musique / look / narration

Musique et SFX (wb-bgm, une chronologie BGM), l'étalonnage des couleurs (wb-look, palette + LUT + post-traitement) et narration (wb-récit, 117 genres × 9 modèles). Détaillé dansChapitre 9 · Récit / musique / look / équilibre.

La couverture article par article est en coursChapitre 9 · Outils de création, letutoriel sur les établis, et lemarché.

Modes d'application Web et de bureau

La même base de code s'exécute sous trois formes :

  • Développement Web—chignon fx démarrerdémarre trois services (serveur/interface utilisateur/moteur) ; ouvrirhttp://localhost:18920dans un navigateur, modifie le rechargement à chaud en direct. Fonctionne sur macOS/Linux/Windows. Installer dansAvant de commencer.
  • Développeur de bureau—Application de démarrage Bun FXouvre une fenêtre native chargeant le même serveur de développement, avec une source live et un HMR identiques ; exécutez d’abord les installations automatiques et démarrez la pile, la fermeture de la fenêtre l’arrête. Disponible sur macOS/Linux/Windows.
  • Desktop .app (emballé)—application de création de bun fxproduit un autonome.app/.dmgqui fonctionne en double-clic avec son propre side-car (ports 18810/15273, délibérément décalés par rapport aux 18900/15173 du développeur afin que les deux puissent coexister) ; sa clé réside dans~/ForgeaxProjects/.env, avec une superposition de première exécution. L'emballage est enPublier et partager.

Les trois ports sont remplaçables dans.envviaFORGEAX_{SERVEUR,INTERFACE,ENGINE}_PORT. ⚠️ La fenêtre du bureau utilise le système WebView, donc la 3D fonctionne sur le WebGPU de WebKit – un peu plus faible que celui de Chrome.Pour les meilleurs visuels, utilisez le navigateur.

Rechargement à chaud : voyez-le lorsque vous le modifiez

Enregistrez et cela prend effet – pas d’actualisation manuelle :

  • Modifiercode de jeu(jeux//src/…) → le moteur remplace à chaud le module en place et l'aperçu se met à jour instantanément (les modifications de Forge utilisent également cela - voirConstruisez en discutant).
  • Des changements dansmonteur de scènevider sur le disque et revenir dans le jeu en cours (voirScènes et éditeur).
Dépannage courant
  • Aperçu vide / erreur moteur— le moteur n'est pas construit ; rediffusionconfiguration du chignon fx.
  • Erreur SSL activée:18920— accès viahttp://localhost(WebGPU fonctionne toujours sur localhost).
  • Port utilisé— un port occupé génère une erreur (il n'en sélectionnera pas automatiquement un autre) ; courirchignon fx arrêteralorschignon fx démarrer, ou changez de port dans.env.
  • Le chat ne dit pas de clé API- ensembleANTHROPIC_API_KEYdans.env(l'application de bureau vous le demande lors de la première exécution) ; la configuration des clés est en coursAvancé.
  • La 3D semble plus faible sur le bureau— une limitation du WebGPU du système WebView ; utilisez la version du navigateur Chrome pour un meilleur rendu.

7Publier et partager

Package en tant qu'application de bureau

application de création de bun fxregroupe l'ensemble du studio avec votre jeu dans unensemble de bureau autonome(macOS.app/.dmg) : un runtime réduit, le serveur, l'interface utilisateur du Studio, la place de marché et le contenu de votre jeu sont tous à l'intérieur, donc ils'exécute en double-clic sans configurationpour l'utilisateur.

Il fonctionne sur un side-car intégré sur ses propres ports (18810/15273), de sorte qu'il n'entre jamais en collision avec votre pile de développement (voirExécuter et prévisualiser). Le packaging doit fonctionner sur macOS ; le emballé.apps'ouvre par double-clic.

Partagez votre projet de jeu

Un jeu en est unautonomejeux//dossier(forge.json+src/+ documents de conception + ressources, voirConcepts de base). Partagez ou validez ce dossier et quelqu'un d'autre l'ouvrira dans son studio pour continuer à jouer ou à construire - la bibliothèque de démonstration stocke plusieurs jeux côte à côte (fps, hellforge, cow-survivor, shoot-opt), voir levitrine.

Pour l'instant, le moyen le plus fiable de proposer une partie aux joueurs est lepaquet de bureauau-dessus de; une « publication Web/lecture en ligne en un clic » plus fluide est toujours en préparation.

8Avancé

Changer/configurer le backend IA

Changer de backend (échanger la puce) :choisissez le noyau à partir du commutateur backend en bas à droite du compositeur ou sous leCLIsection des paramètres -Claude Code (par défaut) / Codex / Curseur / forgeax-native. La section CLI montre chaque backendsantéet unTestbouton. Changer de backend permute également son personnage par défaut (voirL'équipe des agents); détails par backend dans lemarché.

Clés / modèles :définissez la clé API de votre modèle (par ex.ANTHROPIC_API_KEY) sous Paramètres → Clés - ils'applique en direct, pas de redémarrage(vous pouvez également modifier.envdirectement); choisissez le modèle sous Paramètres → Modèles. Le dépannage de clé manquante est en coursExécuter et prévisualiser.

Écrivez votre propre plugin Workbench

Presque toutes les fonctionnalités de ForgeaX sont unplugin chargé à l'exécution(aperçu dans lemarché), afin que vous puissiez ajouter le vôtre.

Le chemin le plus rapide aujourd’hui :copier un plugin workbench existant et l'adapter, avec leauteur du plugin(wb-plugin-auteur) aider ; un éditeur visuel intégré à l'application plus complet (arborescence de fichiers + éditeur de code, sauvegarde → rechargement automatique) est en route. Une fois construit, activez-le et réorganisez-le dans lepanneau d'administration— les plugins sont montés par la CLI au moment de l'exécution. Voir les types d'établis dansOutils de création.

Personnaliser les personnages des agents

Utilisez leéditeur de personnages(personnage-agent-wb) : choisissez un agent dans la liste, modifiez son personnage dans une zone de texte, etsauvegarder → recharger à chaud, pas de redémarrage. Vous pouvez donner à un agent un personnage ou une voix différente sans toucher à aucun code.

Pour savoir qui sont les agents principaux et les sous-agents et d'où viennent les personnages par défaut, voirConcepts de baseetL'équipe des agents; le casting complet est dans lemarché.

9Outils de création (ateliers)

Personnage / animation / VFX
wb-character · éditeur de personnages

Conception du concept du personnage : un brief en une ligne → portrait + retournement. Il y a plusieurs pipelines...faire demi-tour(trois vues),personnage vidéo(retournement → mouvement vidéo AI → extraction d'image → exportation de feuille de sprite), etgénération de monstres(Sprites de monstres à 8 directions × 5 animations). Aucune compétence en dessin n'est nécessaire ; la sortie alimente ensuite l'atelier d'animation (voirActifs).

wb-anim · animation

Utilise un portrait de personnage comme modèle et le fait bouger :pixel à quatre directions, animation de véhicules, sprites de monstres, reliure au dos, génération de courtes vidéos—sans dérive du visage, donc ça reste le même caractère. Panneau intégré avec une fenêtre centrale. Les personnages 3D utilisent le pipeline squelettique natif du moteur — voir lejalon de l'animation squelettiqueetActifs.

wb-skill · compétence / VFX

Édition de l'arbre de compétences + aperçu VFX, répertoriant vos compétences et vos effets en un seul endroit. L'idée clé :les clics du joueur et l'envoi de l'IA partagent une spécification de compétence— les effets s'attachent automatiquement au "moment du lancement", pas d'alignement manuel.

Modélisation et génération 3D
wb-lowpoly-obj · éditeur de caractères en blocs

Construirepersonnages 3D en blocs truqués: soit "vibrez-le" (disons une ligne, générée par l'IA), soit éditez-le à la main (gizmo de style Blender), avec un terrain de jeu intégré pour un aperçu en direct. Exportationsmoteur neutre.glbutilisable dans n'importe quel moteur.

wb-3d-lowpoly · générateur low-poly

Construisez des accessoires/actifs mécaniques 3D avecprogrammation de nœuds("wire up block") : modélisez le processus sous forme de graphe de nœuds, modifiez un paramètre, régénérez l'ensemble. Idéal pour les actifs à surface dure paramétriques, réutilisables et par lots.

wb-gen3d · Génération 3D

Un atout 3Dpoint d'entrée de génération: choisissez un service de génération et donnez une entrée (texte / image / multi-vue), et obtenez undurable, prêt pour le jeuManifeste d’actifs 3D. Branché sur plusieurs générateurs de premier plan pour que vous choisissiez celui qui est le meilleur – pas de dépendance à un seul fournisseur.

Scènes/interface utilisateur/éléments
wb-scene-generator · générateur de scène

Assemblez une scène de jeu entière avecprogrammation de nœuds: présenter la composition, le placement et la texturation sous forme de graphique ; réexécutez à tout moment pour régénérer la scène complète. Pour savoir comment les scènes/niveaux sont organisés, voirScènes et éditeur.

wb-2d-scene-asset-generator · Ressources de scène 2D

Également la programmation de nœuds, pourgénération par lotsles petites choses dans une scène - accessoires, textures, décorations, éléments d'interface utilisateur - puisautomatiquement nommé et classéafin que les actifs ne se transforment pas en désordre.

wb-ui · Atelier UI

Générer une interface complète définie pargenre, déroulement de l'écran et style visuel- Plans d'interface utilisateur, actifs de composants etprototypes interactifs cliquables(pas seulement des images). Menus, boutons et barres de santé en une seule fois.

wb-items · éléments / icônes

Faites du jeuobjets et icônes— pixel art pour les armes, potions, pièces de monnaie — avec leurs données jointes.Art et données dans une seule table(articles.json) que vous et l'IA modifiez ensemble, afin qu'ils ne se séparent jamais.

Récit / musique / look / équilibre
wb-narrative · atelier narratif

Un pipeline narratif basé sur l'IA : d'une étincelle à une histoire et un monde complets. Il couvre117 genres × 9 modèles de pipelineavec un routage par niveau/mode et un planificateur dynamique — l'IA choisit l'approche et les étapes adaptées à votre genre.

wb-bgm · musique / musique de fond

Gérer le jeumusique et effets sonores: une chronologie de musique de fond présentant ce qui est joué au cours d'une session, ainsi que les conventions de dénomination des effets sonores - la partition entière séquencée sous forme d'une seule liste.

wb-look · couleur / look-dev

Unifiez l'ensemble du jeuambiance de couleur— palette + LUT + une pile de post-traitement, comme un filtre sur l'ensemble du jeu : crépuscule chaud, nuit froide, commutés en un clic pour que l'ambiance visuelle s'enclenche en une seule.

wb-balance · équilibre

Testez automatiquement si les chiffres sontéquilibré: il pilote la resimulation de combat (équilibre-resim) sur N essais et tableaux de bordtaux de victoire + un intervalle de confiance de 95 %, puis des boucles avec des ajustements manuels - laissez les données juger du réglage. Cette resimulation est aussi unOutilsur le marché.

Outils système et auteurs
wb-code · code

Parcourir etsauter à traverssrc/fichiersdirectement sur l'établi,collaborer avec l'agent de codage sur les fils de discussion— vous lisez où, l'IA édite où, sur un projet sans lâcher le témoin.

wb-observatory · observatoire

Comme unboîte noire: relecture en direct + hors ligne de chaque tour d'agent/sous-agent, appel d'outil et tranches de l'invite système. Quand quelque chose se brise, tu peuxidentifier quelle étape ou quelle invitel'a causé, et cela aide à gérer le contexte/les compétences/les garde-corps/le cache. Le concept de session & replay est en placeConcepts de base.

wb-agent-persona · éditeur de personnages

Choisissez un agent dans une liste, modifiez son personnage dans une zone de texte etsauvegarder → recharger à chaud, pas de redémarrage. Donnez à un agent un nouveau personnage ou une nouvelle voix sans toucher au code. Le casting est enL'équipe des agents; le comment faire est dansAvancé.

wb-plugin-author · auteur du plugin

Permetnon-codeurscréer leurs propres plugins d'atelier. Le chemin aujourd'hui est "copier un existant + adapter + enregistrer les actions" ; un éditeur visuel intégré à l'application plus complet (arborescence de fichiers + éditeur de code, sauvegarde → rechargement automatique) est en route. La marche à suivre globale est dansAvancé · Écrivez votre propre plugin.

admin · Panneau de contrôle

Celui du studioconsole principale, en quatre sections : activer/réorganiser les ateliers, lier les modèles, vérifier l'authentification et la santé de chaque backend IA et consulter le nombre de plugins. Resté synchronisé avec le panneau Paramètres : chaque statut de plug-in et de modèle sur un seul écran.

Tous ces éléments sontplugins chargeables; le catalogue complet et filtrable se trouve dans lemarché, et un didacticiel pas à pas se trouve dans letutoriel sur les établis.

10L'équipe des agents

Réalisation & architecture

Arin · producteur— un producteur polyvalent qui coordonne le design/le code/l'art/l'audio et possède l'ensemble du jeu.

Reia · directeur de bobine- réalisateur FMV interactif qui crée des invites, rythme les QTE et tisse des branches et des fins, conduisant le wb-reel Reel Studio à transformer une idée en un film à suspense cliquable et jouable.

Ce sontagents nommésexpédié à la demande par Forge (la relation principal/sous-agent est enConcepts de base); le casting complet est dans lemarché.

Quatre piliers de conception
Iori · 核心玩法师— pilier du gameplay

Nommé d'après "庵" (un rocher de montagne). Lorsque Forge l'envoie, il garde les « racines » du jeu – en définissant quelquespiliers de jeu porteurs(mécanique + squelette numérique) qui ne devrait pas être secoué avec désinvolture, capturé dans un document pilier concis. Il n'écrit pas l'architecture, n'ajuste pas les paramètres et ne pose pas de questions (Forge s'en est occupé dès le départ). Une fois pilieré, Suzu prend le relais.

Suzu · 体验设计师— rythme et expérience

Nommé d'après "鈴" (un carillon éolien — rythme). Une fois qu'Iori a défini les piliers, Suzu développe les modules de chaque pilier en une expérience concrète :rythme des joueurs, HUD, intégration. Elle définit ce que l'on ressent en jouant, puis confie les parties nécessitant des atouts/une histoire à Iro/Kotone.

Kotone · 剧情师— récit (sur demande)

Nommé d'après "琴音" (une histoire portée par des ficelles).Tous les jeux n'ont pas besoin d'un concepteur narratif— un tower defense pourrait ne jamais l'appeler ; ce n'est que lorsque le jeu a besoin de personnages/dialogues/branches/narration que Forge la fait intervenir pour produire le monde, les biographies des personnages et les lignes.

Iro · 美术师— ressources visuelles (sur demande)

Nommé d'après "色" (tout ce que l'œil perçoit). Une fois que Suzu a cadré l'expérience d'un module, Forge envoie Iro uniquement s'il a besoin d'actifs visuels (personnages/scènes/UI/VFX). Comment ces actifs sont réellement créés : voirActifsetOutils de création.

Ces spécialistesseulement le plan et la conception – ils ne touchent jamais au code du jeu(Forge écrit du code, voirConcepts de base); leur sortie atterrit dans l'établi (voirScènes et éditeur), et les actifs artistiques sont produits comme dansActifs.

Équipe de codage et de révision
cc-coder · 通用编码— spécification → code

Prend les piliers du gameplay d'Iori, les flux UX de Suzu et les grandes lignes narratives de Kotone et les transforme en TS/React exécutables, etc. ; peut exécuter plusieurs instances sur différents packages en parallèle. Remarque : le code principal du jeu est toujours écrit par Forge lui-même, en boucle fermée avec l'aperçu (voirConcepts de base); cc-coder est davantage destiné au code général/environnant.

Tsumugi · 工程师— construire/chaîne d'outils

Nommé d'après "紡" (tissage de fils dans un système). Une fois qu'Iori/Suzu/Iro ont préparé la conception et les actifs, Tsumugi les intègre dans une version fonctionnelle : construction, chaîne d'outils, déploiement.

Yevi · 审查– chasseur de dettes technologiques

Une observatrice gracieuse, calme comme l'eau profonde, toujours avec une longueur d'avance : elle sait où le code est le plus faible et quel problème vieux de trois semaines est sur le point de faire surface. Un ton mesuré et doux, avec une formulation précise et incisive.

Personnages de compagnon— même compétence, caractère différent

Un ensemble de caractères facultatifs aveccompétences de codage comparables mais personnalités distinctes– certains mesurés, certains ludiques, certains méticuleux. Ils ont la même capacité ; la seule différence est la sensation de travailler à leurs côtés. Les personnalités sont modifiables à tout moment danséditeur de personnages(voirAvancé); le casting complet est dans lemarché.

Il y a aussi un ensemble deagents spécialisés en art/actifs(personnage/animation 2D, low-poly/VFX 3D, réalisateur de film interactif, et plus), chacun étant connecté à son atelier de création correspondant (voirOutils de création).

Personnages par défaut échangeables

Chaque backend CLI est livré avec un personnage prêt à l'emploi :Claude(ClaudeCode),Manuscrit,Curseur, etForgeaX(le forgeax natif auto-construit).Le changement de backend permute le personnage par défaut – aucune configuration nécessaire; quel que soit le noyau que vous choisissez, il est livré avec son personnage par défaut.

Comment changer de backend et modifier les personnages est disponibleAvancé; le casting complet de l'agent et les personnages chargeables sont dans lemarché.
